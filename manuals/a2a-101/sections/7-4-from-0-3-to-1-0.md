# 从 0.3 到 1.0

> 1.0 版重命名了每个操作，改变了每个枚举值，把 card 和 part 扁平化，并拒绝没有 `A2A-Version` 的请求，所以 0.3 客户端需要一个兼容层。

kit 的错误场景发送了两个 0.3 客户端今天会发送的请求。一个省略了 `A2A-Version`，得到 `VersionNotSupportedError`。另一个调用 `message/send`，得到 `MethodNotFoundError`。读完本节后，你能把 0.3 请求映射到它的 1.0 形式，并在参考 SDK 中开启 0.3 兼容层。

```listing
title: a 0.3 method name on a 1.0 endpoint
source: capture/out/11-errors.http
lang: http
note: The third record of the error scenario. The message in the params is cut.
---
POST /a2a/jsonrpc HTTP/1.1
Host: localhost:41241
Content-Type: application/json
A2A-Version: 1.0

{
  "jsonrpc": "2.0",
  "id": 3,
  "method": "message/send",
  …
}

HTTP/1.1 200 OK
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 3,
  "error": {
    "code": -32601,
    "message": "Method not found"
  }
}
```

## 前后对比 {#s-from-0-3-to-1-0-before-and-after}

项目的迁移指南列出了这些变更 {{docs whats-new-v1}}，因为重大的破坏性变更必须在单独的文档中附带迁移指导 {{spec §1.4}}。表中保留了会影响代码的变更。

| 方面 | 0.3 | 1.0 |
|---|---|---|
| 方法名 | `message/send`、`tasks/get`、`tasks/resubscribe` | `SendMessage`、`GetTask`、`SubscribeToTask`，在每种绑定上使用同一个 PascalCase 名称 {{spec §9.1}} |
| 推送配置方法 | `tasks/pushNotificationConfig/set`，以及 `/get`、`/list`、`/delete` | `CreateTaskPushNotificationConfig`，以及 `Get`、`List`（复数 `Configs`）、`Delete` |
| 扩展 card | `agent/getAuthenticatedExtendedCard`，REST `GET /v1/card` | `GetExtendedAgentCard`，REST `GET /extendedAgentCard`，没有 `/v1` 前缀 |
| 任务状态 | `"working"`、`"input-required"` | `TASK_STATE_WORKING`、`TASK_STATE_INPUT_REQUIRED` {{proto TaskState}} |
| 角色 | `"user"`、`"agent"` | `ROLE_USER`、`ROLE_AGENT` {{proto Role}} |
| Part 形状 | `TextPart`、`FilePart`、`DataPart`，各带 `kind` | 一个 `Part`，由其 `text`、`raw`、`url` 或 `data` 成员表明类型 {{proto Part}} |
| 文件字段 | `file.mimeType`、`file.name`、`file.fileWithUri` | `mediaType`、`filename`、`url`，扁平地放在 part 上 |
| 流帧 | `"kind": "status-update"` | 一个 `statusUpdate` 或 `artifactUpdate` 成员 {{proto StreamResponse}} |
| 流的结束 | 最后一个状态更新上的 `final: true` | 由绑定关闭流 |
| Card 端点 | `url`、`protocolVersion`、`preferredTransport`、`additionalInterfaces` | `supportedInterfaces[]`，每个都带 `url`、`protocolBinding`、`protocolVersion` {{proto AgentInterface}} |
| 扩展 card 标志 | `supportsAuthenticatedExtendedCard` | `capabilities.extendedAgentCard` |
| Card 安全 | `security` | `securityRequirements`，每个都带一个 `schemes` 映射 {{proto AgentCard}} |
| 错误 | RFC 9457 problem details | 带 `ErrorInfo` 的 `google.rpc.Status`，外加 `-32008` 和 `-32009` {{spec §5.4}} |
| 版本请求头 | 无 | 每个请求上都有 `A2A-Version: 1.0` {{spec §3.6.1}} |

```listing
title: the five card fields that moved
source: research/sources/docs.md
lang: json
note: The 0.3 card example from the migration guide. The first four fields became supportedInterfaces, and the fifth became capabilities.extendedAgentCard.
---
{
  "protocolVersion": "0.3",
  "url": "https://agent.example.com/a2a",
  "preferredTransport": "JSONRPC",
  "supportsAuthenticatedExtendedCard": true,
  "additionalInterfaces": [...]
}
```

指南漏掉了一项变更。0.3 的标志 `blocking` 默认为 false，所以发送会立即返回。替代它的 `returnImmediately` 默认也是 false，所以现在发送会等待 {{proto SendMessageConfiguration}} {{spec §3.2.2}}。[SendMessage](#s-send-message) 一节展示了两种模式。

## 缺失的请求头 {#s-from-0-3-to-1-0-the-missing-header}

agent 必须把空值读作 0.3 版 {{spec §3.6.2}}。于是只支持 1.0 的接口必须回答 `VersionNotSupportedError` {{spec §5.4}}，kit 就是这样做的。

各 SDK 不同。JS 和 Java 把缺失的请求头当作 0.3，并在每种绑定上拒绝它 {{sdk-js src/server/version.ts at v1.3.0}} {{sdk-java server-common/src/main/java/org/a2aproject/sdk/server/version/A2AVersionValidator.java at v1.4.0.Final}}。Python 在 JSON-RPC 和 REST 上这样做 {{sdk src/a2a/utils/version_validator.py}}，Rust 只在 JSON-RPC 上这样做 {{sdk-rust a2a-server/src/jsonrpc.rs at a2a-server-lf-v0.5.1}}。Go 从不读取该请求头，.NET 接受缺失的请求头 {{sdk-go a2a/svcparams.go at v2.6.0}} {{sdk-dotnet src/A2A.AspNetCore/A2AJsonRpcProcessor.cs at v1.0.0-preview2}}。[版本请求头](#s-version-and-extension-headers)一节有完整的表格。

## 各 SDK 中的 0.3 兼容层 {#s-from-0-3-to-1-0-the-0-3-layer-in-each-sdk}

在过渡期间，服务器可以同时接受请求消息的旧形式和当前形式 {{spec §A.2}}。

- **a2a-python 1.2.2。** 向 `create_jsonrpc_routes` 和 `create_rest_routes` 传入 `enable_v0_3_compat=True`，并在 card 上添加一个 `protocolVersion` 为 `0.3` 的 `AgentInterface` {{sdk src/a2a/server/routes/jsonrpc_routes.py}} {{sdk src/a2a/server/routes/rest_routes.py}}。分派器按方法名路由，所以 `message/send` 在版本检查之前就到达 `JSONRPC03Adapter` {{sdk src/a2a/server/routes/jsonrpc_dispatcher.py}}。对于 gRPC，它在旧包 `a2a.v1` 上添加 `CompatGrpcHandler` {{sdk src/a2a/compat/v0_3/grpc_handler.py}}。客户端不需要开关：`ClientFactory` 会为低于 `1.0` 的接口选择一个兼容传输 {{sdk src/a2a/client/client_factory.py}}。
- **a2a-js 1.3.0。** 在每个处理器上设置 `legacyCompat: { enabled: true }`。它按 `A2A-Version` 路由，缺失的请求头视为 `0.3` {{sdk-js src/server/express/json_rpc_handler.ts at v1.3.0}}。
- **a2a-go 2.6.0。** 在独立的 URL 下挂载来自 `a2acompat/a2av0` 的第二个处理器，并公布第二个接口。它按 URL 路由，从不按请求头路由 {{sdk-go a2acompat/a2av0/jsonrpc_server.go at v2.6.0}}。
- **a2a-java 1.4.0.Final。** 添加 `multiversion-jsonrpc` 或 `multiversion-rest` 参考模块。它的 `VersionRouter` 把 `0.3` 或缺失的请求头发往 0.3 处理器 {{sdk-java docs/content/dev/compatibility.md at v1.4.0.Final}}。
- **a2a-dotnet 1.0.0-preview2。** 调用 `MapA2AWithV03Compat` 而不是 `MapA2A`。它按 `A2A-Version` 路由 {{sdk-dotnet src/A2A.V0_3Compat/V03ServerCompatEndpointExtensions.cs at v1.0.0-preview2}}。
- **a2a-rs 0.5.1。** 没有 {{sdk-rust a2a-client/src/factory.rs at a2a-server-lf-v0.5.1}}。

## 迁移指南错在哪里 {#s-from-0-3-to-1-0-where-the-migration-guide-is-wrong}

proto 是规范性的 {{spec §1.4}}，所以当指南给出 proto 所没有的字段或值时，要以 proto 为准。

- 指南把流成员命名为 `taskStatusUpdate` 和 `taskArtifactUpdate`。proto 中是 `statusUpdate` 和 `artifactUpdate`（[冲突 D9](#s-ref-sources)）。[PR #2056](https://github.com/a2aproject/A2A/pull/2056) 在 v1.0.1 之后于 main 上修正了这一点，尚未发布。
- 指南添加了 proto 所没有的 `Task.createdAt`、`Task.lastModified`、`configId` 和 artifact 的 `index`（[冲突 D10](#s-ref-sources)）。同一个 PR 移除了除 `index` 以外的全部字段。
- 附录 A.2.2 把旧标志称为 `supportsExtendedAgentCard`。指南和 SDK 写的是 `supportsAuthenticatedExtendedCard`（[冲突 D40](#s-ref-sources)），main 上没有修正。
- 指南把扩展放在 `agentCard.extensions`。proto 把它们放在 `capabilities.extensions` {{proto AgentCapabilities}}，正如[扩展](#s-extensions)一节所解释的。

## v1.0.1 之后 {#s-from-0-3-to-1-0-after-v1-0-1}

没有比 `v1.0.1` 更新的标签。自该标签以来，main 上只有一处 proto 变更：gRPC `url` 的注释，现在是 `hostname:port`（[PR #1997](https://github.com/a2aproject/A2A/pull/1997)），它解决了 D34。这是待发布的 1.0.2 版中唯一的条目（[PR #2072](https://github.com/a2aproject/A2A/pull/2072)）。main 上的文档提交解决了 D8、D9、D12 和 D32，以及 D4、D5、D6、D10 和 D23 的一部分（[冲突登记表](#s-ref-sources)）。main 还添加了关于任务内授权范围的 §7.6.4（[PR #2081](https://github.com/a2aproject/A2A/pull/2081)），[安全方案](#s-security-schemes-and-in-task-authorization)一节引用了它。

`dev-1.1` 分支改变了任务记录。`Task.generation` 计数每次状态变化，`GetTaskRequest.currentGeneration` 让客户端可以等待下一次变化。`SendMessageConfiguration.ifGenerationMatch` 让发送成为有条件的，过时的值会得到 `TaskGenerationMismatchError`，即 `-32010`（[PR #1810](https://github.com/a2aproject/A2A/pull/1810)）。`Task.history` 被弃用，改为由消息和状态组成的 `timeline`（[PR #2129](https://github.com/a2aproject/A2A/pull/2129)）。这些都还没有发布，也没有公布 1.1 的日期。

```takeaways
- 在每个请求上发送 `A2A-Version: 1.0`，并在 0.3 客户端依赖 `blocking: false` 的地方设置 `returnImmediately`。
- 在旧客户端仍然存在期间，开启 SDK 的 0.3 兼容层，并在 card 上添加一个 `0.3` 接口。
- 当迁移指南给出 proto 所没有的字段时，以 proto 为准。
- 在有标签包含 `generation` 和 `timeline` 之前，把它们视为未发布。
```
