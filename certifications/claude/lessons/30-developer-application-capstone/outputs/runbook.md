# 订单状态 Assistant 运行手册

## 服务目标

返回经过验证的订单状态或明确的升级处理结果，同时不泄露机密、不跨越租户边界，也不执行变更操作。

## 首次响应

1. 识别追踪记录或请求 ID。
2. 在重试前对故障进行分类。
3. 确认是否执行过任何 Tool。
4. 检查权威订单状态。
5. 当可能存在安全风险或跨租户访问时，限制受影响的能力。

## 故障类别

### 订单 ID 缺失或格式错误

- 响应：请求准确的公开 ID。
- 重试：只能由用户发起。
- 验证：未运行任何查询 Tool。

### 完整响应返回前 Provider 超时

- 响应：将本次尝试标记为未完成。
- 重试：如果未发生 Tool 副作用，则使用有界退避重试一次。
- 验证：检查追踪记录中是否存在完整的终止事件和 Tool 操作。

### 速率限制

- 响应：根据服务目标，将请求加入队列或返回明确的暂时不可用状态。
- 重试：遵循 Provider 指引并使用有界退避。
- 验证：没有重复的 Tool 操作。

### 协议或 schema 错误

- 响应：不要将部分输出作为最终结果显示。
- 重试：仅在重建有效消息状态后，或在有界结构化输出修复策略范围内重试。
- 验证：通过契约测试和线上追踪记录识别已修复的边界。

### 策略拒绝

- 响应：保留拒绝结果，并说明安全的下一步。
- 重试：仅在获得有效的外部批准或修正为低风险请求后重试。
- 验证：禁止使用的 Tool 未执行。

### 未找到订单

- 响应：不要猜测状态；升级至已批准的支持路径。
- 重试：仅使用修正后且经过身份验证的标识符重试。
- 验证：查询使用的是当前用户获授权的订单范围。

### Tool 不可用

- 响应：说明当前无法验证状态。
- 重试：执行一次有界的只读重试，或根据服务目标加入队列。
- 验证：没有出现虚构的状态。

### 安全事件或机密泄露

- 控制：禁用受影响的 Tool、MCP server、plugin、hook 或网络路径。
- 吊销：立即轮换任何可能已泄露的凭证。
- 调查：保留经过脱敏的追踪记录，并查询权威访问日志。
- 恢复：修复失效的信任边界，并将该 fixture 添加到安全 Evaluation 中。
- 还原服务：使用最小权限进行 canary 发布并主动监控。

### Model 或配置变更后的回归

- 控制：回滚 Model、Prompt、schema、Tool、Skill、hook、plugin 或 server 版本。
- 诊断：比较成对的 Evaluation 用例和追踪记录。
- 恢复：处理具体的失效边界。
- 验证：完整的必需测试套件和安全测试套件通过后，方可恢复发布。

## 不明确变更规则

当前应用为只读。如果未来版本添加变更操作，在稳定的幂等键和记录系统对账能够证明第一次尝试是否完成之前，绝不要重试结果不明确的超时请求。

## 升级处理证据

向运维人员提供追踪 ID、故障类别、允许提供时的订单 ID、组件版本、策略决策、Tool 结果类别和当前权威状态。不要包含原始凭证、完整的私密内容或不受限制的 Prompt。
