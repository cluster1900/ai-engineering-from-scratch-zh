# 抽取审阅报告：支持政策变更

## 抽取契约

每条记录都包含政策 ID、生效日期或 `null`、区域、操作类型、阈值或 `null`、证据片段、来源版本和审阅状态。未知值可以表示，额外字段将被拒绝。

## 批处理清单

作业 `policy-w32-review` 包含 40 个输入，通过稳定的 `custom_id`、来源版本、schema `policy-change-2` 和预期输出进行关联。fixture 返回乱序结果，其中有两个依赖失败，并保留 38 条成功记录。带日期的规划假设是 Message Batches 成本降低 50%、服务窗口最长 24 小时，且不保证延迟 SLA；部署前必须重新查阅当前 API 文档。

## 验证层

语法解析通过 40/40。Schema 接受 40 条记录。语义验证拒绝了一条截止日期早于其来源生效日期的记录。溯源验证拒绝了一个证据片段中不存在的虚构阈值。

## 审阅者发现

一名独立审阅者返回了稳定的发现 `REV-017` 和 `REV-018`，其中包含字段、来源片段、原因和处置方式。审阅者没有静默改写输出。

## 裁决

具备资质的政策负责人将不受支持的阈值设为 `null`，确认截止日期例外，并记录原因代码。反复出现的歧义会被升级处理，而不是进入又一次重试。

## 指标

字段精确率：0.98。裁决后的证据支持率：1.00。高风险误报：0。审阅者分歧：40 条中有 2 条。每条已接受记录的成本：0.014 单位。
