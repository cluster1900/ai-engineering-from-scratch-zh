# 参考架构材料包：区域支持问题解决

## 1. 管理层决策

批准开展为期六周、仅支持英语且由人工审核的试点。支持运营团队负责
达成目标：将符合政策的首次响应时间从 11 分钟缩短至 3 分钟以内。
不得自动退款或删除账户。财务团队保留退款权限。安全、隐私和区域数据
负责人审批各自负责的边界。

## 2. 探索

系统对账单和配送工单进行分类，检索当前有效的区域政策，仅读取被分配的
账户，起草回复，并建议操作但不执行操作。质量目标是至少 98% 的草稿
有来源支持。P95 目标为 8 秒。非目标包括自主发送、员工排名、关闭账户，
以及支持试点范围之外的语言。

## 3. 架构决策

选择确定性的接收、检索、起草、验证和审核工作流。拒绝采用单次增强调用，
因为这会使溯源信息和故障情况混杂在一起。拒绝采用自适应 Agent，因为
正常路径已知，并且没有任何经测量的收益足以支持可变的 Tool 选择。
如果超过 20% 的已接受工单需要安全地探索未建模情况，则重新评估该决策。

## 4. 系统与数据视图

经过身份验证的接收步骤会验证工单和区域。使用元数据过滤的检索会返回
当前有效的政策 ID。受限的起草步骤会接收最小化的账户事实。Schema、
语义、溯源和政策验证器会在工单进入审核队列之前运行。每条边都携带
principal、tenant、Schema 版本、超时、错误类别、trace ID 和负责人。
证据不完整时，不生成操作建议。

## 5. RAG 与知识

政策运营团队负责版本化来源。感知标题的分块会保留规则、例外、区域、
生效日期、权威来源和访问元数据。混合检索会在排序前进行过滤。
经过验证的索引以原子方式启用；先前的索引会保留用于回滚。检索关卡
覆盖召回率、时效性、冲突、过期版本、未授权来源和对抗性内容。

## 6. 集成与身份

直接的类型化服务调用适合首次单主机试点。每次调用都会传播可信的
principal 和 tenant 声明。Tools 分为政策读取、已分配账户读取和草稿存储。
不提供退款执行功能。未来的执行器必须包含准确的 principal、账户、金额、
原因、到期时间、单次使用限制和幂等性，并与 system of record 对账。

## 7. Evaluation 与可观测性

黄金集按普通、模糊、过期、冲突、未授权、对抗性、区域性和高风险案例
进行分层。发布要求硬性控制 100% 通过、政策支持率至少达到 98%、
P95 低于 8 秒、没有高风险回归，并且每份已接受草稿的成本处于预算范围内。
Trace 会关联检索、Tool、验证、审核和结果，同时不存储凭据。

## 8. 治理

风险登记册涵盖过期政策、跨 tenant 访问、Prompt 注入、无依据退款、
不同语言之间的不公平表现以及审核人员负荷过重。每项控制都有负责人、
测试、证据、故障响应和审核触发条件。具备资质的审核人员会收到以来源
为先的证据，以及带原因代码的操作。法律、隐私、安全、财务和领域负责人
决定各自承担的义务。

## 9. 运营与移交

发布依次经过影子运行、5% canary、受控的区域扩展和完整试点。
硬性控制、任务质量、P95、时效性、审核负荷和成本告警都会指定负责人
和 runbook。运营团队会在接手前演练政策过期、授权服务中断、工单注入、
Evaluator 漂移、安全关停和回滚。
