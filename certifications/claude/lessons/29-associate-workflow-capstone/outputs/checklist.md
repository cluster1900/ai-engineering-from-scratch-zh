# Associate 工作流综合项目检查清单

使用此检查清单作为综合项目的发布记录。请用证据替换方括号中的提示。不要仅仅因为草稿看起来令人信服就将某项标记为完成。

## 星期一：目的与 Surface

- [ ] 明确说明决策、截止时间、受众和承担责任的负责人。
- [ ] 已记录允许和禁止的操作。
- [ ] 已根据组织政策对数据和后果进行分类。
- [ ] 所选 Claude Surface 已获批用于该目的和数据类别。
- [ ] 已检查当前条款、保留行为、控制措施和限制。
- [ ] 已记录核验日期以及官方或合同来源。

证据：

```text
[Surface 选择记录和政策批准]
```

## 星期二：来源与 Context

- [ ] 每个来源都有 ID、负责人、权威性、生效日期、审查日期和敏感级别。
- [ ] 已被取代或重复的材料不在主动检索范围内。
- [ ] 已明确权威性顺序。
- [ ] 所需地区或业务部门均已包含，或已标记为缺失。
- [ ] 每周来源快照和截止点已经固定。
- [ ] 冲突、过期来源和权限缺口均有负责人。

证据：

```text
[注册表版本、快照 ID、来源例外]
```

## 星期三：Prompt 与任务设计

- [ ] 已包含结果、Context、任务、证据、约束、格式和验收检查。
- [ ] 提取、协调、分析和起草是相互独立的阶段。
- [ ] 每个阶段都有可测试的输入、输出和关卡。
- [ ] 缺少证据时应拒绝作答或升级处理，而不是猜测。
- [ ] 来源内容被视为数据，而不是 Tool 授权。
- [ ] 已记录 Prompt 和工作流版本。

证据：

```text
[Prompt 版本和阶段契约]
```

## 星期四：验证与治理

- [ ] Python 验证器对候选发布版本验证通过。
- [ ] 至少三个有意设计的失败数据包已被阻止或标记为需要修订。
- [ ] 精确总数和 schema 使用确定性检查。
- [ ] 每项会产生实质影响的主张都映射到具有权威性的支持证据。
- [ ] 独立审查将发现的问题与修订内容分开报告。
- [ ] 隐私、偏见、范围和操作权限检查均通过。
- [ ] 移交前已解决所有阻塞问题。

命令与结果：

```text
python3 code/main.py
python3 -m unittest discover -s code/tests -v

[粘贴简明状态和测试数量]
```

## 星期五：移交与恢复

- [ ] 移交内容明确说明具体决策、截止时间和决策负责人。
- [ ] 包含来源快照、草稿版本和工作流版本。
- [ ] 通过的检查、失败的检查、冲突和不确定性均清晰可见。
- [ ] 提供批准、修订、拒绝和升级处理路径。
- [ ] 人工回退方案保持最新，并且已经演练。
- [ ] 外部操作与起草过程相互分离，并受到保护以防止重复执行。
- [ ] 批准后发生来源变更时会触发差异审查。

决策记录：

```text
决策：
决策负责人：
证据快照：
条件：
回退方案：
```

## Evaluation 覆盖范围

- [ ] 四个有代表性的正常案例通过。
- [ ] 三个边缘案例涵盖证据缺失、冲突或过期的情况。
- [ ] 三个治理或对抗性案例涵盖未经授权的目的、敏感数据或 Prompt injection。
- [ ] 高风险表现与总体表现分开报告。
- [ ] 一个留出案例在 Prompt 调优期间始终未被使用。
