## 本地复现步骤

```bash
node site/build.js
node site/build-projects.js --strict
node --test site/test_projects_data.js site/test_project_certificates.js site/test_project_figure_runtime.js site/test_dataset_project_figures.js site/test_budget_project_figures.js site/test_semantic_project_figures.js
python3 scripts/project_test.py --all --solution --strict --report /tmp/project-results.json
python3 scripts/audit_lessons.py
python3 scripts/audit_certifications.py
python3 scripts/check_readme_counts.py
```

本地核心测试环境使用 macOS arm64 架构上的 Python 3.12.12、Node 25.6.1、Rust 1.95.0 以及 Go 1.26.0。可选的 Python SDK 测试套件在隔离的虚拟环境中运行。各框架的版本与安装命令均在对应项目的依赖文件中严格锁定。项目远端 CI 环境配置为 Python 3.12、Node 24、Go 1.23 以及 Runner 镜像自带的 Rust 工具链；本地通过不代表远端 CI 状态。

## 浏览器端与交付产物审查

在初次验收阶段，分别在 1440×950 明亮模式和 390×950 暗色模式下对项目目录、试点项目以及文档抽取页面进行了全面视觉审查。独立打开了全部 48 个项目页面以验证动态加载机制。全部 197 个机制原理图均能正常挂载，接收输入变更并实时更新计算结果，无控制台报错。交互测试覆盖项目条件过滤、阶段导航与浏览器前进后退、保存完成状态、录像播放/暂停以及证书导入导出。

针对八个新增应用赛道产物，在 1120 像素与 390 像素宽度下逐一排查。文档评审用例精准测试了选取 Unicode 字符后的文本跨度、下载真实审批单、通过 CLI 生效并重新打开已批准页面的全流程；学习教练在浏览器中记录答题事件，并通过 CLI 将下载的答题记录正确重放为预期复习排期。

证书导入模块成功识别并拒绝了使用参考答案生成的冒充凭证，而顺利导入了学习者模式下的完整评测报告。证书为纯本地生成的社区学习凭证，不提供身份鉴权，亦无法防止用户直接抄袭代码或手工篡改 JSON。

浏览器 Agent 驱动真实 Chromium 实例完成本地 fixture 测试并截图保留证据。Rust shell 通过真实 stdin/stdout 及伪终端（PTY）完成全链路交互。试点项目研报在 Chromium 中完整验证了引用悬浮高亮及调用链路展开。终端 GIF 忠实录制命令输出；网页应用 GIF 则由实际浏览器渲染帧捕获生成。四个框架对比 GIF 明确区分了核心与扩展 SDK 的测试计数。

## 审查修复与后续复测

在应用审查意见后，提交卡片、预算项目第 4 阶段以及语义搜索第 3 阶段在 1280 像素与 390 像素下完成了 12 组多端测试。预算凭证数据更新为 `events[].status`。语义搜索原理图在可编辑示例中保留复数精确匹配，并正确将 `constructor` 与 `__proto__` 视作常规检索词进行排序。整个测试未发现页面元素溢出或控制台报错。

会议纪要生成的 HTML 在导出时完整保留批准与否决的状态勾选。混合格式的 PR 评审候选数据能生成格式一致的 HTML 与 JSON。浏览器 Agent CLI 在 4 步内顺利完成本地 Chromium fixture 测试并生成合格截图；损坏截图的失败凭证亦被单独妥善测试。在本地 fixture 上测试成功并不等同于在开放网络下的通用浏览器准确率。

回归测试套件全面覆盖了第三方供应商 HTTPS 重定向边界、网络重试后的网关请求幂等重放、有界 HTTP 连接主动释放、切分 UTF-8 请求报文体、可选云端日志窗口、原子补丁回滚、项目根目录通配符匹配以及原生系统进程终端凭据。全量评测器排查并修复了一处并发桌面 fixture 目录冲突；在最终合并前，连续 30 次端到端集成测试均顺利通过全部 150 项断言。

日程规划器保留了显式时间戳子集，包括全天事件的不包含（exclusive）结束时间；数值提取严格支持有界 Python float 语法并覆盖正常与异常用例。上述调整重在理清契约边界，而非无限放大解析器的复杂度。

## 集成与回归验证

持久化任务与分布式评测集群拉起真实子进程，按预期在边界触发崩溃，验证了本地持久化状态的完整恢复并拒绝过期完成消息。评测与网关二进制程序发起了真实的本地回环 HTTP 请求，执行调用预算、独立凭证隔离、超时截止控制以及有界报文体裁剪。Mastra 实现了在一个进程中挂起工作流并在另一进程中从持久化存储恢复执行。官方 MCP Client 通过 stdio 和 HTTP 协议与教学服务端完成了端到端连通验证。

跨项目级端到端测试包括：将已审计的数据集切分送入模型评测、将 PR 变更发现送入代码评审委员会、将已安装的 Skill 接入 Rust 校验器，以及将研报送入裁判程序。独立应用审查还复现并修复了三处新增缺陷：超大 CSV 标识符合并问题、导出时已批准抽取项丢失问题，以及复盘报告文本丢失评审元数据问题。所有回归测试全部通过。

## 适用边界与局限说明

测试过程中未直接执行 macOS 原生桌面环境控制。Fixture 后端的测试通过不代表验证了系统级辅助功能权限（Accessibility）或原生 GUI 交互。可选框架套件在本地加载真实 SDK 并配合确定性 Mock 模型；全程未发起真实的云端大模型 API 调用。语音测试验证真实 PCM/多部分 HTTP 传输协议；由于提供离线参考文本，因此不测试真实语音识别准确率。视觉搜索使用预设文本框，并非测试 OCR 识别引擎。

沙箱阶段专注于安全策略规划，未实际调用可选的 Docker 引擎。任务队列故障恢复测试基于本地文件系统的多进程协同，不涵盖分布式跨机存储。评测数据集为开源教学测试集，测试得分不代表在未知业务数据上的泛化表现。
