# 与霍格威尔德同步!

> 投机式解码将在单个序列内并行行证券――多代理框架会在整个序列之间并行行,但会强制显式协调(投票、分分类子任务) ─霍格威尔德! 推理(Rodionov et al., arXiv:2504.06261) 做了另一件事:并行运行同一个LLM的N个实例,并让它们共享一个关键值缓存――每个工作者都能立即看到其他工作者生成的代币――现代推理模型QwQ、DeepSeek-R1无需任何细节调整,就能通过这个共享缓存自我协调――这个方法仍然处于实验阶段,但它启动了推理平行的全新维度,并与规格解码正交交交――本课程使用stdlib Python实现了两个工作者Hogwild! 模拟器,并解释为什么共享缓存合作会从现有模型的推理能力中涌现出来──

**类型：**建立
**语言：**字符串 (stdlib)
**先修：**期10 · 12 ((推理优化),期10 · 15 ((投机解码)

## 学习目标

- 描述三种常见的平行LLM拓 (投票,子任务,高温!) 并说明每个针对的问题.
- 通过自动促成实现突发的协调.
- 根据工人数量`N`‧任务级平行性`p`和协调总费`c`计算霍格威尔德!的墙时速化.
- 在玩具问题上实现一个两个工人Hogwild!模拟器,并观察新兴任务分类.

## 问题

现代 LLM 通过产生长时间的推理链来解决困难问题5000代币的步骤逻辑 很常见,深度数学问题出现数万代币也没有少见.

通过单个序列内并行化,可带来3-5倍的速度.

显然问题是:我们能否跨序列并行化?在同一问题上运行相同模型的多个副本,让它们协作,让它们分工?

已有工作包括:投票集团 (运行N个模型,选择多数答案) 思考树 (分支推理路径并重新组合) 以及多代理框架 (为每个代理 分配子任务,并使用协调员) 👇 这些都能在特定任务领域提供帮助.

霍格威尔德! 推理 采用不同方法――N个工人共享一个KV缓存――每个工人都会立即看到其他工人生成的代币,就像这些代币已经在自己的背景中一样――工人在没有任何培训或细节调整的情况下,会自己弄清楚如何分工――现代推理模式 (QwQ、DeepSeek-R1、Claude-family推理模式) 能够读取共享缓存,并说出类似的我看到工人2已经处理了基案,所以我来处理诱导步的话――

截至2026年4月,速度依赖于工作负载,并且仍处于实验阶段.

## 概念

### 设置

首先,我们要建立一个员工的存储库,所有运行都与一个LLM一样.`i`生成标志`t_j`时,该代币会被写入共享缓存的下一个位置.`k`执行下一步时,它读取缓存的当前状态,其中包含到目前为止所有 N 工人生成的全部内容.

在步骤时间,工人会竞争写入代币.没有每名工人的位置指数.

### 为什么会出现协调

工作者共享一个提示.通常类似于:你是N实例之一一起解决这个问题.每个实例都会阅读共享内存,并可以看到其他实例所写的内容.避免冗余工作. 这个提示加上共享缓存就足够了.

霍格威尔德! 报纸 ((罗迪诺夫等人, 2025) 报告如下观察:

- 工人会制定计划,通过缓存将其传达给其他工人.
- 工人会注意到其他工人推理中的错误,并指出这些问题.
- 工人会在计划中 失败时适应情况并提出替代方案.
- 当要求检查裁员时,工人会检查到它并转向其他工作.

这些都不需要细节调整. 模式已经具有了推理能力.

### 命名

这篇论文的名字借用了Hogwild! SGD(Recht et al., 2011),一种异步更新优化器.类比是:SGD的异步工作者都写入一个共享参数向量;Hogwild!

### 让这变得可行的

通过Q 和 K 矢量中的旋转编码位置信息──因为位置是旋转,而不是固化的抵消,所以代币的位置可以移动,而不需要重新计算KV缓存输入──当工作者`i`写入共享缓存的位置`p`时,读取该职位的其他员工可以直接使用缓存输入不需要重转.

在学习位置或绝对位置模型中,Hogwild!会在每次同时写的时都需要缓存无效──RoPE 让缓存保持稳定──

### 墙时 数学

设 `T_serial`是一个工人 单独解决问题所需的时间.`p`是任务级平行式分数.`c`是每步协调的总费,并决定要写什么)

单职员工时间:`T_serial`,我知道.
如果协调是免费的,N-工人霍格威尔德!时间为:`T_serial * ((1 - p) + p / N)`这是经典的阿姆达尔.
加入协调总费:`T_serial * ((1 - p) + p / N) + c * steps_per_worker`,我知道.

让工人产生产量,`c`必须相对于每步解码时间 足够小.对于生成5k+代币的推理模型,工人可以承受数百代币的协调费用,并且仍然领先.对于短聊天任务,协调会占主导地位,Hogwild!会比串行更差.

### 具体示例

推理问题:10k代币的思想链――假设问题有`p = 0.7`相关内容 (不同证明策略,不同案例分析),以及每个员工的协调总费为`c = 200`标签──使用 `N = 4`工人:

- 序列时间:10000 解码步骤──
- 霍格威尔德!时间:10000 * (0.3 + 0.7 / 4) + 200 * 4 = 10000 * 0.475 + 800 = 5550 解码步骤──
- 速度:10000 / 5550 = 1.8x──

这只是中等收益. 但在更长的推理问题上,协调上层费将被摊薄,速度将推向2.5-3x.

### 什么时候使用霍格威尔德!

- 长推理问题 (数千个代币),其中任务可以跨越独立的子目标并行化.
- 已被训练为步骤思考的推理模式――非推理模式――无法很好地自我协调――
- 单节点部署,并且有足够的VRAM容量共享缓存加 N 个工作者进程──缓存是共享的,但每个工作者都有自己的激活内存──

### 什么时候不使用

- 短互动聊天――协调总费 会占主导――
- 无法并行化的任务(单一线性证明、单一编译) ――N=1 是上限――
- 不合理的模型――不会出现协调――
- 多节点部署――共享缓存 需要非常快的跨工同步――内部节点可以;跨节点会成为延迟灾难――

### 实验状态

截至2026年4月,Hogwild!是一种研究方法,并有开源PyTorch的实施――尚未出现生产采用――三个阻碍因素:

1. 跨同步过程 管理共享KV缓存是非凡的工程问题.
2. 紧急协调依赖任务;标准仍在构建中.
3. 与投机解码的收益相比,速度较温和;两者可以组合,但组合后的工程复杂性又是一层次.

值得了解.值得实验.

## 构建它

`code/main.py`实现一个玩具Hogwild!模拟器:

- 两个工人过程,每个都是确定性的LLM,将以已知概率产生几类的代币 (工作代币,观察代币,协调代币) 一个.
- 一个共享缓存,只是一个代币列表,两个工人都会读取和写入.
- 一个简单的协调逻辑:当一个工人看到另一个工人已经在某个类别中产生了足够的工作代币时,它会选择不同的类别.

模拟器会在固定阶段预算下运行,并报告:

- 产生的工作标志 总数――
- 总墙时间(工人步骤 数量) 』
- 与单身工人的有效加速.
- 哪个工人写了哪个标志的痕迹.

### 步骤1:共享缓存

一个两个工人都会添加的列表──真实实现中会使用简单锁定(Python `threading.Lock`);这里我们使用电脑模拟.

### 步骤2:工人循环

每个工人在每一步:

- 读取当前共享缓存──
- 根据已有的内容决定要写哪种代币.
- 写入一个标志.

### 步骤3:协调的论

如果类别X在缓存中已经有K个代币,并且工人原本想写的类别是X,那么工人会转换到类别Y──这是一个玩具替代,用来表示推理模式的行为:注意到已经被覆盖了,改做其他事情──

### 步骤 4:测量加速

分别使用N=1工人和N=2工人运行模拟器,使用相同的总阶段预算――统计产生的工作标志――由于协调驱动任务分类,N=2应该产生约1.5-1.8倍的工作标志――

### 步骤5:对协调施压

降低协调学的敏感性――再次运行――观察如果没有良好的协调,N=2 会有余裕产生相同的标志,速度会下降到以下1――这与纸上观察一致:这种技巧只有在工人中具有自我协调的推理能力时才有效――

## 关键术语

| Term | 人们怎么说 | 实际含义 |
|------|----------------|------------------------|
| Hogwild! | “Parallel workers, shared cache” | 同一个 LLM 的 N 个 instances 并发运行，并共享一个 KV cache；通过 self-prompting 实现 emergent coordination |
| Shared KV cache | “The coordination medium” | 一个不断增长的 KV buffer，所有 workers 都会读取和写入；让 tokens 能在 workers 之间立即可见 |
| Emergent coordination | “No training needed” | 具备 reasoning 能力的 LLMs 可以读取 shared cache，并在没有任何 fine-tuning 或显式 protocol 的情况下分工 |
| Coordination overhead (c) | “Tokens spent orienting” | 每个 worker 读取扩展后的 cache 并决定下一步做什么的成本；相对于总 decode time 必须保持较小 |
| Parallelizable fraction (p) | “What can run in parallel” | Task-level parallelism：总工作中并非内在 sequential 的比例 |
| RoPE enables Hogwild! | “Rotary positions are shift-invariant” | 因为 positions 是 rotations，写入 shared cache 不需要重新计算之前的 tokens |
| Voting ensemble | “Run N, pick the majority” | 最简单的 parallel inference topology；适用于 classification，对 long-form reasoning 帮助较小 |
| Tree of thought | “Branch and prune” | 探索多个 branches 并进行 pruning 的 reasoning strategy；使用显式 coordination logic |
| Multi-agent framework | “Assign sub-tasks” | 每个 agent 获得一个 role；由 coordinator 编排；protocol overhead 很重 |
