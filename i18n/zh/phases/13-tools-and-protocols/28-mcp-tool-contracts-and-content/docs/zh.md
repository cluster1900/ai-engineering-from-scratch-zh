## 核心问题

调用普通的Python函数很简单.但通过AI主机调用远程能力,则是一个典型的契约问题.

服务端发布描述符 (descriptor) ⋅客户端将该描述符转换为模型的上下文和用户界面――模型生成调用参数――网关可能根据镜像的HTTP标题进行请求路由――服务端执行该工具――最后,客户端决定返回结果是否足够安全有效,以返回模型――

整条调用链条中只要有一个边界存在漏洞,就会破坏整个局部.

考虑以下五种常见故障:

- 描述符声明返回结果是一个对象,但服务端实际返回一个阵列.
- 客户端在`nextCursor`为空字符串时便提前终止分页.
- 敏感的代币 参数被镜像进入HTTP标题,从而暴露在所有中间代理和日志系统中.
- 包含 Unicode 的路由值被作为原标题发送,导致网关和源站对字节序列的解析不一致.
- 自动补充全端点向一个无权访问生产环境的调用者推了生产环境的名称.

这些故障没有一个更好的解决方案.

## 契约流水线

我们将每次工具调用分为五个执行关口:

1. **发现（Discover）**读取确定性,已分页的工具列表
2. **准入（Admit）**校验每个工具描述符并执行本地安全策略.
3. **调用（Invoke）**校验调用参数并构建传输层元数据.
4. **执行（Execute）**运行工具处理函数并对错误进行正确分类.
5. **消费（Consume）**在交给模型使用之前,校验内容块与结构化输出.

## `x-mcp-header`是由元数据

在`inputSchema`内部的某种属性可以声明`x-mcp-header`在流通 HTTP 传输协议下,客户端会将该参数视图为`Mcp-Param-{name}`标题:

```json
{
  "region": {
    "type": "string",
    "x-mcp-header": "Region"
  }
}
```

当参数为`region: "eu-west"`时,传输层即可发出如下标题:

```http
Mcp-Param-Region: eu-west
```

引入该注解的目的是让负载均衡器,网关或策略引擎在无需解析完整的JSON请求体的情况下完成路由.**绝对不能**用于传递身份证或敏感数据.

协议对该注解施加了严格的约束:

- 标头名称必须非空,且符合HTTP字段名称代币语法规范;
- 标题名称在不区分大小写的前提下必须全局唯一;
- 参数属性类型只能是字符串、整数或布尔式;
- 不允许使用`number`(浮点数)
- 只有一个直接的解决方案.`inputSchema.properties`直接子节点中第一层;
- 整数取值范围必须限制在`-9007199254740991`到了`9007199254740991`它们是可用的.

位置规则是语法级别的,并且必须是安全失败的 (故障关闭) 机制.`properties`现在,`oneOf`在分支中,`items`通过`$ref`在引用的定义中,或任何输出方案中,都必须坚决拒绝.解析引用不会使引用的节点变成直接的一级属性.

本课程增加了一个部署安全策略:凡是镜像名称包含`password`,我知道.`secret`,我知道.`token`,我知道.`api_key`或`authorization`官方规则明确建议服务端作者不要镜像敏感参数,而客户端则可以将这一建议实施为严格的入口控制规则.

审计时只记录标题名称,不记录其具体数值.`Mcp-Param-Region`具体取值`eu-west`排除在审计日志之外

### 在构建HTTP标题前进行数值编码

参数值只有在满足以下条件时,才可以直接以纯文本形式在标题中传输:非空字符串,由ASCII可见字符(`!`到了`~`其他所有取值必须严格采用如下编码格式:

```text
=?base64?{Base64UTF8}?=
```

其中`Base64UTF8`绝对不要在此之前对字符串执行trim(删除首尾空格) 规范化或替换操作.`=?base64?`开始的值,都必须编码.对象象哨兵前的值进行再次编码,正是接收端能够准确恢复原始字面文本,而不会误解为传输层语法的关键保证.

值统一染为小写的`true`或`false`△整数统一以10进制字符串染染,且必须落在 JavaScript 安全整数范围内──超出该范围的数值必须直接拒绝,避免中间代理在解析时发生精确截断或舍入──

### 服务端校验镜像副本

在流通 HTTP 边界中,服务端必须:

1. 在不区分标标题名称大小写的前提下,查找所有识别出来的`Mcp-Param-*`其他
2. 如果有基地64哨兵格式,进行精确解码;
3. 将解码后的文本与对应的JSON请求体参数进行严格比较;
4. 如果发现已识别标志存在缺失,重复,未预期出现,格式错误或与请求不一致,在业务分发前直接拒绝.

拒绝应返回HTTP`400`并且JSON-RPC 错误码`-32020`△要求体的值和编码后标签形式都不属于审计记录的内容,审计记录中仅记录识别的标题名称和拒绝原因类别.

## 自动补充全是授权攻击面

`completion/complete`方法为快速参数与资源模板参数提供自动补充建议. 它在交互式表单中非常有用,但如果不加防护,可能会泄露普通列表接口所保护的敏感名称.

一个补充请求会声明引用的对象以及正在补充的参数:

```json
{
  "method": "completion/complete",
  "params": {
    "ref": {
      "type": "ref/prompt",
      "name": "deployment_review"
    },
    "argument": {
      "name": "environment",
      "value": "st"
    }
  }
}
```

返回结果最多包含100个建议值,并且可以附带`total`与`hasMore`字段.

必须在此应用中与引用的快速或资源完全一致的授权边界.`development`与`staging`只有运维人员才能收到`production`提示

生产级补充服务还需要:

- 严格的入学考试;
- 区分调用者身份过;
- 客户端防(登陆);
- 服务端限流(利率限制);
- 有界的结果数量限制;
- 在日志中避免暴露敏感的补充建议取值.

补充是辅助输入手段,绝不能成为发现权限检查的后门.

## 双层错误机制

必须将协议级错误与工具业务执行错误严格区分开来.

当MCP请求无法正确分发时,使用 **JSON-RPC error**其他:

- 未知的工具名称;
- 格式错误的请求报文;
- 缺失必要的请求元数据;
- 无效的分页游标.

运用成功到达工具,并且工具上报道是可操作的,可纠正的失败,使用带有`isError: true`的**完整工具结果（complete tool result）**其他:

- 报表数据源暂时不可使用;
- 传入日期超出了所支持的范围;
- 商业规则拒绝了所要求的操作.

大模型通常能够理解并纠正工具执行错误,但大模型无法自行纠正违反自身输出方案的服务端.

如果工具声明输出方案,应在该方案内部进行操作性失败的建模.`route_report`失败时,会在回归的人类可读错误文本和`isError: true`其他地区将其请求以`accepted: false`结构化形式一起回归.

| 故障现象 | 学习者看到的表象 | 正确处理方案 |
|---------|-----------------------|------------------|
| 客户端假定输出必定是 object | 合法的数组校验失败或被静默包装 | 依据发布的 Schema 进行校验，不假定结果必须为 object |
| 空字符串游标被当成 False 处理 | 最后一页数据意外丢失 | 只要 `nextCursor` 存在且非 null，就继续拉取下一页 |
| 镜像了敏感参数值 | 凭证密钥暴露在代理、WAF 或链路追踪日志中 | 拒绝该描述符，将机密保留在受保护的请求体内部 |
| 原始 Unicode 或空白字符直接镜像 | 网关与源站解析不一致，或值被意外规范化 | 使用 Base64 UTF-8 哨兵编码并在解码后进行比对 |
| 注解隐藏在 Schema 的复杂分支中 | 客户端在准入时漏检了路由元数据 | 遍历整棵 Schema 树，仅允许直接位于一级的属性携带注解 |
| 镜像了大整数 | 中间 JavaScript 代理对路由数值进行了舍入 | 拒绝超出 JavaScript 安全整数范围的数值 |
| 标头与请求体不一致 | 网关路由给服务 A，而源站实际执行服务 B | 在业务分发前以 HTTP `400` 和 JSON-RPC `-32020` 拒绝 |
| 忽略了输出 Schema | 下游程序消费了损坏的脏数据结构 | 在交给模型或应用程序前进行严格校验 |
| 盲目信任返回的资源链接 | 调用方直接读取了未获授权的 URI | 对每一次资源读取重新执行鉴权 |
| 自动补全共享了全局建议列表 | 多租户敏感隔离名称被泄露 | 按调用者身份、引用上下文与权限范围进行过滤 |
| 将工具注解当作安全策略 | 破坏性危险操作跳过了二次确认 | 在注解之外建立独立的授权与审批流 |
| 单个格式错误的工具搞垮整个发现流程 | 整台 MCP 服务端完全不可用 | 拒绝有问题的描述符，独立准入其余合规工具 |

## 石头

阶段13的Capstone项目需要一个能够从多端服务端集成的网关.

通过本课程的交付工具来评估Capstone的四个核心证书:

- 确定性和完整的游标分页发现过程;
- 在暴露给模型前的工具描述符校验;
- 经过校验的结构化输出与严格界定的内容块;
- 严格保护授权边界的补充与路由元数据.

不要只因为一次`tools/call`调用成功就宣称兼容网关规范――请务必捕获描述符、分页链路追踪、已准备的工具集、被拒绝的工具集,以及至少一个完整的校验通过结果――

## 关键术语

| 术语 | 含义 |
|------|---------|
| `inputSchema` | 定义工具所接受参数的 JSON Schema 对象 |
| `outputSchema` | 定义 `structuredContent` 格式的可选 JSON Schema |
| `structuredContent` | 工具执行结果所生成的任意 JSON 结构化数值 |
| 内容块（Content block） | 具备类型化标记的 text、image、audio、resource_link 或 embedded resource |
| `x-mcp-header` | 将基础类型参数镜像为 Streamable HTTP 标头元数据的 Schema 注解 |
| 不透明游标（Opaque cursor） | 服务端发出的分页标记，客户端不得解释其内部含义 |
| 补全引用（Completion reference） | 正在请求参数补全的 Prompt 名称或资源 URI/模板 |
| 准入（Admission） | 客户端根据本地策略决定公开暴露还是拒绝已发现描述符的决策过程 |
