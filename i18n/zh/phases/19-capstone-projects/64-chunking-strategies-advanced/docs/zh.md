# 分块策略比较

> 区块决定检查器能看到什么. 一旦边界错了,没有嵌入模型,重排器或LLM能在下游修好坏.

**Type:** Build
**Languages:** Python
**Prerequisites:** 第 11 阶段课程 04（嵌入）、06（RAG）、07（高级 RAG）；第 19 阶段 B 轨基础（第 20-29 课）
**Time:** ~90 分钟

## 学习目标
- 从一开始实施五种分块策略:固定窗口,句子,递归分区,语义聚类和结构性分区标题.
- 在带有黄金标签的答案范围的固定语料库上衡量回忆@k,并解释为什么一种策略适合散文,另一个策略适合技术文档.
- 读取块长度分布并识别每个策略注入的故障模式:孤立句子、中间符号剪切、仅标题块、语义漂移──
- 通过检查三个属性来选择新语料库默认值,而无需运行基准测试:文档类型,平均段落长度以及格式是否具有明显结构.

## 问题

每个RAG管道都会先把源文档切成片段:片段要小到可以放进嵌入模型,还要大到足以承载一个独立的想法――选择切分位置不是普通的超参数;它决定检查器最能回复什么――

只有保存停止值的部分可达时,查询预算停止值是什么样的的查询才会成功. 如果固定窗口切割器把值从周围下文中剥离出来,嵌入将移动到另一个,BM25 分数会下降,重排器看到噪音,LLM 生成的答案也会出错.2024年论文 LongRAG:增强复苏-增强代与长文本LLM测试,只单块选择就会带来 35% 的检查回忆 绝对波动.2025年关于文本头的后续工作缩小了这一差距,但没有消除.

本课程并排列构建五种策略,将它们运行在带有金标签答案跨度的固定语料库上,并让你自己阅读回忆数字.

### 固定窗口

蛮力基线――每一个N字符被切断一次――可选地重叠,以便在位置N处切断的句子完整地出现从位置N开始的块内 - 重叠――快速――确定性――边界糟糕――将其作为控制件,而不是默认值――

### 句子

使用正则表达式或简单的状态机分割句子边界――将一个或多个句子打包成一个块,直至达到目标字符预算――停止在单词中间剪切――仍然剪掉中段和中节――许多早期的RAG管道中默认设置,也是没有其他结构的散文的合理选择――

### 递归分离

2023年图书馆流行的层次结构策略――尝试首先分割最强的分隔符 (双换行符、段落),然后回到下一个 (单换行符),然后分割成句子,然后分割成字符――当块符合预算时,归归终止――非常适合结构不一致的文档,因为它会根据区域进行调整――

### 语义聚类

嵌入每个句子.将共享主题质心的连续句子聚类. 每当与质心的运行相似度下降到值以下时,就进行切割.边界反映了意义,而不是字符. 构建速度较慢,依赖于嵌入模型,但对于在段落内切换主题的文档具有弹性.

### 结构化 标题

对于具有明确结构的文档 (Markdown、reStructuredText、RFC 样式编号部分),请在标题边界进行切割. 每个部分都包含标题及其下面的所有内容,直到相同或更高级别的下一个标题.

### 如何衡量边界选择

黄金令牌的查询带有源文档内答案范围的精确字符偏移量. 分块后,你会问:检查器返回的前 k 个块是否与黄金跨度重叠?如果是,则查询的 recall@k 为1.如果不是,则为0.整个查询集的平均值.对每个策略运行相同的评估,分布将向你显示哪个边界策略在你拥有的语料库中幸存下来.

## 构建它

`code/main.py`实现:

- `fixed_window(text, size, overlap)`- 基线――
- `sentence_chunks(text, target)`- 简单句子打包器――
- `recursive_split(text, separators, target)`- 分层递归.
- `semantic_chunks(text, similarity_threshold)`- 基于质量的聚合,在确定性模拟嵌入中.
- `structural_markdown(text)`- 标头感知分离器.
- `mock_embed(text, dim)`基于哈希的嵌入,因此循环可以离线运行.
- `DenseIndex`- 与第19阶段轨道B的混合检查课程中使用的形状相同.
- `eval_recall(strategy, corpus, queries, k)`- 比较循环.
- `main()`语料库运行每个策略并印记回忆@k 表。

运行它:

```bash
python3 code/main.py
```

输出是一个小表,每个策略一行,每个 k 一列――句子策略在结构化固定上失败――结构化 标记下降 在标记下降固定上胜――递归策略在混合固定上有一席之地,因为递归会自适应――语义聚类在没有有用的结构线索的散文固定上胜――

## 表中不会隐藏故障模式

**孤立句子。**句子打包会产生错误的主题句子块.

**中间符号剪切。**代码或YAML中的固定窗口会将标识符分成两半――两半嵌入噪音――

**仅包含标题的 chunk。**结构化 标记会发出只包含`## Title`过掉这些内容,或添加下一个部分的第一段.

**语义漂移。**当语料库一致关注主题时,语义聚类就会减弱.5000个字符的块将许多具体答案包装成一个分散的嵌入中.

**过时的嵌入。**语义聚类使用嵌入模型──如果改模型,你也会改块──将块模型与检索模型分开固定,或者一起重建索引──

## 选择默认值而不运行基准测试

三个属性决定新语料库的默认分块器.

|属性 |值|默认|
|----------|-------|---------|
|文件类型|没有结构的散文 |递归分割，目标 800 |
|文件类型| Markdown / RFC / API 文档 |结构化 Markdown |
|文件类型|代码| AST 感知（超出范围；请参阅第 19 阶段第 02 课）|
|段落长度|长而单一的主题 |句子，目标500 |
|段落长度|简短、混合的主题 |语义，阈值 0.6 |

如果有疑问,请选择回归分拆.

## 使用它

生产模式:

- 在发布新管道之前运行评估;不要相信你的图书馆默认策略.
- 每当你改变嵌入模型或语料库组合时,请重新运行评估;获胜者取决于语料库.
- 策略名称将保留在每个块的元数据中,以便您稍后可以归因回归.

## 关键术语

|术语 |人们怎么说|它实际上意味着什么 |
|------|-----------------|------------------------|
|recall@k | “我们拿到正确 chunk 了吗？” |任何前 k 个 chunk 与 gold answer span 重叠的查询比例 |
|块重叠| “滑动窗口”|将前一个块的最后 N 个字符重新包含在下一个块中 |
|结构分割器| “标题感知块” |在 H1/H2/H3 边界处切分；标题文本也是 chunk 的一部分 |
|语义分块器 | “主题感知块” |嵌入句子、按质心相似度聚类、漂移剪切 |
|质心漂移| 「话题转移」|运行平均值与下一个句子之间的余弦相似度下降超过阈值 |
