# 规模规则

> 2020年卡普兰论文说:模型越大,损失越低.2022年霍夫曼论文说:你们训练不足.计算将进入两个桶:参数和代币,而两者的分配并不显而易见.

## 问题

当你有C FLOPs的训练计算,并想得到最好的模型时,你面临两个旋律:

1. **多少参数 (N)？**模型越大,容量越高.
2. **多少训练 Token (D)？**数据越多,容量越充分利用.

快速飞行`6 × N × D`缩放――你可以提高N、降低D,也可以提高D、降低N──哪种更好?

之前,答案是尽量推高N──────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────

霍夫曼等人 (2022) 训练了一组名为Chinchilla的小型模型家族,发现不同结论:最优比例更接近**每个参数 20 个 Token**△GPT-3 训练不足 10×──Chinchilla(70B参数,1.4T代币) 在推理成本低2.5×的情况下,在所有基准上都击败了GPT-3(175B,300B代币)

2026年是基世界,但有一个重要的转折――Llama 3 8B 在15亿代币上训练,比例是每个参数 1,875 个代币――超过基优质的九十四倍――对于大规模使用模型,推理成本比训练成本更重要,因此为了更小的可部署占用量进行过度训练 (超过基) 是2026年默认选择――

## 概念

![Chinchilla 曲线：不同 N/D 比例下的 Loss vs compute](../assets/scaling-laws.svg)

### 霍夫曼法

,我不想让你这样做.

```
L(N, D) = A / N^α + B / D^β + E
```

- `N`参数 (非嵌入式)
- `D`训练标志
- `α ≈ 0.34`现在`β ≈ 0.28`们都在着.
- `E ≈ 1.69`没有什么可惜的损失.
- `A ≈ 406`现在`B ≈ 411`,我知道.

随着扩张,两个项会相互权衡.`N`求导并求解:

```
N_opt ≈ 0.6 × (C/6)^0.5
D_opt ≈ 0.6 × (C/6)^0.5
D_opt / N_opt ≈ 20
```

计算最佳:每个参数有20个代币.

### 为什么还要过度训练

果最佳最小化是每次训练FLOP对应训练损失.

对于每月服务的10亿代币聊天机器人,推理会主导总成本――Llama 的方法是:模型更小,训练更长.

- 可放入消费级GPU.
- 延迟只是70B的小部分.
- 对于大多数任务来说,质量足够接近.

对于推理主导工作负载,合适比例更接近每参数100-500个代币,具体取决于服务量――

### 涌现与平滑性

主张:某些能力 (算术,多步推理,遵循思想链) 将在某种规模突然涌现──

谢弗等人 (2023) 认为这是测量伪影:涌现指标使用不连续评分(精确匹配、值精度),会隐藏底层逻辑的平滑改进──连续指标(跨) 表示是平滑曲线──

到2026年,共识是:通过连续损失 进行预测是可靠的.

### 2026 年图景

规模化法仍然有效,但:

| 因素 | 如何变化 |
|--------|-------------|
| 数据质量 | 筛选“好”Token（Phi-style）可使曲线移动，相当于 >2× effective compute |
| MoE | 总参数与 active FLOPs 解耦；Scaling Laws 按 per-active-FLOP 计算 |
| 后训练 | 某些能力（指令遵循、代码）受 SFT+RLHF 的影响比 pretraining 更大 |
| Multimodal | 图像 + 文本 Token 一起缩放；每种模态有单独曲线 |
| 合成数据 | 模型生成训练数据；effective compute 可以复合增长 |

根据相比,与亚当W相比,有2x的有效计算增益.一些2026年训练运行默认使用Muon. 它改变了尺度定律中的绝对常数,而不是形状.

### 步骤1: 鱼的损失

```python
def chinchilla_loss(N, D, A=406.4, B=410.7, alpha=0.34, beta=0.28, E=1.69):
    return A / N ** alpha + B / D ** beta + E
```

在固定`C = 6ND`下,将`L`绘制为`(N, D)`找到最小值.

### 步骤2: 计算最优边界

对于`1e17`到了`1e25`计算 预算,找到在约束 `6ND = C`下最小化损失的`(N, D)`△验证比例`D/N ≈ 20`,我知道.

### 步骤3:过度训练成本

计算训练一个小10×的模型(最优N的 1/10,最优D的 10×) 所支付额外损失──报告换来的推理FLOP 节省(与N 成正比)──

## 使用它

你不太可能自己训练边界模型.

1. **你的 fine-tune 是否有足够数据。**如果任务的特定数据低于基模型,每个参数的20个代币,预期会在某个损失地板处和.
2. **是否选择更大的 base model。**如果你的预算全部花在推理上, 优先选择更小的模型,
3. **收益在哪里递减。**超过1000次的氏最佳后, 记录损失变化会变成噪音.

**2026 年的研究轨迹：**

- **数据受限状态。**网络上高质量代币数量有限 (过后约5-10亿英语) 边境预训练正接近这个上限.
- **Compute-multiplier 技巧。**优化器,MoE,更好的数据选,每个都会移动绝对常数,而不是渐近线.
- **RL 的 Scaling Laws。**开放问题──早期证据表明,RL样本中存在权力法,但与预训指数非常不同──

## 关键术语

| 术语 | 人们常说 | 实际含义 |
|------|-----------------|-----------------------|
| Parameters (N) | “模型大小” | 非 Embedding 权重数量；决定容量。 |
| Tokens (D) | “训练数据” | 见过的训练 Token 数；决定参数被利用得有多充分。 |
| Compute (C) | “花费的 FLOPs” | 对标准 Transformer 来说，约为 `6 × N × D`。 |
| Chinchilla-optimal | “D/N ≈ 20” | 最小化 pretraining 每 FLOP Loss 的比例。 |
| Over-training | “超过 Chinchilla” | 花费额外训练 FLOPs 来节省推理 FLOPs；D/N >> 20。 |
| Irreducible loss | “底部” | Scaling Law 中的 `E` 项；数据本身的熵。 |
| Emergent capability | “规模上的突然跳变” | 通常是评分器伪影；连续 Loss 是平滑的。 |
| Effective compute | “训练效率倍增器” | 更好的数据 / Optimizer / 架构会倍增每个 FLOP 的作用距离。 |
