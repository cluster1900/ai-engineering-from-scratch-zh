## 问题

大多数多代理系统都是严格编写的团队:规划者制定计划,编码者编写代码,评论者做审查. 这适用于定义清晰的任务. 它无法捕捉到作为代理, 具有记忆,优先级和开放世界时产生的涌现,非编写行为. 研究,社会模拟以及越来越多的游戏AI都需要第二种类型.

在2026年,如果您在使用Smalville的三个组件,或者需要明确说明为什么不使用.

## 概念

### 三个组件

**Memory stream。**一个只添加的观察,动作,反思和计划 日志.**recency**,我知道.**importance**(代理自评 1-10) 和 **relevance**(与当前查询的余弦相似度)

```
[2026-02-14 09:12:03] observation: Isabella Rodriguez asked me if I like jazz
[2026-02-14 09:14:22] reflection:   I enjoy long conversations about music
[2026-02-14 10:05:00] plan:         Attend Isabella's Valentine's Day party tonight
```

**Reflection。**周期性地(每 N 条记忆或发生重要事件时),代理从最近的记忆 生成更高阶综合――反思条目会写回流,并像其他记忆一样可检查――这就是代理的构建理解的方式,也就是构建中长期信念的等价――

**Plan。**自顶向下分解──首先是粗略的日级计划(去工作,和克劳斯吃饭)──然后是小时级计划──再是动作级计划──计划可以修改:当观察与计划矛盾时,代理会重新规划受影响的段段──

### 为什么三个都重要?

通过" 分析"和" 计划"的分析,

- 没有**observation**据说,这只是一个错误的行为.
- 没有**reflection**交互将停留在低层层.
- 没有**plan**行为会变成反应式噪音;目标会消散.

人类评价者给出的可信度分数在三个组件中最高; 消除任何一个都会产生可测量的退化.

### 情人节的涌现

一名代理人伊萨贝拉·罗德里格斯被植入目标 想在2月14日下午5点在霍布斯咖啡馆举行情人节聚会

1. 伊莎贝拉的计划包括邀请其他人.
2. 每次邀请都会成为邻居记忆流中的一个观察.
3. 邻居的反思生成信念:伊莎贝拉正在举办派对.
4. 邻居的计划是参加2月14日的聚会.
5. 邻居告诉邻居. 邀请在没有中央协调的情况下传播.
6. 星期二,十四日下午五点,几个特工聚集在霍布斯咖啡馆.

这是技术意义上的涌现:系统级行为 (一派对) 来自局部交互 (双边邀请+个体规划),而没有中央管弦乐队.

### 文档记录的失败模式

帕克等明确记录了:

- **空间规范错误。**代理走进已关闭的商店. 代理尝试使用同一个单人卫生间. 代理在不适合用餐的房间里吃饭. 模型不能仅仅从环境推断社会物理规范.
- **Memory overflow。**实用补救:周期性记忆紧缩 (回顾和调整) 以及对低重点的记忆使用衰退.
- **Reflection hallucination。**反射可能编制内存流 中不存在关系――缓解方式:在反射提示中包含源内存ID,并在检索时验证――

这些都是与生产相关的失败模式:任何2026年的代理人都将继承它们.

### 三组件实现规则

1. **Memory 是 append-only。**永远不要修改记忆条目.更正是新的条目.
2. **Importance 分数要便宜。**写入时调用LLM 评估1-10的重要性──缓存该分数──
3. **Retrieval 是排序，不是过滤。**按组合分数取 Top-k;不要使用硬过器(会丢失上下文) 』
4. **Reflection 周期性运行。**当未处理记忆的重要性 总和超过值时触发(例如 150)。
5. **Plans 可以修订。**当新的观察与计划矛盾时,只会重新产生受影响的部分,而不是整个计划.

### 斯摩尔维尔以外的创建代理

2024-2026年后的文献扩展了这一结构:

- **用于政策 / 市场研究的 multi-agent 社会模拟。**类 斯摩尔维尔 群体模拟用户对功能的行为反应――比A/B测试更快;准确性仍存在争议――
- **游戏中的 NPC AI。**带有斯摩尔维尔代理的角色扮演会产生故事线,而不是脚本化任务.
- **Generative-agent 评估基准。**标志不再是任务准确率,而是长期运行中的可信度+行为一致性.

该架构是参考标准――扩展会替换组件――用于存储记忆的矢量,恢复增强反射,神经象征性计划,但保留三部分结构――

现在已经在开源模型上复现了. 更小的LLM可信度是平滑下降,而不是急剧崩.**emergent social behavior**生产系统都会使用这种形状.**tight task execution**系统都会使用本阶段前面介绍的监督者 /角色 /原始模式──

## 构建它

`code/main.py`通过使用Stdlib Python 和脚本化代理政策 (没有真实LLM) 实现三个组件.

- `MemoryStream` 带最新/重要/相关性检索的附加单 日志。
- `reflect(stream)`对最近高意义记忆的脚本化反思.
- `plan(agent_state)` 基于当前信仰的日级和小时级计划.
- 场景:5 个代理――代理1 以投放派对在下午5点开始―― 在模拟中,邀请传播,代理聚集――

运行:

```
python3 code/main.py
```

预期输出:逐个标追踪――到最后标,5 个代理中至少有3个在计划中出现的党,并它们聚集到党的位置――单个种子在没有任何管弦乐器的情况下产生协调到达――

## 使用它

`outputs/skill-simulation-designer.md`设计一个生成代理模拟:代理 数量,记忆模式,反射序列,计划视界和评估指标.

## 发布它

生产模拟规则:

- **Memory 就是数据库。**在规模化时选择真实存储 (VECTOR DB、Postgres) ⋅内存存量只适合原型.
- **记录 retrieval trace。**对于每一个操作,记录驱动它的顶级记忆.
- **为每个 agent 预算 tokens。**每个子 中每一个代理的检索+反射+计划 是 O(k) LLM电话;;
- **周期性 compact memory。**简单简单 低重点 条目――保留政策是设计决策,不是细节――
- **显式检测空间 / 社会规范违规。**建筑不会学会它们.

## 关键术语

| Term | 人们的说法 | 实际含义 |
|------|----------------|------------------------|
| Memory stream | “agent 的日记” | 观察、动作、reflection、plan 的 append-only 日志。 |
| Recency | “这条 memory 有多新” | 按年龄计算的指数衰减分数。 |
| Importance | “agent 有多在意” | 写入时自评 1-10。已缓存。 |
| Relevance | “与当前查询有多相关” | 余弦相似度（Embedding-based）。 |
| Reflection | “更高阶信念” | 从最近 memories 生成的综合，并作为新 memory 重新摄入。 |
| Plan | “日/小时/动作分解” | 自顶向下的 plan tree。当 observation 矛盾时可修订。 |
| Smallville | “Park 2023 的 sandbox” | 产生 Valentine's Day 涌现的 25-agent 模拟。 |
| Believability | “质量指标” | 人类评分者对行为是否像一个可信 agent 的评分。 |
