# 单图像,多图像和视频

> 在LLaVA-OneVision (李等人,2024年8月) 之前,开放的VLM世界有彼此分离的谱系:用于单个图像的LLaVA-1.5,像Mantis 和 VILA这样的多图像模型,以及像视频-LLaVA 和视频-LLaMA这样的视频模型.每个都赢得了自己的基准,但在其他场景上失败了.

**Type:** Build
**Languages:** Python (stdlib, token budget solver + curriculum planner)
**Prerequisites:** Phase 12 · 05 (LLaVA), Phase 12 · 06 (any-resolution)
**Time:** ~180 minutes

## 学习目标
- 设计一个在单图像、多图像和视频输入之间保持恒定的视觉标志 预算。
- 排列一个训练课程,使技能从单图像迁移到视频,同时避免灾难性忘记.
- 解释为什么在相同参数规模下,如果课程做得正确,单一模型会胜过专家模型.
- 报告的三种新兴功能:多摄像头推理,标记提示,iPhone屏幕截图代理.

## 问题
图像,多图像和视频将以不同的方式给模型施压.

单图像需要高分辨率的代币 ((AnyRes,约2880个视觉代币) 来捕捉OCR 和细节──每个样本的预算:1张图像,2880个代币──

多图像需要多张中等分辨率图像 ((每张约576个标记),这样跨图像推理才能将其放入文本中──每个样本的预算:4-8张图像,每张576个标记,总数2300-4600个标记──

视频需要许多低分辨率的 (后集结 后每约196个令牌) 来捕捉时间动态──每样本的预算:8-32个,每 196个令牌,总计1600-6200个令牌──

如果你训练多个独立模型,你会为每个模型选择一个预算.如果你训练一个模型,你需要让预算在不同场景之间合理缩小,同时无法爆文本.

在OneVision之前,默认答案是训练一个场景,忽略其他场景──视频-LLaVA 通过额外训练阶段把视频能力改装成图像模型上──LLaVA-Next 通过造 增加了多个图像支持──没有一个能干净地处理三者──

## 概念
### 预算

选择一个统一的视觉代币 预算,每个样本约3000-4000个代币,并根据场景分配不同:

- 单图像:AnyRes-9(3x3片 + 缩写图片),每个片为384,包含729个补丁,使用激进的2x2双线聚合 → 每个片 182个标记──总计:9 * 182 + 182 = 1820个标记──或AnyRes-4,每个片 729个标记 = 2916 + 729──
- 多图像:每张图像使用中等分辨率(384,不),729 个代币,不聚焦──预算为6张图像 → 4374 个代币──
- 视频:32 ,384 分辨率,使用激进的3x3 双线池 → 每 81 个代币──总数:32 * 81 = 2592 个代币──

这种分配使总代币数大致保持恒定.LLM永远不会看到会爆情境的批量.

### 三阶段课程

拉瓦-一视分三个阶段训练:

1. 单图像 SFT(阶段SI) ⋅所有数据都是单图像加上文本――使用高分辨率AnyRes 输入训练――这会教会模型感知、OCR 和细粒度理解――使用LLaVA-NeXT 数据加上OneVision 特定单图像数据――
2. 一视 SFT(阶段OV) ――混合单图像 + 多图像 + 视频(均采样) ―― 在统一代币 预算上训练――这会教会模型处理异构批形――不重置权重,而是从阶段 SI 继续――
3. 任务转移 (TT) 阶段) 继续使用目标任务组合,通常根据产品需要偏重多图像或视频.

关键点:课程 顺序很重要.即使使用相同的数据,先训练视频或先训练多图像,也会比先训练单个图像得到更差的图像性能.

### 为什么课程有效

单图像训练建立感知基础――补丁符号 携带细粒度视觉特征;LLM 学会把它们与文本整合――多图像和视频引入结构性挑战――哪张图像是哪张,什么先发生),如果没有强大的感知基础,这些挑战很难学习――

如果你从零开始把所有场景混在一起,模型会缺乏合适的感知,并且过于合适的结构,大量的图像/视频数据.

课程排序让你从阶段SI 获得感知强度,再从阶段OV 获得组合/时间推理能力,同时不丢失任何一边.

### 跨场景新兴技能

报告了三种新兴能力:

1. 通过多摄像头驾驶场景进行训练,尽管训练中从未见过这种确切的格式,但模型仍然可以正确整合多个视角.
2. 标记提示──用户使用编号标记注释图像中的对象;模型推理标记 3 相对于标记 7 在做什么──既没有在标记上训练,也没有在注释上训练;它是从空间地接 +多图像参考的组合中学到的──
3. 用户提供一张iPhone屏幕截图,并要求规划下一次点击.

这些不是训练任务;它们来自课程组合结构中.

### 视觉标志集成

标记 预算需要聚合――OneVision 在2D补丁网上上使用二线性插图:24x24 = 576个补丁 变成12x12 = 144(2x因数) 或8x8 = 64(3x因数) ―― 聚合在补丁网空间中完成,而不是在标记空间中完成,以保留局部性──

每场景的聚合因素 选择本身就是一个超参数――更少的聚合 = 更多代币 = 更丰富的表示――更少的聚合 = 更少的代币 = 能放入更多/图像――

### 车车型

后期版2025年 ([[LLaVA-OneVision-1.5,arXiv 2509.23661) 在训练数据,模型权重和代码上都是开的.它在一些基准上缩小了与专有模型的差距,并使这种配方更加民主化.

### 与Qwen2.5VL相比

文2.5 - 文 (VL)  (课 12.09) 做了不同的选择――它使用M-RoPE 和动态FPS,而不是固定聚合物――它的预算会随输入缩放:1 分钟视频使用的代币比5秒视频更多――LLaVA-OneVision 固定预算并缩放聚合物――两者都是有效的;它们在可配置性和可预测性之间做了交换――

## 使用它
`code/main.py`作为一个用于OneVision式VLM的课程和预算规划器.

- 为每场景分配分辨率,聚合因素和框架.
- 检查每个场景是否属于共享预算.
- 报告预期代币数量、LLM FLOPs以及哪些场景未被代币化.
- 打印逐阶段训练计划.

通过它来规划OneVision的细节调整,或者对VLM部署的每次请求成本进行智能检查.

## 交付它
本课会产出 `outputs/skill-onevision-budget-planner.md`△给定目标任务分布和每样本预算,它会输出任何Res因子、每框架聚合、视频数和课程阶段权重──每当你训练或细节调节一个统一场景VLM时,都使用它──

## 练习
1. 你的产品支持80% 单图像,10% 多图像(2-4 张图像) 、10% 视频(8-16 ) ⋅设计标志 预算――由于不重度多图像而省下额外预算,你将把它放在哪里?

2. 阅读LLaVA-OneVision 4.3节 (新兴能力) 提出一个课程可能解锁,但论文没有报告的第四种新兴技能.

3. 交换课程 顺序:先训练多图像,再训练单图像,最后训练视频――预测哪些基准会下降,以及原因――

4. 论文报告的视频基准每样本只需要8训练. 这能否扩展到推理时的30秒视频?

5. 通过使用Stdlib Python实现聚合,并验证每个2x2块的平均值与双线输出匹配.

## 关键术语
| Term | What people say | What it actually means |
|------|-----------------|------------------------|
| OneVision scenario | “单图像、多图像，或视频” | 统一 VLM 处理的三种输入 shape 之一；预算在三者之间保持恒定 |
| Token budget | “每个样本多少 Token” | LLM 在每个训练/推理样本中看到的视觉 Token 总数，通常为 3000-4000 |
| Curriculum | “训练顺序” | 为了 emergent transfer 而选择的阶段排序（单图像 → 多图像 → 视频） |
| Bilinear pooling | “Token 缩减” | 对 patch grid（2D）应用 bilinear interpolation，以在保留局部性的同时减少 Token 数量 |
| Emergent skill | “没训练过，但仍然能用” | 由于 curriculum composition，在没有匹配训练数据的情况下于推理时出现的能力 |
| AnyRes-k | “k-tile setup” | k 个固定分辨率子 tile 加一个 thumbnail，典型 k ∈ {4, 9} |
| Task transfer | “跨场景泛化” | 在单图像上学到的技能，通过共享 backbone 应用于视频（反之亦然） |
