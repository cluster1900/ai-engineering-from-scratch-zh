# 视觉变换器与补丁符号 原语

> 在任何多模拟处理之前,图像都必须变成变压器可处理的代币序列.2020年ViT论文使用16x16像素补丁,线性投影和位置嵌入 回答了这个问题.五年后,每一个2026年边境模型都用了Claude Opus 4.7 原生 2576px,Gemini 3.1 Pro,Qwen3.5-Omni) 仍然从这里开始编码器从ViT 变成DINOv2 再 SigLIP 2,加入注册代币,位置变成2D-RoPE,但这个原始语言保留下来.本课程到端阅读补丁管道,并使用Stdlib Python 构建它,让第12期 后续内容对视觉代币有一个具体的心智模型.

**Type:** Learn
**Languages:** Python (stdlib, patch tokenizer + geometry calculator)
**Prerequisites:** Phase 7 (Transformers), Phase 4 (Computer Vision)
**Time:** ~120 分钟

## 学习目标
- 将 HxWx3 图像转换为带有正确位置编码的补丁符号序列.
- 为给定的VIT(补丁尺寸,分辨率,隐藏的暗度,深度) 计算序列长度,参数数和FLOPs──
- 报告指出,从2020年研究成果推进到2026年生产系统的三项升级:自主监督预训(DINO/MAE) 登记代币以及本地分辨率包装──
- 为下游任务在CLS聚合,意思聚合和注册代币之间做选择.

## 问题
变形器处理的是向量序列──文本本本就是序列──字节或代币──图像是带有三个颜色的2D像素网格,不是序列──如果你展平每一个像素,一张224x224 RGB图像将变成150,528个代币,而这个长度上的自我注意力是完全不可行的(相对于序列长度是二次复杂性) ⋅

2020年之前的方法将在前端接到CNN特征提取器:ResNet 产生由2048维向量组成的7×7特征地图,再把这49个代币输入变压器──这能工作,但会继承CNN的偏置 (翻译等差、本地接收场),并削弱变压器对规模扩展的适应能力──

东索维茨基等人提出了一个直接的问题:如果跳过CNN会怎么把图像分成固定大小的补丁(例如16x16像素),将每个补丁线性投影成一个向量,加入位置嵌入,然后把序列输入一个尼拉变压器.

到2026年,ViT 原语已经是无争议的基础.每个开放权重VLM的视觉塔都是一些后代.问题不再是我们是否应该使用补丁?,而是什么补丁大小,什么分辨率计划,什么预训目标,什么定位编码.

## 概念
### 作为代币的补丁

给定一个形状为`(H, W, 3)`图像`x`和补丁尺寸`P`你将图片切成一个.`(H/P) x (W/P)`没有重叠的补丁 网格. 每个补丁都是一个.`P x P x 3`图像的方体.`3 P^2`矢量. 应用一个形状为`(3 P^2, D)`共有线性投影`W_E`让每个补丁映射到模型的隐藏维度`D`,我知道.

对于ViT-B/16这个经典配置:
- 解析 224,补丁尺寸16 → 网格14x14 → 196 个补丁代币──
- 每个补丁都是`16 x 16 x 3 = 768`个像素值,投影到`D = 768`,我知道.
- 加入一个可学习的`[CLS]`标志 →序列长度 197。

补丁投影在数学上等于内核尺寸为`P`步骤为`P`输出通道数为`D`实际上就是这样实现的.`nn.Conv2d(3, D, kernel_size=P, stride=P)`线性投影的说法是概念表述;核心表述更高效.

### 位置嵌入式

补丁没有内在顺序 变压器 看到的是一个集合.早期的 ViT 加入可学习的 1D 位置 嵌入.每个位置一个 768 维向量,总共 197 个).

现代视觉背骨 使用 2D-RoPE(Qwen2-VL 的 M-RoPE、SigLIP 2 的默认方案) 或因数化 2D 位置──2D-RoPE 会根据补丁的(排列,列) 指引旋转查询 和键向量,因此模型可以从旋转角度推断对 2D 位置──不需要位置表──模型在推理中可以处理任意的格式大小──

### 单元的输出和注册代币

图像级表示是什么?三种选择并存:

1. `[CLS]`符号――把一个可学习的向量 前置到补丁序列――经过所有变压器块后,CLS符号的隐藏状态就是图像表示――继承自BERT──原始 ViT、CLIP 使用这种方式──
2. 平均积分――对补丁代币的输出隐藏状态 取平均――SigLIP、DINOv2 和大多数现代VLM使用这种方式――
3. 登记令牌──达塞特等 (2023) 观察到,没有显式沉没令牌 训练的ViT 会产生高范数的文物补丁,并劫持自我注意力──加入416个可学习登记令牌 可以吸收这个部分负载,并提升密集预测质量(细分,深度)──DINOv2 和 SigLIP 2 都随着模型提供登记──

这个选择会影响下游任务――CLS 适合分类――对于把补丁代币输入LLM的VLM,你会完全跳过聚合 每个补丁都会成为一个LLM输入代币――注册会在交接前被丢弃(它们是支架,不是内容)――

### 预训练:监督式、对比式、面具式、自蒸

2020年ViT使用JFT-300M 上的监督分类 进行预训练――很快被以下方法取代:

- 通过400M对图文数据进行对比图像文本的处理.
- 面具 75% 的补丁,重建像素──自主监督,适用于纯图像──
- 迪诺 (2021) /迪诺夫2 (2023):使用学生-老师做自,无标签、无标题──2023年的迪诺夫2 ViT-g/14 是最强的纯视觉骨干,也是密特征用例的默认选择──
- 标志性/标志性2 (2023, 2025):带标志性损失 和 NaFlex 原生宽高比支持的 CLIP──2026年开放的VLMs(Qwen、Idefics2、LLaVA-OneVision) 中的主流视觉塔──

你选择的预训决定了脊椎 擅长什么:CLIP/SigLIP 擅长与文本做语义匹配,DINOv2 擅长密集的视觉特征,MAE 适合作为下游细节调节的起点.

### 规模化法

维特扩展 (Zhai et al. 2022) 表示,维特的质量在模型尺寸,数据尺寸和计算上遵循可预测规则,在固定计算下:
- 更大的模型+更多数据 →更好的质量――
- 补丁尺寸是序列长度与忠诚度之间的调节杆──补丁14(DINOv2/SigLIP SO400m的典型配置) 相比补丁16 会为每张图像产生更多的标记;更适合OCR和密集任务,但速度更慢──
- 决议是另一个大杆――从224到384再到512几乎总是有帮助,但FLOP成长按二次增长――

维特g/14(1B参数、补丁 14、解析度 224 → 256 代币) 和SigLIP SO400m/14(400M参数、补丁 14) 是2026年开放的VLM的两个主要加码器──

### 维特的参数数

完整计算位于`code/main.py`△对224 下的ViT-B/16:

```
patch_embed = 3 * 16 * 16 * 768 + 768  =  591k
cls + pos    = 768 + 197 * 768          =  152k
block        = 4 * 768^2 (QKVO) + 2 * 4 * 768^2 (MLP) + 2 * 2*768 (LN)
             = 12 * 768^2 + 3k          =  7.1M
12 blocks    = 85M
final LN    = 1.5k
total       ≈ 86M
```

在加载检查点之前,先使用这种方法粗略估计每个VT──脊椎大小会决定任何下游VLM的VRAM下限──

2026年大多数开放的VLM 随模型提供的编码器是原生分辨率的NaFlex) 下 SigLIP 2 SO400m/14──它具有:

## 关键术语
| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Patch | “16x16 像素方块” | 输入图像中固定大小、非重叠的区域；会变成一个 Token |
| Patch embedding | “Linear projection” | 一个共享的学习 Matrix（或 stride=P 的 Conv2d），将展平后的 patch 像素映射到 D-dim Vector |
| CLS token | “Class token” | 前置的可学习 Vector，其最终 hidden state 表示整张图像；在 2026 年是可选项 |
| Register token | “Sink token” | 额外的可学习 Token，用于吸收 ViT 在 pretraining 期间产生的高范数 Attention artifacts |
| Position embedding | “Positional info” | 每个位置的 Vector 或旋转，使序列具备顺序感知；2D-RoPE 是现代默认方案 |
| Grid | “Patch grid” | 对于给定 resolution 和 patch size，patch 形成的 (H/P) x (W/P) 2D 数组 |
| NaFlex | “Native flexible resolution” | SigLIP 2 特性：单个模型无需重新训练即可服务多种 aspect ratios 和 resolutions |
| Backbone | “Vision tower” | 预训练 image encoder，其 patch-token 输出会在 VLM 中输入 LLM |
| Pooling | “Image-level summary” | 将 patch tokens 转换为一个 Vector 的策略：CLS、mean、attention pool 或 register-based |
| Patch 14 vs 16 | “Finer vs coarser grid” | Patch 14 每张图像产生更多 Token，对 OCR 有更好 fidelity，但更慢；patch 16 是经典默认值 |
