## 概念
### 跨模式检索

给定模式A的查询,检索模式B的文件──三种模式:

1. 嵌入式空间──CLIP 和 CLAP 在共享空间中生成文字 + 图像 / 文字 + 音频嵌入式──跨模式的共性相似性可直接使用──受限于 CLIP 训练过的配对──

2. 通过模拟化编码器 + 翻译――文本编码器 + 图像编码器 + 一个小型翻译模块,用于在不同空间之间绘图――古普塔等的 Sen2Sen 以及其他2024年设计属于这一类型――灵活,但增加复杂性――

3. 作为编码器──使用VLM的隐藏状态作为检索表示──VLM 支持的任何模式都可用──质量更高,成本也更高──

选择:文字+图片 用CLIP / SigLIP 2;文字+音频 用CLAP;边界质量跨模式 用VLM隐藏状态──

### 一个生产级旅行规划者示例

问: 帮我找一个安静的,有自然光的素食式午餐.

管道:

1. 分解查询──静 →音频/评论关键词;素食 →菜单项;自然光 →图像功能──
2. 按方式检索:
   - 评论 检索文本:素食式午餐,安静的氛围.
   - 对于餐厅照片做图像检索:自然光,空气.
   - 对于环境声音片段进行音频检索:低分贝,没有音乐.
3. 融合分数――每个餐厅都有复合分数――
4. 带着所有证据 → 带着引用 输出答案

它们都包含了单独的文本,

### 机械多模性RAG

复式跳转:如果第一次检索 没有返回高置信度答案,LLM 会重新构成并再次检索──14期的代理RAG模式适用于这里──示例:

- 检索初始的前十 → LLM 询问太,过为 <40 dB →重新检索──
- 检索图片 → LLM 发现其中一张有菜单 →检索菜单文本 →答案──

这会增加复杂性,但可以处理单次检索无法解决的查询.

### 评估

跨模式评估 仍不成熟──常见代理:

- 每种方式的回忆
- 混合的高-k精度.
- 人工评判的终结满意度.
- 具体任务:完成预订,完成购买.

没有覆盖所有模式的标准基准.

## 关键术语
| Term | What people say | What it actually means |
|------|-----------------|------------------------|
| Cross-modal retrieval | “Query 一个 modality，retrieve 另一个” | Text query retrieve images；image query retrieve text；需要 shared space 或 translator |
| Score fusion | “组合 scores” | 对每种 modality 的 retrieval scores 做 weighted sum；最简单的 fusion |
| MoE fusion | “Modality-routed experts” | Gating network 按 query 选择信任哪种 modality 的 scores |
| Grounded generation | “Cite your sources” | 答案中的每个 claim 都标注 source index |
| MuRAG | “第一个 Multimodal RAG” | 2022 年 paper，建立了 Multimodal RAG 模式 |
| Agentic multi-hop | “Reformulate and retry” | 当 first-pass confidence 较低时，LLM 重新 query retrievers |
