# الإنسان في الحلقة: الاقتراح ثم التزام

> 2026 سنة حول HITL والإجماع هو محدد. انها ليست مُساعدة 发问,用户点击 Approve──它是 اقتراح-ثم-التزام: اقتراح-عمل سيتم ربطها بمفتاح الإعفاء 持久化 إلى متجر دائم; بإرادة DATA lineage、permissions touched、blast radius 和 rollback plan present to the reviewer; فقط في明确肯定确认后才 commit; تنفيذ بعد التحقق مرة أخرى, تأكيد الآثار الجانبية 确实发生──`interrupt()`إضافة إلى تحديد نقاط البحث PostgreSQL`RequestInfoEvent`، و Cloudflare `waitForApproval()`تم تحقيق نفس النوع من الوضع. نموذج النظام الفشل هو موافقة العلامة المطاطية: موافقة؟ 没有经过审查 就被点击──تحفيز الملفات.

**Type:** 学习
**Languages:** Python (stdlib，带 idempotency 的 propose-then-commit state machine)
**前置要求：**المرحلة 15 · 12 (التنفيذ المستدام) ، المرحلة 15 · 14 (الخطوط الثلاثية)
**Time:** ~60 分钟

## 概念

### آلة الدولة المقترحة ثم المفروضة

1. **Propose.**العميل 生成 a المقترح العمل. تم استمرارها إلى متجر دائم.
   - نية ((وكيل لماذا يجب أن تفعل ذلك)
   - سلسلة البيانات ((ما المصدر الذي أدى إلى هذا الاقتراح)
   - الإذنات الملموسة ((哪些 المجال / الملفات / النقاط النهائية)
   - نصف قطر الانفجار ((أسوأ حالة هو ما)
   - خطة إعادة التأثير ((إذا التزمت، كيف ننسحب)
   - مفتاح الإعفاء (كل اقتراح واحد ، يعيد تقديم نفسه)
2. **Surface.**المراجعة 看到包含全部的元数据的提案──المراجعة 是人(不是 وكيل 自己 review 自己)──
3. **Commit.**明确肯定确认──عمل 执行──
4. **Verify.**بعد تنفيذها، فإنك تُؤكد الآثار الجانبية. إذا تحققت من الخطوة الفاشلة، فإن النظام في حالة سيئة معروفة، ولن تُصاب بإبلاغ.

### مفتاح الإستثمار

没有idempotency key 时, transient failure 后后的试图可能重复执行已批准的行动──具体例:用户批准转移100美元从A到B──网络短暂动──网络工作流重新尝试──用户只批准一次,但转移 执行两次──idempotency key 将批准 绑定到单个单个副作用;第二次执行是无-op──

هذا هو نفس نمط الاستخدام المزمن لـ Stripe و AWS APIs.

### الاستدامة: لماذا التوافقات يمكن أن تستمر في عملية

غرفة انتظار الموافقة هي المرحلة غير المرجعية للعميل المملوكة. تدفق العمل تم تعليقه.`interrupt()`مع PostgreSQL التفتيش 配对، بدلا من استخدام فقط في حالة الذاكرة: بعد مرور يومين من الموافقة  مازال يمكن العثور على التدفق العمل الكامل.

### الموافقة على طوابع المطاط مع تخفيف التحديات والرد

HITL معتمدة UI(موافقة / رفض أزرار) سوف تنتج بسرعة الموافقة، ولكن لا وجود مراجعة حقيقية‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬

### ما هي النتيجة

ليس كل عمل يحتاج إلى اقتراح ثم التزام.

- **Consequential actions**(始终 HITL):不可逆写入、金融交易、通讯 خارجية、تغييرات قاعدة البيانات الإنتاج、عمليات نظام الملفات المدمرة。
- **Reversible actions**(有时 HITL): تحرير ملفات محلية  تغييرات المرحلة  مع وضوح الردوب الراجع
- **Reads and inspections**(從不 HITL):读取文件、列出资源、调用读取仅API──

## 关键术语
| Term | What people say | What it actually means |
|---|---|---|
| Propose-then-commit | “Two-phase approval” | 持久化 proposal + positive commit + verify |
| Idempotency key | “Retry-safe token” | 每个 proposal 唯一；第二次 execution 为 no-op |
| Data lineage | “Where it came from” | 导致 proposal 的具体 source content |
| Blast radius | “Worst case” | action 出错时的影响范围 |
| Rubber-stamp | “Fast approval” | 没有真正 review 就点击 “Approve” |
| Challenge-and-response | “Forcing checklist” | Reviewer 必须明确确认具体问题 |
| RequestInfoEvent | “MS Agent Framework primitive” | 带结构化 metadata 的 durable HITL request |
| `interrupt()` / `waitForApproval()` | “Framework primitives” | 同一形态的 LangGraph / Cloudflare 等价物 |
