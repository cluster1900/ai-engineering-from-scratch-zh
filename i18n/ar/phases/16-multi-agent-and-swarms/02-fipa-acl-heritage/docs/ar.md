## 问题

في عام 2026، كان هناك الكثير من المشاريع في مجال بروتوكول العملاء: استخدام MCP للأدوات، استخدام A2A للعملاء، استخدام ACP لتحقيق المؤسسات، استخدام ANP لتعديل الاعتقاد، استخدام NLIP لمحتوى اللغة الطبيعية، إضافة إلى CA-MCP ومزيد من عشرين مقترح دراسية.

诚实地看, معظمهم في إعادة اكتشاف واحد محدد جدا 已有二十年历史的决策树──奥斯丁(1962) و Searle(1969) النظرية الخطاب-عمل 给了我们突出是行动──KQML(1993) جعلها إلى بروتوكول الأسلاك──FIPA-ACL(2000年批准) أعطى تصنيف درجة المرجعية: 20 لغة أداء、SL0/SL1, وكذلك بروتوكولات التفاعل المستخدمة في العقد الشبكة وملحق-إعلامات──JADE 和 JACK هي منصة مرجعية جاوا── هذا الجهد ظهر في وقت لاحق من عام 2010، لأن علم التلفزية 开销太重, بينما يكتسب الويب المكانة السائدة──

عندما ترى MCP `tools/call`عندما تُخزن دورة حياة المهام في A2A أو في CA-MCP، ترى أنّها نوعاً ما من التفكير في قرارات FIPA أكثر مرونة، والتي تكون من نوع JSON. معرفة هذا المقالة ستخبرك بشيءين: أيّة ابتكارات جديدة قد تم إعادة تطورها، وكذلك مواصفات جديدة ستجد مجدداً أيّة أساليب فشل قديمة.

### اثنان من أداءات الفيبا (جزء قائمة)

| Performative | Intent |
|---|---|
| `inform` | “我告诉你 P 为真” |
| `request` | “我请求你执行 X” |
| `query-if` | “P 是否为真？” |
| `query-ref` | “X 的值是什么？” |
| `propose` | “我提议我们执行 X” |
| `accept-proposal` | “我接受该 proposal” |
| `reject-proposal` | “我拒绝该 proposal” |
| `agree` | “我同意执行 X” |
| `refuse` | “我拒绝执行 X” |
| `confirm` | “我确认 P 为真” |
| `disconfirm` | “我否认 P” |
| `not-understood` | “你的 message 无法 parse” |
| `cfp` | “针对 X 发出 proposals 征集” |
| `subscribe` | “当 X 变化时通知我” |
| `cancel` | “取消正在进行的 X” |
| `failure` | “我尝试了 X，但失败了” |

完整列表在 `fipa00037.pdf`(بنية رسالة الفيبا ACL) 中──重点不是 تذكرها، بل كل واحدة من هذه المحتوى، كل على الاطلاق على بروتوكول LLM، وأخيرا سوف إعادة إضافة واحدة البدائية──

### رسالة FIPA-ACL

```
(inform
  :sender       agent1@platform
  :receiver     agent2@platform
  :content      "((price IBM 83))"
  :language     SL0
  :ontology     finance
  :protocol     fipa-request
  :conversation-id   conv-42
  :reply-with   msg-17
)
```

七个字段承载 بروتوكول غلاف ؛一个字段(`content`(حمل الحمل المفيد. والباقي من المقطع هو أنك كل مرة تعطى بروتوكول JSON بالإضافة إلى محاولات إعادة التدريب و التنظيم.

### منصات متبقية

**JADE**(Java Agent DEvelopment framework,19992020s) هو استخدام أوسع وقت تشغيل مطابق لـ FIPA.

**JACK**(برمجيات موجهة للعملاء، تجارة) أكد على BDI في رسائل FIPA 之之(الإيمان-الرغبة-النوايا) التفكير.

两者都在网堆 吞掉多代理使用案例 后走向衰落──MCP 和 A2A 是2026年运行时间 容器──

### لماذا تخرج الفيبا

- **Ontology 开销。**FIPA 要求使用共享 اونتولوجيا 来 parse `content`就 ontologies 达成一致是一个历时数年的标准化过程──web 只是使用HTTP + JSON──
- **没人使用的 formal semantics。**SL ((اللغة السمانية) قدمت ظروف حقيقية صارمة ، ولكن معظم أنظمة الإنتاج تستخدم محتوى شكل حر ،并忽略形式主義。
- **Tooling lock-in。**يدي فقط يدعم جاوا؛ جاك هو منتج تجاري.
- **internet 赢下了 stack。**REST، ثم JSON-RPC، ثم gRPC، استبدل نقل ACL.

### الـ LLM 复兴 هو FIPA-lite

مقارنة مع الفيبا`request`مع شركة`tools/call`:

```
(request                                {
  :sender  agent1                         "jsonrpc": "2.0",
  :receiver tool-server                   "method":  "tools/call",
  :content "(lookup stock IBM)"           "params":  {"name":"lookup_stock",
  :ontology finance                                   "arguments":{"symbol":"IBM"}},
  :conversation-id c42                    "id": 42
)                                        }
```

نفس الغلاف، مختلفة النصوص. كل منهما تحمل: من يعطي من نية، دفع، والعلامة التناسلية. كل منهما ليس ثورة، بل تعادلات مختلفة على نفس التصميم.

مسح ليو وآخرين لعام 2025 ((Survey of Agent Interoperability Protocols: MCP, ACP, A2A, ANP,arXiv:2505.02279) يوضح بوضوح أن هذا التقاليد: MCP على صلة بأفعال الكلام باستخدام الأدوات، A2A على صلة بأفعال الكلام باستخدام العملاء، ACP على صلة بأفعال الكلام باستخدام المسار المختص، ANP على صلة بإمدادات الهوية اللامركزية.

### مباشرة وضاحية التداول

**FIPA 给了你、而现代 specs 放弃的东西：**

- المفاهيم الرسمية: يمكنك أن تثبت`inform`يعني المرسل يصدق المحتوى
- لا داعي للجدل مجدداً حول ما إذا كان يجب أن يكون لدينا`cancel`؟
- نمطات التفاعل-بروتوكول: العقد-شبكة ‬التسجيل-إعلام‬التقديم-المقبول، ويكون هناك خصائص دقة معروفة‬

**现代 specs 给了你、而 FIPA 没有的东西：**

- مع جميع الأدوات الحديثة وموافقة من JSON-أصل الحمل المفيد.
- الـ LLM  بدون حاجة إلى علم التلفزيون المرموز يدويا 即可解释的自然语言内容──
- النقل عبر الإنترنت (http、SSE、WebSocket)
- 通過 حقيقة الوقت من MCP `server/discover`مع بطاقة وكيل A2A  القدرة على العثور على

أكثر تطويرًا لترجمة النية، وتغييرًا لتحقيقًا أسهل.

### بروتوكولات التفاعل التي تستحق النقل

إضافة إلى ذلك، تضمّن الاتحاد الدولي للاتصالات الدولية ما يقرب من 15 بروتوكولاً للتفاعل، ومن بينها ثلاثة من المفروضات التي تنشأ في أنظمة الـ LLM متعددة الوكلاء:

1. **Contract Net Protocol (CNP)。**مدير 发出 `cfp`(دعوة للمقترحات) ؛ المقدمون استخدام`propose`响应;مدير 接受/拒绝──这是规范的任务市场模式(مرحلة 16 · 16 التفاوض)
2. **Subscribe/Notify。**المشترك 发送 `subscribe`الناشر في موضوع 变化时发送 `inform`هذا هو كل حافلة حفلات عام 2026
3. **Request-When。**当条件 Y 成立时执行 X──带预条件的延迟行动──2026 年的模拟是耐用工作流引擎中的延迟任务(Phase 16 · 22 生产规模)──

كل واحد من هذه المواقع يمكن أن يتم تصويرها بوضوح إلى صفوف الرسائل الحديثة أو استطلاعات الإذاعة عبر الإنترنت أو البث عبر الإنترنت.

### ترك علم التخيل   بعد ذلك سوف تظهر أي مشكلة

 بدون علم التلفزيون المشترك، العاملون يتحدثون عن محتوى اللغة الطبيعية 推断含义──2026年有文档记录的失败模式是**semantic drift**: اثنان من الوكلاء باستخدام نفس الكلمة`"customer"`) يظهر مفهوم مختلف قليلا، وكيل المستلم 按误解行动،而没有方案验证器 能捕获它──FIPA的 ontology 要求会在解析时间 拒绝这个消息──

路线 走完整 ontology 路线 缓解措施:

- `content`上的 JSON Schema: في تار 层 رفض النظام الخطأ.
- النوع من الأثاث ((A2A): رفض خطأ طريقة
- الملفات 中的显式表演: حتى لو كان المحتوى لغة طبيعية، أيضا يمكن أن يجعل النية 明确无歧义。

### 2026 المواصفات 映射到 التراث الخطابي-فعالي

| Modern spec | FIPA analog | What it keeps | What it drops |
|---|---|---|---|
| MCP `tools/call` | `request` | explicit intent、correlation id | formal semantics、ontology |
| MCP `resources/read` | `query-ref` | explicit intent、correlation id | formal semantics |
| A2A Task lifecycle | contract-net + request-when | async lifecycle、state transitions | formal completeness guarantees |
| A2A streaming events | subscribe/notify | async push | typed-predicate subscription |
| CA-MCP shared context | blackboard（Hayes-Roth 1985） | multi-writer shared memory | logical consistency model |
| NLIP | natural-language content | LLM-native | schema |

من فوق إلى أسفل قراءة هذا المخطط، النموذج هو: الحفاظ على البدائية الهيكلية، والتخلي عن الفورمالية، والسماح لـ LLM 掩盖歧义──

## 关键术语
| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Speech act | “一种会做事的 utterance” | Austin/Searle：把 utterances 视为 actions。ACL 的理论源头。 |
| FIPA | “那个老 XML 东西” | IEEE Foundation for Intelligent Physical Agents。2000 年标准化了 ACL。 |
| ACL | “Agent Communication Language” | FIPA 的 envelope format：performative + content + metadata。 |
| Performative | “那个动词” | 一条 message 的 intent class：`inform`、`request`、`propose`、`cfp` 等。 |
| KQML | “FIPA 的前身” | Knowledge Query and Manipulation Language（1993）。更简单，范围更窄。 |
| Ontology | “共享词汇表” | 对 content language 所谈论概念的 formal definition。 |
| SL0 / SL1 | “FIPA content languages” | Semantic Language levels 0 and 1，即 formal content language family。 |
| Contract Net | “Task market” | Manager 发出 cfp；bidders propose；manager accepts。规范的 interaction protocol。 |
| Interaction protocol | “Messages 的模式” | 一组具有已知 correctness 的 performatives 序列：request-when、subscribe-notify 等。 |
