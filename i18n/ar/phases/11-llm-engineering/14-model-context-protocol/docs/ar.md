### 三大 Server 原语

1. **Tools（工具）**:可调用动作── كل أداة تحتوي على اسم、 وصف、 JSON Schema 输入约束及执行函数──
2. **Resources（资源）**:具名且按 URI 寻址的内容,供客户 读取──
3. **Prompts（提示模板）**: قابل للنقل: الموديلات المستخدمة للمستخدمين

المضيف يدل على تطبيقات الذكاء الاصطناعي.

### 无状态请求取代 التقليدية اليد

المملكة المتحدة 2026-07-28 تم تحريرها`initialize`和 `notifications/initialized`، و أيضاً نقل الجلسة من مستوى الاتفاقية . كل طلب متوافق`params._meta`ويتم تحليل كل ما يحتاجه

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/list",
  "params": {
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {},
      "io.modelcontextprotocol/clientInfo": {
        "name": "lesson-client",
        "version": "1.0.0"
      }
    }
  }
}
```

### 服务发现与版本协商

جميع الأجهزة الحديثة يجب أن تنفيذها`server/discover`△其返回结果广播支持的协议版本、能力集合与服务身分:

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "resultType": "complete",
    "supportedVersions": ["2026-07-28"],
    "capabilities": {
      "tools": {},
      "resources": {},
      "prompts": {}
    },
    "ttlMs": 3600000,
    "cacheScope": "public",
    "_meta": {
      "io.modelcontextprotocol/serverInfo": {
        "name": "demo-server",
        "version": "1.0.0"
      }
    }
  }
}
```

يمكن للمستخدم أيضاً استخدام طريقة العمل مباشرة ومعالجة إصدار خاطئ، ولكن استخدام إكتشاف يمكن أن يجعل القدرة على عرض الإصدارات ومناقشة الإصدارات أكثر وضوحاً.`UnsupportedProtocolVersionError`, خطأ في القانون`-32022`بياناتها`supported`(خادم 支持的修订版数组) مع `requested`(被拒绝的修订版)

في الاستديو 模式下,双时代(دوئي عصر) العميل استخدام `server/discover`发起探测──发现成功或收到 `UnsupportedProtocolVersionError`等已识别的现代错误,均证明对方为现代服务;唯有非现代错误或超时才允许回到到2025-11-25的旧版本 `initialize`اليد المتحركة. التراث يُعتبر مجرد تعويض متضامن.

### النتائج واضحة

2026-07-28 كل نجاح في النظام الأساسي`resultType`:

- `complete`:表示操作已彻底完成──
- `input_required`: يظهر الخادم  بحاجة إلى مرجعية الطلبات `tools/call`.`resources/read`أو`prompts/get`返回此类型──

العميل يجب أن يكون غائب`resultType`الإصدار القديم يجب أن يكون كامل

الخادم يجب أن يكون في كل نتيجة`_meta`中包含 `io.modelcontextprotocol/serverInfo` هذه الصفة من قبل الخادم الإعلانات الذاتية، فقط للاظهار ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ لا يمكن أن تكون أساساً لقرارات الأمن‬‬

列表和读取操作的结果还附带 `ttlMs`(ملي ثانية من الوقت) و `cacheScope`(缓存范围) ――确定性的 `tools/list`排序加上新鲜度提示,使客户端能够安全缓存服务发现结果,并提升模型 Prompt Cache 的稳定性──`cacheScope: public`允许跨上下文共享缓存،`private`تقيد بشكل صارم في إرسال الطلبات الخاصة على النص التالي

### 线缆格式与传输层

MCP في الاستديو أو HTTP المباشر 上运行 JSON-RPC 2.0:

- طلب:包含 `jsonrpc`.`id`.`method`和 `params`.
- 响应(رد): يتضمن相匹配 `id`و`result`أو`error`.
- 通知(إعلان):无 `id`, لا تحتاج إلى أي رد فعل

现代 Streamable HTTP 暴露单个只接受 POST 的端点──每个 JSON-RPC 消息应应一次独立的 POST──请求 POST 接收单个 JSON 对象,或接收以最终响应结尾的请求作用域 SSE 流──被接受通知 POST 返回无响应体的 HTTP 202──本核心修订版未定义任何通过 Streamable HTTP 从客户端 发送到服务器的通知──

2026-07-28 规范中**不存在**独立的 MCP GET 订阅流、DELETE 注销端点、`Mcp-Session-Id`أو على أساس`Last-Event-ID`                                                                                                                                                                                                                                                              `subscriptions/listen`POST من فضلكم، انجبجوا على الارتباط الطويل

### 无需服务器 发起请求的客户端 输入

旧修订版允许服务 通过流发送 `sampling/createMessage`.`roots/list`أو`elicitation/create`之类的请求──当前协议改用多轮往返请求(MRTR)──符合条件的工具 调用、资源读取或快速 获取会回归 `resultType: input_required`،并至少 حمل `inputRequests`أو`requestState`واحد.  العميل  جمع ما يحتاج إليه من إدخال، استخدام ID JSON-RPC الجديد 和对应的 `inputResponses`重试原始方法;若提供了 `requestState`,إذا كان هناك`inputRequests`,重试时省略 `inputResponses`.

## 动手构建

### 步骤 1: ثبت الخادم 表面

على الرغم من تغييرات في الطلب، فإن طريقة التسجيل لا تزال بسيطة:

```python
server = MCPServer("demo-server")

@server.tool(
    "add",
    "Add two integers.",
    {
        "type": "object",
        "properties": {
            "a": {"type": "integer"},
            "b": {"type": "integer"}
        },
        "required": ["a", "b"]
    }
)
def add(a: int, b: int) -> dict:
    return {"sum": a + b}
```

`code/main.py`تمت إدارة المعلومات المكتوبة في الموقع، حيث تم إرسالها إلى الموقع.

```python
def request(method, params=None):
    body_params = dict(params or {})
```

### الخطوة 4: ضع نفس الطلب على HTTP

远程 `tools/call`POST  تحمل صورة JSON-RPC طلبات الطلبات:

```http
POST /mcp HTTP/1.1
Content-Type: application/json
Accept: application/json, text/event-stream
MCP-Protocol-Version: 2026-07-28
Mcp-Method: tools/call
Mcp-Name: add
```

`MCP-Protocol-Version`الطلب يجب أن يتوافق مع`_meta`نسخة متوافقة`Mcp-Method`في كل طلب JSON-RPC كل طلبات ضرورية، ويجب أن تكون`method`واحد واحد`Mcp-Name`فقط في`tools/call`.`resources/read`مع`prompts/get`时必填,且必须与工具名、资源 URI或提示名一致.`HeaderMismatch`错误码 `-32020`.

### الخطوة 5: تنفيذ الأمن خارج حالة الاتفاق

## التدريب والتفكير

1. إضافة واحدة`subtract`工具,确认 `tools/list`仍按字母序排列──
2. 移除 بروتوكول-version 键,验证返回 غير صالحة`-32602`)¬ ثم إرسال إصدار صحيح ولكن غير مدعوم`2025-11-25`, تجربة عودة`-32022`, تأكد`requested`عكس هذا الإصدار المعدل،`supported`中选择版本──
3. لإنشاء عمليات إضافة من قبل الخادم`draftId`،并要求 تحديث العملية لتوصيلها كعيار. شرح لماذا هذا هو حالة التطبيق وليس جلسة البروتوكول.
4. 让一个需要用户确认的工具返回 `input_required`استخدام هوية جديدة`inputResponses`条目和原样 `requestState`重试原始调用، بدلا من جعل خادم إلى العميل JSON-RPC طلب.
5.  تصميم استديو دو عصر العميل 草图:把结果或已识别的现代错误视为现代对端, فقط في مواجهة خطأ لا يمكن التعرف عليه أو فترة فائقة من الوقت فقط يسمح للعودة إلى `initialize`.

## 核心专业术语

| 术语 | 通俗说法 | 实际含义 |
|------|-----------------|------------------------|
| MCP | “LLM 的工具协议” | 用于服务发现、工具、资源、提示模板与扩展的 JSON-RPC 协议 |
| Host | “AI 应用” | 拥有大模型与用户交互界面、挂载一个或多个 MCP Client 的 AI 应用程序 |
| Client | “连接器” | 代表 Host 与单个具体 Server 执行 MCP 通信的连接器组件 |
| 无状态 MCP (Stateless MCP) | “没有 Session” | 每个请求携带版本与能力元数据，不存在与底层物理连接绑定的协议状态 |
| `server/discover` | “能力探测” | 强制实现的 Server 方法，用于公布支持版本、能力集与身份标识 |
| `resultType` | “结果状态” | 把结果标记为 `complete` 或 `input_required` |
| 显式状态句柄 (State handle) | “工作流 ID” | 由 Server 签发、作为普通业务参数传递的应用层唯一标识符 |
| Streamable HTTP | “远程传输” | 单一 POST 端点架构，返回常规 JSON 或请求作用域的 SSE 响应 |
| MRTR (多轮请求模式) | “请求输入再重试” | 嵌入在响应结果中的输入请求，完成后由客户端重新发起原始操作重试 |
