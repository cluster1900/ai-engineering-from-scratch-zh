# LangGraph: الرسومات المثالية مع التنفيذ الدائم

> لنجراف هو المعيار المرجعي لترتيب الحالة منخفضة المستوى لعام 2026. العامل هو حالة من الأجهزة. العقد هو وظيفة. الحافة هي حالة من الحالة. الحالة هي غير قابلة للتغيير، ويتم اختبارها بعد كل خطوة.

**类型：**学习 + 构建
**语言：**Python (stdlib)
**先修要求：**المرحلة 14 · 01 (حلقة العملاء) ، المرحلة 14 · 12 (أنماط تدفق العمل)
**时间：**75 دقيقة

## 學习目标

- وصف النموذج الأساسي لـ LangGraph:带有不变状态、功能节点、条件边和后步检查站的状态机
- يقولون أن الملفات تؤكد على أربعة قدرات: التنفيذ المستمر  التدفق ‬الإنسان في الحلقة ‬الذاكرة الشاملة‬
- 解释 LangGraph 支持的三种管弦乐类型: المشرف、قرابة إلى قرابة (السحابة)、هيراركية (الخطوط الفرعية المظلمة)。
- 实现 a stdlib حالة الرسم البياني، يحتوي على حالة غير قابلة للتغيير حواف مشروطة، فضلا عن نقطة التفتيش/منهاج سيرها.

## 问题

وكلاء و عمليات العمل هناك مشكلة مشتركة: عندما ينفذ عمل 40 خطوة في الخطوة 38، تريد استئناف من الخطوة 38، وليس من البداية. النموذج الحالي الثاني سوف يجعل المستخدمين حول افتراض أن كل مرة هي مكتبة جديدة تعمل.

الإجابة التصميمية لـ LangGraph هي: الحالة هي كائن من نوع واحد، والتنوينات هي واضحة، ويكون نقاط التفتيش في كل عقدة بعد استمرارها.`load_state(session_id)`调用。

## 概念

### الرسم البياني

واحد الرسم البياني من قبل الجزء التالي تعريف:

- **State type.**نموذج بيدانتي) ، كل عقدة مدينة
- **Nodes.**纯函数 `(state) -> state_update`◊ تحديثات 会在返回后合并进状态‬
- **Edges.**الانتقالات المشروطة أو المباشرة بين العقدة
- **Entry and exit.** `START`和 `END`عقدات الحرس 标记边界。

نموذج: واحد يحتوي`classify`.`refund`.`bug`.`sales`.`done`وكيل العقد، أي رسمية 形式 روटिंग workflow.

### التنفيذ المستمر

كل عقدة عودة بعد، التشغيل 会序列化状态،并将其写入检查点(SQLite、Postgres、Redis、自定义) `resume(session_id)`,并带着精确状态 从第 N+1 步继续──

لاغراف 文档 واضحاً يؤكد على أهمية هذا الأمر على مستخدمي الإنتاج: كلارنا、أوبر、 جي بي مورغان‬

### التدفق

كل عقدة يمكن أن تنتج الناتج الجزئية  الرسم البياني 会向通话 سلسلة لكل عقدة-دلتا الأحداث،让 UI 能在图 运行时更新‬

### البشر في الحلقة

في العقدة  بين المراقبة و تغيير الحالة. طريقة التنفيذ: في العقدة الحرجة  قبل التوقف، سوف تظهر الحالة إلى الإنسان، والقبول بالتغيير، ثم استئناف.

### الذاكرة

قصير الأجل (إنها تاريخ المحادثة في الحالة) و طويل الأجل (إنها عبر النقل، إنها عبر نقطة التفتيش 加上独立长期存储 持久化)

1. **Supervisor.**الجهاز المركزي LLM تم توفيرها إلى المختصين`langgraph-supervisor`وسط`create_supervisor()`(في عام 2026، يوصي فريق لنج تشين بإجراء مكالمات مباشرة من خلال أدوات، للحصول على تحكم أفضل في السياق)

### هذا النمط يسهل الخروج من هناك

- **Checkpoints too small.**فقط محادثة نقطة التفتيش تتحول 会让工具状态 和 ذاكرة الكتابة 无法恢复──状态 必须可序列化──
- **Non-deterministic nodes.**إعادة التأثير  فرض مدخلات العقدة سوف تنتج نفس تحديث الحالة.
- **Over-use of conditional edges.**كل حافة هي رسمية مشروطة، وهي حالة لا يمكن تقييمها.

## بناءها

`code/main.py`实现 a stdlib stateful graph:

- `State`: إصدار مُنْقَطِب، يحتوي على`messages`.`step`.`route`.`output`.`human_approval`.
- `Node`: وصول حالة 并返回 تحديث ديكت
- `StateGraph`:عقد + حواف + حواف مشروطة + تشغيل + استئناف。
- `SQLiteCheckpointer`(مزيف في الذاكرة): في كل عقد 后序列化 حالة`load(session_id)`تعافي
- واحد عرض عرض: تصنيف -> فرع(رد / حذاء / مبيعات) -> البوابة البشرية -> إرسال。

运行它:

```
python3 code/main.py
```

تتبع سوف تظهر أول عملية في البوابة البشرية 失败、完成持久化, ثم استئناف ومنتجة النهائية

## 关键术语

| Term | 人们常说 | 实际含义 |
|------|----------------|------------------------|
| State graph | “Agent 即状态机” | Typed state + nodes + edges + reducers |
| Checkpointer | “Persistence backend” | 在每个 node 后序列化 state；支持 resume |
| Reducer | “State merger” | 将当前 state 与 node update 组合起来的函数 |
| Conditional edge | “Branch” | 由 state 函数选择的 edge |
| Subgraph | “Nested graph” | 作为另一个 graph 中 node 使用的 graph |
| Durable execution | “从失败处 resume” | 使用精确 state 从最后一个成功 node 重启 |
| Supervisor | “Router LLM” | 面向 specialist subagents 的 central dispatcher |
| Swarm | “P2P agents” | Agents 通过 shared tools hand off；没有 central router |
