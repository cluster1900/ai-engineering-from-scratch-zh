## 概念

### أربعة عناصر أساسية

سطح الطاقم صغير جداً. تذكر هذا، الباقي هو التخصيص.

- **Agent。** `role + goal + backstory + tools + (optional) llm`◊خلفية 很关键──它塑造语气、判断,以及 وكيل 何时停止── الأدوات هو وكيل يمكن تعديل وظيفة(下面会讲)。
- **Task。** `description + expected_output + agent + (optional) context + (optional) output_pydantic`❖ الوحدة العمل المستخدمة`expected_output`نعم , نعم`context`列出上游任务,其输遇被传入──`output_pydantic`强制使用结构化形态──
- **Crew。**حاوية`agents`قائمة`tasks`قائمة`process`و الاختيارات`memory`+ `verbose`+ `manager_llm`إعداد
- **Process。**执行策略──序列、 Hierarchical、Consensus(计划中)──选择运行的形态──

العاملون لن يرون بعضهم البعض مباشرة. المهام تقتصر على العاملين. الموظفين على المهام. يقومون بتنظيمها.

> **已针对**CrewAI 0.86(2026-05)验证──更新版本可能会重新命名或合并流程类型; 在依赖具体形态之前,请查看 [CrewAI Processes docs](https://docs.crewai.com/concepts/processes).

### التسلسل ̇الهيركية والاتفاق

- **Sequential。**المهام 按声明顺序运行──مهمة N 的输出可作为 `context`提供给任务 N+1──成本最低──最可预测──当顺序固定时使用──
- **Hierarchical。**مدير وكيل ((مكالمة LLM منفصلة) بين المتخصصين 路由──`manager_llm`إعداد أو افتراضي إعداد المنتج مدير. مدير. كل دورة اختيار المهام التالية، ويمكن رفض أو إعادة توجيهها.
- **Consensus。**في المخطط، لم يتم تنفيذ API العامة الحالية.

في كل مكالمة متخصصة، يزيد المجلس الهرمي من كل دورة واحدة من مكالمة الماجستير في مجال الجامعة.

### الطواقم مقابل التدفقات

هذا هو إطار 2026

- **Crew。**الإطار في التشغيل: البحث، المفاجأة، المخططات الأولى، والطريق نفسه هو جزء من المشكلة.
- **Flow。**الحوادث التي تملكها تحرك الرسم البياني`@start`标记入口──`@listen(topic)`标记一步,它将在另一个步骤中发出这个主题 时触发──每步都是普通 Python(内部可以调用 Crew)──适合:生产──可观测──可测──确定性──

文档在 2026 年的生产建议:从流动 开始――当自主权 值得其成本时,把船员 作为流动步骤 内部的 `Crew.kickoff()`الاتصالات 折进去──Flow 给你审计轨迹, Crew 给你探索──组合使用,不要二选一──

### أداة 集成

أعط الوكيل أداة تسويق هناك ثلاثة طرق. اختر أسهل وأصغر طريقة.

1. **`@tool` decorator。**純函数变成工具──"الوقعة هي مخطط؛ والوثائق هي وصف LLM 看到的──最适合一次性助手──

   ```python
   from crewai.tools import tool

   @tool("Search the web")
   def search(query: str) -> str:
       """Return top results for the query."""
       return run_search(query)
   ```

2. **`BaseTool` subclass。**أداة على أساس الفئة،带显式 args schema、async support、retries──当 tool 有状态(client、cache) أو تحتاج إلى args مهيكلة 时使用──

   ```python
   from crewai.tools import BaseTool
   from pydantic import BaseModel

   class SearchArgs(BaseModel):
       query: str
       limit: int = 10

   class SearchTool(BaseTool):
       name = "web_search"
       description = "Search the web and return top results."
       args_schema = SearchArgs

       def _run(self, query: str, limit: int = 10) -> str:
           return self.client.search(query, limit=limit)
   ```

3. **内置 toolkits。**CrewAI قدم مُعدّلات الطرف الأول:`SerperDevTool`.`FileReadTool`.`DirectoryReadTool`.`CodeInterpreterTool`.`RagTool`.`WebsiteSearchTool` مرة واحدة الإيرادات 即可接入

الخروج المهيكل استخدام Pydantic.`output_pydantic=MyModel` الموظفين سوف يقومون بناء على نموذج 验证 LLM رد،并 إجراء الإكراه أو محاولة أخرى  وضعها مع صرامة `expected_output`سلسلة 配合使用──موارد الناتج المجانية 适合草稿;موارد الناتج المهيكلة 才是下游

### مضادات الذاكرة

المجموعة تسمح بإستخدام أربعة أنواع من الذاكرة في وقت واحد.

> **已针对**كروآي 0.86(2026-05)验证──`Memory`النظام، هذا النظام يحتوي على هذه المتاجر الأربعة. النموذج المفهوم التالي لا يزال قائماً، ولكن في الإصدار الجديد، يمكن أن تكون سطح الطبقة العامة مقبولاً للوحدة.`Memory`نقطة دخول , رجاءاً[CrewAI memory docs](https://docs.crewai.com/concepts/memory)了解当前 API。

- **Short-term。**单次运行内 محادثة بوفر.
- **Long-term。**跨运行持久化──存储在向量DB 中(默认 Chroma,可替换)──按与当前任务的相似性检索──
- **Entity。**按实体 记录事实──客户 X على خطة المؤسسة. 按实体键,而不是按相似度──跨运行保留──
- **Contextual。**组装时检索──在 需要时拉取相关记忆,而不是预载──

في الطاقم`memory=True`أو حسب النوع من التكوينات  فعالة‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬

### 什么时候适合 CrewAI

- ثلاثة إلى ستة وكلاء، مع أدوار واصطناع سير العمل.
- ماجستير في التدريب على الخطوة التالية في نفسها تشكل توجيه القيمة
- 团队更愿意读 `role + goal + backstory`بدلاً من قراءة تعريف الرسم البياني من المشهد

### 什么时候不适合 CrewAI

- 带严格顺序的确定性DAGs──使用LangGraph(درس 13)──形状图是正确抽象;角色框架 会带来摩擦──
- 亚秒级延迟预算── Hierarchical 会增加回路旅行── حتى التسلسل أيضا سوف يحتوي على التسجيلات الخلفية ومعلومات عن النتائج السابقة──
- حلقات وكيل واحد. قفز الإطار. حلقة وكيل.

الدرس 17 ((تجارة الإطار العميل) مع المصفوفة ظهرت هذا النقطة.

### شكل الاعتماد

独立于 朗格链──Python 3.10 إلى 3.13──使用 `uv`✿عدد النجوم:见 [crewAIInc/crewAI](https://github.com/crewAIInc/crewAI)(حتى 2026-05 من اللقطة) ――AWS دمج Bedrock 有文档;بائع مقارنات 报告其在QA workloads 上相比 LangGraph 有显著提速,但方法论(مجموعة بيانات、硬件、قياس المقاييس) غير علنية, لذلك إطار-بائع أرقام يمكن أن تكون فقط كمرجع اتجاهية‬

### هذا النمط سيكون في أي مكان

- **Backstories 导致 prompt-bloat。**كل عميل واحد قصة خلفية من 2000 كلمة، إضافة خمسة أعضاء في طاقم العميل، سوف يكون في أول أداة دعوة قبل حرق الميزانية السياقية، وإضافة قصص خلفية  التحكم في 200 كلمة من الداخل، عبر العميل، إضافة قصة قصة، لا تترك أسلوب المنزل، إضافة خمس مرات.
- **Manager-LLM token tax。**العملية الهرمية سوف تتواجد في كل مكالمة متخصصة 前增加一个经理 LLM call。五个任务 工作人员 会从五次LLM calls 变成六次,而且经理 call 携带完整任务列表加上前输出──除非路由依赖输出,否则切换到序列──
- **Brittle handoffs。**المهمة N `expected_output`نعم، إنها خطة رسمية.`context`读取,并尝试 parse 三个节目──LLM 生成四个──下游 وكيل 即兴处理──修复方式是在任务 N 上使用 `output_pydantic`،让任务 N+1 读取 نوع الكائن، وليس النص الحر.
- **Crew-as-prod。**Freedom Form Crew في حالة عدم وجود غلاف التدفق يتم إصدارها إلى الإنتاج.

## بناءها

`code/main.py`تم تحقيق إصدارات من نوعين من النوعين، وكذلك فريق من العاملين الثلاثة.

形态:

- `Agent`.`Task`فصول البيانات، تتناسب مع سطح كروآاي
- `SequentialCrew.kickoff(inputs)`按声明顺序运行任务,并把输出 作为 `context`传递‬
- `HierarchicalCrew.kickoff(topic)`زيادة مدير وكيل، في كل دورة اختيار المختصين التالي، و دفع 处停止──
- 带 `@start`和 `@listen(topic)`ديكورات `Flow`، حلقة صغيرة جدا من الأحداث، فضلا عن العقب
- `tool(name)`المزخرف، مرآة CrewAI `@tool`شكلها
- 带 `short_term`.`long_term`.`entity`المتاجر `Memory`تمزحين على التشابه استخدامات
- استجابات الـ LLM المزيفة هي حسب الدور 加 input prefix keyed of hardcoded strings──无网络──确定性──

具体 demo:researcher、writer、editor crew,产出一份关于 agent engineering 2026 的简报──Researcher 拉取(拉取(mocked) المصادر──Scrier 起草──Editor 收紧──同一个 crew 通过 Flow 运行,以展示决定性形状──

运行它:

```bash
python3 code/main.py
```

## استخدمها

- **CrewAI Flow**حتى التدفق فقط خطوة واحدة`Crew.kickoff()`تدفقات المراجعة
- **CrewAI Crew (Sequential)**استخدامها في عمل تعاون واضح، وخاصة المخططات الأولى و حلقات المراجعة.
- **CrewAI Crew (Hierarchical)**عندما تقوم بتوجيه الإنتج يتوقف على الخروج، و لديك أربعة أو أكثر من المتخصصين استخدم وقتها
- **LangGraph**(الدرس 13) تستخدم في آلات الحالة الواضحة، استئناف دائم، ترتيب صارم.
- **AutoGen v0.4**(الدرس 14) تستخدم في التوافق مع نموذج الممثل و العزل عن الأخطاء
- **OpenAI Agents SDK**(الدرس 16) تستخدم منتجات OpenAI الأولى، مع التفويضات والحواجز
- **Claude Agent SDK**(الدرس 17) تستخدم منتجات أولى كلويد، مع السباقات و محل جلسات

## 常见坑

- **把 backstory 当作调味。**ستقوم بتشكيل النتائج. كل وكيل يختبر ثلاثة فواركات.
- **跳过 `expected_output`。**没有每个任务的契约,下游任务 会拿到 LLM 产出的任意内容──船员 能跑;审计会失败──
- **Memory always-on。**على المدى الطويل كل مرة تعمل فيها سوف تكتسبها.
- **Manager prompt drift。**إن كان التوجيه غريبًا ، ففي وضع اللفظات ، فلنخرج للقراءة
- **Crews 中 tool side effects。**طاقم قد يكون أكثر من المتوقع المزيد من التدوين أداة.

## 关键术语

| Term | 大家常说 | 实际含义 |
|------|----------------|------------------------|
| Agent | “Persona” | Role + goal + backstory + tools |
| Task | “工作单元” | Description + expected output + assignee + optional structured output |
| Crew | “Agent team” | Agents + Tasks + Process 的容器 |
| Process | “执行策略” | Sequential / Hierarchical / Consensus（计划中） |
| Flow | “Deterministic workflow” | 事件驱动、代码拥有、可测试 |
| Backstory | “Persona prompt” | Agent 的语气与判断塑造器 |
| `@tool` | “Function tool” | 把函数变成 Agent 可调用 tool 的 decorator |
| `BaseTool` | “Class tool” | 带 args schema、retries、async support 的 class-based tool |
| Entity memory | “Per-entity facts” | 限定到某个 customer / account / issue 的 memory |
| Long-term memory | “Cross-run memory” | 在 kickoffs 之间保留的 vector-backed memory |
| Contextual memory | “Just-in-time retrieval” | Agent 需要时才拉取的 memory |
| Manager LLM | “Router agent” | Hierarchical process 中选择下一个 task 的额外 LLM |
| `expected_output` | “Task contract” | 告诉 Agent（和 audit）要返回什么形态的 string |
