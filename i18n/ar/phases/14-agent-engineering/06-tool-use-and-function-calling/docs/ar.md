# استخدام الأدوات و الوظيفة

> أداةformer (Schick et al., 2023) 开创了自监督工具注释──بيركلي وظيفة دعوة لدربورد V4 (باتيل وآخرون، 2025) 设定 2026 年标准:40% وكالة、30% متعددة التحول、10% حي、10% غير حية、10% الهلوسة── التحول الواحد 已解决── ذاكرة、 اتخاذ القرارات الديناميكية وسلسلات الأدوات طويلة الأفق لا يزال هناك حل──

## 问题
早期 tool use 问的是:model 能否预测一个正确的功能调用? 现代 tool use 问的是:model 能否跨 40 个步骤链式调用工具,具备记忆,处理部分可观测性,恢复从工具故障中,并且不幻觉不存在的工具?

أداةformer  أسس أسس: النماذج يمكن أن تمر من خلال الإشراف الذاتي 学会何时调用工具──BFCL V4  حدد هدف التقييم لعام 2026──

## 概念
### أداة (شيك وزملاء، NeurIPS 2023)

فكرت: دع النموذج باستخدام API المرشح يدعو إلى علامة على جسم التدريب الخاص بك.

覆盖的工具:حاسبة QA نظام 搜索引擎 翻译 日历 自我监督信号 纯粹关注工具 是否有助于预测文本,不需要人标签──

规模结果: tool use 会在规模足够时涌现──较小的模型 会因工具注释受损;较大的模型会受益──这就是为什么2026年边界模型内置强的工具使用能力,而大多数7B模型需要明显的工具使用细调才可靠──

### بركلي وظيفة دعوة قائمة V4 (باتيل وزملاء، ICML 2025)

BFCL هي تقييم واقعي لعام 2026──V4 构成:

- **Agentic (40%)** مسارات العملاء الكاملة:ذاكرة عدد التحولات ‬قرارات ديناميكية‬
- **Multi-Turn (30%)** 带 أدوات سلسلة من المحادثات
- **Live (10%)** مستخدم تقديم التحذيرات الحقيقية ((更难的分布) 。
- **Non-Live (10%)** حالات اختبار اصطناعية
- **Hallucination (10%)** 检测何时不应调用 الوسيلة

V3 قدمت تقييمًا قائمًا على الحالة: بعد ذلك ، فحص الحالة الفعلية لل API (مثل: هل تم إنشاء ملفات؟) ، بدلاً من دعوات أدوات مطابقة AST。 V4 ، زادت من بحث الويب、ذاكرة و فئات حساسية النمط。

2026 年关键发现:تدعوة وظيفة التحول الواحد 基本已解决──失败集中在记忆(跨轮 携带背景)、 اتخاذ القرارات الديناميكية(基于先前结果选择工具)、长视线链(20+ خطوة 后漂移) واكتشاف الهلوسة(没有合适工具 时拒调用)。

كل مزود لديه مخطط مختلف، ولكن يشترك في نفس الشكل:

### تأكيد الحجج

لا تثق بأي أداة

1. **Type coercion.**النموذج ممكن في النموذج  مطلوب int 的地方返回字符串 `"5"`如果明确无歧义就强制;否则拒绝
2. **Enum validation.**إذا كان النظام يكتب`status in {"open", "closed"}`النموذج 输出 `"in_progress"`، على استخدام خطأ تصريح رفض
3. **Required fields.**缺少 مطلوب الحقل -> 立即把错误观察 返回模型,而不是崩──
4. **Format validation.**التاريخ والبريد الإلكتروني والURLs باستخدام المستخدمين المحددين للتحقق وليس regex

كل فشل في التحقق يجب أن يعود إلى الملاحظة الهيكلية، فيمكن أن يستخدم النموذج بشكل صحيح.

### مكالمات الأدوات المتوازية

مزودي الحديث 支持在一个助手转 中并行 أداة الاتصال.

1. النموذج أطلق 3 مكالمات أداة، كل منها مختلف`tool_use_id`.
2. وقت تشغيله  تنفيذها 
3. كل نتيجة كانت كـ`tool_result`الحظر عودة،并通过 `tool_use_id`关联──

工程规则:把相关性 ID 当作关键约束──把它们交换,就会导致错工具到错结果路由──

## 关键术语
| Term | 人们怎么说 | 它实际意味着什么 |
|------|----------------|------------------------|
| Function calling | "Tool use" | 使用 validated schema 的 structured-output tool invocation |
| Toolformer | "Self-supervised tool annotation" | Schick 2023 — 保留那些结果能降低 next-Token Loss 的 tool calls |
| BFCL | "Berkeley Function Calling Leaderboard" | 2026 benchmark：40% agentic、30% multi-turn、10% live、10% non-live、10% hallucination |
| Tool schema | "给 model 的 function signature" | name、description、arguments 的 JSON Schema |
| tool_use_id | "Correlation ID" | 将 tool call 与其 result 绑定；对 parallel dispatch 至关重要 |
| Hallucination detection | "知道何时不调用" | V4 category：没有合适 tool 时拒绝调用 |
| Argument coercion | "String-to-int repair" | 针对可预测 schema mismatch 的窄修复；如果有歧义则 reject |
| Sandboxing | "Tool execution boundary" | 每个 tool 的 read/write surface、network、timeout、memory cap |
