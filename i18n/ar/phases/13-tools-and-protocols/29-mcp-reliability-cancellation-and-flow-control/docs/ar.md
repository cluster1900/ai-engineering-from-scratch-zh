## 取消 هو حالة

كلّ حوادثٍ تُحَدثَتْ بشكلٍ قانوني تماماً

### 取消获胜

```text
request starts（请求启动）
client sends cancellation signal（客户端发送取消信号）
server marks request cancelled（服务端将请求标记为已取消）
worker reaches completion（工作线程执行完成）
server suppresses the response（服务端抑制并不发送响应）
```

### 完成获胜

```text
request starts（请求启动）
worker commits the result（工作线程提交业务结果）
server sends the response（服务端发送响应）
cancellation arrives late（取消信号迟到）
server ignores the late notification（服务端忽略迟到的通知）
```

يجب على المستخدم أيضاً أن يتجاهل بشكل مباشر ردود الفعل المتأخرة على الطلبات التي تم التخلي عنها.

```figure
mcp-reliability-race
```

## الـ " سوفر تايم " يحتاج ساعتين

单一的无活动(无活动) الاسبوع هو بعيد جدا غير كافى

يجب أن يُدخّل في نفس الوقت اثنين من الحدود:

1. **空闲超时（Idle timeout）**: طلب لم يحدث أي نشاط مفيد في فترة طويلة
2. **最大超时（Maximum timeout）**: من الطلب الأول إطلاق وقت حسابات الوقود المادي المفروض

يمكن إعادة وضع فترة**绝不能**推迟或消除最大截止时间──

```text
start: 0 ms
progress: 400 ms
progress: 800 ms
progress: 1200 ms
idle timeout: 500 ms
maximum timeout: 2000 ms
```

في 1500 ms، ما زال الطلب في حالة نشطة، لأن المسافة من الحدث التقدم السابق تجاوزت 300 ms فقط. ولكن في 2000 ms، سيتم إلغاء الطلب بشكل قاسٍ، حتى في 1999 ms عندما يظهر حدوث تقدم جديد.

إشعار التقدم هو اختياري. يمكن للجهاز الخدمي قبول إشعار التقدم بالكامل. ولكن لا يتم إرسال أي تحديثات خلال فترة التنفيذ.

يجب أن يزداد عدد الإنجازات في مؤسسة التنمية المعدنية. يجب أن يتوقف كل الإخطارات على الفور بعد الانتهاء أو إلغاءها. يجب أن يحد من السرعة في الإخطار المعدني.

## طلب取消不等于`tasks/cancel`

هذه الآليات الحل مشكلة مختلفة تماما من مستوى دورة الحياة.

| 机制 | 作用目标 | 线路信号 | 成功意味着什么 |
|-----------|--------|--------|--------------------|
| stdio 上的请求取消 | 单次在途 RPC | `notifications/cancelled` | 客户端放弃了该请求；若可行服务端应当停止执行 |
| HTTP 上的请求取消 | 单个在途响应流 | 关闭该流 | 客户端放弃了该请求；若可行服务端应当停止执行 |
| `tasks/cancel` | 单个持久化 Task | 普通 MCP 请求 | 服务端已确认收到取消意图 |

`tasks/cancel`لا يثبت نجاح استخدام العاملات الخلفية`working`وضع، حتى يعمل في نقطة فحص ما (checkpoint) يدرك أنه يتم إزالة العلامة؛ العمل قد يكون قد تم إنجازه بنجاح قبل أن يدرك أنه تم إزالة العلامة.

عندما يقطع اتصال HTTP**绝不要**清除持久化任务的状态──创建任务的初衷正是让其生命周期能够超越单次请求与单条连接的限制──

## ID JSON-RPC الجديد  مطلقًا ليس مساوًا ل

يستخدم ID JSON-RPC فقط لتنسيق طلبات وردود، فهي لا تمثل عمليات الأعمال نفسها.

假设客户端提交一笔账单扣款`41`), في الطريق فقدت استجابة الخدمة، ثم استخدم المستخدم الهوية `42`发起重试―― خدمة端看到是两条截然不同的消息――如果没有应用层的唯一标识,服务端根本无法了解它们代表同一结账请求――

等键(إعفاءة المفتاح)

```json
{
  "name": "charge_account",
  "arguments": {
    "account": "acct-7",
    "cents": 1200,
    "idempotencyKey": "checkout-7"
  }
}
```

服务端会持久化记录:

- 等键
- 操作参数的哈希指纹(طباعة أصابع الحجج) ؛
- نتائج تنفيذ قدمتها

سوف يعود المفتاح نفسه مع نفس العناصر مباشرة إلى نتائج المخزن السابق. إذا كان نفس المفتاح يحمل عناصر مختلفة، فسيتم رفضه بشكل حاسم.

### 重试决策矩阵

قبل تحقيق التجربة الثانية، يجب إجراء التجربة الثانية بشكل واضح.

| 类别 | 示例 | 重试规则 |
|------|---------|------------|
| 安全（Safe） | 无副作用的确定性读操作 | 在明确故障边界后，可使用新的 JSON-RPC id 直接重试 |
| 有条件（Conditional） | 具备持久化幂等键的写操作（Mutation） | 必须使用完全相同的幂等键和完全相同的参数发起重试 |
| 不安全（Unsafe） | 未提供业务去重机制的写操作 | 严禁自动重试；必须先进入人工或系统对账调和流程 |

工具描述符中附带的 `readOnlyHint`和 `idempotentHint`فقط من المفاهيم الخارجية لا يمكن الاعتماد عليها.

3. 将事件流标记为需要权威数据重拉需要权威重复);
4. 始终完整保留最终响应
5. إذا كان الحفاظ على الإجابة النهائية يتطلب التخلي عن الإجابة النهائية الأخرى مقابل ذلك، فإنّه يرفض هذه الحالة.

هذا هو الاختفاء من الجهاز التجاري المُحدد.

### 代理缓冲问题

服务端可能在完美流式输出中,而中间的反向代理却在私积事件缓冲中.

بالنسبة لـ SSE 响应، يجب أن يظهر على النحو التالي:

```http
Content-Type: text/event-stream
Cache-Control: no-cache
X-Accel-Buffering: no
```

2026 سنة التدفق HTTP 规范强烈建议配置 `X-Accel-Buffering: no`، لكي تتوافق الخدمة الوكالة مثل Nginx) قادرة على الانتقال فوريا إلى العملاء

对于长期处于静默状态长连接,需要定期发送 SSE 注释行(保活心跳):

```text
:
```

客户端会自动忽略注释行──中间代理设备则能看到网络活动,从而避免断断看似空的连接──

传输保活不等于业务进步――绝不能因为收到传输层的保活注释就顺带重置业务操作的语义空超时计时器――

## الارتفاع يعني إعادة التأثير

现代 Streamable HTTP 协议**不支持** من خلال `Last-Event-ID`إجراء عملية التسجيل

عندما`subscriptions/listen`بعد وقوع حادثة

1. استخدام ID JSON-RPC الجديد
2. 重新注册 مطلوبة
3. 调用权威接口全量拉取可能受影响的工具、资源、提示或任务;
4. وفقاً لثبات المجلس الوحيد للتعرف على حالة الطابق التطبيقي
5. لا تتركوا أعينكم في خطورة عدم الحماية فقط بسبب فقدان الإجابة السابقة

في المثال، سيتم إعادة التأهيل بشكل واضح`sendLastEventId`إعداد كاذب، ومع ذلك قائمة الموارد التي تحتاج إلى كامل الوزن.

### 防止重连风暴 (تأثير القطيع)

إذا كان 10 آلاف مشترك في الانتصال بعد انقطاع الانتصال في كل ثانية واحدة في نفس الوقت، فإن خدمة الانتصال التي تم استعادتها سوف يتم إعادة تعيينها مرة أخرى في اللحظة.

يجب أن تتبنى مع وجود تحركات متزايدة (Jitter) مع آلية إعادة الوصول إلى المؤشر الحماية العليا.

```text
attempt 0: up to 250 ms
attempt 1: up to 500 ms
attempt 2: up to 1000 ms
...
cap: 8000 ms
```

يمكن استخدام بيئة الإنتاج في الأمان أو التشغيل.

## النمو البيئي

| 故障现象 | 观察到的表象 | 正确处理方案 |
|---------|--------------------|------------------|
| HTTP 客户端 POST 发送取消通知 | 服务端与客户端对请求的生命周期产生分歧 | 直接关闭该请求专有的 SSE 响应流 |
| 服务端在接受取消后依然回传响应 | 客户端收到一份已无法使用的陈旧无用结果 | 当取消获胜时停止业务计算并抑制所有后续消息 |
| 进度通知无限重置所有超时时钟 | 挂起卡死的任务永久占用资源无法退出 | 维持一个独立的全局绝对最大超时硬上限 |
| 将新的 RPC id 当成请求去重依据 | 扣款、发布或删除操作被多次重复执行 | 在应用层引入并强制校验持久化幂等键 |
| 键检查与业务副作用彼此分离 | 并发执行的多个 worker 同时判定键不存在 | 将键占位、副作用记录与结果提交放入单次原子事务 |
| 在多副本集群中使用内存级账本 | 节点重启或换到另一台机器后遗忘了先前的提交 | 使用持久化共享存储或依赖上游系统的幂等支持 |
| 直接返回底层存储的可变对象引用 | 调用方的内存修改意外污染了后续重放结果 | 将提交结果序列化存储，返回时构造深拷贝副本 |
| 相同的键被复用于篡改后的参数 | 单个幂等键混淆了两种不同的业务意图 | 持久化记录并校验调用参数的哈希指纹 |
| 进度通知队列无界增长 | 遇到慢消费者时服务内存持续飙升直至 OOM | 在容量限制内对可替代的进度通知进行合并与淘汰 |
| 在高压下误丢弃了最终响应 | 客户端永远无法获知该请求的最终成败 | 预留专用容量或只淘汰进度通知，绝不丢弃最终响应 |
| 反向代理缓冲了 SSE 事件 | 进度事件呈突发性到达，或在全部执行完后才下发 | 禁用代理缓冲（`X-Accel-Buffering: no`）并调整代理超时 |
| 盲目假定支持 `Last-Event-ID` | 客户端尝试从服务端根本不支持的位点续传 | 使用新请求重连并向权威数据源全量拉取 |
| 所有客户端在断开后同一瞬间重连 | 系统恢复的瞬间引发严重的次生雪崩风暴 | 采用带上限保护、结合随机抖动的指数退避重连机制 |
| 将 Task 的确认回执当成已完成取消 | 前端界面显示已停止，而后台 worker 仍在计费运行 | 持续轮询 Task 状态直到其真正进入终态 |

## 关键术语

| 术语 | 含义 |
|------|---------|
| 请求取消（Request cancellation） | 放弃单次处于在途状态的 MCP RPC 请求 |
| 取消竞态（Cancellation race） | 终态执行完成与取消信号抵达之间的时序争夺 |
| 空闲超时（Idle timeout） | 距离上一次产生有效请求活动的最大允许时间 |
| 最大超时（Maximum timeout） | 从请求开始时刻算起、不受进度通知影响的全局绝对时间上限 |
| 幂等键（Idempotency key） | 唯一标识单次特定业务意图的应用层去重标识符 |
| 原子账本（Atomic ledger） | 将键校验、副作用记录与结果提交绑定为不可分割单元的持久化存储 |
| 背压（Backpressure） | 在生产者生成速度超过消费者处理能力时施加的流量控制机制 |
| 进度合并（Progress coalescing） | 用更新的权威进度数值替换掉旧的进度更新 |
| 权威重拉（Refetch） | 在数据流中断或出现断层后，向权威接口重新读取当前全量状态 |
| 抖动（Jitter） | 在重试退避间隔中引入的随机偏移，用于在时间轴上打散瞬时并发高峰 |
