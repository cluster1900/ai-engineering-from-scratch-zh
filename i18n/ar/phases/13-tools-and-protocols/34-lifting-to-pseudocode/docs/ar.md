## المرحلة الثالثة: تحسين لـ IR الصغيرة

IR 包含六种语句:`Assign`.`Store`.`Branch`.`Jump`.`IndirectJump`和 `Return` تعبير يشمل الحجم العادي                                                                                                                                                                                                                                                          `sext`.`zext`.`trunc`(وإضافة إلى الحملة، هناك خمسة أشكال أخرى فقط تم تبسيطها و إزالتها لاحقاً:`Flags`.`Cond`.`Concat`.`SignFill`和 `Symbolic`.

寄存器被表示为其64位寄存器族命名的变量──写入`%eax`نعم على`rax`لمرة واحدة على 32 `Assign`,读取 `%eax`则是以 32 位宽读取 `rax` في وضع 64 نقطة، 32 نقطة إضافة إلى صفر تمتد إلى جميع المرجعي، لذلك يتم بعد ذلك إضافة 64 نقطة إلى نفس القيمة مرة واحدة `zext` المرفق لا يعرف ما هو تعريف الموقع، لذلك أولاً سجل الموقع، دع SSA في المرحلة 5 插入转换。

| 指令 | IR 语句 |
|---|---|
| `subl %edi, %esi` | `flags = cmp(esi, edi)`，然后是 `esi = esi - edi` |
| `testl %edi, %edi` | `flags = test(edi, edi)` |
| `je 0xd` | `if je(flags) goto 0xd else goto 0x4` |
| `xorl %eax, %eax` | `eax = 0` |
| `cltd` | `edx = signfill(eax)` |
| `idivl %edi` | `dividend = edx:eax`, `eax = dividend / edi`, `edx = dividend % edi` |
| `movslq %edi, %rax` | `rax = sext64(edi)` |
| `sarq $0x22, %rcx` | `rcx = rcx >>s 34` |
| `shrq $0x3f, %rax` | `rax = rax >>u 63` |
| `addl (%rdi,%rdx,4), %eax` | `flags = add(eax, load32(rdi + rdx * 4))`，然后是 `eax = eax + load32(rdi + rdx * 4)` |

## المرحلة 4: من调用约定恢复参数

النظام V AMD64 psABI 第 3.2.3 节 规则,INTEGER 类参数依次通过 `%rdi`.`%rsi`.`%rdx`.`%rcx`.`%r8`.`%r9`传递──结果先通过 `%rax`, مرة أخرى`%rdx`返回. 节说明,`%rbp`.`%rbx`和 `%r12`إلى`%r15`属于调用方,必须保留; بقية寄存器属于被调用方.

`collect_params()`应用一条规则: في وظيفة قبل قراءة بعد كتابة المرجعية العنصرة هو شكل 参. من بينها الأول رقم أعلى المرجعية تحدد عدد المرجعية، لذلك فقط قراءة `%rsi`、从不读 `%rdi`وظيفة لا تزال لديها اثنين من العناصر.`percent_change`读取 `%edi`和 `%esi`، لذلك هناك`param_1`和 `param_2`.`grade`فقط اقرأ`%edi`.`total`ستعمل`%rdi`作为 64 位基址读取,将 `%esi`作为 32 位计数读取──

الآن، يمكنك تفسير غيدرا`param_3`-إنه`idivl`سأكتب`%rdx`و السبية تسمح بالمرور`%rax:%rdx`返回 128 位 INTEGER. في الملف المستهدف، لا يوجد طريقة يمكن استخدامها لتخبرنا عن قيمة العودة بالضبط.

| `*(uint *)(&DAT_001000b4 + (ulong)uVar2 * 4)` 与 `lookup_14[...]` | 来自指令加重定位。Ghidra 加载目标文件时，将 `.rodata` 放在 `0x001000a0`，所以 `0x001000b4` 就是 `.rodata + 0x14`。它应用了重定位并保留字节地址。我们为表命名，并读取了其中五个值。 |
| `uint` 返回值与 `int` | 两边都是猜测。指令只说明是 32 位。 |

|---|---|

| `uint param_2` 与 `(int)param_2`，对比 `int param_2` | Ghidra 选择无符号类型，因为 `cmpq %rdx, %rcx` 比较的是零扩展后的计数。我们保留 `int`，在比较处转换。 |
| 两者都有 `do { } while` | 来自块跳回自身的指令 `jne 0x50`。编译器旋转了循环。`-O0` 目标文件保留 `while`。 |
| 保留 `ecx_1 = param_2`，对比 `param_2 != uVar2` | 我们的替换规则仅限于同一基本块。复制 `movl %esi, %ecx` 位于初始化块，而比较位于循环内，所以变量保留。Ghidra 则传播了它。 |
| `(unsigned long)(unsigned int)ecx_1` | 来自指令。`movl %esi, %ecx` 执行零扩展，64 位比较读取整个寄存器。 |

| 反编译器增加参数 | “接收三个参数” | 只是因为猜测了返回位宽，才在一条路径上读取该寄存器 |
| 未识别惯用模式 | “乘以魔数常量” | 乘数是 `2^s / d` 向上取整的结果，且满足误差界 |
| 识别了惯用模式，却丢失 `xor` | “默认值依赖输入” | `xorl %eax, %eax` 写入零，同一位的两种表达相互抵消 |
| 指针被定为整数类型 | “接收一个 long” | 从该寄存器进行带比例因子的 4 字节加载，是指针的证据 |
| 表长未知 | “读出了表的范围” | 下一个被引用的偏移或节末尾限定表边界，且范围检查与此吻合 |
| 误读循环结构 | “while 循环” | 循环头没有出口，闩锁块向后跳转，因此是 `do while` |
| 猜测间接跳转 | “有五个 case 的 switch” | 目标来自 `.rela.rodata`，否则应报告跳转未解析 |
| 跨存储进行替换 | “一个表达式” | 将已加载的值移过存储或调用，会改变含义 |
| 修订模型编辑文本 | “能够编译，看起来没错” | 构建成功率上升，行为匹配率下降，编造的保护条件替换了显式未知项 |
| 解码器猜测未知操作码 | “反汇编看起来没问题” | 抛出含地址与字节的 `DecodeError`，然后增加一个经 `llvm-objdump` 验证的表项 |

## 操作原则

تعتبر الكود الزائف عملية توجيه لم تريها بعد. باستخدام جهاز تعزيز يمكنك قراءته، من إرشادات إعادة وضعه. سوف تضع اثنين من المواد في صف ووضعها، للكتابة أو تخمينات خلفية لكل سطر. إذا كان هناك كود مصدر، فلن نستخدم الاثنين ونتقارن مع الكود المصدر.
