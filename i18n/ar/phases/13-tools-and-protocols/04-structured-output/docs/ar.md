## 概念

### مخطط JSON 2020-12  通用语

كل مزود يقبل مخطط JSON 2020-12.

- `type`:`object`.`array`.`string`.`number`.`integer`.`boolean`.`null`واحد
- `properties`:字段名到 فرعي المخططات
- `required`يجب أن يظهر:
- `enum`:允许值的封闭集合──
- `minimum`- لا ، لا`maximum`(رقم)`minLength`- لا ، لا`maxLength`- لا ، لا`pattern`(字符串)
- `items`: تُستخدم في النظام الفرعي لكل عنصر
- `additionalProperties`:`false`ممنوعة الإضافة إلى المعدلات

وضع "OpenAI" الصارم يزيد من ثلاثة متطلبات: كل ممتلكة يجب أن تكون قائمة`required`في وسط، كل المواقع يجب أن يكون`additionalProperties: false`و لا يمكن أن يكون هناك غير حل`$ref`إذا كانت هذه المواصفات مخالفة، سوف يعود الـAPI في وقت الطلب

### (بايتن)

(بيدانتيك)`model_json_schema()`من النموذج من صفوف البيانات 生成 JSON Schema。 عملت AI البيانية على هذا الغلاف، لذلك يمكنك كتابة:

```python
class Invoice(BaseModel):
    customer: str
    line_items: list[LineItem]
    total_usd: Decimal
```

الإطار الوكيل 会在边界处把方案 转换到OpenAI 严格模式、人类`input_schema`أو التوأم`responseSchema` نموذج التواصل في التنوع`Invoice`实例返回──验证错误会抛出 `ValidationError`، ومنها وجود خطأ في تصنيفها.

### زود، تايب سكريبت

(زود)`z.object({customer: z.string(), ...})`) هو TS 等价物──OpenAI's Node SDK 暴露 `zodResponseFormat(Invoice)`، سوف تحويل إلى API من JSON Schema فائدة .

### الرفض

النظام الصارم 不能强迫模型回答──如果输入不能适应方案(邮件是一首诗,不是发票),模型会发出包含原因的 `refusal`字段── يجب أن يعتبر رمزك نتيجة أولى للتعامل معها، وليس كفشل──رفض أيضا كإشارة أمنية: عندما يتم طلب النموذج من البريد المحمّن لتحميل رقم بطاقة ائتمان، فإنه سيعود مع رفض سبب أمني──

### 开放环境中的 تشفير القيود المحدود

开放权重实现使用三种技术──

1. **Grammar-based decoding**(`outlines`.`guidance`.`lm-format-enforcer`): من الخطة 构建决定主义有限自动机; 在每一步,mask 掉会违反 FSM 的代币逻辑──
2. **带 JSON parser 的 logit masking**:运行一个与模型同步的流媒体 JSON解析器;在每一步计算有效-下一个代码集合──
3. **带 verifier 的 speculative decoding**: سعر غير مسبق النموذج 提议 Token,verifier 强制执行方案。

### ثلاثة أشكال فاشلة

1. **Parse error。**输出 غير فعال JSON. في وضع صارم.
2. **Schema violation。**النتائج يمكن أن تحل، ولكن مخالفة للنظام.
3. **Refusal。**模型拒绝── يجب أن تكون تصنيف النتائج معالجتها──

### 重试策略

```
generate -> parse -> validate -> if fail, inject error and retry, max 3x
```

## 关键术语

| 术语 | 人们常说 | 实际含义 |
|------|----------------|------------------------|
| JSON Schema 2020-12 | “schema spec” | 每个现代提供商都支持的 IETF-draft schema dialect |
| Strict mode | “保证符合 schema” | OpenAI 通过 Constrained Decoding 强制执行 schema 的标志 |
| Constrained decoding | “Logit masking” | decode 时的强制执行，会 mask 无效的下一个 Token |
| Refusal | “模型拒绝” | 输入无法适配 schema 时的类型化结果 |
| Parse error | “无效 JSON” | 输出无法解析为 JSON；在 strict 下不可能发生 |
| Schema violation | “形状错误” | 已解析但违反 type / required / enum / range |
| `additionalProperties: false` | “不允许额外字段” | 禁止未知字段；OpenAI strict 中必需 |
| Pydantic BaseModel | “类型化输出” | 会发出并验证 JSON Schema 的 Python class |
| Zod schema | “TypeScript output type” | 用于提供商输出验证的 TS runtime schema |
| Grammar enforcement | “开放权重 constrained decode” | 基于 FSM 的 logit masking，如 outlines / guidance 中所用 |
