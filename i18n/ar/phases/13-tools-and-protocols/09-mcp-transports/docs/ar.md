## 问题背景

早期的 Streamable HTTP 修订版将协议协商与底层的连接和会议 绑定混为一谈――服务器可以发发`Mcp-Session-Id`、تعرض مستقلة GET 推送流、قبل إزالة `Last-Event-ID`恢复 SSE 断点。

المفوضية`2026-07-28`تمت إزالة هذه الآليات بشكل كامل من خطوط الشبكة. يمكن توزيع أي طلب إلى أي عامل صحي ، لأن إصدارات البروتوكول والقدرة على العميل كلها مغلقة داخل جسم الطلب.

النظام الذي تم بناؤه بهذه الطريقة لديه قدرة أكبر على التوسع عبر الاتجاه والذكاء التجريبي أكثر وضوحا. وهذا يعني أيضًا: إذا استمر في تعيين طبقة النقل في عام 2025 كالمعايير الحالية، فسوف يتم إدخال نموذج خطأ والسلامة.

### 纯 POST(POST فقط)

现代 Streamable HTTP 不存在独立的 GET 推送端点,也没有 DELETE Session 端点:

- `GET /mcp`عودة مباشرة`405 Method Not Allowed`.
- `DELETE /mcp`عودة مباشرة`405 Method Not Allowed`.
- `Mcp-Session-Id`لا يُظهر أبداً
- `Last-Event-ID`يتم تجاهلها مباشرة، لأن الحديث لا يدعم الانقطاع

إذا كان SSE في المجال المستخدم للمطالبة يتدفق في وصوله إلى الإجابة النهائية قبل الانقطاع، يمكن للعميل استخدام ID JSON-RPC الجديد لإطلاق طلب مستقل جديد، ولكن لا يمكن محاولة استعادة هذا التدفق.

### 源站校验(تأكيد الأصل)

الخادم في الاستلام الإرسال في اتصال`Origin`طلب الرأس للوقاية من DNS 重绑定攻击(DNS Rebinding)`403 Forbidden`──非浏览器 العميل يمكن أن ينقص `Origin`، قواعد النقل الرسمية تسمح بذلك

本地开发 Server 应绑定到 `127.0.0.1`ليس كل المواصلات على شبكة الإنترنت. يجب أن تقوم الخدمة على كل طلب بتنفيذ التأهب والتمكين. لا يمكن استبدال التأهب الأصلي على الإطلاق.

في الانتهاء من تحديد المواقف بعد استخدام المواقف المصدرة المحددة مثل`origin.startswith("https://trusted.example")`لا يمكن أن يكون التحقيق الأمامي آمناً لأنه قد يتقبل السيطرة المهاجمة بعد ذلك

### مطلوب HTTP بيانات الطلب

كل يوم في كل يوم

```http
MCP-Protocol-Version: 2026-07-28
Mcp-Method: tools/call
Mcp-Name: notes_search
```

规则要求:

- `MCP-Protocol-Version`لملءها، ويجب أن`params._meta.io.modelcontextprotocol/protocolVersion`تماماً متوافقة
- `Mcp-Method`لملء، ويجب أن يكون مع JSON-RPC `method`تماماً متوافقة
- `Mcp-Name`في`tools/call`.`resources/read`和 `prompts/get`时强制必填──
- `Mcp-Name`على`params.name`(أو `resources/read`时的 `params.uri`(‬)
- طلبة رأس القيمة تفرق كتبها، على الرغم من طلبة رأس الاسم لا تفرق كتبها..

对于包含非 ASCII أو خاصة الأحرف `Mcp-Name`, باستخدام صيغة UTF-8 Base64

```text
=?base64?{Base64EncodedValue}?=
```

الخادم في مقارنة مع الطلبات قبل أن يضع هذا القيمة.

أي غياب أو شكلاً غير متوافق مع الطلب، عود إلى HTTP على الفور`400`مع الخطأ`-32020`إذا كان الإصدار متوافق ولكن الخادم لا يدعم هذا الإصدار، عود إلى HTTP `400`مع الخطأ`-32022`، ومضافة إلى بيانات خاطئة دقيقة ، على سبيل المثال`{"supported":["2026-07-28"],"requested":"2027-01-01"}`.

غير معقول طريقة للعودة إلى HTTP `404`مع JSON-RPC `-32601`◊ JSON-RPC 响应体 مهم، لأن كلا الزمنين العميل يعتمد على ذلك التمييز بين الأخطاء الحديثة وراثية 端点未命中──

### الطلبات دورة قصيرة من النطاق

يمكن للخادم أن يستغرق وقتًا أطول من طلبات واحدة باستخدام SSE:

```text
POST tools/call id=41
  <- notifications/progress related to id=41
  <- notifications/progress related to id=41
  <- JSON-RPC response id=41
stream closes
```

الخادم 绝不能在这个流中主动向客户端发起独立的 JSON-RPC 请求──样本化、Elicitation与 Roots 交互使用多轮往返请求(多轮往返请求(Multi Round-Trip Request) 结果──关闭响应流即代表取消该请求──

لا تُرجع إضافة هوية الحادث`Last-Event-ID`الهيئة لا تنتمي إلى الحديثة.

### 长周期变更推送:`subscriptions/listen`

يجب أن يتم إعلام التغيير من خلال طلب العميل المباشر ، وليس من خلال GET مستقل:

```json
{
  "jsonrpc": "2.0",
  "id": "listen-1",
  "method": "subscriptions/listen",
  "params": {
    "notifications": {
      "toolsListChanged": true,
      "resourceSubscriptions": ["notes://note-1"]
    },
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {},
      "io.modelcontextprotocol/clientInfo": {
        "name": "course-client",
        "version": "1.0.0"
      }
    }
  }
}
```

POST 响应是一个长连接 SSE 流──其首条协议消息为 `notifications/subscriptions/acknowledged` إشعار التأكيد  إشعار كل تغيير في التالي والنتيجة النهائية،`_meta`- لا تقلق`io.modelcontextprotocol/subscriptionId`و قيمة تساوي اسم طلب المراقبة. يمكن للخادم إرسال SSE تعليقات كإشارة حية. بعد الانقطاع، العميل يبدأ جديد.`subscriptions/listen`و لا يستعيدون البيانات التي تغيرت

`resources/subscribe`مع`resources/unsubscribe`属于 Legacy 时代, لا تستخدمها على اتصال الحديث.

## التدريب والتفكير

1. من POST إلى تحويل`Mcp-Method`, تأكد من العودة إلى HTTP `400`مع الخطأ`-32020`.
2. 发送请求头与请求体一致的版本 `2027-01-01`, تأكد من العودة إلى HTTP `400`خطأ`-32022`و البيانات المحددة`{"supported":["2026-07-28"],"requested":"2027-01-01"}`.
3. لمصادر غير ASCII أوراي إرسال قاعدة64`Mcp-Name`, تأكيد قيمة الحل`params.uri`قياس
4. في المنتظر المحدد 流返回最终响应前将其中断, باستخدام ID JSON-RPC الجديد 重新发起并重新拉取工具──
5. وذلك لـ إضافة أدوات عمل واضحة إلى الحكم، والتحديد من خلال الجهة المفروضة، دون الاعتماد على الصلة المباشرة.

| stdio | 基于 Client 发起的子进程 stdin/stdout、以换行符分隔的 JSON-RPC 传输 |
| Streamable HTTP | 单一端点架构，其中每条现代消息均为一次全新的 HTTP POST 调用 |
| 请求作用域 SSE (Request-scoped SSE) | 针对单个请求的 POST 响应流，输出相关通知及最终响应后自动关闭 |
| `subscriptions/listen` | 客户端主动开启的长周期 POST 请求，用于接收选择订阅的变更通知 |
| 请求头不匹配 (Header mismatch) | 当镜像请求头与请求体内容不一致时，返回 HTTP 400 与 -32020 报错 |
| 源站校验 (Origin validation) | 针对传入网络连接的 DNS 重绑定防御机制，不能替代身份认证 |
| 显式状态句柄 (Explicit state handle) | 作为普通业务参数传递的应用层 Token，代替隐藏的 Session 状态 |
| Legacy 桥接层 (Legacy bridge) | 专门隔离保留的旧版本行为，仅用于向后兼容历史客户端 |
