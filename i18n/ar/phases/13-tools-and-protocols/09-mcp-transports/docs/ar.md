## 问题背景

早期的 Streamable HTTP 修订版将协议协商与底层的连接和会议 绑定混为一谈――服务器可以发发`Mcp-Session-Id`、تعرض مستقلة GET 推送流、قبل إزالة `Last-Event-ID`恢复 SSE 断点。

المفوضية`2026-07-28`تمت إزالة هذه الآليات بشكل كامل من خطوط الشبكة. يمكن توزيع أي طلب إلى أي عامل صحي ، لأن إصدارات البروتوكول والقدرة على العميل كلها مغلقة داخل جسم الطلب.

النظام الذي تم بناؤه بهذه الطريقة لديه قدرة أكبر على التوسع عبر الاتجاه والذكاء التجريبي أكثر وضوحا. وهذا يعني أيضًا: إذا استمر في تعيين طبقة النقل في عام 2025 كالمعايير الحالية، فسوف يتم إدخال نموذج خطأ والسلامة.

## مفهوم الأساسي

### ستديو 模式

ستديو 绑定专用于 العميل 启动本地子进程:

- العميل كل خط نحو stdin 写入一条 UTF-8 编码的 JSON-RPC 消息──
- الخادم كل خط نحو stdout 写入一条 UTF-8 编码的 JSON-RPC 消息──
- سيرفر سيضع كل المعلومات المخصصة للكتابة في الموقع
- عندما تصل إلى EOF، يجب أن يخرج الخادم بسرعة.
- كل طلب جديد`params._meta`تمتلك نسخة و قدرات

周期 الحياة العملية هي دورة الحياة المادية، ليست أبدا الاتفاق الحديث جلسة.

### 2026-07-28 وسط التسريب HTTP

现代 Server 暴露一个单一的 MCP 端点(如 `/mcp`), و فقط تقبل POST

كل طلب أو إشعار JSON-RPC،都 a全新的 HTTP POST── طلبات تتضمن 1条 JSON-RPC 报文── العميل 绝不会向服务 发送 JSON-RPC 响应──

对于收到的请求,Server 返回其中一个:

- `Content-Type: application/json`: إعادة واحد JSON-RPC 响应؛
- `Content-Type: text/event-stream`: العودة إلى الحدث الإخطاري المتعلق بالطلب ، في النهاية على التابعة النهائية لرد JSON-RPC ‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬

### 纯 POST(POST فقط)

现代 Streamable HTTP 不存在独立的 GET 推送端点,也没有 DELETE Session 端点:

- `GET /mcp`عودة مباشرة`405 Method Not Allowed`.
- `DELETE /mcp`عودة مباشرة`405 Method Not Allowed`.
- `Mcp-Session-Id`لا يُظهر أبداً
- `Last-Event-ID`يتم تجاهلها مباشرة، لأن الحديث لا يدعم الانقطاع

إذا كان SSE من المجال المستخدم للمطالبة يتدفق في وصوله إلى الإجابة النهائية قبل وقف، يمكن للعميل أن يرى أن الطلب في المرحلة الأخيرة قد فقدت. بعد تأكيد الأمان، يمكن للعميل استخدام ID JSON-RPC الجديد لإطلاق طلب مستقل جديد.

### 源站校验(تأكيد الأصل)

الخادم في الاستلام الإرسال في اتصال`Origin`طلب الرأس للوقاية من DNS 重绑定攻击(DNS Rebinding)`403 Forbidden`──非浏览器 العميل يمكن أن ينقص `Origin`، قواعد النقل الرسمية تسمح بذلك

本地开发 Server 应绑定到 `127.0.0.1`بدلاً من ذلك`0.0.0.0` يجب أن تنفيذ خدمة الإنترنت على كل طلب و تمكين؛ لا يمكن استبدال التأهب الأصلي بالهوية.

### مطلوب HTTP بيانات الطلب

كل يوم في كل يوم

```http
MCP-Protocol-Version: 2026-07-28
Mcp-Method: tools/call
Mcp-Name: notes_search
```

规则要求:

- `MCP-Protocol-Version`يجب أن`params._meta.io.modelcontextprotocol/protocolVersion`تماماً متوافقة
- `Mcp-Method`يجب أن تكون مع JSON-RPC`method`تماماً متوافقة
- `Mcp-Name`في`tools/call`.`resources/read`和 `prompts/get`时强制必填──
- `Mcp-Name`على`params.name`(أو `resources/read`时的 `params.uri`(‬)
- طلبات القيمة

对于包含非 ASCII أو خاصة الأحرف `Mcp-Name`, استخدام معيار Base64 哨兵格式:

```text
=?base64?{Base64EncodedValue}?=
```

أي غياب أو شكلاً غير متوافق مع الطلب، عود إلى HTTP على الفور`400`مع الخطأ`-32020`إذا كان الإصدار متوافق ولكن الخادم لا يدعم هذا الإصدار، عود إلى HTTP `400`مع الخطأ`-32022`.

### الطلبات دورة قصيرة من النطاق

يمكن للخادم أن يستغرق وقتًا أطول من طلبات واحدة باستخدام SSE:

```text
POST tools/call id=41
  <- notifications/progress (针对 id=41)
  <- notifications/progress (针对 id=41)
  <- JSON-RPC response (id=41)
流关闭
```

لا يمكن للخادم أن يتحرك في هذا التدفق إلى العميل لإطلاق طلب JSON-RPC مستقل.

### 长周期变更推送:`subscriptions/listen`

变更通知 يجب أن تمر من خلال العميل 主动发起的专用 POST

```json
{
  "jsonrpc": "2.0",
  "id": "listen-1",
  "method": "subscriptions/listen",
  "params": {
    "notifications": {
      "toolsListChanged": true,
      "resourceSubscriptions": ["notes://note-1"]
    },
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {},
      "io.modelcontextprotocol/clientInfo": {
        "name": "course-client",
        "version": "1.0.0"
      }
    }
  }
}
```

POST 响应是一个长连接 SSE 流──其首条协议消息为 `notifications/subscriptions/acknowledged` إشعار التأكيد  إشعار كل تغيير في التالي والنتيجة النهائية،`_meta`- لا تقلق`io.modelcontextprotocol/subscriptionId`, و قيمة تساوي هوية طلب المراقبة.`subscriptions/listen`و لا يستعيدون البيانات التي تغيرت

## 核心专业术语

| 术语 | 规范定义 |
|------|---------|
| stdio | 基于 Client 发起的子进程 stdin/stdout、以换行符分隔的 JSON-RPC 传输 |
| Streamable HTTP | 单一端点架构，其中每条现代消息均为一次全新的 HTTP POST 调用 |
| 请求作用域 SSE (Request-scoped SSE) | 针对单个请求的 POST 响应流，输出相关通知及最终响应后自动关闭 |
| `subscriptions/listen` | 客户端主动开启的长周期 POST 请求，用于接收选择订阅的变更通知 |
| 请求头不匹配 (Header mismatch) | 当镜像请求头与请求体内容不一致时，返回 HTTP 400 与 -32020 报错 |
| 源站校验 (Origin validation) | 针对传入网络连接的 DNS 重绑定防御机制，不能替代身份认证 |
| 显式状态句柄 (Explicit state handle) | 作为普通业务参数传递的应用层 Token，代替底层隐藏的传输连接状态 |
| Legacy 桥接层 (Legacy bridge) | 专门隔离保留的旧版本行为，仅用于向后兼容历史客户端 |
