# 构建 MCP Client: خدمة العثور 路由与双时代回归

> يتعلق الأمر بالقرارات المتوافقة الأكثر تحدياً، وذلك في الحكم على أن الخادم القديم هو بنية Legacy الحقيقية، كما أن الخادم الحديث يمكن تصحيحه أيضاً.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 13 · 07（构建 MCP Server）
**Time:** ~85 分钟

## 學习目标

- لكل مؤسسة`2026-07-28`من فضلكم من صفر بني أحدث بيانات الملفات
- استخدام `server/discover`探测 مستخدم مستخدم على أساس الاستديو،并协商双方均支持版本──
- فقط للانضمام إلى قائمة البيضاء على وجه الخصوص
- فقط في التحقق من النسخة المدعومة الصالحة`initialize`بعد ذلك، فقط اقبل التراث
- 合并确定性 أداة 列表,杜绝静默覆盖重名冲突──
- سوف تستخدم الوسائل بشكل صحيح من خلال الاتجاهات المرتبطة بها ، دون الحاجة إلى إدخال أي اتفاقية الجلسة.

## 问题背景

وكيل المضيف عادة ما يحتاج إلى مع العديد من خادم MCP مع مواصلة نفس الوقت. يجب أن تجد كل خادم.

`2026-07-28`يجعلها الحكمات السهولة في العمل بسيطة جداً، لأن كل طلب يحتوي على نفسه تماماً.

- 支持首选版本的现代 Server
- رجع إصدار قابل للتعرف أو عنوان  خطأ من الخادم الحديث ؛
- لم أسمع`server/discover`الخادم القديم
- حتى تصل`initialize`يُمسّكُ يديّكَ قبلُكَ وَأبْقَى صَمتَ الخادمِ القديمِ القديمِ.

إذا كان كل الخطأ الكشف يُعتبر على حد سواء خادم Legacy، فهي خطرة للغاية.

## مفهوم الأساسي

### على وجه الخصوص (مثل) ،而非 اتفاقية الجلسة

لكل عملية خادم أو نقطة شبكة维护一份传输对端(Transport Peer) سجل:

- 传输句柄或发送函数
-  selected agreement时代 مع إصدار محدد رقم
- أحدث إمكانات الخادم التي اكتشفتها
- أداة الوصول إلى اليقين مؤخراً قائمة؛
- إرسال بطلبات الهوية
- 传输层的物理健康状态──

هذا ينتمي إلى دفتر الإدارة الداخلي للعميل، ليس على الإطلاق ما يسمى بـ"توصيلات الجلسة حالة . في MCP الحديثة، لا يزال الخادم في كل طلب عمل يتلقى إصدارًا ومصادرة إعلانات مستقلة حاليًا.

### من零构建 إلى كل طلب حديث

```python
def modern_request(request_id, method, params, version, capabilities):
    return {
        "jsonrpc": "2.0",
        "id": request_id,
        "method": method,
        "params": {
            **params,
            "_meta": {
                "io.modelcontextprotocol/protocolVersion": version,
                "io.modelcontextprotocol/clientCapabilities": capabilities,
                "io.modelcontextprotocol/clientInfo": CLIENT_INFO,
            },
        },
    }
```

لا يجب أبداً إضافة بيانات واحدة على جسم متصل فقط للافتراض أنه يمكن أن يصل إلى خطوط الشبكة. يجب إجراء إعدادات وتجارب كاملة لطلب التسلسل النهائي.

### 现代服务发现

`server/discover`返回支持的版本、Server 能力、使用说明、缓存提示以及推的 Server 身份──客户端 选择双方均支持的最高现代版本──

بالنسبة للعميل الحديث، فإن العثور على الخدمة هو الخيار؛ ولكن في حالة الاستديو، يوصى بشدة باستخدامها.`tools/list`قد يكون هناك نجاح مزيف`server/discover`قادرة على بناء خطوط التعرف على الأوقات

### ستديو 兼容性探测流程

双时代(دوئي العصر) استديو العميل في ارسال أي طلب آخر قبل، الأولوية إرسال حملة له الأول المختار`server/discover`可能产生三类结果:

1. **DiscoverResult（成功发现）**: الخادم للمصممة الحديثة. اختيار الإصدار المشترك، ومواصلة الاتصال التجاري على كل طلب يحمل بيانات.
2. **Recognized modern error（已识别的现代协议错误）**الخادم لا يزال للفنية الحديثة`-32022`, من`data.supported`中选择可用版本并使用新请求 ID 重试;若为头条或能力 错误,修改请求内容即可──**严禁回退发送 `initialize`。**
3. **Ambiguous signal（歧义信号）**: غير معروف JSON-RPC 报错、超时、连接关闭或空响应均无法确定协议时代──必须默认按失败关闭(فايل关闭),除非该端被运维显式配置了遗产 兼容白名单──

已识别的现代协议错误码 تشمل:

- `-32020`عنوان غير متطابق (طلبة رأس مع طلبات لا تتطابق)
- `-32021`غيابالمطلوبالمستقبلقدرة
- `-32022`غير مدعوم (ProtocolVersion)

حتى على الإطلاق تم إدراجها في ورثة White list، وقد تم التعرف على الأخطاء الحديثة أيضا يثبت ذلك على Server الحديث.`initialize`بناء على التخفيضات

لا يمكن أن`-32601`(نهج غير موجود) كدليل كامل على دخول الهيبة. يُمثّل فقط أنّ الهيبة المؤهلة لإطلاق مرة واحدة مع قيود في الوقت المحدد.

###                                                                                                                                                                                                                                                               

يجب أن يكون التوافق التراثي هو الخصائص الواضحة للمحدد على تكوين النهاية:

```python
client.add_server("archive", archive_transport, allow_legacy=True)
```

يجب أن يكون هذا المنتخب مقيدًا إلى أمر أو نقطة تعيين محددة. يجب أن يكون المنتخب محظورًا على استخدام المكونات.`allow_legacy=True`لا يمكن أن تُحصل على أي إشارة مباشرة بعد أن تُكتشف نتائج الفشل`initialize`.

تمنح البيانات السرية فقط لإطلاق البحث. لا يحدد الوقت الذي ينتهي به العميل.`initialize`رجاءً، ثمّ تطلب صارمًا لتلبية جميع الشروط التالية:

-  استلام JSON-RPC يتناسب مع هذا الطلب`2.0`响应
- فقط يحتوي`result`字段,且无 `error`(إنه)
- `protocolVersion`ينتمي إلى مجموعة النسخة القديمة من المستخدمين
- 包含对象类型 `capabilities`字段
- 包含非空字符串 `name`مع`version``serverInfo`المُجرد

أي إصدارات فوق الوقت أو غير مدعومة تفشل مباشرة. فقط النتائج الصالحة التي تتفق تماما مع الهيكل يمكن أن تكون على المحطة تسمى لليجاسي 时代.`legacy_probe_timeout_ms`传给传输适配器; ستديو حقيقي أو HTTP 适配器 يجب أن تنفيذ هذا الوقت النهائي فعلياً، وليس مجرد تسجيل ذلك.

لـ إرسال إلى الحافظة المحددة، لا تستكشفها قبل كل عملية تطبيقها.

### التراث هو جزء متوافق

مرة واحدة محظورة الاختبار يعود إلى صالحة الوصول إلى إثبات الوريث ، العميل على صارمة وفقا لتحديدات النسخة المعدلة استخدام المختار إثبات الوريث:

1. 校验响应信封与关联 ID──
2. 校验协商出的修订版属于已配置的遗产集合──
3. سجل قدرات التجربة مع Server Personality
4. فقط في كل المراقبة من خلال بعد إرسال`notifications/initialized`.
5. في هذه النقل المستخدمة في دورة الحياة التراث الطلبات

هذا الفرع موجود فقط للتواصل مع النظام المحلي المعروف، وليس تصميمًا افتراضيًا للخادم الجديد أو الطلب الجديد. إذا حدث إعادة تشغيل النظام أو تغيير النقطة المحلية، فيتم التخلي عن الاحتفاظ والبحث مرة أخرى.

### 工具发现与缓存

لكل نشاط على آخر`tools/list`现代结果包含 `resultType`.`ttlMs`مع`cacheScope`: الالتزام بهذا النص الجديد في ما يلي على المفوضية الصالحة؛ وإعادة الالتحاق بعد انتهاء المدة أو وصول الحالات التي تغير فيها القائمة المشتركة.

对于 Legacy Server 缺失 `resultType`حالة العميل يجب أن يضعها في اعتباره`"complete"`不要要求更早的协商时代的响应携带现代缓存字段──

الخادم 应返回确定性排序── العميل أيضاً يجب أن يكون في المجموعة 已排序,使本地注册表顺序不依赖进程启动时序──

### 命名空间无冲突合并

خادمين قد يكونوا قد أظهروا اسمهم`search`أدوات: يجب أن تتبنى استراتيجية بيانات واضحة:

1. **冲突时加前缀（Prefix on collision）**: الحفاظ على أول أدواتها، ولاحقاً إعادة تسمية أدواتها`<server>/<tool>`.
2. **冲突时拒绝（Reject on collision）**:不加载重复工具,并抛出清晰的配置报错.
3. **静默覆盖（Silent overwrite）**:**坚决杜绝** سوف يخفي النموذج المستهدف المستخدم الحقيقي

مع الوقت حفظ النموذج مع اسم محلي.`tools/call`استخداماتها الخادم 声明的本地名──

### 调用路由机器

路由是纯粹的映射查找:

```text
canonical tool name
  -> peer name + local tool name
  -> new JSON-RPC request id
  -> modern request metadata or explicit legacy shape
  -> matching response id
```

عندما لا يُستخدم الإرسال المُتعلق به، لا ترسل إرسالًا أو إعادة تشغيل الإرسال، وإعادة تنفيذ الخدمة`tools/list` في طلبات الأسلحة المتضمنة في الوقت الذي يتم فيه إزالة عملية التوصيل، إذا سمحت استراتيجية الأمن في العملية، يمكن استخدام ID JSON-RPC الجديد لإعادة المحاولة

### 通知与订阅

قائمة ومصادر الحديثة تتغير فقط من خلال العميل`subscriptions/listen`流到达── العميل 发送通知过器,等待 `notifications/subscriptions/acknowledged`,并用通知元数据中的听 请求身份证 关联事件──

قطع بعد، إطلاق جديد الاستماع  طلب ومعاونة إعادة إعادة إرسال قائمة أو موارد`Last-Event-ID`تعافي

### لا يوجد طلب من الخادم

现代 Server 不会为样本化、征集或根向客户端发起独立的JSON-RPC 请求──它们回归 `input_required`, العميل في تلبية طلب الدخول المتضمنة بعد محاولة مرة أخرى الطلب الأصلي

满足输入期间不要阻塞端的响应读取器──保持关联关系,并为重试生成新的 JSON-RPC ID──

```figure
tp-client-merge
```

单元测试覆盖常规演示易忽视的边界条件:

- 现代请求逐次重复元数据
- -أقابلني`-32022`时重试现代发现 ,绝不退化为握手;
- 已识别的现代错误绝不发生降级 (حتى على الأقل في قائمة البيانات البيضاء) ؛
- 超时、连接关闭、空响应与未识别的错误在无白名单时绝不触发 `initialize`(إنه)
-  white list على المحطة فقط في الحصول على الموافقة`initialize`响应后才确立为 Legacy
- النتائج التي لا تؤيد أو لا تؤيد الوصول إلى التراث تجعل النتائج غير صالحة للحفاظ على التراث.

## 核心专业术语

| 术语 | 规范定义 |
|------|---------|
| 对端 (Peer) | Client 端维护的单个 Server 传输句柄及其发现信息的记录实体 |
| 协议时代 (Protocol era) | 现代逐请求元数据模式，或旧版初始化握手语义 |
| 服务发现探测 (Discovery probe) | 用于识别 stdio 对端时代的初始 `server/discover` 请求 |
| 已识别现代错误 (Recognized modern error) | 证明对端属于现代架构并禁止 Legacy 回退的特定协议错误 |
| Legacy 白名单 (Legacy allowlist) | 运维显式授权对指定对端进行一次受限兼容探测的配置 |
| 正向 Legacy 证据 (Positive legacy evidence) | 针对受支持旧版协议返回的有效、ID 匹配的 `initialize` 结果 |
| 合并命名空间 (Merged namespace) | 跨所有活跃对端规范化后的工具全局名称集合 |
| 冲突策略 (Collision policy) | 处理重名工具的加前缀或报错拒绝规则 |
| 时代缓存 (Era cache) | 为单个传输对端保存的已选现代或 Legacy 行为 |
| 传输恢复 (Transport recovery) | 重启或重连、重新发现、重新列出，并以新 ID 安全重试 |
