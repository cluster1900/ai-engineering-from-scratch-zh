## الجذور فقط لتحرك

早期 MCP 规范允许客户端 声明 Roots,并在列表发生变化时通知服务器──然而 Roots 只是提示性引导信息(指导信息)──它既没有限制服务器 进程实际可以读哪些文件,也没有对调用者完成识别权,也没有建立任何操作系统级别的安全沙箱──

المملكة المتحدة 2026-07-28  لمصممة جديدة تم التخلي عنها بالكامل `roots/list`مع`notifications/roots/list_changed` تُوصى باستخدام الحلول الروتينية التالية:

- عندما يتغير نطاق كل مرة تطبيقها، استخدام`workspaceUri`أو`directory`أداة 参数。
- عندما تعمل على نفسها على الموارد المحددة، استخدم الموارد URI.
- عندما يحتل موظف واحد في قسم العمل المحدد، استخدم الخادم الموثوقات.
- عندما يجب أن تمنع الكود من التكنولوجيا عبر界, استخدام عملية沙箱 (عبارة عن صندوق رمل) أو نظام ملفات منفصلة (نظام ملفات محبوسة)

إذا كان الحل الحالي 2026-07-28  إدخال الحل في فترة انتقال مستبعدة لا تزال مطلوبة `roots/list`، الخادم يجب أن يكون متضمن في MRTR`inputRequests`في المقابل، لا يمكن إرسال طلبات مضادة في الوقت الحقيقي.

模型能够看清并复述显式的句柄 (手柄) 而隐藏在传输层会议话中的隐式范围则更难审查、重放、审计和路由──

### ثلاثة مستويات دفاع

لا يحتوي الـ URI الواضح على إثبات الشرعية. يجب أن يتم تنفيذها بشكل صارم على ثلاثة مستويات:

1. **鉴权（Authorization）：**هل يسمح للمسؤول عن حق التعرف باستخدام المنطقة؟
2. **路径限制（Containment）：**هل يحتفظ الـ URI بقوة داخل حدود المنطقة المختصة للعمل؟
3. **沙箱隔离（Sandbox）：**إذا كان الخادم قد تعرض للانخراط في النظام، هل يمكن أن يمنع نظام التشغيل بشكل فعال الهروب عبر الحدود؟

الخادم قابل للعمل 会维护一个信任工作区 URI 白名单,规范化处理百分号编码的路径,校验真实的路径组件边界,并执行物理删除前即刻重新检查路径限制──

幼稚的字符串前检查是存在严重漏洞的:

```text
allowed:   file:///work/notes
attacker:  file:///work/notes-evil/secret.md
traversal: file:///work/notes/%2e%2e/private.md
```

يجب أن يتم أولاً تنظيمها، ثم إعادة تصنيفها على مكونات الطرق. يجب أن يتحمل خادم نظام الملفات من مستوى الإنتاج أيضًا مقاومة سباق الرمز والربط (سباق المرافق) ، فضلاً عن الهجمات على الطرق المحددة.

## URL 模式(وضع URL)

URL 模式发送一个安全的网址以进行带外(خارج الشريط)交互:

```json
{
  "method": "elicitation/create",
  "params": {
    "mode": "url",
    "message": "Connect the report service to continue.",
    "url": "https://mcp.example.com/connect/report-service"
  }
}
```

عندما يجب أن يتم إدخال المعلومات الحساسة مباشرة إلى الويب الذي يتم التحكم فيه من قبل الخادم (مثل: OAuth) ، فان استخدم نموذج URL.

`accept`رد فعل فقط يظهر المستخدم موافقة على فتح عنوان URL، لا يثبت أن الاتصال الخارجي قد تم إنجازه بنجاح.`input_required`نتيجة

إن إرسال URL 绝不能替代 MCP client و MCP server 之间的识别权机制── هو من أجل جعل MCP server 代表用户执行外部交互而设计的──. يجب على الخادم 绑定浏览器端的用户与发起 MCP 操作的同一已识别权主体密切的──.

## 响应分支与处理分支

التصرفات المختلفة تتمثل في اتخاذ قرارات منطقية منتجات صارمة، وليس في التصرفات الأخرى:

| 动作 | 含义 | 安全的 Server 处理行为 |

## 关键术语

| 术语 | 2026-07-28 中的含义 |
|------|------------------------|
| Roots | 已弃用的提示性工作区指引，不具备鉴权或沙箱隔离能力 |
| 显式权限范围（Explicit scope） | 在请求参数中清晰可见的工作区、目录或 resource 句柄 |
| 路径限制（Containment） | 规范化路径组件校验，确保目标严格限制在受控边界之内 |
| Elicitation | 在 MCP 操作执行期间用于获取用户输入的 client 特性 |
| 表单模式（Form mode） | 使用受限扁平 schema 的带内（in-band）结构化用户输入 |
| URL 模式（URL mode） | 针对敏感或外部工作流的带外（out-of-band）Web 交互 |
| MRTR | 多轮往返请求，返回 input-required 结果后由 client 发起全新重试 |
| `requestState` | 不透明的状态凭证，由 client 原样回显并由 server 进行完整性校验 |
| Decline（拒绝） | 用户明确作出的拒绝操作 |
| Cancel（取消） | 用户主动关闭界面或在未获批准的情况下中断交互 |
