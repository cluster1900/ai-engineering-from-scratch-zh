# مهام MCP  توسيع: بناء على محور لا حالة في المهام الدائمة

> لا يعني أن كل عملية يجب أن تتم في طلب واحد. المهام الرسمية تمتد على طول دورة الحياة.`tools/call`في العودة إلى هذه القصيدة، أي حالة يمكن أن تستجيب`tasks/get`و المدخلات العميل من خلال`tasks/update`لا حاجة للاستمرار في أي اتفاقية

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 13 · 09 (transports), Phase 13 · 11 (stateless MRTR), Phase 13 · 12 (elicitation)
**Time:** ~90 minutes

## 學习目标

- التمييز بين الصفوف التنقلية للاتفاقية والصفوف التطبيقية المستمرة.
- في كل طلب قدرات مع`server/discover`中协商 `io.modelcontextprotocol/tasks`扩展‬
- فقط بعد الانتهاء من الإنشاء، العودة من قبل الخادم`resultType: "task"``CreateTaskResult`.
- استخدام `tasks/get` إجراء استفسار، استخدام `tasks/update`提交任务输入,并使用 `tasks/cancel`发起协作式取消──
- 彻底弃旧版中关于 `tasks/status`.`tasks/result`和 `tasks/list`من المفترض أن يكون
- 通過 POST 响应的 SSE 流使用 `subscriptions/listen`订阅可选的任务变更通知──
- صحيح建模任务过期机制、重启恢复逻辑、输入钥匙 去重以及执行错语义。

## لماذا المهام هي توسيع

المهام في البداية كخصائص تجربية أساسية ظهرت في 2025-11-25 规范中.`io.modelcontextprotocol/tasks`‬التوسع، مما يسمح للعميل والخادم بالانتخاب الذاتي ما إذا كان قد يصل إلى دورة حياة المهمة الإضافية، دون الحاجة إلى كل المشهد التوسع MCP ‬

على الرغم من أن هذه المواصفات التوسيعية هي حالياً المرجع الرسمي للمهام، إلا أنها لا تزال في وضع مسودة (مصورة) التطور.

عندما يكون لدى عملية واحدة أو أكثر من هذه الخصائص، فاستخدم المهمة:

- إنفاذ الوقت قد يتجاوز الطلب العادي
- 已由工作队列 (ظاهري قطار) أو خارجية
- العميل بحاجة إلى القدرة على استعادة استفساراتها بعد إعادة تشغيلها
- عملية التنفيذ تحتاج إلى وقف في انتظار المستخدم أو النموذج لتقديم إدخال آخر.
- 支持取消操作与持久化结果检索是明确的产品功能需求──

لا تبحث عن عملية إنشاء مهمة لتحديد رخيص. تعريف القواعد، وتحقيق الاحتفاظ بالمخزنات، وتحديد الآلية، وتحديد المدة المحددة، وتحديد التدفقات، ستؤدي إلى تعقيدات حقيقية.

## 无状态核心,有状态应用

المملكة المتحدة 2026-07-28 移除了 `initialize`.`notifications/initialized`、 إتفاقية`Mcp-Session-Id` هذا لا يستبعد تماماً وظائف المنتجات المُبنية بالحالة

تحديد المهام يقع في حالة التطبيقات:

- يجب أن يكون الخادم في عودة المهام ID قبل أن يكون مدامها.
- العميل قادر على تخزين هذه الهوية، وإعادة تشغيلها بعد إعادة استفسارها.
- يمكن توجيه هذه الهوية إلى أي خادم من نفس النسخة المثالية.
- كل عمل يرتبط بالطرق يجب أن يُعيد التحقق منه.
- 过期与清理是由任务 字段定义的而不是由传输层连接生命周期决定的.

هذا ووضع الاختباء المضاف على الاتصال يوجد اختلاف طبيعي على مستوى النقل.

ستقوم بتفريق أربع دورات حياة واضحة:

| 状态类别 | 生命周期 | 归属位置 |
|---|---|---|
| 协议元数据 | 单次请求 | `params._meta`，在每次调用中重新校验 |
| 传输层任务 | 单个 stdio 请求或 HTTP 响应 | 具有有界超时期限的正在进行的协调器（in-flight coordinator） |
| MRTR 交互延续 | 单次重试序列 | 受完整性保护的 `requestState`，必要时叠加防重放控制 |
| 持久化任务 | 跨越请求、副本、重启与重连 | 以受权的 `taskId` 为键的共享应用程序存储 |

لا يمكن أن يجعل MCP يتحول إلى اتفاقية حالة ، إلا أنه يجعل التطبيق غير موثوق للغاية.`tasks/get`يتم توجيهها إلى نسخة أخرى، لن يتم استعادة هذا السجل. يجب أن يتم إكمال الكتابة الدائمة قبل العودة إلى العنوان، وترك كل مهمة يتمكن من حل نفس السجل المشترك تحت فحص المستأجر والمركز.

## إنشاء المهام المستهدفة للخادم

旧版的客户端标志 `params._meta.task.required`تمت إزالة كاملة. الجهاز الآن هو: العميل  إعلان دعم هذا التوسع، ثم من قبل الخادم تحديد تحديدا محدد.`tools/call`نعم أو لا تحويلها إلى مهمة

التماس:

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "generate_report",
    "arguments": {"size": "large"},
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {
        "extensions": {
          "io.modelcontextprotocol/tasks": {}
        }
      }
    }
  }
}
```

响应:

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "resultType": "task",
    "taskId": "tsk_786512e29e0d",
    "status": "working",
    "statusMessage": "Preparing report outline.",
    "createdAt": "2026-08-21T10:30:00Z",
    "lastUpdatedAt": "2026-08-21T10:30:00Z",
    "ttlMs": 900000,
    "pollIntervalMs": 1000
  }
}
```

حتى يتم إصلاحها`tasks/get`في نظام الاحتفاظ بالاتفاقية النهائية، يجب أن ينتظر أن يكون متواجدًا للقراءة (قراءة الرؤية) بعد ذلك، وإلا فإن العميل يصل إلى معرف يبدو مشروعًا ، ولكن سيتعرض على الفور إلى خطأ غير مكتشف.

المهام 响应具有非主动请求未请求的特征,即 العميل ليس واضحاً مطالباً بدخول نمط المهام; ولكنّها لا تتمّ التفاوض معها未经协商:

## هيكل المهام

كل مهمة على كل من المواد تحمل:

- `taskId`: من قبل الخادم 生成的稳定标识符;
- `status`:取值为 `working`.`input_required`.`completed`.`cancelled`أو`failed`(إنه)
- `createdAt`مع`lastUpdatedAt`:ISO 8601 时间؛
- `ttlMs`: منذ تأسيسها`null`عن غير تعبير على الحد الأقصى
- `pollIntervalMs`:خادم عند اقصى عدد من المراحل المطلوبة
- `statusMessage`: وجه إلى المستخدم أو النموذج على النص التالي وصف:

الصفحة المخصصة للحالة المحددة تظهر فقط في الوقت المتعلق:

- `input_required`包含 `inputRequests`.
- `completed`包含原始请求的 `result`结构。
- `failed`包含 JSON-RPC `error`المُجرد

العميل يجب أن يتبع`pollIntervalMs`يمكن للخادم أن يضيف حدود لتدريبات الطلبات المتحركة بشكل كبير، ويمكن أن يعدل الحركات في دورة الحياة في هذه الفترة الزمنية.

## استخدام المهام/ الحصول على إجراء استفسار

العميل يطلب حالياً

```http
POST /mcp HTTP/1.1
Content-Type: application/json
MCP-Protocol-Version: 2026-07-28
Mcp-Method: tasks/get
Mcp-Name: tsk_786512e29e0d
```

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tasks/get",
  "params": {
    "taskId": "tsk_786512e29e0d",
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {
        "extensions": {
          "io.modelcontextprotocol/tasks": {}
        }
      }
    }
  }
}
```

`tasks/get`وقد تم إنجاز عملية التدوين في هذه المرحلة، وبالتالي فإن ردود الفعل الأكثر إضافة لها تتضمن`resultType: "complete"` و وظيفة داخل المجموعة لمعالجتها `status`لا يزال بإمكانه`working`أو`input_required`.

هذا التمييز قادر على تجنب حدوث حوادث تحليل عادة:

```text
result.resultType = complete    表示 tasks/get RPC 本次调用完成
result.status = working        表示其代表的后台作业仍在运行中
```

لا يوجد قائمة`tasks/result`طريقة: عندما تقوم بالمهام`tasks/get`响应会直接在 `result`字段内嵌原始的 `CallToolResult`:

```json
{
  "resultType": "complete",
  "taskId": "tsk_786512e29e0d",
  "status": "completed",
  "createdAt": "2026-08-21T10:30:00Z",
  "lastUpdatedAt": "2026-08-21T10:34:12Z",
  "ttlMs": 900000,
  "result": {
    "resultType": "complete",
    "content": [
      {"type": "text", "text": "Generated large report with approved outline."}
    ],
    "structuredContent": {"size": "large", "approved": true},
    "isError": false,
    "_meta": {
      "io.modelcontextprotocol/serverInfo": {
        "name": "tasks-demo",
        "version": "1.0.0"
      }
    }
  },
  "_meta": {
    "io.modelcontextprotocol/serverInfo": {
      "name": "tasks-demo",
      "version": "1.0.0"
    }
  }
}
```

خارج الطبقة`resultType` عرض`tasks/get`الـ RPC 顺利执行;内层的 `result.resultType`تعبر عن الأداة الأصلية 调用已执行完成── هذا المستوى الداخلي هو القوة المطلوبة── داخل المستوى`CallToolResult`كما يجب أن تحمل نفسها`io.modelcontextprotocol/serverInfo`؛ هذا الدرس سيتم الاحتفاظ به بالكامل وليس تخزينه لعدم نوع من الحمولة العادية

لا يوجد قائمة`tasks/list` لا يمكن للخادم أن يحدد بشكل آمن أي مهام يجب أن تظهر في قائمة من مجالات الدور المرتبطة.

## إدخال و صفقة خلال عملية تنفيذ المهام

تبدو المهام داخل المدخلات مشابهة لـ MRTR المركزي، ولكن تتبنى آلية متواصلة مختلفة للعمليات.

### 任务创建前所需的输入

من الأصل`tools/call`中返回核心 `resultType: "input_required"` العميل 履行输入并重试该原始调用── فقط بعد انتهاء كل دورات MRTR من هذه المواجهات،才创建持久化任务──

### 任务创建后所需输入

سأضع المهمة في حالة`input_required`‬ ‫مِن خلال`tasks/get` المعلن غير المقرر `inputRequests`من العميل`tasks/update`提交响应── العميل **不需要**重试原始的`tools/call`.

快照:

```json
{
  "resultType": "complete",
  "taskId": "tsk_786512e29e0d",
  "status": "input_required",
  "createdAt": "2026-08-21T10:30:00Z",
  "lastUpdatedAt": "2026-08-21T10:31:00Z",
  "ttlMs": 900000,
  "inputRequests": {
    "approve_outline": {
      "method": "elicitation/create",
      "params": {
        "mode": "form",
        "message": "Approve the generated report outline?",
        "requestedSchema": {
          "type": "object",
          "properties": {"approved": {"type": "boolean"}},
          "required": ["approved"]
        }
      }
    }
  }
}
```

更新:

```http
POST /mcp HTTP/1.1
Content-Type: application/json
MCP-Protocol-Version: 2026-07-28
Mcp-Method: tasks/update
Mcp-Name: tsk_786512e29e0d
```

```json
{
  "jsonrpc": "2.0",
  "id": 4,
  "method": "tasks/update",
  "params": {
    "taskId": "tsk_786512e29e0d",
    "inputResponses": {
      "approve_outline": {
        "action": "accept",
        "content": {"approved": true}
      }
    },
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {
        "extensions": {
          "io.modelcontextprotocol/tasks": {}
        }
      }
    }
  }
}
```

نجاح الإجابة هو إثبات الفراغ`resultType: "complete"` لأن الحالة تتغير بشكل ممكن بشكل نهائي، يجب على العميل أن يواصل الاستفسار أو الإستماع.

كل واحد`inputRequests`المفتاح في كل مهمة يجب أن تكون في كل دورة الحياة واحدة`tasks/get`快照可能會顯示相同未决密钥; يجب على العميل أن يقوم بإعادة الإصلاح على مستوى UI ، بينما يجب على الخادم أن يتجاهل استجابة المفاتيح غير المعروفة أو المغطاة أو المفعولة.`input_required`حتى يتم إجابة جميع المفاتيح الضرورية

## إشعار تحويل

轮询是基准方案──期望推送更新客户可以发送带有任务 id 列表 `subscriptions/listen` في HTTP التدفقية، هذا POST طلب، والرد على طلب من نطاق رول رول.

الخادم   `notifications/subscriptions/acknowledged`确认接受的 id 列表, ثم يمكن أن تمر `notifications/tasks`إرسال كامل الصور، إشعار تأكيد مع كل مهمة إشعار موجود`_meta`- لا تقلق`io.modelcontextprotocol/subscriptionId`(قيمةها = `subscriptions/listen`في المقابل، كل مهمة 通知都等价于此时调用 `tasks/get`"المرحلة"

يجب على العميل أن يعلن المهام  توسيعها  يجب أن تستند إلى إعادة التواصل والإعادة إلى العمل المتمثلة في عملية استمرارية  وليس على إعادة التأثير أو`Last-Event-ID`.

## 失败语义

رجاءً، صحيح التمييز بين خطأين:

### 协议错误

无效方法参数或未知的任务 id سوف يعود إلى JSON-RPC 错误,通常为 `-32602`◊ غياب توسيع دعم العودة `-32021`و في البيانات تحمل القدرة اللازمة للموضوع

### 任务执行结果

- معهم`isError: true`أداة عادية  نتائج لا تزال تنتمي`completed`المهمة، لأن الوسيلة 调用已经产出其定义的结果结构──

## 手写实现

`code/main.py`实现一个确定性的任务服务:

- `server/discover`عودتي`supportedVersions`、缓存提示与 扩展的任务
- `tools/list`عودة إلى التأكد `generate_report`描述符,附带合法输入方案──
- `tools/call`في العودة`resultType: "task"`之前完成任务的创建与持久化──
- مثال جديد للخدمات إعادة تحميل نفس المهمة، يظهر القدرة على إعادة تشغيل.
- `tasks/get`返回完整的任务快照──
- العامل من`working` حالت流转至 `input_required`.
- `tasks/update`收表单响应并返回空的完整确认──
- العامل مخزن داخل `CallToolResult`(تحتوي على نفسها)`resultType`مع الخادم ، ثم الحالة تتحول إلى`completed`.
- 本实现中`tasks/cancel`تمتلكون جنسًا مثله
- HTTP  المُصمم `tasks/get`.`tasks/update`和 `tasks/cancel``Mcp-Name`头统一设置为 `params.taskId`.
- 通知助手函数使用 `notifications/subscriptions/acknowledged`مع`notifications/tasks`, من المفترض أن تسمع , من فضلك
- 无 id 的通知不产生任何 JSON-RPC 响应──

العامل يستخدم حالة التقدم الواضح بدلاً من النوم في الخطوط الخلفية. وهذا يجعل كل حالة من التحولات ذات اليقين، ويحل نموذج الاتفاقية وآلية صف الرسائل بشكل واضح.

## 关键术语

| 术语 | 当前扩展中的含义 |
|------|----------------------------------|
| Tasks 扩展 | 用于持久化异步工作的可选 `io.modelcontextprotocol/tasks` capability |
| `CreateTaskResult` | 对符合条件请求返回的、由 server 主导的 `resultType: "task"` 响应 |
| `tasks/get` | 轮询完整的当前任务快照，包含终态结果或未决输入 |
| `tasks/update` | 针对任务当前未决的 `inputRequests` 提交响应 |
| `tasks/cancel` | 确认接收到协作式取消的意图 |
| `input_required` | 表示任务正在等待 client 提供输入的任务状态 |
| `pollIntervalMs` | Server 建议的下次轮询前的最小等待时长 |
| `ttlMs` | 自任务创建起计算的有效时长 |
| 返回前持久化（Durable-before-return） | 必须在 task id 具备可解析可读性之后才能发出其句柄的规则 |
| `notifications/tasks` | 在已订阅的 SSE 响应流上投递的可选完整任务快照 |
