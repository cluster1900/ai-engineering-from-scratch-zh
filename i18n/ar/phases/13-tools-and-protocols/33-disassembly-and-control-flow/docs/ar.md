## 手工解码一条命令

قبل أن يصل إلى الحل`grade`وسط`48 69 c0 67 66 66 66`.

1. `48`位于 `40`إلى`4F`بيننا، لذلك هو`W = 1`عدد عمليات REX ∼ 64 بـت
2. `69`نعم`IMUL r, r/m, imm32`.
3. `c0`هو ModRM `11 000 000`:寄存器形式,reg 为 `%rax`, r/m 为 `%rax`.
4. القادم أربعة أجزاء هي عدد صغير`0x66666667`.
5. AT&T 顺序为立即数、源、目标:`imulq $0x66666667, %rax, %rax`.

总计七字节،`llvm-objdump`المقالة المطبوعة هي نفسها تماما. هذا العدد العادي هو عدد عكس، دعونا نرى كيف يمكن أن نصل إلى ضربة و التالي.`sarq $0x22`(右移 34 位) التحقق من إعادة 10 ◦ 34 课也会遇到此对操作,届时提升器将将将将其恢复为`score / 10`.

## 线性扫描

شوارز، ديبراي واندروز في إزالة كود تنفيذي تم مراجعته (WCRE 2002) ، حد 3.1 节 وصف التصفحات السريرية: من الحرف الأول من الحرف الكودية بدء، فك الحرف التوجيهي، ومع ذلك من الحرف الخلفي من ذلك استمر حتى النهاية.`objdump`如此工作،`llvm-objdump`كذلك كذلك

```python
def linear_sweep(code: bytes, start: int = 0, end: int | None = None) -> SweepResult:
    position = start
    while position < end:
        try:
            instruction = decode(code[:end], position)
        except DecodeError:
            undecodable.append((position, code[position]))
            position += 1
            continue
        instructions.append(instruction)
        position = instruction.end
```

هذا الطرق لديه نمط فشل، ورقة الرسم 1 تظهر ذلك. يتم تحرير الطوائف البيانية كإرشاد، ثم يتم تحرير الخوارزمية لفترة قصيرة عبر الحدود الحقيقية للطلب. في x86، عادة ما يتم تعديل الخوارزمية في غضون عدة طوائف، مما يجعل الخطأ صعب التعرف عليه.

هناك أمرين آخرين`python3 code/main.py disasm FILE.o`طبع قائمة، وظهر هذا الهدف بعد كل أمر من إعادة تحديد الهدف.`python3 code/main.py cfg FILE.o FUNCTION`打印单个函数的分析──

## 实际使用

لملفات الأهداف الجديدة، ففي هذا الترتيب استخدام ثلاث طرق:

1. قبل أن يتم تشغيل المراجعة`llvm-objdump`لا يتناسب، هناك حذاء، بعد كل البنية سوف تتبعه.
2. من كل رمز وظيفي بدأ في التنقل والانخفاض،并阅读 `unresolved`كل شيء هو ما لم تتحكم في الهدف
3. على كل قفزة غير محلولة، البحث عن النموذج المعتاد للصفحة وكذلك إشارة إلى وضعية الوضع الثابت للصفحة.
4. 字节 توازنة التصفحات الخطية والعودة إلى الأسفل. فقط المخطوطات التي تم تحديدها للتوجيهات هي المكتملة أو البيانات. كل منهما غير معترف بها هي غير قابل للتوصيل إلى الكود، أو تنتمي إلى وظيفة لم تجدها بعد.
5. مع استعادة جدول بعد الانخفاض والعودة النتيجة بناء CFG، ومشاهدة الجانب الآخر.`while`أو`for`.

عندما تنتقل إلى إصدار المُعدّل الجديد، إعادة التقاطها، لأن التغييرات الصفحة تعني أن النموذج قد تغير أيضاً.

## النظام النظام

| 故障 | 较弱工具的报告 | 分析必须证明的内容 |
|---|---|---|
| `.text` 内有数据 | 每个字节都被解码、看似合理的清单 | 递归下降未认定任何数据字节为指令，且跳转目标是指令起点 |
| 最后一次返回之后的填充 | 函数末尾有一条 `nopw` | 这些字节从入口不可达 |
| 通过表的间接跳转 | “jmp rax”和四个死块 | 表地址来自 `lea` 重定位，条目数来自边界检查，目标来自 `.rela.rodata` |
| switch 变成值表 | “带重定位的跳转表” | 从 `.rodata+0x14` 进行 `movl` 加载，三个块，没有间接转移 |
| 位移为零的调用 | `callq 0x113`，即下一条指令 | `R_X86_64_PLT32 grade-0x4` 解析为 `0x30` |
| 解码器猜测未知操作码 | 看起来正确的助记符 | 带地址的 `DecodeError`，扫描记录该字节 |
| 指令超过 15 字节 | 一条很长的“指令” | 游标在读取第 16 字节之前抛出异常 |
| 分支进入指令中间 | 两份重叠的清单 | 包含两个地址的冲突记录 |
| 循环被报告为直线代码 | 伪代码中没有 `while` | 一条目标支配源节点的回边 |
| 参考输出来自不同编译器 | 测试在过时文本上通过 | 样例 README 标明精确的编译器和命令 |
