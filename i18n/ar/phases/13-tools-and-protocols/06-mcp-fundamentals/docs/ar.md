## 问题背景

في نفس العملية التشغيلية أو عامل HTTP ، يمكن أن يستقبل خادم MCP استمرارًا طلبين من عملاء مختلفين ذوي قدرات مختلفة. إذا كان الخادم يتذكر أو يعتمد على النص الأدناه التي أعلنت عنها الطلب ، فسوف يقع خطأ في قواعد تطبيق الحدود ، أو يعود إلى بنية رسالة غير متوافقة.

المفوضية`2026-07-28`قواعد القوانين القائمة على القواعد القائمة على القوانين القائمة**协议核心完全无状态**يجب على الخادم أن يقرر بنفسه كيفية معالجة الطلبات الحالية، ولا يعتمد على سجلات التاريخ للاتصال.

هذا تغير تماما النموذج الذهني. التسلسل القديم هو: أولاً بناء الاتصال، ثم تنفيذ اليدين، وأخيراً بدء عمليات الأعمال.

1. العميل يرسل طلب مستقل يصف نفسه تماما
2. خادم 校验该请求携带的协议版本和客户端能力──
3. الخادم 处理对应的方法──
4. الخادم 返回带类型标识的结果(نوع النتيجة) أو JSON-RPC 错误──

التماس التالي سوف يبدأ من الصفر في إعادة هذه العملية الكاملة.

## مفهوم الأساسي

### الخادم 原语(خادم بدائية)

MCP Server 暴露三个核心原语:

1. **Tools（工具）**: بواسطة النموذج المحرك`tools/list`发现并由 `tools/call`调用。
2. **Resources（资源）**: حسب بيانات الرسوم البحثية، من خلال`resources/list`发现并由 `resources/read`读取:
3. **Prompts（提示模板）**: قابل الاستعمال`prompts/list`发现并由 `prompts/get`染──

الجذور ‬المعينة و التسجيل `2026-07-28`في الموديل من أجل التضامن تم الاحتفاظ به، ولكن تم وضع علامة واضحة على أنه تم التخلي عنهم. في التنفيذ الجديد، يجب استخدام أداة أو موارد واضحة أو إدخال بديل للجذر، باستخدام API المقدمة للموديل المباشر أو OpenTelemetry استبدال العينات، باستخدام stderr أو OpenTelemetry استبدال تسجيل المعلومات.

### غلافات JSON-RPC

MCP 底层 باستخدام JSON-RPC 2.0:

- رجاءاً`{jsonrpc, id, method, params}`
- 响应(رد):`{jsonrpc, id, result}`أو`{jsonrpc, id, error}`
- إشعار:`{jsonrpc, method, params}`, بدون`id`字段

في طلبات`id`لا تُنشئ أي جلسة من أشكال الاتفاقية

### مطلوبة طلبات البيانات

كل طلب جديد موجود`params`内部 حمل واحد `_meta`المواد:

```json
{
  "jsonrpc": "2.0",
  "id": 7,
  "method": "tools/list",
  "params": {
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {},
      "io.modelcontextprotocol/clientInfo": {
        "name": "course-client",
        "version": "1.0.0"
      }
    }
  }
}
```

协议版本号(`protocolVersion`) و قدرة العميل`clientCapabilities`) هو ضرورة ضرورية...`clientInfo`) للمشروعات الترويجية، والتي تنتمي إلى تقارير التفاصيل والتحقيقات، لا يمكن أن تكون كدليل أمني على الإطلاق.

الخادم  strictly banned من قبل طلبات studio  عملية البيئة HTTP  اتصال أو انتقال مستوى الطلبات من خلال التخمين بشكل منفصل على هذه البيانات 

### 完整结果与 Server هوية

كل ناجح من النتائج الحديثة`resultType`◊ استعمال النتائج النهائية للقانون`"complete"`يجب على الخادم أيضاً أن يعلن عن هويته في النتائج:

```json
{
  "jsonrpc": "2.0",
  "id": 7,
  "result": {
    "resultType": "complete",
    "tools": [],
    "ttlMs": 30000,
    "cacheScope": "public",
    "_meta": {
      "io.modelcontextprotocol/serverInfo": {
        "name": "notes-server",
        "version": "1.0.0"
      }
    }
  }
}
```

`tools/list`.`resources/list`.`prompts/list`.`resources/templates/list`.`resources/read`و`server/discover`均为可存储结果, يجب أن تتضمن `ttlMs`(毫秒存活时间) و `cacheScope`(缓存范围) ◦安全的默认值是 `ttlMs: 0`和 `cacheScope: "private"` يجب أن يتبنى النظام التالي لتحديد النظام (التسلسلات المحددة) ، لضمان أن الإجابة المتساوية يمكن أن تولد كيوز حافظ ثابت وموافقة على النموذج

### 无握手的服务发现(الاكتشاف بدون ضغط اليد)

كلّ خادم جديد يجب أن يتمّ تنفيذه`server/discover`يمكن للعميل أن يستخدمها في إطلاق طريقة عمل قبل الحصول على:

- `supportedVersions`:Server 支持的协议版本列表
- `capabilities`: الخادم  تقديم الكفاءة
- المعلومات المتاحة`instructions`)
-  نتائج `_meta`عريفة شخصية الخادم
- 缓存提示`ttlMs`和 `cacheScope`)

خدمة العثور مفيدة جدا، ولكن ليس من المفترض زيارة.`tools/list`كطلب أولى، لأن الطلب نفسه بالفعل يحمل إصدار الاتفاقية والقدرة العميل.

إذا لم يتم دعم إصدار الطلب ، الخادم  عودة JSON-RPC  errorcode `-32022`وبالإضافة إلى البيانات:

```json
{
  "requested": "2027-01-01",
  "supported": ["2026-07-28"]
}
```

العميل يختار نسخة الحديثة من الاتفاقية المدعومة من الطرفين ، و يستخدم كل جديد JSON-RPC طلب الهوية  إجراء إعادة التجربة

### دورة حياة كاملة من طلب واحد

رجاءً على الدرجة التالية

1. حل واحد JSON-RPC غلافة
2. 校验 `jsonrpc`字段为 `"2.0"`، وجود`id`،`method`为字符串, و`params`لأجل المشهد
3. 校验 `params._meta`中包含版本字符串与能力对象; إذا كان هناك فقدان بيانات أو شكل غير قانوني ، عودة خطأ رمز `-32602`.
4. على الحدود HTTP، مقارنة مع عنوان الإصدارات من البروتوكول، طريقة عنوان والجهاز التالي اسم الطلب والطلبات ما إذا كان متوافق.`-32020`(حتى واحدة من قيم الإصدارات غير مدعومة)
5. في حالة تأسيس الاتفاق، إذا تم دعم إصدار الطلب ولكن الخادم غير متوافق، عود `-32022`.
6. اختبار المهارات المطلوبة، ثم حسب `method`路由并校验方法专有参数──
7. في المراقبة المحددة 执行前完成认证 (تصديق)
8. 返回带有 Server 身份信息的完整结果(نتيجة كاملة)。
9. 立即遗忘当前请求作用域的协议元数据──

هذا النظام الصارم يمكن أن يخلق عدم توافق بين المكونات على استخدامات مختلفة.`Mcp-Name: notes.read`في الوقت نفسه من قبل محطة تنفيذ`params.name: notes.delete` يسمح أيضاً بإدخال الصور  مخططات المعلومات  إصدارات المفاوضات  عدم وجود القدرات  عدم وجود الهيمنة والإخفاقات في الإدارة  إخطاءات الأعمال لتصبح دليلاً على التعرف على بعضها البعض 

关闭 stdin أو关闭 HTTP 响应连接 仅代表结束传输层生命周期,它不会终结任何协议会议,因为现代MCP 根本不存在协议会议

### 显式 Legacy 兼容

`2025-11-25`及更早版本依赖 `initialize`.`notifications/initialized`القدرات المرتبطة بالاتصال، وكذلك في الأيام الأولى من جلسات HTTP المباشرة.

ولكن يجب أن يتم فصل الزمنين بشكل كامل. الطلب الحديث من خلال كل طلب من الضروري لتحديد البيانات. يمكن فقط اختيار الاتصال القديم من خلال طريق الرد الخلفي المحدد في المستندات الخاصة.**绝不能把 `initialize` 当作连接 `2026-07-28` Server 的默认行为。**

## التدريب والتفكير

1. سوف تغير نسخة الاتفاقية لطلب`2027-01-01` إثبات خطأ`-32022`, و العودة للبيانات 字段中正确广播了支持版本列表──
2. من طلب ثان نقل`io.modelcontextprotocol/clientCapabilities`أكد الخادم لن يسترد القدرة على إعلان الطلب الأول
3. 颠倒内存中的工具注册表顺序──确认 `tools/list`输出 لا يزال يحافظ على نفس التسلسل التأكيد تماما
4. ستعمل`cacheScope`من`public`修改为 `private` شرح في حالات مختلفة تسمح ما تمنحها على النص التالي
5. 编写一个省略 `clientInfo`حالة الاختبار: دعوة التأكيد لا تزال سارية، لأن الهوية الشخصية للعميل ليست مجرد دعوة.

## 核心专业术语

| 术语 | 规范定义 |
|------|---------|
| 无状态协议 (Stateless protocol) | 每一个请求都自包含解析它所需的完整元数据 |
| 请求元数据 (Request metadata) | 在 `params._meta` 中携带的协议版本、Client 能力声明及推荐的 Client 身份 |
| `server/discover` | 强制实现的 Server 方法，用于声明支持版本、能力、使用说明及身份 |
| `resultType` | 每个现代成功结果上的类型鉴别字段（如 `"complete"`） |
| 可缓存结果 (Cacheable result) | 必须包含 `ttlMs` 与 `cacheScope` 提示的查询或列表结果 |
| 协议时代 (Protocol era) | 现代基于每次请求元数据的模式，或旧版连接作用域初始化的模式 |
| 传输生命周期 (Transport lifetime) | 进程、连接或响应流的物理生存周期，不等同于协议 Session |
| `-32022` | 不支持的协议版本错误码，返回请求的版本及支持的版本列表 |
