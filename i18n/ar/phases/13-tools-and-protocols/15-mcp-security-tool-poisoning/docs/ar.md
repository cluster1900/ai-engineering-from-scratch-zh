## 问题

模型依赖读取工具描述 来决定调用什么――路由器依赖读取工具名称 来决定将请求发送到哪儿――用户依赖读取界面标签来决定批准什么操作――只需要一个恶意构建的描述器,就能同时发起攻击对此三者――

إرشادات الأمن الرسمية للمكسب مباشرة جدا: ما لم تكن وصفات وتعليقات من خادم موثوق به بالكامل، وإلا فكان يجب اعتبارها غير موثوق بها البيانات. حتى ولو كان ذلك، فإن حالة موثوق بها أثناء التشغيل قد تتغير أيضا.

في 2026-07-28 ، لا يوجد مرحلة يدوية ، ولا يوجد جلسة سطح نقل.`Mcp-Session-Id`لا يعد هناك أي تصميمات أمنية لتحديد التصديق أو الحد من السرعة أو التدقيق، تتوافق مع المعايير الحالية للاتفاقية.

## 概念

### 7 أشكال هجومية تستحق الفحص

بدلاً من التذكير المظلم، لا عليك أن تتبع قائمة دفاع واضحة:

1. **元数据投毒（Metadata poisoning）：**وصف تم تضمين أداة مع الإعلانات 行为完全无关的指令(如提示注入、越狱)
2. **Descriptor 恶意篡改（Descriptor rug pull）：** قبل أن تمت الموافقة على اسم المستخدم أو النظام ‬التصفية‬الخطة‬ أو الملاحظة‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬
3. **跨 server 名字遮蔽（Cross-server shadowing）：**أظهرت النوافذ الثنائية نفس اسم الأداة غير المحدد، بينما اختار الممركز واحد منها بناءً على الترتيبات التسجيلية.
4. **Header 与 Body 混淆（Header and body confusion）：**HTTP 头部 `Mcp-Method`أو`Mcp-Name`مع JSON-RPC المحتوى في الطلبات غير متطابقة.
5. **Capability 权限提权（Capability escalation）：**على المحطة في الطلب إعلان عن امتداد أو خصائص المستخدم، بينما الخادم  خطأ يُعتبر هذا الإعلان كذات الوصفة المفروضة.
6. **MRTR 状态篡改（MRTR state tampering）：**客户端改了 `requestState`、 أجاب على سؤال تأكيد آخر مختلف تماما، أو إعادة استخدام شهادة تأكيد قديمة إلى الحجج التي تغيرت
7. **供应链身份混淆（Supply-chain identity confusion）：**سوف يكون اسم عرض (ظاهرًا مألوفًا) كموثوق أو خادم

هذه المداخلات تتواصل بشكل متواصل. الحش مقفل. يساعد على اكتشاف التغييرات التالية للمصفوف، ولكن لا يمكن إثبات المصفوف الأولي.

### عندما طلبنا أن نصل إلى إثبات وليس إلى شخصية

كل نسخة من 2026-07-28 تشتمل على:

```json
{
  "_meta": {
    "io.modelcontextprotocol/protocolVersion": "2026-07-28",
    "io.modelcontextprotocol/clientCapabilities": {
      "elicitation": {"form": {}}
    },
    "io.modelcontextprotocol/clientInfo": {
      "name": "security-lab",
      "version": "1.0.0"
    }
  }
}
```

على كل طلب يجب أن يثبت نسخة بروتوكول مع فعالية هيكل القدرة.**绝不能**- لا .`clientInfo`عندما تم تصنيفها، فإن العلامة الرئيسية هي مجرد بيانات من المستخدم الذاتي.

نفس التحذير ينطبق على النتائج`io.modelcontextprotocol/serverInfo` إنه مفيد جداً في سجلات السجلات والتحققات، لكنه ليس شهادة رقمية، ولا شهادة سجل، ولا يمكن أن يكون أساساً لقرارات المفوضية.

### طريق التحقق، وإعادة تنفيذ استراتيجية


طريقة وسط الرأس يجب أن تكون متوافقة تماما مع طريقة وسط الجسم`params.name`完全一致──在选择后端、应用 RBAC(基于角色的访问控制) أو الاستهلاك الحد من التيار الجهاز 之前, once found inconsistent, must return immediately `-32020`خطأ في رفضها

 التحقق من النصوص التالية: أولاً التحقق من نوع JSON-RPC وواحد نوع البيانات، مقارنة مع القيمة للقائمة والجسم، ثم التحقق من ما إذا كان الإصدار المتماثل مدعوم.`-32020` إذا كان الرأس مع الجسم واحد ولكن الإصدار غير مدعوم، عود إلى HTTP 400 مع الخطأ `-32022`و`data`يجب أن يكون واضحاً`{"supported":["2026-07-28"],"requested":"<actual>"}`◊ إذا طلبت طريقة غير معروفة، ثم عود إلى HTTP 404 مع الخطأ الرمز `-32601`.

عندما يتطلب الاتفاقية إعادة هيكلة المعلومات، كل خطأ يمكن أن يحتوي على الاختيارات.`data`字段──由于通知(إخطار) 没有 `id`، لذلك لن يتلقى أبداً JSON-RPC نجاح أو خطأ في الاستجابة.

### على كل Descriptor  إجراء hashlocking(التقاط)

仅对描述 计算哈希会遗漏 schema 和注释的改──必须对用户批准的所有描述符 字段进行规范化(canonicalize)并计算哈希:

```python
normalized = json.dumps(tool, sort_keys=True, separators=(",", ":"))
digest = hashlib.sha256(normalized.encode()).hexdigest()
```

سوف يتم هضمها وتخزينها في كليات محددة تماما`notes.export`) ، و سجل في بيئة الإنتاج شهادة و وقت الموافقة

في كل مرة يتم فيها إصلاح أو اكتشاف:

- غير معروف: إعلان الحجر الصحي حتى يتم إجراء المراجعة الإصطناعية
- مثلما هو الحال، مختلفة: كمناسبة
- 重复的未限定名称: تطلبات قاطعة لتحديد اسم الفضاء
- 静态扫描命中:拦截并全面审查整个描述器──

哈希一致 فقط يمكن أن يثبت المحتوى غير تغير، لا يمكن أن يثبت سلامته الطبيعية.

### 保护无状态 MRTR 确认

أداة ذات تأثير كبير (أداة متابعة) قد تحتاج إلى تأكيد المستخدم.

أول رد:

```json
{
  "resultType": "input_required",
  "inputRequests": {
    "confirm": {
      "method": "elicitation/create",
      "params": {
        "mode": "form",
        "message": "Export notes to archive?",
        "requestedSchema": {
          "type": "object",
          "properties": {
            "confirm": {"type": "boolean"}
          },
          "required": ["confirm"]
        }
      }
    }
  },
  "requestState": "opaque-integrity-protected-value"
}
```

بعد الحصول على المستخدم بعد إدخال المستخدم، استخدم طريقة جديدة JSON-RPC

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {
    "name": "notes.export",
    "arguments": {"query": "private", "destination": "archive"},
    "requestState": "opaque-integrity-protected-value",
    "inputResponses": {
      "confirm": {
        "action": "accept",
        "content": {"confirm": true}
      }
    },
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {
        "elicitation": {"form": {}}
      }
    }
  }
}
```

كل واحد`inputRequests`قيمة كل واحد يحتوي`method`和 `params`طلب كامل للدخول.`inputResponses`中的对应条目一致──表单诱导(شكل تحفيز) استخدام كمناسبة`requestedSchema`، ويجب على العميل أن يكون لديه القدرة على طلب النموذج على الخادم 

الاتفاقية الحالية لديها نوعان من القانونية إمكانية إظهار واحد:`{"elicitation":{}}`隐式支持表单;而`{"elicitation":{"form":{}}}`为了显式声明──若仅声明URL 支持(例如 `{"elicitation":{"url":{}}}`),则不支持表单请求──此时服务会返回HTTP 400 与错误码 `-32021`و`data.requiredCapabilities`لأجل`{"elicitation":{"form":{}}}`.

يجب أن يكون`requestState`视为不可信输入──对其签名或加密,严密验证,并将其与方法,工具,精确论点,操作目的,过期时间,认证主体以及一次性随机数((nonce,用于防重放)强力绑定──本课代码演示了使用HMAC和精确参数比对构建清晰的安全边界──

لا يمكن أن يكون هناك أي نظام إضافي في الخدمة، ويمكن أن يكون هناك أي نظام إضافي في الخدمة، ويمكن أن يكون هناك أي نظام إضافي في الخدمة، ويمكن أن يكون هناك أي نظام إضافي في الخدمة.`cancel`لا تنفذ أي عملية، وتحتفظ بحالة قابلة للقيام بإعادة التجربة قبل انتهاء المدة. تحتاج مجموعة الإنتاج إلى تحقيق نفس الجهاز التجاري الشروطي في مخزن الاستمرار المشترك.

### في تنفيذ قبل تقليص الحقوق

عدم الحالة نفسها لا تساوي الأمن. على الرغم من أنها قد أزالت مخاطر التاريخ المخبأ ، إلا أن طلبات المحتملة نفسها لا تزال ممكنة باستخدام المعاملات المفرطة للفضح أو التسبب في التدمير. يأتي الأمن الحقيقي من تقليص الحدود في كل مستوى الحدود:

1. **类型化动词（Typed verb）：**暴露单一受限操作`archive_note`), بدلاً من التغير`run`أو`request`هذه النوع من الأدوات التي يمكن أن تنتج القدرة غير المتوقعة.
2. **校验参数（Validated arguments）：**尽可能采用封闭的方案,拒绝未知字段,进行单次规范化标识符,限制用负载大小,并评估策略前验证目标地址、租户归属与资源所有权──
3. **即时鉴权（Current authorization）：**سيتم تحديد المواضيع المعتمدة مع الكلمات والموارد والبيئة والمعايير المحددة.
4. **绑定动作的审批（Action-bound approval）：** لتحديد التأثيرات العالية، يجب إعادة إطلاق أي تغييرات في العناصر على الاختيار.
5. **一等拒绝（First-class refusal）：**سوف يرفض المستخدم رفض وأغراض غير آمنة على أنه نتيجة متوقعة عادية، لا تنفيذ أي آثار جانبية، لا يمكن أبدا رفض الارتفاع إلى أداة الاحتياطي الأقل قدرة على الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى الوصول إلى.

## 关键术语

| 术语 | 含义 |
|------|------|
| 元数据投毒（Metadata poisoning） | 在 tool descriptor 中嵌入恶意提示词指令或欺骗性声明 |
| 恶意篡改（Rug pull） | 针对先前已获审批的 descriptor 进行未授权的静默修改 |
| 名字遮蔽（Tool shadowing） | 由未加限定的重复 tool name 导致的路由歧义与覆盖 |
| 头部不匹配（Header mismatch） | 路由 header 与 JSON-RPC body 内容冲突，触发错误 `-32020` |
| 哈希锁定（Hash pin） | 对经审核批准的完整规范化 descriptor 计算所得的 SHA-256 digest |
| MRTR | 多往返请求模式（Multi Round-Trip Requests），用于 server 主动请求输入并由 client 无状态重试 |
| `requestState` | 往返传递的不透明状态值，必须作为不可信输入进行完整性保护与校验 |
| Capability 声明 | 仅表示协议特性的兼容性声明，绝不代表授权与访问许可 |
| 隐式表单支持 | 空的 `elicitation` capability 对象 `{}`，等同于显式声明支持表单 |
| 完全限定名（Qualified tool name） | 网关层稳定的命名，如 `notes.search`，防止命名冲突 |
