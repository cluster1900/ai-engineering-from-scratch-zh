## 契约流水线

سنقوم بتقسيم كل أداة إلى خمس أجهزة:

1. **发现（Discover）**:读取确定性、已分页的工具列表──
2. **准入（Admit）**: تجربة كل أداة وصف符并 تنفيذ استراتيجية الأمن المحلية
3. **调用（Invoke）**: تجربة استخدام العناصر و بناء انتقال الطبقة من البيانات.
4. **执行（Execute）**:运行工具处理函数并对错误进行正确分类──
5. **消费（Consume）**: قبل استخدام النموذج، تحليل المكونات من الكتلة والإصدارات المهيكلية.

## JSON Schema هو运行时边界

في MCP `2026-07-28`规范中،`inputSchema`مع`outputSchema`均采用 JSON Schema──当省略 `$schema`声明时,默认方言为 2020-12。

输入 Schema 必须是一个 schema object. حتى لو كان الوسيلة لا تحتاج إلى أي عناصر، يجب أن تكون على وجه اليقين تعلن عن صيغة مقبولة:

```json
{
  "type": "object",
  "additionalProperties": false
}
```

هذا أكثر من`{ "type": "object" }`                                                                                                                                                                                                                                                              

الخطة المخرجة هي اختيارية ولكن الخدمة ستصدر مرة واحدة`outputSchema`كل مرة يعود فيها كامل الوسائل نتيجة كل مرة يعد العودة وفقا للاتفاقية`structuredContent`حتى لو كانت النتائج تتضمن`isError: true`كذلك هو الحال. علامة الخطأ هي مجرد فئة من نتائج التنفيذ، فإنها لا يمكن أن تحرر من الموافقة المطبوعة. يجب على العميل أن يكون محركا في نتائج التجربة، وليس مصطلحا في التوصية.

## `x-mcp-header`هو طريق من بيانات

في`inputSchema`يمكن أن يعلن عن صفة داخلية`x-mcp-header`تحت اتفاقية نقل HTTP المباشرة، سيتم تعيين المستخدمين في هذا المجال`Mcp-Param-{name}`العنوان

```json
{
  "region": {
    "type": "string",
    "x-mcp-header": "Region"
  }
}
```

عندما تكون`region: "eu-west"`时، transmis layer即可发发出如下标题:

```http
Mcp-Param-Region: eu-west
```

 إدخال هذا النظام هو الهدف من جعل محرك توازن الحمل أو محرك التخطيط أو محرك الاستراتيجية في حالة عدم الحل الكامل JSON طلبات الطلبات.**绝对不能**يستخدم لتقديم شهادة تحديد الحقوق أو بيانات حساسة

ووضع القيود الصارمة على هذا التنفيذ:

- 标头名称必须非空,且符合 HTTP رمز اسم الحقل 语法规范;
- يجب أن تكون المادة الوحيدة في جميع أنحاء العالم على أساس عدم الاختلاف في الكتب الكبيرة.
- نوع الخصائص العاملة فقط يمكن أن يكون سلسلة أو عدد كامل أو بولي
- غير مسموح باستخدامها`number`(浮点数)
- لا يمكن أن يظهر هذا مباشرة`inputSchema.properties`من الدرجة الأولى مباشرة في الدرجة الأولى
- المجموع المحدد يجب أن يكون محدوداً `-9007199254740991`إلى`9007199254740991`(JavaScript 安全整数范围)

位置规则是语法级别的,而且必须是安全失败(故障-closed) 机制──必须穿越整个树 Schema 树,而不能仅仅检查校验器巧识别顶级属性──只要注解现身嵌套对象的`properties`أسفل`oneOf`في المرحلة`items`من خلال`$ref`في تعريف المقتبس، أو أي إصدار في الخطة، يجب أن يكون هناك رفض قاطع.

هذا الدروس يضيف استراتيجية أمن التنفيذ:`password`.`secret`.`token`.`api_key`أو`authorization`وصف符一律予以拒绝. القواعد الرسمية تشير إلى أن مؤلف الخدمة لا يجب أن يكون عبارة عن عبارة حساسة عن المرآة، ولكن يمكن للعملاء تنفيذ هذا النظام على قواعد حكم الدخول الصارمة.

审计时只记录标题名称,不记录其具体数值.`Mcp-Param-Region`و سيتم تحديد قيمتها`eu-west`خارجة في الامتحانات

### 服务端校验镜像副本

في الحدود المتداولة من HTTP ، يجب أن يكون جهاز الخدمة:

1. في ظل عدم الاختلاف في النص، أبحث عن كل المعلومات`Mcp-Param-*`(إنه)
2. إذا كان هناك قاعدة 64 哨兵格式، إجراء تحديد
3. إجراء مقارنة صارمة بين النص الذي يتم فكيه بعد ذلك والمتطلبات JSON المتعلقة بالمساعدة؛
4. إذا أكتشفت أن العلامة المحددة قد اختفت، وكررت، و لم تتوقع ظهورها، أو أن الخطأ في الشكل أو عدم الاتفاق مع الطلب، فمنع مباشرة قبل إطلاق العمل.

يجب أن يعود إلى HTTP`400`و أيضاً JSON-RPC  خطأ كود `-32020` لا تشمل قيمة الطلبات والشكل العلامي بعد التدوين محتوى السجلات المراجعة، ويتم الاعتراف فقط بالشكل العلامي الذي تم تحديده في السجلات المراجعة و فئة أسباب الرفض.

## المخططات غير شفافة

عمل MCP على استخدام الميزان المخصص للصفحات.

```python
if result.get("nextCursor") is None:
    break
cursor = result["nextCursor"]
```

**绝对不要**写成如下形式:

```python
if not result.get("nextCursor"):
    break
```

لأنّه لا يزال`""`أيضاً هو القيمة القانونية للعبور! إذا استخدموا مباشرةً قيمة Python الحقيقية لتحديد الحقيقة، فسوف يؤدي إلى الانقطاع المبكر في التعبير.

لا يمكن للعميل محاولة حل علامة الموقع، أو إضافةها إلى النظام الخاص، أو تقييمها على النظام أو اقتراح صفحة الموقع. يمكن للجهاز الخدمي التوقيع على علامة الموقع، أو ربطها إلى إصدارات قائمة معينة، أو تحديدها إلى حالة خاصة في المستوى السفلي، كل هذا ينتمي إلى التنفيذ الداخلي للجهاز الخدمي.

## التأثير الذاتي هو المفوضية

`completion/complete`方法为快速 参数和资源模板参数提供自动补充建议── إنها مفيدة جداً في جدول التفاعل، ولكن إذا لم يتم إضافة الحماية، فمن الممكن أن تفشأ اسم حساس محمي واجهة المواصلات العادية.

بيان طلب كامل عن العنصر المذكور والمعايير المكتملة حالياً:

```json
{
  "method": "completion/complete",
  "params": {
    "ref": {
      "type": "ref/prompt",
      "name": "deployment_review"
    },
    "argument": {
      "name": "environment",
      "value": "st"
    }
  }
}
```

أعادتها النتائج الأكثر تضم 100 قيمة مقترحة، ويمكن أن تضم `total`مع`hasMore`字段。

يجب أن يكون في هذا التطبيق مع المرجع أو الموارد المتطابقة تماما مع الحدود المفروضة. في تحقيق المثال، يمكن للمحلل العادي الحصول على`development`مع`staging`إضافة كاملة: فقط المدير المدير قادر على الحصول على`production`من النصيحة

ويتطلب أيضاً وجود:

- 严格的入学考试;
- 区分调用者身份过؛
- 客户端防(إقلاع)
- 服务端限流(حد من المعدلات) ؛
- الحد من عدد النتائج
- في يجيج تجنب التعرض للمكافآت الحساسة

والإضافة كلها هي وسيلة إدخال مساعدة، لا يمكن أن تكون أبداً بوابة خلفية لتحقيق الحقوق.

## الجهاز الخطأ

يجب أن يتم التمييز بين خطأ درجة الاتفاقية وأخطاء أداة التنفيذ

عندما MCP طلبات لا يمكن أن تكون صحيحة分发时, استخدام **JSON-RPC error**:

- اسم أدوات غير معروفة
- 格式错误的请求报文;
- عدم وجود بيانات مطلوبة
- لا فائدة من النقاط

عندما تستخدم أداة الوصول الناجحة، و أداة على التقارير هي عملية يمكن تصحيحها عندما فشل، استخدام مع وجود`isError: true`**完整工具结果（complete tool result）**:

- مصدر بيانات تقرير غير مستخدم لفترة مؤقتة
- 传入日期 تجاوزت المدى المدعوم؛
- قواعد العمل رفضت عمليات طلبها

عادة ما يكون لدى النموذج الكبير القدرة على فهم وإصلاح أدوات تنفيذ الأخطاء، ولكن لا يمكن للنموذج الكبير إصلاح نفسه في خرق الخطة الخارجة الخاصة به.

إذا أُعلنت أداة الخروج من الخطة، يجب أن يتم بناء النظام داخل الخطة على فشل عملياتها.`route_report`عندما تفشل، سوف تعود`isError: true`خارج المنطقة التي طلبها`accepted: false`شكلاً مهيكلاً معاً

## النمو البيئي

| 故障现象 | 学习者看到的表象 | 正确处理方案 |
|---------|-----------------------|------------------|
| 客户端假定输出必定是 object | 合法的数组校验失败或被静默包装 | 依据发布的 Schema 进行校验，不假定结果必须为 object |
| 空字符串游标被当成 False 处理 | 最后一页数据意外丢失 | 只要 `nextCursor` 存在且非 null，就继续拉取下一页 |
| 镜像了敏感参数值 | 凭证密钥暴露在代理、WAF 或链路追踪日志中 | 拒绝该描述符，将机密保留在受保护的请求体内部 |
| 原始 Unicode 或空白字符直接镜像 | 网关与源站解析不一致，或值被意外规范化 | 使用 Base64 UTF-8 哨兵编码并在解码后进行比对 |
| 注解隐藏在 Schema 的复杂分支中 | 客户端在准入时漏检了路由元数据 | 遍历整棵 Schema 树，仅允许直接位于一级的属性携带注解 |
| 镜像了大整数 | 中间 JavaScript 代理对路由数值进行了舍入 | 拒绝超出 JavaScript 安全整数范围的数值 |
| 标头与请求体不一致 | 网关路由给服务 A，而源站实际执行服务 B | 在业务分发前以 HTTP `400` 和 JSON-RPC `-32020` 拒绝 |
| 忽略了输出 Schema | 下游程序消费了损坏的脏数据结构 | 在交给模型或应用程序前进行严格校验 |
| 盲目信任返回的资源链接 | 调用方直接读取了未获授权的 URI | 对每一次资源读取重新执行鉴权 |
| 自动补全共享了全局建议列表 | 多租户敏感隔离名称被泄露 | 按调用者身份、引用上下文与权限范围进行过滤 |
| 将工具注解当作安全策略 | 破坏性危险操作跳过了二次确认 | 在注解之外建立独立的授权与审批流 |
| 单个格式错误的工具搞垮整个发现流程 | 整台 MCP 服务端完全不可用 | 拒绝有问题的描述符，独立准入其余合规工具 |

## 关键术语

| 术语 | 含义 |
|------|---------|
| `inputSchema` | 定义工具所接受参数的 JSON Schema 对象 |
| `outputSchema` | 定义 `structuredContent` 格式的可选 JSON Schema |
| `structuredContent` | 工具执行结果所生成的任意 JSON 结构化数值 |
| 内容块（Content block） | 具备类型化标记的 text、image、audio、resource_link 或 embedded resource |
| `x-mcp-header` | 将基础类型参数镜像为 Streamable HTTP 标头元数据的 Schema 注解 |
| 不透明游标（Opaque cursor） | 服务端发出的分页标记，客户端不得解释其内部含义 |
| 补全引用（Completion reference） | 正在请求参数补全的 Prompt 名称或资源 URI/模板 |
| 准入（Admission） | 客户端根据本地策略决定公开暴露还是拒绝已发现描述符的决策过程 |
