## 问题
经典服务 会把每个请求的提示 当作不透明──即使 5,000 RAG 请求都用同一个2000-Token系统提示加同一个检索序言 开头,vLLM也会对这个2000-Token序言预填5000次──GPU 一次又一次地做同样工作──

观察结论是:agentic 和 RAG workloads 中的提示 几乎总是共享长时间的预写.──系统提示、工具方案、少数截图示例、检索标题、对话历史,全都会在请求之间重复──如果你把这个预写的KV缓存存一次并复用它,就不需要再填充──

الإنتباه الجذري هو بالضبط ما يحدث. يتم تحديد الجيوب في شجرة الجذري. كل عقدة تمتلك تسلسل الجيوب على طريق الجذر إلى هذا العقدة على حجر KV المتوافق.

التحدي هو الجدول. إذا كان هناك طلبان يشتركون في 2000 رمز، بينما الطلب الثالث يشتركون فقط في 200 رمز من نفس المرفق، سوف ترغب في وضع طلبان مشتركين في الخدمة معا، جعل المرفق الطويل يظل في HBM.

## 概念
### كـ مؤشر KV

شجرة راديكس ((مختلفة ثلاثية) تخزين تسلسلات الوهمات。 كل عقد  امتلك مجموعة من الوهمات، فضلا عن كتلة KV المحسوبة لهذا النطاق── الأطفال 会把 تسلسل 扩展一个或多个 Token──

```
root
 |- "You are a helpful assistant..."  (2,000 tokens, 124 KV blocks)
      |- "Context: <doc A>..."        (500 tokens, 31 blocks)
           |- "Question: Alice..."    (80 tokens, 5 blocks)
           |- "Question: Bob..."      (95 tokens, 6 blocks)
      |- "Context: <doc B>..."        (520 tokens, 33 blocks)
```

واحد طلب جديد مع طلب النظام + "مواصلة: <doc A>" + "سؤال: كارول" 进来──调度器遍历:نظام المقبلات 匹配(复用124 كتلة) ،doc-A فرع 匹配(复用31 كتلة) ، ثم فقط ل "سؤال: كارول" 分配 كتلة جديدة(4 كتلة)── تكلفة المقبلات: 4 كتلة: علامات جديدة── بدون هذا الشجرة: 160 كتلة── قبل المقبلات 省省约 ~40x──

### التخطيط المعرف على الاحتفاظ بالخزنة

إذا كان الكاش لا يتوقف عن التشغيل، لا معنى لها استخدام إعادة التشغيل على أساس شجرة راديكس.

1. **Depth-first dispatch** عند اختيار طلب في الصف ، قم باختيار الأولوية مع مجموعة تشغيل الحالية ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬
2. **Branch level 的 LRU，而不是 block level 的 LRU** القضاء على جميع الفروع (من أقصر الأوراق المستخدمة) ، بدلاً من الكتل المفردة، مثل شكل الاحتفاظ 才与基底形匹配.

وخلق الفدرالية الفيدرالية هذه النقاط، تمت إعادة تشغيل طلبات الـ 2000 رمز بعد طلب 50 رمز، ثم تم طرد فرع الـ 2000 رمز، كي يتسنى لها قبول طلبات الـ50 رمز.

### أمر 陷

## 关键术语
| Term | What people say | What it actually means |
|------|----------------|------------------------|
| RadixAttention | "SGLang 那个东西" | KV cache 以 radix tree 索引，使 shared prefixes 能复用 blocks |
| Radix tree | "compact trie" | 每个 node 拥有一个 Token range 及其 KV blocks 的 tree |
| Cache-aware scheduler | "hot-branch-first" | 优先处理共享 resident branch 的请求的调度器 |
| Prefix-cache hit rate | "你的 prompt 有多少是免费的" | 从复用 KV blocks 服务的 prompt Tokens 比例 |
| FCFS | "first-come first-served" | 会破坏 prefix locality 的默认 scheduling |
| Branch-level LRU | "驱逐 leaf" | 与 radix shape 匹配的 eviction policy |
| Prompt template ordering | "cache key" | prompt 的 component order 决定 tree 能共享什么 |
| System prompt pinning | "resident prefix" | 保持 immutable system portion pinned，以避免 eviction thrash |
