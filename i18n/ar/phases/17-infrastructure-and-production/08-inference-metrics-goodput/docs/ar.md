## 概念
### TTFT  وقت لأول رمز

`TTFT = queue_time + network_request + prefill_time`

عندما تطلبات 很长时,预填 占主导──在 H100 上运行的 Llama-3.3-70B FP8 , a 32k عرض 需要大约 800 ms 的纯预填──排列时间是负载下调度器 行为──网络请求是包含 TLS 的线程时间──TTFT 是用户在任何内容流 返回之前看到的延迟──

### التخميس بين الشعار

مع ذلك، هناك الكثير من الأسماء.`TPOT`(الوقت لكل رمز الخروج)`ITL`(التأخير بين الشعار)`decode latency per token` 都是同一个东西──它是首个代币 之后,连续流媒体代币 间时间──

`TPOT = (decode_forward_time + scheduler_overhead) / tokens_produced`

في نفس مع معملة المقبلات المقطوعة من Llama-3.3-70B H100 كومة فوق، TPOT متوسط ≈ 7 ms‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ ‬ 

### تأخير E2E

`E2E = TTFT + TPOT * output_tokens + network_response`

对于长输出(>500 Token),E2E بواسطة TPOT 主导──对于带长提示的短输出,E2E بواسطة TTFT 主导──报告按输出长度分组的 E2E──

### التشغيل

`throughput = total_output_tokens / elapsed_time`

聚合指标── أخبرك كفاءة الأسطول── لا أستطيع أن أخبرك بموقف صحي واحد‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬‬

### جيدبوت  أنت حقا اهتم

`goodput = fraction of requests meeting (TTFT <= a) AND (TPOT <= b) AND (E2E <= c)`

SLO هو مقيد متعدد القيود. فقط كل قيود تم تلبيتها، وطلب واحد هو فقطخير🏼خير🏼خير🏻 هو هذا النسبة. في 60% من الخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخيرخير

بحلول عام 2026، أصبح Goodput إيداعات MLPerf Inference v6.0 ومقدمي منصات الذكاء الاصطناعي تعقب SLA داخل المؤشرات المستخدمة.

### لماذا يعني هذا الإحصاءات الخطأ

توزيعات تأخر LLM هي في اليمين من جانبها. في مجموعة إزالة التعريفات، إذا كان هناك طلب قريب من التمديد، قد يكون هناك 500 رمز TPOT لمدة 7 ms، بينما هناك 20 رمز TPOT لمدة 60 ms. متوسط TPOT هو 9 ms.

### فخ القياس

أدوات المقياس المستخدمة بشكل عام في عام 2026 ستعطى نتائج مختلفة على TPOT على نفس المرحلة:

- **NVIDIA GenAI-Perf**: في ITL 计算中排除 TTFT──ITL 从 Token 2 开始──
- **LLMPerf**:包含 TTFT──ITL 从 Token 1 开始──

 بالنسبة لمطلبات TTFT لمدة 500 ms  100 رموز خروج  مجموع رمز التشخيص  700 ms  GenAI-Perf  تقرير `ITL = 700/99 = 7.07 ms`,LLMPerf  تقرير `ITL = 1200/100 = 12.00 ms` الوسائل التي ستغير الأرقام

始终说明使用了哪个工具──始终发布定义──

### بناء SLO

2026 سنة في وجه المستهلكين 70B نموذج دردشة معقولة SLO:

- TTFT P99 <= 800 ms¬
- TPOT P99 <= 25 ms。
- لـ <300-Token 输出,E2E P99 <= 3 ثانية
- هدف الإنتاج الجيد >= 99%

ستقوم أجهزة التشغيل التشغيلي المشتركة بإصدار TTFT ((200-400 ms) ومساعدة E2E.

## 关键术语
| Term | What people say | What it actually means |
|------|----------------|------------------------|
| TTFT | “time to first token” | Queue + network + prefill；在长 prompts 下由 prefill 主导 |
| TPOT | “time per output token” | 首个 Token 之后每个 Token 的 memory-bound decode 成本 |
| ITL | “inter-token latency” | 在大多数工具中与 TPOT 相同（不是全部，见 GenAI-Perf） |
| E2E | “end to end” | TTFT + TPOT * output_len；再加上 response-side network |
| Throughput | “tok/s” | Fleet efficiency；没有 latency percentiles 时没有意义 |
| Goodput | “SLO-met rate” | 同时满足每个 SLO constraint 的请求比例 |
| P99 | “tail” | 百分之一最差情形 latency；用户体验指标 |
| SLO multi-constraint | “the joint” | 三个 latency bounds 的 AND；只要违反任意一个，请求就失败 |
| GenAI-Perf vs LLMPerf | “the tool trap” | 工具对 ITL 是否包含 TTFT 的定义不一致 |
