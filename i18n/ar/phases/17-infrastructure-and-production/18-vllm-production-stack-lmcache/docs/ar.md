## 问题
تعرضت طلبات تم طردها، ثم تم إعادة ملءها في خلال دقيقة واحدة، تم إعادة ملءها أربع مرات. تم إعادة ملء حسابات GPU. تم إعادة ملءها.

زيادة المزيد من تكاليف الجيبو هي خطية. زيادة المزيد من HBM غير ممكن. ولكن CPU DRAM  رخيصة جدا، وحدة مغلقة واحدة تبلغ 512 جيجابايت، وتأخير مقارنة مع HBM  مختلفة عن عدد من المستويات، ولكن بالنسبة للحفاظ على درجة الحرارة الزمنية KV التخزين  يكفي.

LMCache 会把 KV cache 抽取到CPU DRAM,让预先请求 快速恢复,并让引擎 之间的重复预先语 共享缓存,而不需要每个引擎都重新预充.

## 概念
### مجموعة إنتاج vLLM

`github.com/vllm-project/production-stack`إشارة إلى Kubernetes 部署:

- **Router** الوعي بالخلفية(مرحلة 17 · 11)。消费 KV الأحداث。
- **Engines**عمال التشغيل العام. كل GPU واحد، أو كل مجموعة TP/PP واحد.
- **KV cache offload** نشر LMCache أو رابط محلي
- **Observability** مُخزّر Prometheus 、 لوحات التحكم في Grafana ٬ آثار OTel‬
- **Control plane** اكتشاف الخدمات ‬التكوين ‬التطورات المتحركة‬‬

以 مخطط القيادة + عامل 形式交付。

### API لجهاز اتصال إزالة KV (v0.9.0+)

vLLM 0.9.0  أدخل API الصلة، للاستخدام الكشاف KV القابل للدخول الخلفيات. محركك سوف تحميل الكتل إلى الصلة. الصلة تخزينها.

vLLM 0.11.0(2026 سنة 1 月) زيادة مسار الإفراج غير المزامن: في حالات عادة، يمكن أن يحدث الإفراج في الخلفية، لذلك المحرك لن يتم إيقافه. تأخر نهاية إلى نهاية ومدرجة  لا يزال يعتمد على شكل عبء العمل، وتيرة ضرب cache KV و ضغط النظام. vLLM  وضاحته أيضا، وتحديد إفراج الأساسية-الذرة في معدلات الضربة المنخفضة.

**LMCache connector**:: كلاستر-مقياسها──把 بلوك 存储在共享 LMCache 服务器(CPU DRAM + Ceph/S3 tier) 中── أي محرك يمكن الوصول إلى الكتل──已有16x H100 مقياس التوجه 发布──

عندما محرك واحد لديه ضغط HBM 时选择本土──当多发动机 共享前置 时选择 LMCache(带共同系统提示的RAG、带共享模板的多租户)──

### سلوك المرجعية

تمتزج في 4 台 a3-highgpu-4g 上的 16x H100(80 GB HBM)测试:

- انخفاض مستوى KV ((تفاصيل قصيرة تزامن منخفض): كل التشغيلات مع الخط الأساسي 相当,LMCache  زيادة حوالي 3-5% في التكلفة العامة‬
- الاحتباس الوسيط:LMCache  بدأ في استخدام المواصلات بين المحركات  上带来帮助。
- كيف أكثر من HBM:تحميل CPU الأصلي و LMCache ستحسن بشكل كبير التعبئة؛LMCache زيادة النسبة أكبر، لأن هناك مشاركة عبر المحركات.

### عندما يكون LMCache حاسم

- 多个租客 共享系统提示的多租客服务──
- قطع المستندات في استفسارات 之间重复的RAG──
- مع نفس القاعدة العليا من التغيرات المعدلة الدقيقة ((LoRA) ، من بينها النموذج الأساسي KV إعادة الاستخدام 会减少重复工作。
- تحميلات عمل ثقيلة: من إعادة تشغيل المعالجة المركزية 比重新 prefill 更便宜。

### عندما لا يتمكن من تفعيل

- ضغط الـ HBM 很小: ستدفع تكاليفها فوق الصفحة 却没有收益.
- سياقات قصيرة ((< 1K tokens): وقت نقل > 重新 prefill。
- عبء عمل واحد المستأجر واحد: لا يوجد إعادة استخدام قابل للاستعادة.

## 关键术语
| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Production-stack | “参考部署” | vLLM 的 Kubernetes Helm chart + operator |
| Connector API | “KV backend interface” | vLLM 0.9.0+ 的 pluggable KV store interface |
| Native CPU offload | “engine-local spill” | 把 KV 存到同一 engine 的 host RAM 中 |
| LMCache | “cluster KV cache” | CPU DRAM + disk 上的 cross-engine KV cache server |
| 0.11.0 async | “non-blocking offload” | 隐藏在 engine stream 后面的 offload |
| Preemption | “evict to make room” | HBM 满时的 KV cache shuffle |
| Prefix reuse | “same system prompt” | 多个 queries 共享开头；cache hit |
| Ceph tier | “disk tier” | cache hierarchy 中 DRAM 下方的 durable storage |
