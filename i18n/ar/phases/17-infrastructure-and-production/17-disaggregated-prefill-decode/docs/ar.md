## 问题

أنت في 8 كتلة H100 上运行 Llama 3.3 70B. في خليط العمل تحميل:长提示 + 短输出) 下,GPU 在解码 期间空,因为大部分 الحساب 已花在预填上.

预算影响:20-40% من GPU 时间浪费在错误资源上──你正在购买H100计算去运行内存绑定解码,或购买H100 HBM带宽去运行计算绑定预填──两者都是昂贵的浪费──

التقسيم 会把 prefill 和 decode 拆分到独立资源池,并按各自瓶进行尺寸──KV cache 通过高带宽互连从 prefill pool 传输到 decode pool──

## 概念

### لماذا مختلفة

**Prefill** لتحقيق استهداف كامل للدخول  تنفيذ محول واحد إلى الأمام  تعدد المصفوفة 占主导;computing-bound ・ H100 FP8 可提供约2000 TFLOPS 的有效吞吐量──

**Decode** 一次生成一个代币,每次代都读取完整重量── ذاكرة- عرض النطاق المحدود──HBM3 提供约3TB/s──批量效率 只有在高 concurrency 下才好,因为重量读会在批量 上分摊──

ضعها في مكان: أنت تشتري في نفس الوقت لـ H100 GPU مثالي. H100  كلا منهم جيد، ولكن بغض النظر عن نوعية الاستخدام تكلفة كل شيء.

### دينامو مقابل إلم-د

**NVIDIA Dynamo**(موجب المعلومات العامة 2025 发布,1.0 GA):
- كموسيقي يقع في كلّ مكان
- المخطط الموضح 测量工作负载,SLA المخطط الذاتية التكوين المسبق:الترابط 比例。
- النواة الصدأ، التوسع في Python.
- 吞吐提升:NVIDIA 报告称,在 GB200 NVL72 + Dynamo 上,DeepSeek-R1 MoE 在中等延迟区间达到6x(developer.nvidia.com,2025-06);社区关于全布莱克威尔 + 迪纳莫 + ديبسيك-ر1堆 多达30x 的报告缺少单一主要来源,应视为方向性信息──
- GB300 NVL72 + Dynamo: حسب Dynamo 产品页面(developer.nvidia.com,未注明期),相比霍珀,MOE 吞吐最高可可达50x──

**llm-d**(Red Hat + AWS،Kubernetes-native):
- إعداد / فك رمز / راوتر 作为独立 Kubernetes Services。
- لكل دور HPA استخدام عمق الصفوف (prefill) / استخدام KV (decode) signal。
- `topologyConstraint packDomain: rack`سوف نضع كليكات التمليح المسبق + إعادة تشكيل على نفس الرف ، لتحقيق نقل KV عالية التنقل الموسع.
- إم-د 0.5(2026):إزالة KV الهرمية توجيه LoRA الوعي بالخزنة شبكات UCCL توسع إلى الصفر‬

إذا كنت تريد إدارة كومة فوق الموسيقي، استخدام دينامو. إذا كنت تريد كوبرنيتس-أصل البدائيين، ووضع في CNCF 生态، استخدام llm-d.

### لا تتفرق

- الإشارات < 512 رموز 且輸出 < 200 رموز:传输税主导收益。

## 关键术语

| Term | 人们怎么说 | 实际含义 |
|------|----------------|------------------------|
| Disaggregated serving | “split prefill/decode” | 为每个阶段使用独立 GPU pools |
| NIXL | “NVIDIA transport” | Dynamo 的 inter-node KV transfer（RDMA/TCP） |
| NVIDIA Dynamo | “the orchestrator” | vLLM/SGLang/TRT-LLM 的 stack-above coordinator |
| llm-d | “Kubernetes native” | Red Hat + AWS K8s disaggregated stack |
| Planner Profiler | “Dynamo auto-config” | 测量工作负载，配置 pool ratios |
| SLA Planner | “Dynamo policy” | 自动按速率匹配 prefill:decode 以满足 SLOs |
| `packDomain: rack` | “llm-d topology” | 将 prefill+decode 放在同一 rack 上以实现快速 KV |
| UCCL | “unified collective” | llm-d 0.5 用于 scale-to-zero 的 networking layer |
| MoE expert routing | “expert per token” | DeepSeek-V3 pattern；disaggregation 有帮助 |
