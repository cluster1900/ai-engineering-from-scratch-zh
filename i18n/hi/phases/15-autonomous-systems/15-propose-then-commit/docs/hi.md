# मानव-संदर्भ में प्रस्ताव-फिर-संकल्प

> 2026 साल के बारे में HITL का सहमति है विशिष्ट. यह नहीं है एजेंट 发问, उपयोगकर्ता点击 Approve── यह है प्रस्ताव-फिर-प्रतिबंधः प्रस्तावित कार्रवाई 会连同无权关键 持久化到耐用存储; हेतु DATA lineage、 अनुमति 触摸、爆射和滚动计划 呈现给评审员; केवल明确确认后才承诺;执行后再验证,确认副作用 确实发生──长图的`interrupt()`PostgreSQL चेकपॉइंटिंग Microsoft एजेंट फ्रेमवर्क `RequestInfoEvent`, और Cloudflare के साथ `waitForApproval()` अनुमोदन  कोई समीक्षा नहीं हुई                                                                                                                                                                                                                                                         

**Type:** 学习
**Languages:** Python (stdlib，带 idempotency 的 propose-then-commit state machine)
**前置要求：**चरण 15 · 12 (स्थायी निष्पादन), चरण 15 · 14 (ट्रिवायर्स)
**Time:** ~60 分钟

## 问题

एजेंट  एक कार्य को निष्पादित करे  उपयोगकर्ता को निर्णय लेना चाहिए: अनुमोदन या अस्वीकार करना  यदि निर्णय तत्काल है, तो यह समीक्षा नहीं हो सकती  यदि निर्णय संरचनात्मक है, तो यह धीमा होगा, लेकिन विश्वसनीय है  इंजीनियरिंग प्रश्न यह है कि संरचनात्मक समीक्षा  कैसे संरचनात्मक समीक्षा  को न्यूनतम बाधा बनाने का मार्ग बना 

2023 के दशक का HITL पैटर्न है同步提示:एजेंट को शरीर Y  अनुमोदित के साथ X को ईमेल भेजना है?उपभोक्ता क्लिक करें अनुमोदित करें। प्रत्येक व्यक्ति प्रणाली को सुरक्षित महसूस करता है।

2026 साल का पैटर्न, यानि प्रस्ताव-फिर-कंपिट,把 HITL 移至耐用基板上,附加结构化转基因,并要求积极承诺── प्रत्येक प्रबंधित एजेंट SDK 都提供某版本:LangGraph `interrupt()`、Microsoft एजेंट फ्रेमवर्क `RequestInfoEvent`、Cloudflare `waitForApproval()`API 名称不同;形态相同──

## 概念

### प्रस्ताव-फिर-कमादेश राज्य मशीन

1. **Propose.**एजेंट 生成 एक प्रस्तावित कार्रवाई── इसे स्थायी स्टोर में कायम किया गया है(PostgreSQL、Redis、Durable Object)── इसमें शामिल हैंः
   - इरादा (एजेंट ऐसा क्यों करना है)
   - डेटा वंशज (कौन सा स्रोत इस प्रस्ताव का नेतृत्व किया)
   - अनुमतिओं को छुआ(哪些 स्कोप / फ़ाइलें / अंत बिंदुओं)
   - विस्फोट त्रिज्या ((अधिक खराब स्थिति क्या है)
   - रोलबैक योजना ((यदि प्रतिबद्ध 了, हम कैसे रद्द)
   - idempotency key( प्रत्येक प्रस्ताव 唯一;重复提交返回同一条记录)
2. **Surface.**समीक्षक 看到包含全部转度资料的提案── समीक्षक 是人(不是代理 自己 review 自己)──
3. **Commit.**明确肯定确认──क्रिया 执行──
4. **Verify.**执行后,读取并确认副作用── यदि चरण 失败 सत्यापित करें, सिस्टम已知坏状态 में है,并触发警告──

### निष्क्रियता कुंजी

没有无缺失关键 时,过渡失败 后后的试验可能重复执行已批准的行动――具体例:用户批准转移$100 from A to B──网络短暂动──网络工作流重新尝试──用户只批准一次,但转移 执行两次──缺失关键将批准 绑定到单个单个副作用;第二次执行是无开――

यह स्ट्रिप और AWS एपीआई के उपयोग की असमर्थता पैटर्न के समान है।

### स्थायित्व: अनुमोदन प्रक्रिया में क्यों बने रहेंगे

अनुमोदन प्रतीक्षा कक्ष है एक段不归代理所有的状态──工作流被暂停了──12 पाठ──当批准到来时,工作流将从那精确位置恢复──这就是为什么LangGraph把`interrupt()`PostgreSQL चेकपॉइंटिंग के साथ 配对, केवल इन-मेमोरी स्टेट के बजाय: दो दिन बाद अनुमोदन  अभी भी पूर्ण वर्कफ़्लो पा सकते हैं।

### रबर टिकट स्वीकृति तथा चुनौती-उत्तर-मदत

HITL का डिफ़ॉल्ट UI(अनुमोदित /  अस्वीकार बटन) शीघ्र अनुमोदन उत्पन्न होगा, लेकिन कोई वास्तविक समीक्षा नहीं है──文档化缓解: चुनौती-और-प्रतिक्रिया चेकलिस्ट, आवश्यकताएँ अनुमोदित बटन 启用 से पहले, विशिष्ट प्रश्नों के लिए स्पष्ट पुष्टि उत्तर देना──具体形态:

- क्या आप समझते हैं कि यह ऑपरेशन किस संसाधन से संबंधित होगा?
- आप विस्फोट त्रिज्या की पुष्टि कर सकते हैं स्वीकार?
- अगर असफल हो, क्या आपके पास एक वापसी योजना है?

यह एक प्रवृत्ति और प्रवृत्ति के लिए नहीं है, बल्कि एक बाध्यकारी कार्य है।

###  क्या परिणाम है

प्रत्येक कार्य के लिए प्रस्ताव-फिर-प्रतिबंध की आवश्यकता होती है।

- **Consequential actions**(始终 HITL):不可逆写入、金融交易、 आउटबाउंड संचार、उत्पादन डेटाबेस परिवर्तन、 विनाशकारी फाइल सिस्टम संचालन。
- **Reversible actions**(有时 HITL): स्थानीय फ़ाइलों के संपादन, चरण-env परिवर्तन, स्पष्ट रोलबैक के प्रतिवर्ती लिखता है
- **Reads and inspections**(從不 HITL):读取文件、列出资源、调用 केवल-पढ़ने वाला एपीआई。

### कार्रवाई के बाद की जांच

संयोजन चला गया  不等于 副作用 हुआ── नेटवर्क-भागन तथा दौड़ की स्थिति हो सकती है ताकि कार्यप्रवाह को स्वयं सफल बनाया जा सके, जबकि बैकेंड 实际并非持续── सत्यापन चरण 会在提交 后重新阅读目标资源 以确认── यह उपयोग के साथ `RETURNING`खंडों के डेटाबेस लेनदेन, या`PutObject`后执行 AWS `GetObject`यह एक ही पैटर्न है।

## अभ्यास

1. 运行 `code/main.py` पुष्टि अनुमोदित प्रस्ताव का पुनः प्रयास करें, स्थायी रिकॉर्ड का उपयोग करें, और पुनः निष्पादन नहीं करेंगे।

2. उपयोग `rollback`क्षेत्र  विस्तार प्रस्ताव रिकॉर्ड──模拟 एक बार सत्यापित चरण 失败的执行── प्रदर्शन रोलबैक 会自动触发──

3. 阅读 Microsoft एजेंट फ्रेमवर्क की `RequestInfoEvent`डॉक्स── खोजें एपीआई 包含但玩具机 缺失一个元数据领域──添加它,并解释它防护的风险──

4. एक विशिष्ट क्रिया के लिए (उदाहरण के लिए, सार्वजनिक ट्विटर खाते पर पोस्ट करें) चुनौती-उत्तर चेकलिस्ट डिजाइन करें। समीक्षक को कौन से तीन प्रश्नों का उत्तर देना चाहिए?

5. 选择一个同步 批准? शीघ्र 足够的场景(不需要耐用店) 解释原因,并说明你接受的风险类──

## 关键术语
| Term | What people say | What it actually means |
|---|---|---|
| Propose-then-commit | “Two-phase approval” | 持久化 proposal + positive commit + verify |
| Idempotency key | “Retry-safe token” | 每个 proposal 唯一；第二次 execution 为 no-op |
| Data lineage | “Where it came from” | 导致 proposal 的具体 source content |
| Blast radius | “Worst case” | action 出错时的影响范围 |
| Rubber-stamp | “Fast approval” | 没有真正 review 就点击 “Approve” |
| Challenge-and-response | “Forcing checklist” | Reviewer 必须明确确认具体问题 |
| RequestInfoEvent | “MS Agent Framework primitive” | 带结构化 metadata 的 durable HITL request |
| `interrupt()` / `waitForApproval()` | “Framework primitives” | 同一形态的 LangGraph / Cloudflare 等价物 |
