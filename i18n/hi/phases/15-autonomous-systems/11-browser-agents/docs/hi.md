## 问题

ब्राउज़र एजेंट एक लंबी दूरी का एजेंट हैः यह अविश्वसनीय सामग्री को पढ़ता है, और परिणामी संचालन करता है। एजेंट द्वारा देखे जाने वाले प्रत्येक पृष्ठ, उपयोगकर्ता द्वारा लिखित प्रविष्टियों के बिना होते हैं। प्रत्येक पृष्ठ पर प्रत्येक पृष्ठ, संभावित आदेश मार्गों के साथ होता है। 2025 से 2026 के हमले के लिए सामग्री से पता चलता है कि यह एक परिकल्पना नहीं हैः दूषित स्मृति  हमलावर को ध्यान से बनाए गए पृष्ठों के माध्यम से खराब इरादे के निर्देशों को एजेंट की स्मृति में बांधने की अनुमति देता है। हैशजैक आदेश एजेंट द्वारा देखे गए URL टुकड़ों में छिपा होगा; भ्रम कॉमेट की अपहरण केवल एक बार क्लिक करने के लिए संभव है।

防御图景不舒服──OpenAI की तैयारी 负责人 ने एक गुप्त तथ्य सामने लायाः अप्रत्यक्ष शीघ्र इंजेक्शन एक बग नहीं है जिसे पूरी तरह से ठीक किया जा सकता── कारण एजेंट के पढ़ने और संचालन की सीमा में हमले के होने पर है, जबकि यह सीमा संरचना में अस्पष्ट है मॉडल पढ़ने के प्रत्येक टोकन, सिद्धांत रूप में एक निर्देश के रूप में पढ़ा जा सकता है──

इस वर्ग का नाम इस हमले के चेहरे, नाम बेंचमार्क 版图(BrowseComp、OSWorld、WebArena-Verified),并建模一个最小的间接-即时注射场景,让你推推理14和18中的真实防御──

### क्यों  पूरी तरह से सुधार नहीं किया जा सकता 

इस प्रकार के हमले और एजेंट की क्षमता और संरचना। कार्य को पूरा करने के लिए एजेंट को अविश्वासित सामग्री पढ़नी होगी। एजेंट द्वारा पढ़ी गई किसी भी सामग्री में निर्देश शामिल हो सकते हैं। एजेंट द्वारा अनुशंसित किसी भी निर्देश में उपयोगकर्ता के वास्तविक अनुरोध के अनुरूप नहीं हो सकता है। रक्षा।

यह लोब के प्रमेय के साथ है (Lection 8) यह एक ही विचारधारा हैः एजेंट 无法证明下一个代币是安全的; यह केवल एक प्रणाली का निर्माण कर सकता है, जिससे सुरक्षित नहीं होने वाला代币 अधिक आसानी से बाहर जा सकता है।

### सच्ची रक्षा की स्थिति

- **Read / write boundary.**读取永远不会产生后果──写入(提交表单、发布内容、调用有副作用的工具) यदि विश्वास सीमा से बाहरी सामग्री शुरू होती है, तो नई मानव श्रम अनुमोदन की आवश्यकता होती है──
- **Tool allowlist per task.**एजेंट ब्राउज़ कर सकता है; जब तक कि किसी उपकरण को इस मिशन के लिए स्पष्ट रूप से सक्षम नहीं किया गया हो, अन्यथा यह वायर ट्रांसफर नहीं कर सकता है।
- **Session isolation.**ब्राउज़र एजेंट सत्र केवल स्कोप योग्य क्रेडेंशियल का उपयोग करते हैं 运行── कोई उत्पादन लेखक नहीं, कोई व्यक्तिगत ईमेल नहीं── प्रत्येक HTTP अनुरोध का लेखापरीक्षण के लिए日志 को बनाए रखें──
- **Content sanitizer.**HTML लाया गया है, जो मॉडल संदर्भ में पहले से ही ज्ञात खराब पैटर्न से अलग है।
- **对 consequential actions 使用 HITL。**प्रस्ताव-फिर-कार्य-आदर्शण (पढ़ें)
- **Canary tokens on memory.**यदि एक मेमोरी प्रविष्टि 触发, उपयोगकर्ता इसे देखेंगे

## 关键术语

| Term | 人们怎么说 | 实际含义 |
|---|---|---|
| Indirect prompt injection | “坏页面文本” | Agent 读取的页面中有不受信任内容，其中包含 agent 会执行的指令 |
| Tainted Memories | “Memory attack” | Agent 将攻击者提供的指令写入 durable memory；下一次 session 触发 |
| HashJack | “URL fragment attack” | 隐藏在 URL fragment / query string 中的 payload 位于 agent 的 context 中，但不会被可见渲染 |
| One-click hijack | “坏按钮” | 可见 affordance 承载 agent 会执行的后续 payload |
| BrowseComp | “Web search benchmark” | 在开放 Web 上查找特定事实；分钟级 horizon |
| OSWorld | “Desktop benchmark” | 完整 OS control；多步骤 GUI tasks |
| WebArena-Verified | “修复后的 web-task benchmark” | ServiceNow 重新评分的 WebArena，带 Hard subset |
| Read/write boundary | “Side-effect gate” | 读取永远不产生后果；如果内容来自 trust 外部，写入需要新的批准 |
