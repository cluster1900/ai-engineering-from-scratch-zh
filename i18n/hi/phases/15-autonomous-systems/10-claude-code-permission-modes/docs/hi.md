# स्वायत्त एजेंट का अधिकार मोड

> 权限阶梯 प्रत्येक क्रिया के बाद चरणबद्ध समीक्षा से सब कुछ के अनुमोदन तक की श्रेणीबद्ध स्वायत्तता स्तर है उपयोग 管理控自治代理 无需问问就能做什么方式──本课的实例 Claude Code 暴露了六种这样的模式:"计划"会在每动作前询,"默认"(UI 中标为手册) केवल जोखिम वाले क्रिया के प्रश्न पर विचार करेगा, "स्वीकार"会自动批准文件写入,但仍确认会执行, "bypassPermissions"会批准一切──Auto Mode即`auto`权限模式 एक स्वतंत्र वर्गीकरण मॉडल 取代逐动作批准: यह प्रत्येक动作运行前审阅该动作,并阻止任何超越请求范围的升级──动作预算通过 `max_turns`和 `max_budget_usd`强制执行――`auto`क्या यह योजना पर निर्भर करता है, संगठन को सक्षम किया गया है या नहीं, मॉडल और प्रदाता  मानव 已明确表示, वर्गीकरणकर्ता 单独使用并不足──

## 问题

आपके मशीन पर स्वायत्त कोडिंग एजेंट एक स्वतंत्र सुरक्षा श्रेणी है। यह हमला उस एजेंट का है जो सभी फ़ाइल सिस्टम, नेटवर्क, क्रेडेंशियल, क्लिपबोर्ड, किसी भी ब्राउज़र टैब, किसी भी खुले टर्मिनल तक पहुंच सकता है। ब्रूस श्नायर आदि ने इस बात पर खुलासा किया हैः कंप्यूटर-उपयोग एजेंट चैटबॉट के लिए एक बार नहीं हैं, बल्कि एक नया उपकरण है, जिसमें एक नया प्रकार का एक नया प्रकार है।

क्लाउड कोड का अधिकार प्रणाली एक मानव द्वारा दिया गया उत्तर है। यह एक स्वायत्त / स्वायत्त नहीं है, बल्कि छह प्रकार के मॉडल बनाने की क्षमता हैः चरणः योजना → डिफ़ॉल्ट → स्वीकार करेंसंपादित करें → ... → बायपासपरमिशन। प्रत्येक प्रकार की विधि गति और प्रत्येक क्रिया की समीक्षा के बीच अलग-अलग होती है। ऑटो मोड।

工程 प्रश्न यह है कि यह प्रणाली क्या पकड़ सकती है, क्या खो सकती है, और किसी दिए गए कार्य के लिए किस प्रकार का मॉडल उपयोग करना चाहिए?

## 概念

### 六种权限模式

| 模式 | 行为 | 使用场景 |
|---|---|---|
| `plan` | Agent 提出计划；用户批准整个计划；每个动作在执行前都会被审查 | 不熟悉的任务；接近 prod 的代码；第一次在某个 repo 上使用 agent |
| `default` | 在 UI 中标为 “Manual”。Agent 运行动作；对任何“有风险”的动作提示用户（shell exec、destructive operations、network calls） | 大多数交互式 coding sessions |
| `acceptEdits` | 文件写入自动批准；shell exec 和 network calls 仍然提示 | 跨很多文件的 refactoring pass |
| `auto` | 由一个独立的 classifier model 在每个动作运行前审阅它；阻止任何超出请求范围的升级 | 受限 workspace 中的 long-horizon unattended runs |
| `dontAsk` | 从不提示；未被 permission rules 预先批准的动作一律拒绝 | 临时 sandboxes、CI jobs、research scripts |
| `bypassPermissions` | 批准一切 | 文档说明为“只在你愿意丢弃的 ephemeral containers 内使用” |

(ऊपर के नाम के साथ सार्वजनिक क्लाउड कोड डॉक्स एक致;UI 把 `default`标为  मैन्युअल。)

### एक पृष्ठ को समझने ऑटो मोड

ऑटो मोड ([[2026 साल 3 月 24 日发布) पहली बार मॉडल को एक-एक करके अनुमोदित करने का अधिकार मोड है।

1. **一个独立的 classifier model。**प्रत्येक प्रस्तावित क्रिया को चलाने से पहले इसे समीक्षा करें, वर्तमान स्थिति के अनुसार कार्य और सत्र के अनुसार निर्णय करें, और अनुरोध सीमा से परे किसी भी उन्नयन को रोके।
2. **受限的可用性。**`auto` निर्भर करता है योजना 、 संगठन सक्षम है या नहीं 、 मॉडल तथा प्रदाता 

 बजट नियंत्रण तथा वर्गीकरण में निम्नलिखित शामिल हैंः

- `max_turns` एक सत्र 中中总代次数──
- `max_budget_usd` 触发 सत्र 中止的美元上限──
- प्रत्येक उपकरण की गति के समय सीमा (उदाहरण के लिए N से अधिक नहीं)`WebFetch`कॉल) 

### 系统能捕捉什么

- उपकरण इनपुट में प्रत्यक्ष शीघ्र इंजेक्शन, जिसमें निर्देशों को ज्ञात जोखिम वाले गतिशील रूपों में प्रदर्शित किया गया है।
- 重复 उपकरण लूप वर्गीकरण क्रिया N+1 के साथ क्रिया N 连续五次几乎相同的.
- इस सत्र में, स्पष्ट रूप से सीमा पार के शेल कमांडों को संपादित करना चाहिए।

### 系统可能会错失什么

- **微妙的 prompt injection**, यह व्यवहार को समायोजित करेगा, लेकिन एक एकल चिह्नित आंदोलन उत्पन्न नहीं करेगा। अप्रत्यक्ष शीघ्र इंजेक्शन एक पूरी तरह से सुधार योग्य त्रुटि नहीं है।
- **语义层面的不当行为。**प्रत्येक एकल क्रिया सुरक्षित प्रतीत होती है, लेकिन संयोजन उत्पन्न होने की प्रवृत्ति हानिकारक है।
- **通过合法渠道 exfiltration。**अपने पास के दस्तावेजों में डेटा लिखें, और फिर `git push`सार्वजनिक रेपो में, एक श्रृंखला अनुमति है, लेकिन समस्या उनके संयोजन में है।

### अनुसंधान पूर्वावलोकन 定位

मानव विज्ञान  ऑटो मोड  अनुसंधान पूर्वावलोकन 发布──文档明确说明, वर्गीकरणकर्ता एक स्तर सुरक्षा है, पूर्ण समाधान नहींः उपयोगकर्ता को ऑटो मोड को बजट, Allowists, अलग कार्यक्षेत्रों और ट्रैकरी ऑडिटों के साथ करना चाहिए।

## 关键术语

| 术语 | 人们常说 | 实际含义 |
|---|---|---|
| 权限模式 | “agent 能做多少事” | 控制逐动作批准的六种命名 policy 之一 |
| plan mode | “做任何事前都询问” | Agent 编写计划；用户在执行前批准 |
| acceptEdits | “让它写文件” | 文件写入自动批准；shell exec 仍然提示 |
| auto | “Auto approvals” | 独立的 classifier model 审阅每个动作；阻止超出请求范围的升级 |
| bypassPermissions | “Full YOLO” | 批准一切；预期用于 ephemeral containers |
| Stage 1（simulator） | “Fast keyword check” | `code/main.py` 中针对拟议动作的廉价 rule |
| Stage 2（simulator） | “Deep review” | `code/main.py` 中针对被标记动作的更慢 multi-rule reviewer |
| Research preview | “Not GA” | Anthropic 对 failure mode 仍在被映射的功能所使用的定位 |
