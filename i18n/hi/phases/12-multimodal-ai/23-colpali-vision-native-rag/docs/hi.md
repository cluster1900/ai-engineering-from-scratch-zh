## 问题

पीडीएफ पर पाठ-आरएजी दस्तावेजों की अधिकांश जानकारी खो जाएगी। वित्तीय रिपोर्ट की तिमाही में राजस्व वृद्धि आमतौर पर चार्ट में होती है। मेडिकल रिपोर्ट के निष्कर्षों में नोट की गई छवियों में। कानूनी अनुबंध के हस्ताक्षर ब्लॉक लेआउट तथ्य हैं, पाठ तथ्य नहीं हैं।

पाठ-आरएजी पाइपलाइनः

1. ओसीआर / पीडीएफ पाठ के माध्यम से पाठ
2. पाठ → 300-500 टोकन टुकड़े
3. Chunk → द्वि-संकेतक सम्मिलित करना(एक वेक्टर)。
4. उपयोगकर्ता क्वेरी → एम्बेडिंग → कॉसिन समानता → शीर्ष-क टुकड़े。
5. चुंक + क्वेरी → LLM。

五个有损步骤── चार्ट 捕获不到── सारणी 被块 打断──बहु स्तंभ लेआउट 被展平──आंकड़े के नोट्स 消失──

ColPali का修复方式:跳过 OCR, सीधे पृष्ठ छवि पर करें एम्बेडिंग── ColBERT शैली देर से बातचीत का उपयोग करें, रिट्रीवल करें, मॉडल को क्वेरी समय में 关注细粒度 patches──

## 概念

### कोल्बर्ट (2020)

ColBERT(Khattab & Zaharia, arXiv:2004.12832) एक पाठ पुनर्प्राप्ति विधि है। यह प्रत्येक दस्तावेज़ के लिए एक वेक्टर नहीं बनता है, बल्कि प्रत्येक टोकन के लिए एक वेक्टर बनता है।

- क्वेरी टोकन  प्राप्त अपने आप के एम्बेडिंग्स(N_q वेक्टर)
- दस्तावेज़ टोकन  प्राप्त एम्बेडिंग्स(N_d वेक्टर, आमतौर पर कैश)
- स्कोर = क्वेरी टोकन के लिए 求和, प्रत्येक क्वेरी टोकन 取所有文档 टोकन 中 cosine similarity 的最大值:Σ_i max_j cos(q_i, d_j) 』

यह मैक्ससिम ऑपरेशन है। प्रत्येक क्वेरी टोकन में सबसे उपयुक्त दस्तावेज़ टोकन का चयन किया जाता है। अंतिम स्कोर इन मानों का योग है।

优点:recall 强,能处理 टर्म-स्तर के अर्थशास्त्र――缺点: प्रत्येक दस्तावेज़ 需要 N_d वेक्टर, भंडारण 昂贵――

### कोलपाली

ColPali(Faysse et al., arXiv:2407.01449) को ColBERT पैटर्न  को चित्रों पर लागू करेगा

- प्रत्येक पृष्ठ PaliGemma द्वारा (ViT + भाषा)编码为补丁嵌入:每页 N_p वेक्टर──
- प्रत्येक उपयोगकर्ता क्वेरी (उपयोगकर्ता क्वेरी) को क्वेरी-टोकन एम्बेडमेंट्स के लिए कोडित किया गया हैः
- स्कोर = Σ_i max_j cos(q_i, p_j),也就是在查询文字- टोकन 和 पृष्ठ-छवि-पटच 上做MaxSim。
- 通过 कुल स्कोर रिट्रीवल शीर्ष-के पृष्ठों

दस्तावेज़-इंग्ज़ेशन समय: उपयोग करें PaliGemma के लिए प्रत्येक पृष्ठ पर एम्बेडिंग, भंडारण सभी पैच एम्बेडिंगों हेतु──

优点: दृश्य रूप से समृद्ध दस्तावेजों में ऊपर, अंत-से-अंत से पाठ-RAG उच्च 20-40%── प्रत्येक पैच-वेक्टर 捕获局部布局和内容──

缺点: प्रति पृष्ठ N_p पैच × 4-बाइट फ्लोट × D-dim वेक्टर = भंडारण 增长很快──可通过 PQ / OPQ क्वांटिज़ेशन 缓解──

### कोलक्वीन2 तथा कोलस्मोल

ColQwen2 (इललुइन-टेक, 2024-2025) PaliGemma को Qwen2-VL के लिए प्रतिस्थापित करेगा।

ColSmol स्थानीय / किनारे उपयोग के लिए एक छोटे पैमाने पर संस्करण है।

### विसराग

VisRAG(Yu et al., arXiv:2410.10594) एक और प्रकार का संस्करण हैः पैचों में नहीं ऊपर MaxSim करने के लिए, बल्कि VLM का उपयोग करके प्रत्येक पृष्ठ पूल को एक वेक्टर में बदल देगा, फिर द्वि-संकेतक प्राप्त करना होगा।

गुणवत्ता-मूल्य-बदला-बदलाः गुणवत्ता को प्राथमिकता ColPali, आकार को प्राथमिकता VisRAG

### एम३डोक्राग

M3DocRAG(Cho et al., arXiv:2411.04952) बहु-मॉडल रिट्रीवल  विस्तार से बहु-पृष्ठ बहु-दस्तावेज तर्क में होगा── यह दस्तावेजों के रिट्रीवल पृष्ठों के पार है,并为 VLM 组合 बहु-पृष्ठ संदर्भ──

### ViDoRe  बेंचमार्क

ColPali का साथी बेंचमार्क── दृश्य दस्तावेज पुनर्प्राप्ति मूल्यांकन──कार्य वित्तीय रिपोर्ट, वैज्ञानिक पत्र, प्रशासनिक दस्तावेज, चिकित्सा रिकॉर्ड, पुस्तिकाएँ──मेट्रिकःnDCG@5── शामिल हैं।

ColPali-v1 में ViDoRe ऊपर लगभग 80% nDCG@5; उसी बैच दस्तावेजों ऊपर पाठ-RAG ऊपर लगभग 50-60% है।

### अंत-से-अंत RAG पाइपलाइन

दृष्टि-निवासी आरएजी के लिएः

1. 摄取:पीडीएफ → 页面图像 → पालीगेमा एन्कोडिंग → 存储所有补丁嵌入式──
2. 查询:用户文本 → क्वेरी-टोकन एम्बेडिंग → सभी पहले से ही अनुक्रमित पृष्ठों पर MaxSim → शीर्ष-के 页面──
3. 生成:top-k 页面图像 + query → VLM(Qwen2.5-VL या क्लाउड)→ 答案。

全程没有OCR──图形,图表,字体,布局 全部流入答案──

### भंडारण गणित

एक 50-पृष्ठीय वित्तीय रिपोर्ट, प्रति पृष्ठ 729 पैच,128-आयामी एम्बेडिंग्सः

- ColPali:50 * 729 * 128 * 4 बाइट = ~18 MB कच्चे,PQ 后 ~4 MB。
- पाठ-RAG:50 टुकड़े * 768-dim * 4 बाइट = ~150 kB──

ColPali प्रत्येक दस्तावेज़ का भंडारण  30x से अधिक है  आकार के परिदृश्य में, ओपीक्यू/पीक्यू को 5-10x तक कम किया जा सकता है, आमतौर पर स्वीकार्य है

### पाठ-RAG 仍然胜出的场景

- 没有布局信号的纯文本文档(wiki लेख、聊天日志) ――文字-RAG 更简单,存储 更便宜──
- 存储主导成本 के बहु-मिलियन पृष्ठों के अभिलेखागार
- 严格监管要求在检索 旁边保留取取OCR पाठ──

 2026 के अन्य परिदृश्यों के लिए, अर्थात् वित्तीय रिपोर्ट, वैज्ञानिक पत्र, कानूनी अनुबंध, चिकित्सा रिकॉर्ड, यूएक्स दस्तावेज, दृष्टि-देशी आरएजी 胜出──

## 关键术语

| Term | 人们常说 | 它的实际含义 |
|------|-----------------|------------------------|
| Late interaction | "ColBERT-style" | 使用 per-token 或 per-patch embeddings + MaxSim 做 retrieval，而不是 single doc Vector |
| MaxSim | "Max-over-patches" | 对每个 query token，选择 similarity 最高的 document token；跨 query 求和 |
| Bi-encoder | "Single-vector" | 每个 document 一个 Vector；更快，但会丢失粒度 |
| Multi-vector | "Many-vectors-per-doc" | 每个 document / page 存储 N_p Vectors；storage cost 增长，但 recall 提升 |
| Patch embedding | "Page feature" | 来自 VLM encoder 的每个 image patch 的一个 Vector，按页 cached |
| ViDoRe | "Vision doc bench" | ColPali 用于 visual document retrieval 的 benchmark suite |
| PQ quantization | "Product quantization" | 在缩小 storage 约 8x 的同时保持 Vector similarity 的压缩方法 |
