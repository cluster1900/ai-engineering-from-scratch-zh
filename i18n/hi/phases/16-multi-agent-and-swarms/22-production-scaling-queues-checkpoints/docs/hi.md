## 概念

### टिकाऊ निष्पादन, इस मॉडल

टिकाऊ-कार्यकारी इंजन 会在每一个"步骤" (LangGraph 术语中的超级步骤) के बाद持久化完整程序状态──崩时:

```
worker crashes mid-step
  -> lease timeout
  -> another worker picks up the thread_id
  -> resumes from last checkpoint
  -> no duplicate side effects
```

इसे काम करने के लिए, यह पूरा करने की आवश्यकता हैः

- **Serializable state。**सभी एजेंट राज्य सभी को स्थायी होना चाहिए।
- **Deterministic resume。** एक ही स्थिति और एक ही इनपुट दिए जाने पर, एजेंट एक ही क्रिया उत्पन्न करेगा  या एलएलएम कॉल  बाहरी निर्धारक ओरेकल को सौंप देगा) 
- **Idempotent side effects。**बाहरी कॉल (आउटपुट कॉल, भुगतान) अपरिहार्य होना चाहिए, या डिडप्लिकेशन कुंजी का उपयोग करना चाहिए।

LangGraph 在每一个超级步骤后写检查点;Temporal 在每一个活动后写;Restate 使用事件来源的期刊──三者实现的是同一个模式──

### LangGraph का रनटाइम

हर एजेंट के पास एक है`thread_id`;state is typed dict; प्रत्येक सुपर-स्टेप सभी चेकपॉइंट तालिका 写入一行──恢复时, रनटाइम अंतिम चेकपॉइंट से 继续, बजाय 头开始── एजेंटों को `interrupt()`आवेदक के लिए प्रतीक्षा करें; रनटाइम में कर्मचारी को स्थायी रूप से जारी किया जाएगा।

यह 2026 के अप्रैल के संदर्भ उत्पादन डिजाइन है।

### MegaAgent की प्रति एजेंट कतार

arXiv:2408.09955  एक पैमाने पर प्रयोग का वर्णन करेंः एक क्लस्टर के बीच हजारों并发 एजेंट हैं।

```
agent i:
  state ∈ {Idle, Processing, Response}
  in_queue   <- messages addressed to agent i
  out_queue  -> replies + side effects

coordinators:
  intra-group chat  (agents in the same group)
  inter-group admin chat  (high-level routing)
```

दो स्तरों के समन्वय से समूह में बातचीत की उच्च घनत्व होती है, जबकि समूह के बीच दुर्लभता बनी रहती है। यह हजारों एजेंटों के बीच लागत-रेखीय ढांचा बनाए रखता है।

### कार्य के प्रति धागा बनाम समक्रमण

LLM कॉल I/O-bound हैं। अगले टोकन के थ्रेड का इंतजार 99% समय का समय है। प्रत्येक थ्रेड में लगभग 1MB रैम का उपयोग होता है। 10,000 में, प्रकाश स्टैक 10GB की आवश्यकता होती है।

फाइबर (पाइटन)`asyncio`、गूरूटीन 、रस्ट `tokio`) I/O में ऊपर सहयोग करने के लिए एक प्रक्रिया में आसानी से 10,000 कॉल डाल दिया जा सकता है।

उदाहरण:CPU-bound पोस्ट-प्रोसेसिंग (इम्बेडिंग, टोकनराइज़र) अभी भी थ्रेड या प्रक्रियाओं की आवश्यकता है।

### एक बार के लिए सही अर्थशास्त्र

👉 भुगतान एजेंट के लिए, आपको "एक बार प्रभावी" की आवश्यकता होती है

- **每个 run 一个 dedup key。**प्रत्येक साइड इफेक्ट कॉल में शामिल है
- **Outbox pattern。**दुष्प्रभाव पहले एक तालिका में लिखे, फिर स्वतंत्र प्रक्रिया द्वारा निष्पादित किये गये।
- **Compensating transactions。**जब दुष्प्रभाव सफल लेकिन ट्रैकिंग लिखें 失败时, व्यवस्था क्षतिपूर्ति ऑपरेशन

ये डाटाबेस इंजीनियरिंग पैटर्न हैं, LLM-विशिष्ट नहीं हैं। LLM कर केवल LLM कॉल पर निर्भर करता है।

## 关键术语

| Term | 人们的说法 | 它实际的含义 |
|------|----------------|------------------------|
| Durable execution | "Persist the program state" | Engine 在每个 super-step 后写入 state；crash recovery 是 deterministic 的。 |
| Super-step | "Transactional boundary" | Checkpoints 之间的 work unit。LangGraph 术语。 |
| thread_id | "Agent run identifier" | 绑定 checkpoints 和 resume logic 的 key。 |
| Idempotency | "Safe to retry" | 重复一个 side effect 产生的结果与一次尝试相同。 |
| Outbox pattern | "Decouple side effects" | 将 intent 写入 table；独立 executor 执行并标记完成。 |
| At-least-once delivery | "Possible duplicates" | Message queue semantics；dedup key 让 consumer 达到 effective-once。 |
| Rainbow deploy | "Overlapping versions" | 长时间运行 workloads 期间多个 runtime versions 并发存在。 |
| Async fiber | "Cooperative yielding" | User-mode concurrency；对于 I/O-bound loads，相比 threads 成本很低。 |
| Checkpoint | "State snapshot" | super-step 边界处的 serialized state；是 resume 的 key。 |
