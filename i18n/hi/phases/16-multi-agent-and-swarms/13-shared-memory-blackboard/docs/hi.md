# साझा स्मृति तथा ब्लैकबोर्ड 模式

> 2026 के मल्टी-एजेंट सिस्टम में दो तरह के तरीके मौजूद हैंः**message pool**(सभी लोग सभी के संदेश देख सकते हैं, जैसे ऑटोजेन ग्रुपचैट या मेटाजीपीटी) और**带 subscription 的 blackboard**(एजेंट 订阅相关事件, जैसे Context-Aware MCP या मैट्रिक्स फ्रेमवर्क)  दोनों ही मल्टी-एजेंट 系统 में एकमात्र स्थिति वाला हिस्सा हैं  इसका मतलब है कि दिलचस्प बग भी इसमें छिपा है **memory poisoning**एक एजेंट 幻觉出一个事实, अन्य एजेंट इसे सत्यापित सामग्री के रूप में रखें, सटीकता धीरे-धीरे घटती है, और यह घटना तत्काल क्रैश से अधिक कठिन है डिबग करना।

## 概念

### 两种主要拓

**Full message pool。**प्रत्येक एजेंट 读取每条消息──AutoGen GroupChat 和 MetaGPT इस प्रकार उपयोग करते हैं── सरल, पारदर्शी, जाँच योग्य, लेकिन लगभग 10 एजेंटों तक विस्तार नहीं कर सकते, क्योंकि प्रत्येक एजेंट के ऊपर नीचे प्रत्येक एजेंट के काम से भरा होता है।

```
agent-A ──write──▶ ┌────────────────┐ ◀──read── agent-D
                   │ message pool   │
agent-B ──write──▶ │                │ ◀──read── agent-E
                   │ (global log)   │
agent-C ──write──▶ └────────────────┘ ◀──read── agent-F
```

**带 subscription 的 Blackboard。**एजेंट 声明自己感兴趣的主题;底层基板 只路由相关消息──CA-MCP(arXiv:2601.11595) और मैट्रिक्स विकेन्द्रीकृत ढांचे(arXiv:2511.21686) इस तरह का उपयोग करते हैं──扩展性更强, लेकिन सदस्यता लेने के लिए पूर्व-डिज़ाइन योजना की आवश्यकता होती है।

```
                   ┌─ topic: prices ──┐
agent-A ──pub────▶ │                  │ ──▶ agent-D (subscribed)
                   ├─ topic: orders ──┤
agent-B ──pub────▶ │                  │ ──▶ agent-E (subscribed)
                   ├─ topic: alerts ──┤
agent-C ──pub────▶ │                  │ ──▶ agent-F (subscribed)
                   └──────────────────┘
```

### ब्लैकबोर्ड 先例 (Hayes-Roth, 1985)

ब्लैकबोर्ड 模式比LLM एजेंट्स早已四十年──Hayes-Roth(1985,A Blackboard Architecture for Control) विशेषज्ञ ज्ञान स्रोतों का वर्णन करते हैंः वे एक समग्र ब्लैकबोर्ड देखते हैं, आंशिक समाधानों का योगदान देते हैं,并触发其他 स्रोतों──2026 साल का ब्लैकबोर्ड(CA-MCP、矩阵) एक ही मॉडल है, केवल एलएलएम एजेंटों के साथ ज्ञान स्रोतों के रूप में, JSON ब्लॉब्स के साथ  جزय समाधानों के रूप में। पुरानी साहित्य ने लेखन के विवादों को रिकॉर्ड किया है, अवसरवादी नियंत्रण और सुसंगतता के समाधान, जबकि आधुनिक प्रणाली उन्हें फिर से खोज रही है──

### लेखन-सामग्री 模式

कई एजेंट एक समकालीन  समस्या, न केवल LLM  समस्या 

- **Sequential writer（single producer）。**सभी लेखन एक समन्वयक एजेंट के माध्यम से होते हैं 串行化──简单,但会成为瓶──
- **带 versioning 的 optimistic concurrency。**प्रत्येक प्रविष्टि का संस्करण होता है; लेखक संस्करण में असंगतता 失败并重试──经典数据库技术──
- **Topic partitioning。**अलग एजेंट 拥有不同主题──没有跨主题争议──需要设计好的分区界限──

##  इसे निर्माण

`code/main.py`स्ट्डलिब पायथन के साथ दो प्रकार के विषाक्तता के साथ-साथ एक खिलौना विषाक्तता हमले और तीन राहत उपायों को पूरा किया गया।

- `MessagePool` 线程安全的附录-मात्र लॉग, समर्थन पूर्ण读出──
- `Blackboard`  विषय के आधार पर कीड की गई pub/sub, support per-agent subscriptions──
- `ProvenanceEntry` प्रत्येक बार लिखना दर्ज करना (लेखक, समय टिकट, त्वरित हैश, स्रोत)
- `PoisoningScenario` 运行一个三 经纪人研究任务, जिनमें से एजेंट ए 幻觉出小数点――印印最终报告――
- `Verifier` एक केवल-पढ़ने वाला एजेंट, स्रोतों को पुनः प्राप्त करेगा और वेरिफायर के अस्तित्व में एक ही परिदृश्य को चलाएगा।

## 关键术语

| Term | 人们怎么说 | 它实际意味着什么 |
|------|----------------|------------------------|
| Message pool | “Shared chat history” | 每个 Agent 都会读取的 append-only log。完全透明，但扩展性差。 |
| Blackboard | “Shared workspace” | 按 topic keyed 的 pub/sub。Agent 订阅相关 topics。扩展更远。 |
| Provenance | “谁写了什么” | 每次写入的 metadata：writer、timestamp、prompt、sources。 |
| Memory poisoning | “幻觉在扩散” | 一个 Agent 的错误进入共享状态，下游 Agent 将其当作事实。 |
| Append-only | “没有原地更新” | Corrections 是用来 supersede 的新 entries。保留 audit trail。 |
| Unwritable verifier | “Independent auditor” | read-only Agent，会重新获取 sources 并标记不一致。 |
| Projection | “Scoped view” | 从 global state 计算出的 per-agent view。LangGraph reducers 是规范案例。 |
| Knowledge Source | “Specialist agent” | Hayes-Roth 在 1985 年对 blackboard participant 的称呼。 |
