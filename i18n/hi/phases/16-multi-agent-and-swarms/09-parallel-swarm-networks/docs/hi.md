# समानांतर / झुंड / नेटवर्क आर्किटेक्चर

> पर्यवेक्षक के मुकाबले: कोई केंद्रीय निर्णयकर्ता नहीं है। एजेंट 读取共享事件bus,异步领取工作,并写回结果. लांगग्राफ 明确支持面向去中心化、动态环境的"Swarm Architecture"――मातृकृति (arXiv:2511.21686) 将控制流和数据流都表示通过分布式队列传递的序列化消息,以消除乐队员 瓶──权衡很明确:确定性和可追溯性 换可扩展性──Swarm 适合包含许多独立子任务;不适合需要单连贯计划的任务──

**Type:** Learn + Build
**Languages:** Python (stdlib, `threading`, `queue`)
**前置要求：**चरण 16 · 05 (पर्यवेक्षक पैटर्न), चरण 16 · 04 (प्राथमिक मॉडल)
**Time:** ~75 minutes

## 问题
पर्यवेक्षक स्वयं बन जाएगा बोतलः जो कोई भी निर्णय लेता है, उसे एक एजेंट द्वारा पारित किया जाना चाहिए। एक धीमी योजना चरण पूरे सिस्टम को खींच लेगा।

स्वार्म आर्किटेक्चर इस डिजाइन को उलट बदल दिया है। यह केंद्रीय योजनाकार द्वारा नहीं, बल्कि श्रमिकों द्वारा साझा कतार में प्राप्त कार्य है।

## 概念
### आकार

```
                ┌──── shared queue ────┐
                │                      │
       ┌────────┼────────┐  ◄──────┬───┘
       ▼        ▼        ▼         │
     Worker  Worker  Worker   Worker
      A       B       C        D
       │        │        │         │
       └────────┴────────┴─────────┘
                 │
                 ▼
            results pool
```

没有管家──每一个工人 反复执行:拉取一个任务,处理,写入结果(并可选地排列后续)──

### जब झुंड मिल जाता है

- **许多独立 tasks。**स्क्रैपिंग, ट्रांसफॉर्मेशन, वर्गीकरण, कार्य एक दूसरे पर निर्भर नहीं करते हैं।
- **可变时长的工作。**यदि कुछ कार्यों को 100ms की आवश्यकता होती है, जबकि अन्य को 10ms की आवश्यकता होती है, तो झुंड स्वचालित रूप से भार संतुलन करेगा।
- **Throughput 优先于 determinism。**आप पर ध्यान है पूर्ण पूरा समय, न कि सख्त आदेशों.

### जब झुंड विफल हो जाता है

- **有序 workflows。**यदि चरण 3 需要步骤 2 的输出,swarm可能让步骤 3 在步骤 2 完成前触发──
- **Global-plan tasks。**复杂 अनुसंधान प्रश्न 受益于规划者── एक शोधकर्ता झुंड 会产出独立事实,而不是连贯报告──
- **Debugging。**没有中央日志 且工作 异步时,复现错误 成本很高──

### मैट्रिक्स (arXiv:2511.21686)

मैट्रिक्स 2025 का एक पेपर है, यह एक झुंड होगा  प्राकृतिक निष्कर्षः नियंत्रण प्रवाह और डेटा प्रवाह सभी वितरित कतारों में हैं ऊपर क्रमबद्ध संदेशों में।

贡献: एक प्रोग्रामिंग मॉडल, जिसमें मल्टी-एजेंट समन्वय है  यह एजेंट 订阅哪个信息主题?, बजाय 监督者 下一步选择哪个代理? यह प्रणाली एक पब / उप घटना जाल की तरह दिखने दें

## 交付 यह
चेकलिस्टः

- **带 aging 的 Priority queue。** दीर्घकालिक भूख से बचें。
- **Worker idempotency。**यदि मध्यकाल में एक कार्यकारी घट जाता है, तो एक कार्य को कई बार संचालित किया जा सकता है।
- **Durable queue。**生产环境使用 काफका、रेडिस स्ट्रीम या डेटाबेस समर्थित कतार`queue.Queue` केवल内存 में
- **每个 task 的 observability。**प्रत्येक कार्य में पहचान पत्र होता है; प्रत्येक कार्यकर्ता इसके साथ शुरू/अंत रिकॉर्ड करता है।
- **Back-pressure。**यदि कतार में तेजी से वृद्धि होती है तो श्रमिकों की गति घट जाती है, तो उत्पादक धीमा हो जाता है।

## 关键术语
| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Swarm architecture | "Decentralized agents" | Workers 从 shared queue 中拉取；没有 central orchestrator。 |
| Event bus | "Agents subscribe to topics" | 按 type 或 content 将 tasks 路由给 workers 的 message broker。 |
| Starvation | "Task never runs" | 因为 higher-priority work 持续到达，low-priority task 永远不会被选中。 |
| Hot-spotting | "One worker drowns" | 一个 worker 获得大多数 tasks 的 load imbalance。 |
| Back-pressure | "Slow down the producer" | 当 queue 填满时，向 upstream 发出停止生产信号的 mechanism。 |
| Idempotent worker | "Safe to re-run" | 一个 task 被处理两次会产生相同 result。因为 workers 可能在 mid-run 崩溃，所以这是必需的。 |
| Durable queue | "Survives crashes" | 由 disk 或 replicated storage 支持的 queue；worker 崩溃时 tasks 不会丢失。 |
| Matrix framework | "Full message-passing swarm" | Data 和 control flow 都是在 distributed queues 上的 serialized messages。 |
