## 问题

2026 के एजेंट-प्रोटोकॉल के क्षेत्र में बहुत भीड़ हैः उपकरण के लिए एमसीपी, एजेंटों के लिए ए2ए, उद्यम लेखा परीक्षा के लिए एसीपी, एएनपी के लिए विकेंद्रीकृत विश्वास, प्राकृतिक भाषा सामग्री के लिए एनएलआईपी, फिर से सीए-एमसीपी और बीस से अधिक शोध प्रस्तावों के लिए। प्रत्येक विनिर्देश खुद को आधारभूत घोषित करते हैं।

诚实地看, उनमें से अधिकांश एक बहुत ही विशिष्ट 已有二十年历史的决策树──奥斯丁(1962) और सीरल(1969) के भाषण-क्रिया सिद्धांत  हमें प्रदर्शन हैं क्रिया──KQML(1993) इसे वायर प्रोटोकॉल में बदल दिया──FIPA-ACL(2000 साल की मंजूरी) ने संदर्भ स्तरीय मानकीकरण दियाः बीस प्रदर्शन भाषाएँ SL0/SL1, साथ ही अनुबंध-नेट और सदस्यता-विज्ञापन के लिए बातचीत प्रोटोकॉल──JADE 和 JACK है जावा 参考 मंच── यह प्रयास 2010 के बाद में हल्का हुआ, क्योंकि ontology 开销太重, जबकि वेब वर्चस्व जीत रहा है।

जब आप MCP के देखते हैं `tools/call`、A2A के कार्य जीवन चक्र, या CA-MCP के साझा संदर्भ स्टोर ⇒, आप FIPA  निर्णय की एक प्रकार की अधिक लचीली 、JSON-देशी की पुनरावृत्ति देखते हैं। इस अनुच्छेद को समझने से आपको दो चीजें पता चलेंगीः कौन सी नई  नवाचार  वास्तव में फिर से विकसित किया गया है, और नए विनिर्देश जो फिर से पता लगाएंगे कि कौन से पुराने विफलता मोड 

## 概念

### 用一段话理解 भाषण कार्य

ऑस्टिन ने ध्यान दिया कि कुछ वाक्य दुनिया का वर्णन नहीं करते हैं, बल्कि दुनिया को बदलते हैं। मैं वादा करता हूं।   मैं अनुरोध करता हूं।  मैं घोषणा करता हूं। उन्होंने इन्हें प्रदर्शनकारी बयानों कहा।

### 十个 FIPA प्रदर्शनियाँ (भाग सूची)

| Performative | Intent |
|---|---|
| `inform` | “我告诉你 P 为真” |
| `request` | “我请求你执行 X” |
| `query-if` | “P 是否为真？” |
| `query-ref` | “X 的值是什么？” |
| `propose` | “我提议我们执行 X” |
| `accept-proposal` | “我接受该 proposal” |
| `reject-proposal` | “我拒绝该 proposal” |
| `agree` | “我同意执行 X” |
| `refuse` | “我拒绝执行 X” |
| `confirm` | “我确认 P 为真” |
| `disconfirm` | “我否认 P” |
| `not-understood` | “你的 message 无法 parse” |
| `cfp` | “针对 X 发出 proposals 征集” |
| `subscribe` | “当 X 变化时通知我” |
| `cancel` | “取消正在进行的 X” |
| `failure` | “我尝试了 X，但失败了” |

完整列表在 `fipa00037.pdf`(FIPA ACL Message Structure) 中──重点 इसे याद रखना नहीं है, बल्कि इन सामग्री में से प्रत्येक, सभी LLM प्रोटोकॉल के अनुरूप है, अंततः एक आदिम को पुनः जोड़ा जाएगा──

### 规范的 FIPA-ACL संदेश

```
(inform
  :sender       agent1@platform
  :receiver     agent2@platform
  :content      "((price IBM 83))"
  :language     SL0
  :ontology     finance
  :protocol     fipa-request
  :conversation-id   conv-42
  :reply-with   msg-17
)
```

七个字段承载 प्रोटोकॉल लिफाफा; एक字段(`content`) उपयोगिता लोड लोड करें। शेष अंश सही है कि आप प्रत्येक बार JSON प्रोटोकॉल के साथ पुनः प्रयासों, थ्रेडिंग और ontology के साथ पुनः आविष्कार करेंगे।

### FIPA क्यों बाहर

- **Ontology 开销。**FIPA 要求使用共享 ontology 来 parse `content`
- **没人使用的 formal semantics。**एसएल (Semantic Language) ने सख्त सत्य शर्तें प्रदान की हैं, लेकिन अधिकांश उत्पादन प्रणाली मुक्त रूप सामग्री का उपयोग करती हैं, औपचारिकता को अनदेखा करती हैं।
- **Tooling lock-in。**जेएडीई केवल जावा का समर्थन करता है; जैक वाणिज्यिक उत्पाद है। बहुभाषी टीमों ने इन दोनों को पार कर लिया है।
- **internet 赢下了 stack。**REST, फिर JSON-RPC, फिर बाद में gRPC, ACL के परिवहन को बदल दिया।

### सीधा-सादा विवरण

**FIPA 给了你、而现代 specs 放弃的东西：**

- औपचारिक अर्थशास्त्रः आप साबित कर सकते हैं `inform`मतलब प्रेषक 相信内容──
- एक नियम के प्रदर्शनियों का एक उदाहरणः आप फिर से बहस करने की जरूरत नहीं है हम एक होना चाहिए या नहीं`cancel`?
- कई दशकों के इंटरैक्शन-प्रोटोकॉल पैटर्नःकॉन्ट्रैक्ट-नेट,सब्सक्राइब-नोटीफिकेशन,प्रस्ताव-स्वीकार, तथा ज्ञात सटीकता गुणों के साथ।

**现代 specs 给了你、而 FIPA 没有的东西：**

- सभी आधुनिक उपकरण और JSON-निवासी उपयोगिता लोड के साथ संगत
- LLM 无需手编码的ontology 即可解释的自然语言内容──
- वेब-स्टैक परिवहन(HTTP、SSE、WebSocket)
- 通过实时的MCP `server/discover`ए2ए एजेंट कार्ड के साथ  क्षमता का पता लगाने

अधिक लचीला इरादा अर्थशास्त्र, अधिक आसान कार्यान्वयन के लिए परिवर्तन।

### परित्याग करने योग्य इंटरैक्शन प्रोटोकॉल

FIPA या साथ लगभग 15 इंटरैक्शन प्रोटोकॉल  हैं जिनमें से तीन LLM मल्टी-एजेंट सिस्टम में शामिल हैंः

1. **Contract Net Protocol (CNP)。**प्रबंधक 发出 `cfp`(प्रस्तावों के लिए आह्वान); बोली लगाने वाले उपयोग `propose`响应;manager 接受/拒绝──这是规范的任务市场模式(चरण 16 · 16 वार्ता)
2. **Subscribe/Notify。**ग्राहक 发送 `subscribe`; प्रकाशक 变化时发送 `inform` यही 2026 के हर इवेंट-बस है
3. **Request-When。**当条件 Y 成立时执行 X──带预条件的延迟行动──2026 साल का एनालॉग है टिकाऊ वर्कफ़्लो इंजनों के बीच के स्थगित कार्य ((Phase 16 · 22 उत्पादन स्केलिंग) ⋅

प्रत्येक एक स्पष्ट रूप से आधुनिक संदेश कतारों में प्रदर्शित किया जा सकता है, या एचटीटीपी + मतदान, या एसएसई स्ट्रीमिंग।

###  त्याग Ontology  के बाद क्या समस्या होगी

 बिना साझा ओंटोलॉजी, एजेंट्स प्राकृतिक भाषा सामग्री से बैठक 推断含义──2026 साल के साथ दस्तावेज रिकॉर्ड के विफलता मोड **semantic drift**: दो एजेंटों एक ही शब्द के साथ`"customer"`) का अर्थ है कि कुछ अलग अवधारणाएं हैं, प्राप्तकर्ता के एजेंट ने गलत व्याख्या के अनुसार कार्रवाई की है, जबकि कोई स्कीम सत्यापनकर्ता इसे पकड़ सकता है।

路线的缓解措施:

- `content`上的 JSON योजना: में तार 层拒绝结构错误──
- प्रकार के कलाकृतियाँ ((A2A): अस्वीकार त्रुटि का तरीका
- संक्षिप्त में स्पष्ट रूप से प्रदर्शनात्मकः भले ही सामग्री प्राकृतिक भाषा हो, भी कर सकता है अभिप्राय 明确无歧义──

### 2026 स्पेसिफिकेशन्स 映射到 भाषण-क्रिया विरासत

| Modern spec | FIPA analog | What it keeps | What it drops |
|---|---|---|---|
| MCP `tools/call` | `request` | explicit intent、correlation id | formal semantics、ontology |
| MCP `resources/read` | `query-ref` | explicit intent、correlation id | formal semantics |
| A2A Task lifecycle | contract-net + request-when | async lifecycle、state transitions | formal completeness guarantees |
| A2A streaming events | subscribe/notify | async push | typed-predicate subscription |
| CA-MCP shared context | blackboard（Hayes-Roth 1985） | multi-writer shared memory | logical consistency model |
| NLIP | natural-language content | LLM-native | schema |

इस आलेख को ऊपर से नीचे तक पढ़ना, मॉडल हैः संरचनात्मक आदिमता को बनाए रखना, औपचारिकता को त्यागना, LLM को भेदभाव को छिपाकर रखना।

##  इसे निर्माण

## 关键术语
| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Speech act | “一种会做事的 utterance” | Austin/Searle：把 utterances 视为 actions。ACL 的理论源头。 |
| FIPA | “那个老 XML 东西” | IEEE Foundation for Intelligent Physical Agents。2000 年标准化了 ACL。 |
| ACL | “Agent Communication Language” | FIPA 的 envelope format：performative + content + metadata。 |
| Performative | “那个动词” | 一条 message 的 intent class：`inform`、`request`、`propose`、`cfp` 等。 |
| KQML | “FIPA 的前身” | Knowledge Query and Manipulation Language（1993）。更简单，范围更窄。 |
| Ontology | “共享词汇表” | 对 content language 所谈论概念的 formal definition。 |
| SL0 / SL1 | “FIPA content languages” | Semantic Language levels 0 and 1，即 formal content language family。 |
| Contract Net | “Task market” | Manager 发出 cfp；bidders propose；manager accepts。规范的 interaction protocol。 |
| Interaction protocol | “Messages 的模式” | 一组具有已知 correctness 的 performatives 序列：request-when、subscribe-notify 等。 |
