# ऑटोजेन v0.4:एक्टर मॉडल और एजेंट फ्रेमवर्क

> ऑटोजेन v0.4 (Microsoft Research, 2025 साल जनवरी) अभिनेता मॉडल के आसपास 重新设计了代理配套── असिनक संदेश विनिमय、घटना-चालित एजेंट、दोष पृथक्करण、自然并发── यह ढांचा अब रखरखाव मोड में है, जबकि Microsoft एजेंट ढांचा (Microsoft Agent Framework, 2025 साल अक्टूबर सार्वजनिक पूर्वावलोकन) इसके उत्तराधिकारी बन रहा है──

**类型：**学习 + 构建
**语言：**पायथन (stdlib)
**先修：**चरण 14 · 01 (एजेंट लूप), चरण 14 · 12 (वर्कफ्लो पैटर्न)
**时间：** 75 मिनट

- 描述 अभिनेता मॉडल:एजेंट 作为 अभिनेता, संदेश 唯一的IPC, प्रत्येक अभिनेता 独立隔离故障──
- AutoGen v0.4 के तीन एपीआई स्तरों को बताएंः कोर, एजेंटचैट, एक्सटेंशन, तथा उनके उपयोगों के साथ-साथ
- 解释为什么将消息传递与处理 解会带来故障隔离 和自然并发──
- Python में एक stdlib अभिनेता रनटाइम को लागू करने के लिए,并将一个双代理代码-पुनरावलोकन प्रवाह 移植到其上

अधिकांश एजेंट ढांचे होते हैं एक साथः एक एजेंट  उत्पन्न सामग्री, एक एजेंट  खपत सामग्री, एक कॉल स्टैक में काम करते हैं।

ऑटोजेन v0.4 का उत्तर हैः अभिनेता मॉडल। प्रत्येक एजेंट एक निजी इनबॉक्स वाला अभिनेता है। संदेश एकमात्र संचार विधि है। रनटाइम वितरण और संभाल के लिए है।

## 概念

### अभिनेता

एक अभिनेता 拥有:

- निजी राज्य (बाहरी कभी सीधे संपर्क नहीं कर सकते)
- एक इनबॉक्स (इंबाक्स)
- एक संचालकः`receive(message) -> effects`, इनमें से प्रभाव हो सकता है reply

 दो अभिनेता  नहीं साझा कर सकते स्मृति वे केवल संदेश भेज सकते हैं

### ऑटोजेन v0.4 中的三个API 层

1. **Core.** निम्न स्तर के अभिनेता ढांचे`AgentRuntime``Agent``Message``Topic`सिनक्रॉन संदेश विनिमय, घटना-चालित
2. **AgentChat.**面向任务的高层API(替代 v0.2 का ConversableAgent)`AssistantAgent``UserProxyAgent``RoundRobinGroupChat``SelectorGroupChat`
3. **Extensions.**集成:OpenAI、Anthropic、Azure、tools、memory──

### क्यों यह महत्वपूर्ण है

v0.2 模型中,同步调用 `agent_a.chat(agent_b)`                                                                                                                                                                                                                                                              `send(agent_b, msg)`会把消息 放入代理_b的收件箱,然后立即回来──运行时间 稍后交付──它带来了三个结果:

- **Fault isolation.**एजेंट बी                                                                                                                                                                                                                                                              
- **自然并发。**很多 संदेश एक साथ हो सकते हैं; अभिनेता अपने इनबॉक्स को संसाधित नहीं कर सकता है।
- **面向分布式。**चाहे अभिनेता प्रक्रिया में हो या दूसरे मेजबान पर, इनबॉक्स + परिवहन एक ही सार है।

##  इसे निर्माण

`code/main.py`实现 एक stdlib अभिनेता रनटाइम:

- `Message``sender``recipient``topic``body`के प्रकार के उपयोगिता लोड
- `Actor``receive(message, runtime)`का सार।
- `Runtime`:带有共享队列、交付、दोष पृथक्करण का घटना लूप。
- एक दोहरे अभिनेता डेमोः`ReviewerAgent`समीक्षा कोड,`ChecklistAgent`运行 चेकलिस्ट; वे आम सहमति तक संदेशों का आदान-प्रदान करते हैं।

运行:

```
python3 code/main.py
```

ट्रैक बैठक संदेश वितरण प्रदर्शित करती है, एक अभिनेता के बीच एक अन्य अभिनेता को विफल होने की अनुमति नहीं देता है, साथ ही साथ वे एक साथ निर्णय प्राप्त करने की प्रक्रिया को भी प्रदर्शित करते हैं।

## 关键术语

| 术语 | 人们怎么说 | 它实际意味着什么 |
|------|----------------|------------------------|
| Actor | "Agent" | 私有 state + inbox + handler；没有共享 memory |
| Message | "Event" | 类型化 payload；actor 交互的唯一方式 |
| Inbox | "Mailbox" | 每个 actor 的 pending message queue |
| Runtime | "Agent host" | 路由 message 并隔离失败的 event loop |
| Topic | "Channel" | actor 之间命名的 publish-subscribe route |
| Fault isolation | "Let it crash" | 一个 actor 失败不会让其他 actor 崩溃 |
| RoundRobinGroupChat | "固定轮转 team" | Agent 按顺序轮流行动 |
| SelectorGroupChat | "按 context 路由的 team" | Selector 选择下一位 |
| Magentic-One | "参考 team" | 用于 web + code + files 的 multi-agent squad |
