## 学习目标

- तीन शीर्ष ओपन सोर्स एजेंट दृश्यमानता मंच और लाइसेंस
- 区分每个平台最擅长的方面:लंगफ्यूज (त्वरित एमजीएमटी + सत्र)  फिनिक्स (RAG + ऑटो-इंस्ट्रूमेंटेशन)  ओपिक (अनुकूलन + गार्डरेल्स)

## 问题

OTel GenAI(Lection 23) ने आपको योजना दी है। आपको अभी भी अवधि को निगलने के लिए एक मंच की आवश्यकता है, परिचालन मूल्यांकन, भंडारण त्वरित संस्करण, और प्रतिगमन का खुलासा करना है।

## 核心概念

### लैंगफ्यूज (एमआईटी)

- प्रति माह 6M+ SDK स्थापित करता है,19k+ GitHub सितारे
- 功能:tracing、带 versioning + playground का शीघ्र प्रबंधन、 मूल्यांकन(LLM-as-judge、user反、自定义)、session replacements──
- 2025 साल 6 月:原先的商业模块(LLM-as-a-judge、नोटेशन कतार、प्राम्प्ट प्रयोग、प्लेग्राउंड) MIT में नीचे ओपन सोर्स वाली है。
-                                                                                                                                                                                                                                                               

### एरिज़ फीनिक्स (ईलास्टिक लाइसेंस 2.0)

- अधिक गहराई से एजेंट 专用评估:ट्रैक क्लस्टरिंग, विसंगतियों का पता लगाना, RAG के लिए प्रासंगिकता का सामना करना
- मूल भाषा ओपन इन्फेरेंस ऑटो-इंस्ट्रूमेंटेशन
-                                                                                                                                                                                                                                                               
-  定位是与更广泛平台配合使用的漂移/व्यवहार-प्रतिगमन 工具──
- 最擅长:RAG 相关性、व्यवहार संबंधी बहाव、अवशिष्टता का पता लगाना―

### उपग्रह ओपिक (अपाचे 2.0)

-  ए/बी प्रयोगों के माध्यम से  स्वचालितता शीघ्र 优化 
- सुरक्षा रैलियाँ (PII संपादन, विषयगत प्रतिबंध)
- LLM-जजज 幻觉检测──
- Comet से स्वयं मापने का बेंचमार्क: ओपिक लॉग + मूल्यांकन 23.44 से अधिक समय के साथ, जबकि लैंगफ्यूज 327.15 से अधिक से अधिक है।
- 最擅长:अनुकूलन लूप, स्वचालित प्रयोग, सुरक्षा बल

### उद्योग डेटा

मैक्सिम के अनुसार: 2026 के क्षेत्र विश्लेषण के अनुसार: 89% संगठनों ने एजेंट को तैनात किया है; गुणवत्ता का मुद्दा सबसे प्रमुख उत्पादन बाधा है।

### 如何选择

| 需求 | 选择 |
|------|------|
| 带 prompt management 的一体化方案 | Langfuse |
| 深度 RAG 评估 + drift | Phoenix |
| 自动化 optimization + guardrails | Opik |
| 开放 license，不要 ELv2 | Langfuse (MIT) 或 Opik (Apache 2.0) |
| Datadog / New Relic 集成 | 任意 — 它们都导出 OTel |

### यह तरीका आसानी से गलत जगह पर है

- **没有 eval strategy。** कोई मूल्यांकन नहीं  केवल महंगी लकड़ी की खोज 
- **没有 grounding 的自建 LLM-judge。**महत्वपूर्ण पैटर्न (Lection 05)  न्यायाधीशों  बाहरी उपकरणों की आवश्यकता है
- **Prompt versions 没有关联到 traces。**जब प्रूड रिग्रेशन होता है, तो आप समस्या के कारण तक काटा नहीं सकते हैं।

## 关键术语

| 术语 | 人们的说法 | 实际含义 |
|------|----------------|------------------------|
| Tracing | “Spans collector” | Ingest OTel / SDK spans；按 session 建索引 |
| Prompt management | “Prompt CMS” | 关联到 traces 的 versioned prompts |
| LLM-as-judge | “Automated eval” | 单独的 LLM 按 rubric 对 Agent output 评分 |
| Session replay | “Trace playback” | 逐步回放过去的 runs 以便 debugging |
| RAG relevancy | “Retrieval quality” | retrieved context 是否匹配 query |
| Trace clustering | “Behavioral grouping” | 对相似 runs 聚类，用于 drift detection |
| Guardrail enforcement | “Policy at log time” | 对 logged content 做 PII/toxicity/scope checks |
