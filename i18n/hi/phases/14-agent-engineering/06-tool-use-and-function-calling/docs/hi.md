## 概念
### उपकरणformer (Schick et al., NeurIPS 2023)

विचारः चलो मॉडल का उपयोग करें उम्मीदवार एपीआई कॉल 标签自己的预训体──对每个候选人 执行它──只有当包含工具结果 能降低一个代币上的损失时,才保留该注释──然后在过后的体上细节──

覆盖的工具:कल्कुलेटर、QA प्रणाली、搜索引擎、翻译、日历──自监信号 纯粹关注工具 是否有助于预测文本,不需要人标签──

规模 परिणाम: उपकरण उपयोग 会在规模足够时涌现──较小的模型 会因工具注释受损;较大的模型会受益──这就是为什么2026 के सीमांत मॉडल内置强的工具使用能力,而大多数7B मॉडल 需要显然工具使用精细调才可靠──

### बर्कले फ़ंक्शन कॉलिंग लीडरबोर्ड V4 (पैटिल एट अल., आईसीएमएल 2025)

बीएफसीएल 2026 साल का वास्तविक मूल्यांकन है।

- **Agentic (40%)** 完整代理轨迹:स्मृति、बहु-टर्न、गतिशील निर्णय──
- **Multi-Turn (30%)** 带 उपकरण श्रृंखलाओं के परस्पर बातचीत
- **Live (10%)** उपयोगकर्ता के प्रस्तुत करने के वास्तविक संकेतों (अधिक कठिन वितरण) 
- **Non-Live (10%)** सिंथेटिक टेस्ट केसों में
- **Hallucination (10%)** 检测何时不应调用 उपकरण──

V3 ने राज्य-आधारित मूल्यांकन शुरू कियाः उपकरण अनुक्रम के बाद, एपीआई की वास्तविक स्थिति की जांच करें (उदाहरण के लिए, क्या फ़ाइलें बनाई गई हैं?), बजाय एएसटी के अनुरूप उपकरण कॉल के।

2026 साल की महत्वपूर्ण खोजः एकल-टर्न फ़ंक्शन कॉल करना 基本已解决──失败集中在记忆(跨轮 携带背景)、 गतिशील निर्णय लेने(基于先前结果选择工具)、长视线链(20+ कदम 后漂移) और幻觉检测(没有合适工具 时拒调用)。

### उपकरण योजना

प्रत्येक प्रदाता की एक योजना होती है।

```
name: string
description: string (what it does, when to use it)
input_schema: JSON Schema (properties, required, types, enums)
```

मानव 直接使用 `input_schema`✿OpenAI प्रयोग `function.parameters` दुनों JSON Schema को स्वीकार करते हैं विवरण  महत्वपूर्ण भूमिका निभाते हैं, मॉडल उन्हें सही उपकरण का चयन करने के लिए पढ़ेंगे खराब उपकरण विवरण  असफलता का पहला कारण

### तर्क सत्यापन

किसी भी उपकरण को मत विश्वास करो।

1. **Type coercion.**मॉडल संभव है schema 要求 int 的地方返回字符串 `"5"`यदि明确无歧义就强制;否则拒绝
2. **Enum validation.**यदि योजना लिखित है `status in {"open", "closed"}`, और मॉडल आउटपुट `"in_progress"`, वर्णनात्मक त्रुटि से इनकार करना
3. **Required fields.**缺少 required field -> 立即把错误观察 返回模型, बजाय दुर्घटना
4. **Format validation.**दिनांक, ईमेल, यूआरएल  विशिष्ट पार्सर 验证, बजाय regex  के साथ प्रयोग करें

प्रत्येक सत्यापन विफलता का परिणाम संरचनात्मक अवलोकन में लौटना चाहिए, ताकि मॉडल सही रूप से पुनः प्रयोग कर सके।

### समानांतर उपकरण कॉल

现代 प्रदाता 支持在一个助手转中并行工具调用──循环:

1. मॉडल 3 उपकरण कॉल, प्रत्येक अलग है।`tool_use_id`
2. रनटाइम  उन्हें निष्पादित करना  यदि आप एक दूसरे से स्वतंत्र हों तो并行)
3. प्रत्येक परिणाम के रूप में `tool_result`ब्लॉक  लौटें,并通过 `tool_use_id`关联──

工程规则:把相关性 IDs 当作关键约束──把它们交换,就会导致错误工具到错误结果路由──

## 关键术语
| Term | 人们怎么说 | 它实际意味着什么 |
|------|----------------|------------------------|
| Function calling | "Tool use" | 使用 validated schema 的 structured-output tool invocation |
| Toolformer | "Self-supervised tool annotation" | Schick 2023 — 保留那些结果能降低 next-Token Loss 的 tool calls |
| BFCL | "Berkeley Function Calling Leaderboard" | 2026 benchmark：40% agentic、30% multi-turn、10% live、10% non-live、10% hallucination |
| Tool schema | "给 model 的 function signature" | name、description、arguments 的 JSON Schema |
| tool_use_id | "Correlation ID" | 将 tool call 与其 result 绑定；对 parallel dispatch 至关重要 |
| Hallucination detection | "知道何时不调用" | V4 category：没有合适 tool 时拒绝调用 |
| Argument coercion | "String-to-int repair" | 针对可预测 schema mismatch 的窄修复；如果有歧义则 reject |
| Sandboxing | "Tool execution boundary" | 每个 tool 的 read/write surface、network、timeout、memory cap |
