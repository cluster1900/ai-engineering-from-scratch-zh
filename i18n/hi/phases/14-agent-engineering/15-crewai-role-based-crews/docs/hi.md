# क्रूएआई: भूमिका आधारित क्रू और प्रवाह

> क्रूएआई 2026 वर्ष के भूमिका आधारित बहु-एजेंट ढांचे में शामिल हैः चार बुनियादी घटकः एजेंट, टास्क, क्रू, प्रक्रिया, दो प्रकार के शीर्ष स्तरीय ढांचेः क्रू (स्वचालित) और प्रवाह (प्रवाह) घटना संचालित (परिभाषित) ।

**类型：**学习 + 构建
**语言：**पायथन (stdlib)
**先修：**चरण 14 · 12 (कार्यप्रवाह पैटर्न), चरण 14 · 14 (अभिनेता मॉडल)
**时间：** 75 मिनट

## 学习目标

- बताएं कि क्रूएआई के चार बुनियादी घटक हैं (एजेंट, टास्क, क्रू, प्रक्रिया) और प्रत्येक घटक जिम्मेदार है।
- 区分 क्रमशः、 पदानुक्रमिक 和 योजना में सहमति प्रक्रिया;
- 区分 Crews (स्वतः के आधार पर भूमिका) और Flow (घटना संचालित की निश्चितता),并解释文档中的生产建议──
- उपयोग `@tool`सजावटकर्ता 和 `BaseTool`उपवर्ग 接入 उपकरण; संरचित आउटपुट को समझना तथा मुक्त पाठ का उपयोग करना
- चार प्रकार की क्रूएएआई मेमोरी प्रकारों के साथ-साथ प्रत्येक में किस समय उपयोग करने लायक हैं।
- 实现一个工作三 工作人员团队 研究员  लेखक  संपादक  ,产出一份简报
- 识别三种 CrewAI विफलता मोड: शीघ्र-ब्लाट, प्रबंधक-LLM कर, संकुचित हस्तान्तरण

## 概念

### चार मूलभूत घटक

CrewAI की सतह 很小──记住这个,剩余都是配置──

- **Agent。** `role + goal + backstory + tools + (optional) llm` पृष्ठभूमि 很关键──它塑造语气、判断,以及代理 何时停止──工具是代理 可以调用函数(下面会讲)。
- **Task。** `description + expected_output + agent + (optional) context + (optional) output_pydantic`可复用工作单元──`expected_output`यह एक समझौता है।`context`列出上游任务,其输遇被传入──`output_pydantic`强制使用结构化形态──
- **Crew。**容器──拥有 `agents`सूची`tasks`सूची`process`, तथा विकल्प `memory`+ `verbose`+ `manager_llm`设置──
- **Process。**执行策略── क्रमशः、 पदानुक्रमिक、 सहमति(计划中)── चयन कार्य के प्रारूप──

एजेंट एक दूसरे को सीधे नहीं देखेंगे। कार्य कर्मियों का संदर्भ कर्मियों को संभालेंगे। कार्य के लिए टीम  कार्य की व्यवस्था करेगी। प्रक्रिया तय करेगी कि कौन अगला कार्य चुनता है।

> **已针对**CrewAI 0.86(2026-05)验证──更新版本可能会重新命名或合并过程类型;在依赖具体形态之前,请查看 [CrewAI Processes docs](https://docs.crewai.com/concepts/processes)

### अनुक्रमिक पदानुक्रमिक एवं सहमति

- **Sequential。**कार्य 按声明顺序运行──कार्य N का输出可作为 `context`提供给任务 N+1──成本最低──最可预测──当顺序固定时使用──
- **Hierarchical。**एक प्रबंधक एजेंट (एक अलग एलएलएम कॉल) विशेषज्ञों के बीच मार्गों में।`manager_llm`config या default configuration generate manager──manager प्रत्येक दौर अगले कार्य का चयन करता है, और यह अस्वीकार या पुनः मार्ग से गुजर सकता है──जब आपके पास चार या अधिक विशेषज्ञ होते हैं, और क्रम वास्तव में पूर्व क्रम पर निर्भर करता है।
- **Consensus。** योजना में, वर्तमान सार्वजनिक एपीआई  अभी तक लागू नहीं किया गया है 文档保留该名称用于未来基于投票的过程── आज इस पर निर्भर न करें──

प्रत्येक विशेषज्ञ कॉल पर पदानुक्रमिक बैठक में प्रत्येक बार LLM कॉल में वृद्धि होती है।

### चालक दल बनाम प्रवाह

यह 2026 के लिए एक महत्वपूर्ण ढांचा है।

- **Crew。**LLM-चालित स्वायत्तता― फ्रेमवर्क 在运行时选择形态―适合: अनुसंधान、brainstorming、प्रथम मसौदा,以及路径本身就是答案的一部分的场景―难以重复―难以测试―原型成本低―
- **Flow。**आपके पास होने वाली घटनाओं का ड्राइविंग ग्राफ`@start`标记入口──`@listen(topic)`标记一步,它会在另一个步骤中发出这个话题 时触发──每一步都是普通 Python(内部可以调用机组)──适合:生产──可观测──可测──确定性──

文档在 2026年生产建议: से प्रवाह 开始――当自主权 值得其成本时,把船员 作为流动步骤 内部的 `Crew.kickoff()`कॉल 折进去──Flow 给你审计轨道, क्रू 给你探索──组合使用,不要二选一──

### उपकरण 集成

एजेंट 配备 उपकरण 有三种方式──选择最简单而适合的一种──

1. **`@tool` decorator。**纯函数变成工具──签名是方案;docstring是LLM 见的描述──最适合一次性辅助者──

   ```python
   from crewai.tools import tool

   @tool("Search the web")
   def search(query: str) -> str:
       """Return top results for the query."""
       return run_search(query)
   ```

2. **`BaseTool` subclass。**基于类的工具,带显式 args schema、async support、retries──当工具 有状态(client、cache) 或需要结构化 args 时使用──

   ```python
   from crewai.tools import BaseTool
   from pydantic import BaseModel

   class SearchArgs(BaseModel):
       query: str
       limit: int = 10

   class SearchTool(BaseTool):
       name = "web_search"
       description = "Search the web and return top results."
       args_schema = SearchArgs

       def _run(self, query: str, limit: int = 10) -> str:
           return self.client.search(query, limit=limit)
   ```

3. **内置 toolkits。**CrewAI  प्रदान प्रथम पक्ष एडाप्टरः`SerperDevTool``FileReadTool``DirectoryReadTool``CodeInterpreterTool``RagTool``WebsiteSearchTool` एक बार आयात 即可接入

संरचित आउटपुट उपयोग Pydantic──在 टास्क 上传入 `output_pydantic=MyModel`कर्मचारी एआईआई एएलएम प्रतिक्रिया के मॉडल के आधार पर वीजाई,并 कर मजबूर या पुनः प्रयास ए इसे कठोरता से `expected_output`string 配合使用── मुक्त-पाठ आउटपुट 适合草稿; संरचित आउटपुट 才是下游 प्रवाह 能消费的内容──

### स्मृति हुक

CrewAI 开箱提供四种内存类型──它们可以组合:一个 Crew可以同时启用四种──

> **已针对**CrewAI 0.86(2026-05) सत्यापन── हालिया संस्करण सभी सामग्री को एकजुट करने के लिए मार्ग पर रखा गया है `Memory`सिस्टम, इस प्रणाली को चार प्रकार के स्टोरों में पैक किया गया है। नीचे दिए गए अवधारणा मॉडल अभी भी मौजूद हैं, लेकिन अद्यतन संस्करण में, सार्वजनिक वर्ग सतह को एक के लिए प्राप्त किया जा सकता है।`Memory`प्रवेश बिंदु; कृपया देखें [CrewAI memory docs](https://docs.crewai.com/concepts/memory)了解当前 एपीआई──

- **Short-term。**单次运行内 वार्तालाप बफर──结束时清空──
- **Long-term。**跨运行持久化── भंडारण में वेक्टर DB 中(默认 Chroma,可替换)──按当前任务的相似度检索──
- **Entity。**按实体 记录事实──ग्राहक X उद्यम योजना पर है। 按实体 keyed, बजाय相似度──跨运行保留──
- **Contextual。**组装时检索──在代理 需要时拉取相关记忆,而不是预载──

चालक दल के ऊपर उपयोग में`memory=True`या प्रकार के कॉन्फ़िग  सक्षम करना                                                                                                                                                                                                                                                          

### 什么时候适合 CrewAI

- तीन से छह एजेंट, चरित्र नाम और सहयोग कार्यप्रवाह──起草、レビュー、計画、brainstorming──
- LLM अगले चरण के लिए निर्णय स्वयं मूल्य के रुटिंग का निर्माण करता है।
- 团队更愿意读 `role + goal + backstory`, बजाय ग्राफ परिभाषा के दृश्यों को पढ़ना

### 什么时候不适合 CrewAI

- 带严格顺序的确定性 DAGs──使用LangGraph(Lesson 13)──ग्राफ आकार सही अमूर्तता है;CrewAI के रोल फ्रेमिंग 会带来摩擦──
- 亚秒级延迟预算── Hierarchical 会增加回路旅行── यहां तक कि अनुक्रमिक भी序列化包含背景故事和前输出的提示──
- एकल एजेंट लूप्स──跳过框架; एक एजेंट लूप(लक्ष 1) जोड़ने उपकरण रजिस्ट्री 更短──

पाठ 17 (एजेंट फ्रेमवर्क ट्रेडऑफ) Matrix के साथ इस बात को प्रदर्शित किया गया है।

### निर्भरता का आकार

独立于 朗链──पायथन 3.10 से 3.13──使用 `uv` तारा गिनती:见 [crewAIInc/crewAI](https://github.com/crewAIInc/crewAI)(२०२६-०५ तक की स्नैपशॉट) ःAWS बेड्रॉक एकीकरण 有文档;विक्रेता बेंचमार्क 报告其在QA कार्यभार上相比LangGraph有显著提速,但方法论(数据集、硬件、评估指标) 未公开,因此框架-विक्रेता संख्या केवल दिशा-निर्देश संदर्भ के रूप में ही इस्तेमाल की जा सकती है。

### यह पैटर्न कहाँ से बाहर आ जाएगा

- **Backstories 导致 prompt-bloat。**प्रत्येक एजेंट एक 2000 शब्द की पृष्ठभूमि, पुनः पाँच एजेंटों के चालक दल, पहले उपकरण कॉल में होंगे पूर्व जल掉 संदर्भ बजट――把 पृष्ठभूमि कहानियाँ 控制在 200 词以内――跨 एजेंट 复用短语;不要把家风重复五遍――
- **Manager-LLM token tax。**पदानुक्रमिक प्रक्रिया प्रत्येक विशेषज्ञ कॉल में होगी पूर्व एक प्रबंधक LLM कॉल में वृद्धि करेगा── पांच कार्य कार्य के साथ कार्यबल के सदस्य पाँच बार LLM कॉल से छह बार में बदल जाएंगे, और प्रबंधक कॉल पूर्ण कार्य सूची के साथ अग्रिम आउटपुटों को जोड़ देगा── सिवाय रूटिंग के निर्भर आउटपुट पर, अन्यथा क्रमिक में स्विच करेगा──
- **Brittle handoffs。**कार्य N `expected_output`एक रूपरेखा──कार्य N+1 इसे `context`读取,并尝试 parse 三个节目──LLM 生成四个──下游 एजेंट 即兴处理──修复方式是任务 N 上使用 `output_pydantic`,让任务 N+1 读取 टाइप किया गया वस्तु, बजाय मुक्त पाठ.
- **Crew-as-prod。**स्वतंत्रता स्वरूप चालक दल बिना प्रवाह के रैपर के उत्पादन तक जारी किया जाता है।

##  इसे निर्माण

`code/main.py` दो प्रकार के स्टडीलिब संस्करण, तथा एक त्रि एजेंट चालक दल को प्राप्त किया गया

形态:

- `Agent``Task`डेटाक्लास, CrewAI की सतह से मेल खाती हैं
- `SequentialCrew.kickoff(inputs)`按声明顺序运行任务,并把输出 作为 `context`传递──
- `HierarchicalCrew.kickoff(topic)`एक प्रबंधक एजेंट, प्रत्येक दौर में अगले विशेषज्ञ का चयन करें, और एक 处停止
- 带 `@start`和 `@listen(topic)`सजावटकारों की `Flow`, एक बहुत ही छोटी घटना लूप, साथ ही साथ निशान.
- `tool(name)`सजावट, दर्पण CrewAI का `@tool`आकार
- 带 `short_term``long_term``entity`दुकानों के `Memory`; मजाकिया समानता प्रयोग नम्पि。
- नकली LLM प्रतिक्रियाएँ भूमिका के आधार पर हैं, जो कि इनपुट प्रीफिक्स कीवर्ड की हार्डकोड स्ट्रिंग्स के आधार पर हैं।

具体 demo:researcher、writer、editor crew,产出一份关于 agent engineering 2026 的简报──Researcher 拉取(mocked) स्रोतों── लेखक 起草──editor 收紧──同一个 crew 通过流动 运行,以展示决定性形──

运行它:

```bash
python3 code/main.py
```

अनुक्रमिक चालक दल के माध्यम से`context`串接 आउटपुट, पदानुक्रमिक टीम 带 प्रबंधक चयन  शोधकर्ता  लेखक  संपादक, फिर  किया), प्रवाह  स्पष्ट विषयों का उपयोग `researched``drafted``edited`)运行同样三步, उपकरण कॉल 通过 `@tool`路由, तथा दीर्घकालिक स्मृति में दो बार कीचड़ 之间保留

चालक दल का निशान है流动的; प्रबंधक मूलतः पुनः क्रमबद्ध किया जा सकता है।

## इसका उपयोग करें

- **CrewAI Flow**उत्पादन के लिए उपयोग किया जाता है. यहां तक कि प्रवाह केवल एक कदम है।`Crew.kickoff()`◊प्रवाह ⇒ लेखापरीक्षा सीमा प्रदान करना
- **CrewAI Crew (Sequential)**विशेष रूप से पहले मसौदे तथा समीक्षा लूप्स में स्पष्ट सहयोग के लिए प्रयोग किया जाता है।
- **CrewAI Crew (Hierarchical)**जब रूटिंग आउटपुट पर निर्भर करता है, और आप चार या अधिक विशेषज्ञों  उपयोग करते हैं.
- **LangGraph**(पाठ 13) स्पष्ट राज्य मशीनों में प्रयोग किया जाता है, टिकाऊ रिज्यूमे, सख्त आदेशों में।
- **AutoGen v0.4**(पाठ 14) अभिनेता-मॉडल समवर्तीता तथा दोष पृथक्करण हेतु प्रयोग किया जाता है
- **OpenAI Agents SDK**(पाठ 16) ओपनएआई-प्रथम उत्पादों, हाथों के साथ और पहरा के साथ प्रयोग किया जाता है
- **Claude Agent SDK**(पाठ 17) क्लाउड-प्रथम उत्पादों के लिए, साथ उपभोग्य सामग्रियों और सत्र स्टोर

## 常见坑

- **把 backstory 当作调味。**यह आउटपुटों को आकार देगा। प्रत्येक एजेंट तीन प्रकार का परीक्षण करेगा।
- **跳过 `expected_output`。**没有每个任务的契约,下游任务会拿到LLM 产出的任意内容── चालक दल 能跑;审计会失败──
- **Memory always-on。**दीर्घकालिक प्रत्येक बार परिचालन में प्रवेश किया जाता है। वेक्टर डीबी  वृद्धि                                                                                                                                                                                                                                                      
- **Manager prompt drift。**पदानुक्रम के प्रबंधक का संकेत है छिपा हुआ है। यदि रूटिंग  विचित्र हो जाती है, तो  शब्द मोड में  बाहर निकल पढ़िये।
- **Crews 中 tool side effects。**चालक दल संभवतः अपेक्षित से अधिक बार उपकरण का उपयोग करेगा।

## 关键术语

| Term | 大家常说 | 实际含义 |
|------|----------------|------------------------|
| Agent | “Persona” | Role + goal + backstory + tools |
| Task | “工作单元” | Description + expected output + assignee + optional structured output |
| Crew | “Agent team” | Agents + Tasks + Process 的容器 |
| Process | “执行策略” | Sequential / Hierarchical / Consensus（计划中） |
| Flow | “Deterministic workflow” | 事件驱动、代码拥有、可测试 |
| Backstory | “Persona prompt” | Agent 的语气与判断塑造器 |
| `@tool` | “Function tool” | 把函数变成 Agent 可调用 tool 的 decorator |
| `BaseTool` | “Class tool” | 带 args schema、retries、async support 的 class-based tool |
| Entity memory | “Per-entity facts” | 限定到某个 customer / account / issue 的 memory |
| Long-term memory | “Cross-run memory” | 在 kickoffs 之间保留的 vector-backed memory |
| Contextual memory | “Just-in-time retrieval” | Agent 需要时才拉取的 memory |
| Manager LLM | “Router agent” | Hierarchical process 中选择下一个 task 的额外 LLM |
| `expected_output` | “Task contract” | 告诉 Agent（和 audit）要返回什么形态的 string |
