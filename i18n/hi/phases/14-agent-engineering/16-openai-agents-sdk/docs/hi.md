### गार्डरेल्स

- **Input guardrails.**प्रथम एजेंट के इनपुट ऊपर चलना। किसी भी एलएलएम कॉल से पहले असुरक्षा या सीमा से बाहर के अनुरोधों को अस्वीकार करना।
- **Output guardrails.**                                                                                                                                                                                                                                                              
- **Tool guardrails.**按功能-工具 运行──कार्य-सामग्री सत्यापित करें、परीक्षण अनुमतिएँ、ऑडिट निष्पादन──

### ट्रैक करना

默认开启──每次LLM पीढ़ी、工具 कॉल、赞助和 guardrail都会发射一个跨度──`OPENAI_AGENTS_DISABLE_TRACING=1`मैं बाहर आ जाएगा.`add_trace_processor(processor)`会将扩展到你的自己的后端,同时也发送到OpenAI的后端──

### सत्र

`Session` वार्तालाप इतिहास 存储在后端 中(SQLite、Redis、自定义)`Runner.run(agent, input, session=session)`会自动加载并添加──

### यह तरीका आसानी से गलत जगह पर है

- **Handoff drift.**एजेंट ए को हाथ छोड़ें एजेंट बी को, एजेंट बी को फिर हाथ वापस दें एजेंट ए को।
- **Guardrail bypass.**उपकरण गार्डरेल्स केवल कार्य उपकरण में ही हैं; अंदर रखा उपकरण (फाइल रीडर, वेब लिक) को एक अलग नीति की आवश्यकता है।
- **Over-tracing.**समावेशी सामग्री शामिल है।

## 关键术语
| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Agent | "LLM + instructions" | SDK 中的 Agent type；拥有 tools 和 handoffs |
| Handoff | "Transfer" | 模型调用以 delegate 给另一个 agent 的 tool |
| Guardrail | "Policy check" | 对 input / output / tool invocation 的 validation |
| Tripwire | "Guardrail trip" | guardrail 拒绝时抛出的 exception |
| Session | "History store" | runs 之间持久化的 conversation memory |
| Tracing | "Spans" | 覆盖 LLM + tool + handoff + guardrail 的内置 observability |
| Blocking guardrail | "Sequential check" | Guardrail 先运行；trip 时不浪费 Token |
| Parallel guardrail | "Concurrent check" | Guardrail 同时运行；latency 更低，trip 时浪费 Token |
