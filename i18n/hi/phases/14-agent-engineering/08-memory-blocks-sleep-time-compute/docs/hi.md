# स्मृति ब्लॉक और नींद समय गणना (लेटा)

> 2024 में लेटा बनने के लिए मेमजीपीटी ने 2026 के विकास में दो विचार शामिल किएः मॉडल सीधे अलग-अलग कार्यात्मक स्मृति ब्लॉकों को संपादित कर सकता है, और प्राथमिक एजेंट में याददाश्त को एकीकृत करने के लिए नींद-समय एजेंट।

**Type:** Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 14 · 07 (MemGPT)
**Time:** ~75 minutes

## 学习目标
- व्याख्या करें Letta उपयोग के तीन परतों की स्मृति (core, recall, archive) तथा प्रत्येक परत के प्रभाव
- 解释memory-block pattern:Human block、Persona block, तथा एक जैसे टाइप किए गए वस्तुओं के उपयोगकर्ता द्वारा परिभाषित ब्लॉक
-  नींद समय गणना क्या है, यह महत्वपूर्ण पथ से बाहर क्यों स्थित है, और यह प्राथमिक एजेंट से अधिक शक्तिशाली मॉडल से क्यों चल सकता है 
-  एक लिखित द्वि एजेंट 循环 को प्राप्त करना, जिसमें प्राथमिक एजेंट  प्रतिक्रिया प्रदान करना, नींद समय एजेंट  轮次之间整合块

## 问题
MemGPT ((Lection 07) ने वर्चुअल मेमोरी कंट्रोल फ्लो को हल किया। इसके बाद तीन उत्पादन समस्याएं उत्पन्न हुईंः

1. **Latency.**प्रत्येक मेमोरी ऑपरेशन महत्वपूर्ण पथ पर स्थित है। यदि एजेंट को उपयोगकर्ता के इंतजार के दौरान कटौती करना होगा, तो पूंछ की लटेंसी तेजी से बढ़ जाएगी।
2. **Memory rot.**写入会不断累积――被矛盾推翻的事实会留下――检索会被陈旧内容淹没――
3. **Structure loss.**平的档案库 无法表达Human block 总是在提示中;Persona block 总是在提示中;Task block 按会议 交换──

Letta (letta.com) है 2026 साल का重写版本── स्मृति ब्लॉक 让结构显式化; नींद समय गणना 将整合移出关键路──

## 概念
### तीन स्तर

| Tier | Scope | Where it lives | Written by |
|------|-------|----------------|------------|
| Core | 始终可见 | 在 main prompt 内 | Agent tool call + sleep-time rewrites |
| Recall | 对话历史 | 可检索 | 自动轮次日志 |
| Archival | 任意事实 | Vector + KV + graph | Agent tool call + sleep-time ingest |

कोर MemGPT कोर है――Remember is conversation buffer  और इसके द्वारा निष्कासित किए गए尾部──Archival is external store── यह डिलीवरी MemGPT के दो परतों को रिलीज़ कर चुकी है──

### स्मृति ब्लॉक

ब्लॉक एक कोर स्तर है, जिसमें एक टाइप किया गया, निरंतर, संपादन योग्य खंड है।

- **Human block** 关于用户的事实(姓名、角色、偏好、目标) 
- **Persona block** एजेंट की आत्म-धारणा (身份、语气、约束)

Letta इसे किसी भी उपयोगकर्ता द्वारा परिभाषित ब्लॉक में सामान्यीकरण करेगा: वर्तमान लक्ष्य के लिए उपयोग किया जाएगा `Task`ब्लॉक, कोडबेस के लिए प्रयोग तथ्य `Project`ब्लॉक, हार्ड बॉन्ड के लिए प्रयोग किया जाता है `Safety`ब्लॉक  हर ब्लॉक  है`id``label``value``limit`(字符上限)`description`(让模型知道何时编辑它)

ब्लॉक उपकरण सतह के माध्यम से 编辑:

- `block_append(label, text)`
- `block_replace(label, old, new)`
- `block_read(label)`
- `block_summarize(label)`

### लेटा वी 1 और मूल जीवन तर्क

लेटा V1 (`letta_v1_agent`, 2026)  त्याग `send_message`/ दिल की धड़कन और इनलाइन `Thought:`टोकन,转而支持本土推理――Responses API (OpenAI) 和带延伸思维的消息 API (Anthropic) 会在单独的频道上发出推理,并跨轮次传递(在生产中跨供应商加密) ――नियंत्रण लूप 仍是 ReAct──思维痕迹是结构性的,而不是快速形的──

### यह तरीका आसानी से गलत जगह पर है

- **Block bloat.**无限 `block_append`会很快触及限度──在会导致超出帽的写入前接入区块总结──
- **Silent drift.**नींद समय एजेंट ने ब्लॉक को फिर से लिखा है, जबकि प्राथमिक एजेंट ने ब्लॉक को नहीं देखा है।
- **Poisoned consolidation.**नींद समय एजेंट हमलावर को स्पर्श सामग्री को कोर में संसाधित करेगा।

## 关键术语
| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Memory block | “可编辑的 prompt section” | Core memory 中 typed、persistent、LLM-editable 的 segment |
| Human block | “用户记忆” | 关于用户的事实，固定在 core 中 |
| Persona block | “Agent 身份” | Self-concept、语气、约束，固定在 core 中 |
| Sleep-time compute | “异步记忆工作” | 第二个 agent 在 critical path 之外执行整合 |
| Core / Recall / Archival | “层级” | 三层记忆拆分：始终可见 / 对话 / external |
| Block limit | “上限” | 每个 block 的字符限制；迫使进行 summarization |
| Native reasoning | “Thinking channel” | Provider-level reasoning output，而不是 prompt-level `Thought:` |
| Learned context | “Sleep output” | Sleep-time agent 写入 shared blocks 的事实 |
