# आत्म-संशोधन एवं आलोचनाः 代式输出改进

> स्व-संशोधन (Madaan et al., 2023) एक LLM को चक्र में तीन भूमिकाएं निभाने देंः उत्पन्न करें, प्रतिक्रियाएँ प्राप्त करें, शुद्ध करें। औसत लाभः 7 个任务上绝对提升 +20──CRITIC(Gou et al., 2023) द्वारा परीक्षण मार्ग से बाहरी उपकरणों तक प्रतिक्रिया को मजबूत करने के लिए 步骤── 2026 तक, यह मॉडल  मूल्यांकनकर्ता-अनुकूलनकर्ता️ मानवतावादी) या गार्डरेल लूप️OpenAI Agents SDK के रूप में प्रत्येक ढांचे में दिखाई देगा।

**Type:** Build

## 学习目标

- कहने के लिए आत्म-शुद्ध करने के तीन संकेतों का निर्माण, प्रतिक्रिया, शुद्धीकरण), और व्याख्या क्यों इतिहास के बारे में शुद्ध करने के संकेतों  बहुत महत्वपूर्ण है।
- 解释 CRITIC 的关键洞见: कोई बाहरी आधार नहीं, एलएलएम में स्व-पुष्टि 上不可靠──
- 实现一个带历史 和可选外部验证器的自定义循环──
- इस मॉडल को मानविकी के मूल्यांकन-अनुकूलन  कार्यप्रवाह और OpenAI एजेंट्स SDK के आउटपुट गार्डरेल्स में मैप करना

## 问题

एक एजेंट एक लगभग सही उत्तर उत्पन्न करता है। शायद कोड की एक पंक्ति में वाक्यरचना त्रुटि है। शायद सारांश बहुत लंबा है। शायद एक एज केस खो गया है।

स्व-संशोधन 表明: एकल मॉडल के साथ 没有需要培训数据、没有需要RL,也能做到这一点──但有一个问题:LLMs 没有擅长对硬实实做自我验证──Critic 命名了这个修复方案:把验证 步骤路由到外部工具(搜索、代码解释器、计算器、测试运行者) 

इन दो लेखों ने 2026 में 代式改进的默认模式:生成、verify(能外部验证就外部验证) 、炼,在验证器 通过时停止── को संयुक्त रूप से परिभाषित किया है।

## 概念

### स्व-रिफाइन (Madaan et al., NeurIPS 2023)

एक LLM, तीन भूमिकाएं:

```
generate(task)            -> output_0
feedback(task, output_0)  -> critique_0
refine(task, output_0, critique_0, history) -> output_1
feedback(task, output_1)  -> critique_1
refine(task, output_1, critique_1, history) -> output_2
...
stop when feedback says "no issues" or budget exhausted.
```

关键细节:`refine`इतिहास को समाप्त करने के लिए, गुणवत्ता में तेजी से गिरावट आई है।

核心结果: 7 个任务 (गणित, कोड, संक्षिप्त नाम, संवाद) पर औसत +20 का निरपेक्ष उन्नयन, GPT-4 सहित, लाया गया।

### आलोचनात्मक (Gou et al., arXiv:2305.11738, v4 Feb 2024)

आत्म-संशोधन की कमजोरीः प्रतिक्रिया 步骤是 LLM 给自己打分── तथ्य के दावे के लिए, यह अविश्वसनीय है(हल्लूसिनेशन 往往在生成它的模型看来很有说服力)──CRITIC UZ`verify(task, output, tools)`替换 `feedback(task, output)`, उनमें से `tools`इसमें शामिल हैंः

- वास्तविकता के दावे के खोज इंजन का उपयोग करके
- कोड सटीकता के कोड व्याख्याता के साथ प्रयोग किया गया है
- अंकगणित की कैलकुलेटर के साथ
- क्षेत्र विशिष्ट सत्यापितकर्ता (इकाई परीक्षण, प्रकार के चेकर, लैंटर)

सत्यापक उपकरण परिणामों के आधार पर संरचनात्मक आलोचना उत्पन्न करेगा।

核心结果:CRITIC 在事实性任务上优于自炼,因为批判有基地──在没有外部验证者的任务上(创意写作、格式化),CRITIC 会退化为自炼──

### 停止条件

两种常见形态:

1. **Verifier 通过。**बाहरी परीक्षण  वापसी सफलता ️ उपलब्ध शर्तें ️ इकाई परीक्षण  प्रकार परीक्षक ️ गार्डरेल का दावा)
2. **没有发出 feedback。**मॉडल कहते हैं आउटपुट ठीक है. 成本更低但不可靠; 要搭配最大化 cap──

2026 默认做法:组合二者── यदि सत्यापितकर्ता 通过, या मॉडल 说好且 पुनरावृत्तियाँ >= 2, या पुनरावृत्तियाँ >= max_iterations,则停止──

### मूल्यांकनकर्ता-अनुकूलनकर्ता (Anthropic, 2024)

मानव विज्ञान ने इसे 2024 के दिसंबर में एक लेख में पांच प्रकार के कार्यप्रवाह पैटर्न के रूप में नामित किया।

- मूल्यांकनकर्ता:给输出打分并生成批评──
- अनुकूलक: आलोचना के अनुसार 修订输出。

循环直到评估者通过──这就是人类表述中的自精/CRITIC──人类补充的关键工程细节是:评估者和优化者提示 应该有明显不同的结构,这样的模型 才不会只是膠盖章──

### OpenAI एजेंट्स SDK आउटपुट गार्डरेल

OpenAI एजेंट्स SDK इस मोड को  आउटपुट गार्डरेल्स 提供── गार्डरेल                                                                                                                                                                                                                                                  `OutputGuardrailTripwireTriggered`),输遇被拒绝, एजेंट पुनः प्रयास कर सकते हैं.

### 2026 साल की खाड़ी

- **Rubber-stamp loops。**एक ही मॉडल के साथ एक ही त्वरित शैली के साथ करें पीढ़ी और आलोचना,  प्राप्त करने तक मुझे अच्छा लगता है── संरचना पर अलग-अलग संकेतों का उपयोग करें, या एक और अधिक छोटे  सस्ते मॉडल के साथ करें आलोचना──
- **过度 refine。**प्रत्येक बार परिष्कृत पास में देरी और टोकन वृद्धि होती है। बजट 1-3 बार पास के लिए सेट किया जाता है। इसके बाद मानव समीक्षा तक उन्नयन किया जाता है।
- **在 trivial tasks 上使用 CRITIC。**यदि कोई बाहरी सत्यापनकर्ता नहीं है, तो क्रिटिक रिफिन के लिए वापस आ जाएगा; स्टब सत्यापनकर्ता के लिए 支付 latency न करें。

##  इसे निर्माण

`code/main.py`एक खिलौना कार्य में स्व-शुद्धता और आलोचनात्मकता को लागू करेंः एक विशिष्ट विषय उत्पन्न करें, एक छोटी गोली सूची उत्पन्न करें, सत्यापितकर्ता, जांच प्रारूप, प्रत्येक में 60 वर्णों से कम के साथ तीन गोलीएं।

组件:

- `generate` पटकथा निर्माता
- `feedback` LLM शैली की आत्म-आलोचना。
- `verify_external` क्रिटिक शैली के जमीनी सत्यापनकर्ता。
- `refine` 根据历史 改写输出──
- स्टॉप कंडीशन  सत्यापनकर्ता 通过或最多 4 बार पुनरावृत्ति──

运行:

```
python3 code/main.py
```

तुलना करें स्व-संशोधन और आलोचनात्मक का परिचालन परिणाम──CRITIC 捕捉到了 स्व-संशोधन 漏掉的事实错误, क्योंकि बाहरी सत्यापनकर्ता 拥有自我批判 不具备的基础──

## 关键术语

| Term | 人们怎么说 | 它实际是什么意思 |
|------|----------------|------------------------|
| Self-Refine | “会修复自己的 LLM” | 在一个 model 中执行 Generate -> feedback -> refine loop，并带 history |
| CRITIC | “Tool-grounded verification” | 用外部 verifier（search、code、calc、tests）替换 feedback |
| Evaluator-Optimizer | “Anthropic workflow pattern” | 两个角色：evaluator 打分，optimizer 修订，并循环到收敛 |
| Output guardrail | “Post-hoc check” | OpenAI Agents SDK validator，在 agent 生成输出后运行 |
| Verify step | “Critique phase” | 承重决策点：grounded 还是 self-rated |
| Refine history | “Model 已经尝试过的内容” | 先前 outputs + critiques 被前置到 refine prompt；去掉后质量会崩塌 |
| Rubber-stamp loop | “Self-agreement failure” | 相同 prompt 的 critique 返回 “looks good”；用结构上不同的 prompts 修复 |
| Stop condition | “Convergence test” | Verifier 通过，或没有 feedback 且达到 iteration cap；绝不能只有单一条件 |
