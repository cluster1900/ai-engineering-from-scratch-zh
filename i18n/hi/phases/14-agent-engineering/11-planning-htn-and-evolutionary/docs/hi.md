1. **可证明正确的 plans。**नियोजन, उड़ान पथ, अनुपालन कार्यप्रवाह  योजना  निर्माण पर होना चाहिए  ध्वनि  एक प्रवाह  लेकिन कभी-कभी भ्रम  चरणों का LLM योजना  अस्वीकार्य है

## 概念

### पदानुक्रमिक कार्य नेटवर्क

HTN 包含:

- **Tasks** यौगिक (अवरोधित) और आदिम (प्रत्यक्ष निष्पादन)
- **Methods** एक जटिल कार्य को उप-कार्य में विभाजित करने के तरीके को पूर्व शर्तों के साथ प्रस्तुत करना
- **Operators** 带有前条件和效果的原始行动──
- **State** एक संच तथ्य

नियोजनः एक लक्ष्य कार्य तथा प्रारंभिक स्थिति निर्धारित करें, एक को विभाजित करें, जिससे यह पूर्व शर्तों में बदल जाए 按顺序满足的原始运算者──

एचटीएन पहले ही एलएलएम में आया था और अभी भी सही योजनाओं का प्रमाणन करने योग्य संदर्भ विधि है।

### अल्फाईवोल्व (नोविकोव एट अल., 2025)

अल्फा इवोल्व (ArXiv:2506.13131, डीपमाइंड, जून 2025) एक और प्रकार की चीज हैः जेमिनी 2.0 फ्लैश / प्रो एंसम्बल द्वारा 编排的进化代码搜索──

लूप:

1. से बीज कार्यक्रम + कार्यक्रम मूल्यांकनकर्ता 开始(返回 फिटनेस स्कोर)。
2. LLM समूह  उत्परिवर्तन प्रस्तावित किया गया
3.                                                                                                                                                                                                                                                               
4. सबसे अच्छा रखना; जारी रखें उत्परिवर्तन करना

已发表成果:

- 56 वर्षों में पहली बार सुधार हुआ स्ट्रैसन का 4x4 जटिल मैट्रिक्स गुणा (48 बार स्केलर गुणा)
- 通过 बोर्ग शेड्यूलिंग हेरिस्टिक 恢复 0.7% का गूगल कंप्यूटिंग 
- फ़्लैशअटेंशन गति 32% तक पहुंचाने के लिए सीमावर्ती कार्यभार में वृद्धि

硬性约束:फिटनेस फ़ंक्शन 必须可由机器检查──

### 何時使用哪个

| 问题类别 | 使用 | 原因 |
|---------------|-----|-----|
| 带硬约束的 Scheduling | HTN + ChatHTN | 可证明的 soundness |
| Compiler optimization | AlphaEvolve | 机器可检查的 fitness |
| Multi-step task execution | ReAct / ReWOO | LLM in the loop，没有 formal guarantees |
| 带 tests 的 Code improvement | AlphaEvolve | Tests 就是 evaluator |
| Policy-bound automation | HTN | Preconditions 编码 policy |

### यह तरीका आसान है

- **没有 operators 的 HTN。**没有前条件/效果方案,健全性 主张就会崩塌──ChatHTN के LLM का सुझाव है विघटन要求方案 能拒绝无效运动──
- **没有真实 evaluator 的 AlphaEvolve。** पूछना LLM 代码 क्या बेहतर  नहीं फिटनेस फ़ंक्शन है― मूल्यांकनकर्ता  अनिवार्य  अनिश्चित  और त्वरित 
- **过度工程化。**अधिकांश एजेंट कार्यों को इन दोनों की आवश्यकता नहीं है।

##  इसे निर्माण

`code/main.py` दो खेल के उदाहरणों को प्राप्त किया गयाः

- एक स्टडलिब एचटीएन प्लानर, जिसमें ऑपरेटर, पद्धति, पूर्व शर्तें, प्रभाव शामिल हैं, तथा जब कोई विधि नहीं होती है संयोजित कार्य `LLMFallback`LLM एक scripted decomposer है, इसलिए प्लानर 可离线运行──
- एक अंकगणितीय कार्यक्रमों के लिए स्ट्डलिब विकासवादी खोजः वृद्धि अभिव्यक्ति, make its output in test set 上 न्यूनतम `|f(x) - target|` मूल्यांकनकर्ता  निर्धारक 

运行:

```
python3 code/main.py
```

Trace 会展示 HTN प्लानर 分解一个复合任务 (中途带一次LLM fallback) तथा विकासात्मक लूप 收到一个目标表达──

## इसका उपयोग करें

- **HTN planners** `pyhop``SHOP3`, या डोमेन-विशिष्ट नीति प्रवर्तन के लिए  अपने स्वयं के निर्माण 
- **ChatHTN** अनुसंधान कोड; यह मोड (चित्रात्मक + LLM fallback) किसी भी HTN योजनाकार पर लागू किया जा सकता है
- **AlphaEvolve** DeepMind पेपर; यह मोड(ensemble + evaluator)可复现──OpenEvolve 和类似开源叉 正在出现──
- **Agent frameworks** वर्तमान में पहले श्रेणी का कोई HTN या AlphaEvolve नहीं है।

## 关键术语

| 术语 | 人们的说法 | 实际含义 |
|------|----------------|------------------------|
| HTN | “Hierarchical planner” | 带有 operators、preconditions、effects 的 task decomposition |
| Method | “Decomposition rule” | 将 compound task 拆分为 subtasks 的方式 |
| Operator | “Primitive action” | 带有 precondition 和 effect 的具体步骤 |
| ChatHTN | “LLM + HTN” | 当没有 method 匹配时，symbolic planner 询问 LLM |
| AlphaEvolve | “Evolutionary code search” | Ensemble LLMs mutate code；deterministic evaluator 负责选择 |
| Fitness function | “Evaluator” | 针对 outputs 的 deterministic、机器可检查 score |
| Online method learning | “Cached LLM decomposition” | 存储并泛化 LLM plans，以降低 query cost |
