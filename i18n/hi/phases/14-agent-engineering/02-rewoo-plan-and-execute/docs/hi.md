# रिवो और प्लान-एंड-एक्ज्यूट:解式规划

> ReAct एक धारा में 中交错思想和行动――ReWOO उन्हें अलग करेगा: पहले एक पूर्ण बड़ी योजना बनाएं, फिर निष्पादित करें―― टोकन  घटाएं 5x, हॉटपॉटQA पर सटीकता  बढ़ाएं +4%, और आप प्लानर को 7B मॉडल में डिस्टिल कर सकते हैं――प्लान-एंड-एक्सक्यूट इसे व्यापक रूप से विकसित करेगा; प्लान-एंड-एक्ट इसे वेब नेविगेशन में विस्तारित करेगा――

**类型：**构建
**语言：**पायथन (stdlib)
**先修要求：**चरण 14 · 01 (एजेंट लूप)

## 学习目标
- 解释为什么ReWOO के प्लानर / वर्कर / सॉल्वर 拆分相比ReAct के交错循环 能省 टोकन并提升强度──
- 实现 एक योजना DAG、 एक क्रमबद्ध निष्पादन करने वाला निष्पादक, तथा एक संयोजन कार्यकर्ता आउटपुट का हलकर्ता  全部 उपयोग stdlib。
- उपयोग 2026 साल पांच कार्यप्रवाह पैटर्न 框架 Anthropic), निर्णय कार्य योजना-फिर-कार्यकारी अथवा交错式 ReAct──
- 识别什么时候 योजना-और-कार्य के सिंथेटिक योजना डेटा दीर्घकालिक वेब या मोबाइल कार्यों के लिए आवश्यक है

## 问题
ReAct का विलय सोच-क्रिया-निरीक्षण लूप  सरल और लचीला है, लेकिन प्रत्येक उपकरण कॉल  के पूर्ण पूर्व संदर्भ  सहित पूर्व में प्रत्येक विचार  को ले जाना चाहिए।

ReWOO(Xu et al., arXiv:2305.18323, May 2023) इस बात पर ध्यान देते हुए, एक विकल्प बनाया: पहले पूर्ण नियोजन, समानांतर  सबूत प्राप्त करना, अंतिम संयोजन उत्तर देना। एक बार एलएलएम कॉल उपयोग करने के लिए नियोजन, N बार उपकरण कॉल उपयोग करने के लिए सबूतों के लिए उपयोग करना।

## 概念
### तीन भूमिकाएँ

```
Planner:  user_question -> [plan_dag]
Workers:  [plan_dag]     -> [evidence]        (tool calls, possibly parallel)
Solver:   user_question, plan_dag, evidence -> final_answer
```

नियोजक एक DAG उत्पन्न करते हैं। प्रत्येक नोड एक उपकरण, उसके तर्क, और यह निर्भर करता है जो कुछ पहले के नोडों के लिए विशिष्ट हैं। उदाहरण के लिए,`#E1``#E2`इस प्रकार के संदर्भ) ・ श्रमिक  शीर्षिकीय क्रम  निष्पादन नोड्स── सॉल्वर सभी सामग्री को एक साथ拼接 करेगा──

### क्यों 5 गुना कम टोकन

ReAct की शीघ्र लंबाई 会随步数 线性增长──在第十步, शीघ्र 包含思想 1加行动 1加观察 1加思想 2加行动 2加观察 2,依此类推── प्रत्येक मध्यवर्ती चरण में अतिरिक्त冗余包含原始提示──

ReWOO केवल एक बार भुगतान योजनाकार शीघ्र(较大) 、N 个小工人 शीघ्र(प्रत्येक केवल उपकरण कॉल, कोई श्रृंखला नहीं) और एक बार समाधानकर्ता शीघ्र──论文在 HotpotQA 上测得 टोकन 减少约5x,同时绝对精度 提升 +4──

### यह अधिक मजबूत क्यों है

यदि कार्यकर्ता 3 ReAct में विफल रहता है, तो लूप को स्ट्रिम में होना चाहिए त्रुटियों से मध्य मार्ग में पुनः प्राप्ति का विचार करना चाहिए।

### प्लानर डिस्टिलिशन

论文的第二个结果:因为规划师看不到观测,你可以用175B शिक्षक के规划师的输出来细节调整一个7B模型──小模型 负责规划;大模型 在推断时不再需要──现在已经很常见 许多2026生产代理使用小规划师 和大执行员,或反过来使用──

### योजना और निष्पादन (लंगचेन, 2023)

LangChain 团队 में 2023 साल के अगस्त के लेख में ReWOO 泛化为一个模式名称:Plan-and-Execute──Up-front planner 输出一个步骤列表,执行人 执行人 执行人 每一步,可选的重组规划者 可以在观察结果后进行修改──这比 ReWOO 更接近 ReAct(重组规划者 会将观察带回规划),但保留了令牌节省──

### योजना और अधिनियम (एर्दोआन एट अल., arXiv:2503.09572, ICML 2025)

योजना-और-कार्य इस पैटर्न को विस्तारित करेगा लंबी दूरी की वेब और मोबाइल एजेंटों में। महत्वपूर्ण योगदान सिंथेटिक योजना डेटा हैः एक लेबलबद्ध ट्रैक्टरी जनरेटर। यह योजना के प्रशिक्षण डेटा को स्पष्ट रूप से शामिल करता है। यह वेबएरेना जैसे कार्यों में ठीक-ठीक योजनाकार मॉडल के लिए उपयोग किया जाता है, जो इसे 30-50 से अधिक चरणों के बाद भी सामान्य काम कर सकता है, जबकि एकल खंड ReAct ट्रैक्टरी इस श्रेणी के कार्यों में एकीकरण खो देगा।

### कौन सी चुनना है

| Pattern | When |
|---------|------|
| ReAct | 短任务、未知 environment、需要 reactive exception handling |
| ReWOO | 具备已知 tools 的结构化任务、对 token 敏感、evidence 可 parallelize |
| Plan-and-Execute | 类似 ReWOO，但在 partial execution 后支持 replanning |
| Plan-and-Act | Long-horizon（>30 步）、web/mobile/computer-use |
| Tree of Thoughts | Search 值得付出成本（Lesson 04） |

मानव विज्ञान का 2024 साल 12 月指导: सबसे सरल तरीके से शुरू करें। यदि कार्य केवल एक उपकरण कॉल है, एक सारांश जोड़ें, तो ReWOO का निर्माण न करें। यदि कार्य 40 चरणों का अनुसंधान कार्य है, तो केवल ReAct का उपयोग न करें।

##  इसे निर्माण
`code/main.py`实现一个玩具版 ReWOO:

- `Planner` एक स्क्रिप्ट नीति, शीघ्र 输出 योजना DAG के अनुसार
- `Worker`  रजिस्ट्री के माध्यम से प्रत्येक नोड का उपकरण कॉल 分发
- `Solver` स्क्रिप्ट रचना, पढ取 सबूत并生成 अंतिम उत्तर──
- निर्भरता संकल्प  类似 `#E1`के संदर्भों को पहले के श्रमिक आउटपुट के लिए बदल दिया जाएगा।

इस डेमो  उत्तर फ्रांस की राजधानी की जनसंख्या कितनी है, लाखों में गोल?, उपयोग दो चरण योजना:(1) राजधानी ढूँढना,(2) जनसंख्या ढूँढना, फिर मांगना

运行它:

```
python3 code/main.py
```

पहले पूर्ण योजना दिखाएँ, फिर कार्यकर्ताओं के परिणाम दिखाएँ, अंतिम रूप से समाधान की संरचना दिखाएँ।

## 关键术语
| Term | What people say | What it actually means |
|------|----------------|------------------------|
| ReWOO | “Reasoning without observations” | 先 plan，然后 parallel 获取 evidence，最后 solve —— planning prompt 中没有 observations |
| Plan-and-Execute | “LangChain's plan-execute pattern” | ReWOO 加上 execution 后可选的 replanner node |
| Plan-and-Act | “Scaled plan-execute” | 显式 planner/executor 拆分，并用 synthetic plan training data 支持 long-horizon tasks |
| Evidence reference | “#E1, #E2, ...” | plan-node placeholder，在 dispatch 时用先前的 worker output 替换 |
| Planner distillation | “Small planner, big executor” | 用 large teacher 的 planner traces 来 fine-tune small model |
| Token efficiency | “Fewer round trips” | 论文中在 HotpotQA 上相对 ReAct 减少 5x tokens |
| DAG executor | “Topological dispatcher” | 按 dependency order 运行 plan nodes；每一层可 parallel |
