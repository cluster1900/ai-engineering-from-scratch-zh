शुद्ध पाठ परिणाम समय रेखा का वर्णन कर सकते हैं, लेकिन उपयोगकर्ता को एक गतिशील समय रेखा प्रदान नहीं कर सकते हैं जिसे वे स्वतंत्र रूप से चुन सकते हैं, समीक्षा कर सकते हैं या बातचीत कर सकते हैं।

## 核心概念

### दो प्रोटोकॉल लेयर, एक पूर्ण विशेषता

保持清晰的分层视角:

1. एमसीपी 核心协议承载 `server/discover``tools/list``tools/call``resources/list`और `resources/read`
2. MCP Apps  विस्तारित करने के लिए घोषणा UI,并定义 iframe到主机的桥接交互──
3. ब्राउज़र सा बॉक्स नियम इस UI की सीमाओं को सख्ती से सीमित करते हैं।

扩展标识符为 `io.modelcontextprotocol/ui`◊ दोउन्दे दोनों विकल्पों का उपयोग करते हैं ◊ ऑप्ट-इन तंत्र।

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "server/discover",
  "params": {
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {
        "extensions": {
          "io.modelcontextprotocol/ui": {}
        }
      },
      "io.modelcontextprotocol/clientInfo": {
        "name": "timeline-host",
        "version": "1.0.0"
      }
    }
  }
}
```

`clientInfo` निदान के लिए अनुशंसित  यह स्व-घोषणात्मक डेटा है, जो कि पहचान के अधिकार का प्रमाण नहीं है

### 染前发现声明

सर्वर की खोज के परिणाम इस विस्तार का समर्थन करते हैंः

```json
{
  "resultType": "complete",
  "supportedVersions": ["2026-07-28"],
  "capabilities": {
    "tools": {},
    "resources": {},
    "extensions": {
      "io.modelcontextprotocol/ui": {}
    }

  "ttlMs": 300000,

  "_meta": {
    "io.modelcontextprotocol/serverInfo": {
      "name": "timeline-app-server",
      "version": "2.0.0"
    }
  }
}
```

सर्वर को खोज का समर्थन करना चाहिए। लेकिन ग्राहक को खोज को हर गति से पहले नहीं जाना चाहिए क्योंकि प्रत्येक गति से स्वयं अपनी क्षमताएं होती हैं।

### में टूल  परिभाषा में UI का वर्णन करें

现代 Apps 契约在 `tools/list`中将 UI  बंधा विशिष्ट उपकरण मेंः

```json
{
  "name": "notes_timeline",
  "description": "Render a timeline of notes.",
  "inputSchema": {
    "type": "object",
    "properties": {}
  },
  "_meta": {
    "ui": {
      "resourceUri": "ui://notes/timeline.html"
    }
  }
}
```

यह पूर्व-उपयोगी स्थैतिक डेटा के लिए डिज़ाइन किया गया है। होस्ट HTML को वास्तविक रूपांतरण परिणामों की आवश्यकता से पहले प्रदर्शित कर सकता है, पूर्व-लोड, कैश और उस HTML पर सुरक्षा समीक्षा कर सकता है। हालांकि संगतता कोड पुराने संस्करण के 平元 डेटा कुंजी को स्वीकार कर सकता है, लेकिन नए निर्मित सर्वर  को एकीकृत आउटपुट नेम्बेट का उपयोग करना चाहिए।`_meta.ui.resourceUri` संरचना

वर्तमान में केंद्रीय विनियमों में`tools/list`                                                                                                                                                                                                                                                              `ttlMs`और `cacheScope`यदि उपयोगकर्ता या प्रमाणपत्र के आधार पर कोई अंतर है, तो कृपया उपयोग करें `private`

### App  के रूप में संसाधन  सेवा प्रदान करने

由于 सर्वर में खोज में घोषणा की `resources`, इसलिए अनिवार्य को लागू करना होगा।`resources/list`操作──其确定性列表条目包含规范 URI、稳定的名称、描述以及 MIME 类型──列表结果也包含 `resultType`、सर्वर अपने डेटा की पहचान करें`ttlMs`和 `cacheScope`, जैसा कि निश्चितता के उपकरण 列表一样.

मेजबान 发送 `resources/read`在 Streamable HTTP 上, अनुरोध निम्न संरचना के साथ हैः

```text
POST /mcp
MCP-Protocol-Version: 2026-07-28
Mcp-Method: resources/read
Mcp-Name: ui://notes/timeline.html
```

### यूआई संसाधन 视作可执行内容缓存

एप संसाधन सामान्य पाठ सामग्री से वास्तविक भिन्नता है। इसका कैशिंग अनुक्रम पुल कोड, रेंडर उपकरण, डेटा और अनुरोध होस्ट, एजेंट के आंदोलनों को निष्पादित करने में सक्षम है।`cacheScope`निजी तौर पर, भंडारण कुंजी में विनियमन शामिल होना चाहिए।`ui://`यूआरआई, प्रवेश सर्वर, संस्करण, संसाधन, सामग्री सारांश और पहचान अधिकार पर नीचे दिए गए। किसी भी विषय के पार निजी ऐप संसाधन का उपयोग करने की आवश्यकता नहीं है, क्योंकि यहां तक कि यूआरआई पूरी तरह से एक ही है, HTML के अंदर या इसके रणनीति डेटा में भी महत्वपूर्ण अंतर हो सकता है।

निम्नलिखित परिस्थितियों में कैशिंग को निष्क्रिय करना अनिवार्य हैः`ttlMs`तक期 工具 的 `_meta.ui.resourceUri`绑定发生变化、服务器 版本或准入描述符固定指纹变化, या पहले से ही पुष्टि संसाधन परिवर्तन सदस्यता में इस URI को निर्दिष्ट किया गया है. पुनः अपलोड करने के लिए, यह आवश्यक है कि CSP और अधिकार समीक्षा को फिर से लोड किया जाए।

校验逻辑 के पास सख्त पूर्व क्रम हैः पहले JSON-RPC प्रारूप का校验 करें, अनिवार्य आवश्यकताएँ स्ट्रिंग प्रोटोकॉल डेटा और वस्तु प्रकार के क्लाइंट क्षमताओं का मानचित्रण करें; फिर जांच करें कि रूट के अनुरोध का शीर्षक सही सामग्री के साथ मेल खाता है या नहीं; अंतिम निर्णय लें कि क्या उपयुक्त प्रोटोकॉल संस्करण समर्थित है। यह क्रम प्रभावी रूप से एक ही अनुरोध के लिए अंतर-विचार को रोकने में सक्षम है।

| 异常情况 | HTTP 状态码 | JSON-RPC 错误 |
|---|---|---|
| 请求头与正文在版本、方法或名称上不一致 | 400 | `-32020` |
| 请求头与正文一致，但版本不受支持 | 400 | `-32022`，且 `data` 准确为 `{"supported":["2026-07-28"],"requested":"<实际版本>"}` |
| `resources/read` 缺少 Apps 扩展 capability | 400 | `-32021`，附带 `data.requiredCapabilities.extensions.io.modelcontextprotocol/ui` |
| 请求的方法未知 | 404 | `-32601` |

JSON-RPC सूचना 没有 `id`, इसलिए सर्वर 绝不能为其生成 JSON-RPC 响应── स्वीकृत HTTP अधिसूचना 会返回带有空正文的 202── हालांकि त्रुटि HTTP 状态码 को बदल सकती है, लेकिन अभी भी अधिसूचना के लिए उत्पन्न नहीं कर सकती  JSON-RPC 错误正文──

### अनुप्रयोगों के लिए एक स्वतंत्र जीवन चक्र है

अनुप्रयोगों के लिए एक पुल पर हस्ताक्षर किए गए हैं`postMessage`之上 JSON-RPC 方言──它可以交换 `ui/initialize``ui/*`通知, भी कर सकते हैं एजेंट की तरह केंद्रीय समझौते के तरीकों`tools/call`)。

दृश्य 发送带有 `appInfo`和 `appCapabilities`वस्तुओं के`ui/initialize` होस्ट  अपनी क्षमताओं को वापस करने के लिए होस्ट  से ऊपर नीचे नीचे  के साथ  केवल इस प्रतिक्रिया प्राप्त करने के बाद,View 才会发送 `ui/notifications/initialized`होस्ट को प्रतीक्षा करनी होगी ऐप्स को सूचना भेजने के बाद, पहुंचने के लिए प्रसारण संदेश

इसने एक ही iframe और एक ही होस्ट विंडो के बीच एक पुल बनाया है। यह MCP 协议 संस्करण पर चर्चा करने के लिए जिम्मेदार नहीं है, सर्वर  स्टेटस नहीं बनाता है, न ही ट्रांसफर लेयर बैठक बनाता है।`notifications/initialized` हटा दिया गया है, जबकि अनुप्रयोग  विस्तारित में `ui/notifications/initialized`依然保留── पुल के माध्यम से उत्पन्न उपकरण 调用所触发的核心请求, एक पूर्ण नया JSON-RPC id और पूर्ण अनुरोध के लिए स्वतंत्र अनुरोध 

### मेजबान 上下文、动作代理与权限撤销

पुल के मार्ग के प्रारंभ के बाद, होस्ट  सर्वोच्च अधिकार को बनाए रखता है।  केवल होस्ट द्वारा स्पष्ट घोषणाओं की क्षमता को देखने के लिए अनुरोध करने के लिए उपकरण  गति  पृष्ठ  मार्गनिर्देशन  क्लिपबोर्ड उपयोग या अन्य विशेषताओं का परिणाम  होस्ट बैठक  प्रयोग  अनुरोध  वर्तमान उपयोगकर्ता  संचालन लक्ष्य और पैरामीटर, अनुप्रयोग अनुमोदन रणनीति, और अस्वीकार करने की शक्ति को बनाए रखने  क्लिक करें  कानूनी पुल के संदेश केवल इरादे का प्रतिनिधित्व करते हैं, दोनों को कोई वास्तविक अधिकार नहीं दिया गया है।

विषय, आकार और सहजता को गतिशीलता में परिवर्तन के मेजबान के रूप में देखना ऊपर नीचे, एक बार में नहींः

- 应用 होस्ट  प्रदान रंग और संस्करण टोकन, और विषय या तुलना की वरीयता में परिवर्तन वास्तविक समय प्रतिक्रिया
-  अनुमति दी गई है देखने के लिए ऊपर रिपोर्ट करने के लिए अपनी अपेक्षाओं का आकार, लेकिन होस्ट द्वारा  प्रतिबंधित और लागू आईफ़्रेम आकार, सामग्री के रूपरेखा से बाहर या निर्माण धोखाधड़ी को कवर परतों को रोकने के लिए
- iframe  आंतरिक में कीबोर्ड की दिशा क्रम 可见焦点 无障碍名称 屏幕 पाठक की स्थिति 充足的对比度 缩放支持以及减弱动画 
- विंडो में आकार और पुनः प्रसंस्करण के बाद, पुनः परीक्षण मेजबान 控件 और दृश्य 控件 के बीच फोकस स्थानांतरण।

ऐप के खुलने के दौरान, उपयोगकर्ता खाते में बदलाव के कारण, सुरक्षा रणनीति में बदलाव, सर्वर पर अलग-अलग जांच या होस्ट की कमी से संबंधित क्षमताओं को हटा दिया जा सकता है।`ui/initialize`握手时检查── एक बार अधिकार निरस्त होने पर, तत्काल अनन्य अधिकारों का उपयोग करने से इनकार करना चाहिए, रणनीतिक नेटवर्क गतिविधि के अनुरूप नहीं होना चाहिए, संवेदनशील संक्रमित स्थिति को साफ करना चाहिए, और यूआई संसाधन में प्रवेश करने पर पुनः अपलोड या डाउनग्रेड करना चाहिए।

## 关键术语

| 术语 | 含义 |
|------|---------|
| MCP Apps | 由 MCP host 渲染交互式 HTML 的可选扩展规范 |
| `io.modelcontextprotocol/ui` | 通信双方声明的扩展标识符 |
| `ui://` | 用于标识 App UI 模板的专用 resource scheme |
| `text/html;profile=mcp-app` | 用于 MCP App HTML 的标准 MIME 类型 |
| `server/discover` | 用于协议与 capability 发现的当前规范 RPC 方法 |
| `resources/list` | 当 server 声明支持 resources 时强制必须实现的资源枚举方法 |
| `resultType` | 现代协议规范中成功的返回结果所必须携带的判别器 |
| `ui/initialize` | Apps 桥接通道的首个请求，与已移除的核心协议握手完全独立 |
| `ui/notifications/initialized` | Apps View 在收到 host 响应后发出的就绪通知 |
| CSP | 用于限制脚本、样式、图片和网络 origin 的浏览器内容安全策略 |
| 文本降级（Text fallback） | 面向不支持 Apps 扩展的 host 所保留的 tool 基础行为 |
