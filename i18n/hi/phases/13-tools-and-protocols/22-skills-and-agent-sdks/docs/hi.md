# एजेंट कौशल: हस्तांतरण करार एवं परिचालन समय सीमा

> कौशल केवल एक बेहतर फ़ाइल नाम का परिवर्तन करने का एक लंबा संकेत नहीं है। यह एक निर्देश, संसाधन और निष्पादित सहायक उपकरण के साथ एक खोज योग्य प्रोग्राम पैकेज है, जो स्पष्ट रूप से संचालित होने के दौरान एजेंट के अनुबंध में शामिल है।

**Type:** Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 13 · 01 (The Tool Interface), Phase 13 · 05 (Tool Schema Design)
**Time:** ~90 minutes

## 学习目标

- 明确定义 एजेंट कौशल,不将其与 prompt、代码库规范文件(रिपॉजिटरी निर्देश) 、工具、 हुक、subbagent या प्लगइन 混──
- 研读可移植的 `SKILL.md`契约,并将其与特定运行时专专有扩展清晰解──
- 将服务发现 (Discovery) 选择 (Selection) 激活 (Activation) 资源加载 (Resource Loading) 工具调用 (Tool Use) 验证 (Verification) 解释为独立的生命周期阶段──
- प्रचालन के दौरान कौशल को एजेंट  कौशल सूची में शामिल किया जाएगा, इसके सॉफ्टवेयर पैकेज पर कठोर स्थिरता सत्यापन लागू किया जाएगा।
-  विशिष्ट परियोजना कार्यों के लिए, कौशल MCP उपकरण हुक उपयोगी या साधारण कोड के बीच तर्कसंगत तकनीकी चयन प्रकारों को बनाना

## 十分钟极速初体验

इस कार्य को पहले पूरा करें। आप एक सूक्ष्म कौशल का निर्माण करेंगे, पूर्ण परीक्षक प्रोग्राम पैक को वास्तविक एजेंट होस्ट वातावरण में स्थापित करेंगे, इसका उपयोग करेंगे, परिणामों का परीक्षण करेंगे, और इसे उतारेंगे।

### वास्तविक मेजबान प्रयोग पूर्वस्थापना जाँच

असली मेजबान चेक पॉइंट Node.js की जरूरत है`npx`、पायथन 3、 एक चयनित समर्थित कौशल के होस्ट वातावरण, तथा आपके द्वारा इंस्टॉलर में चुने गए प्रोजेक्ट या उपयोगकर्ता भूमिका क्षेत्र पर लेखन अधिकारों का प्रयोग करना।

```bash
node --version
npx --version
python3 --version
```

स्थापना से पहले, पहले निर्धारित करें कि आप किस होस्ट और स्थापना भूमिका क्षेत्र का उपयोग करना चाहते हैं। यदि उपरोक्त किसी भी निर्भरता की कमी है, तो आप इस पाठ्यक्रम को वेबसाइट पर पढ़ सकते हैं, या सीधे नीचे दिए गए सॉफ्टवेयर पैक में हाथ से अभ्यास कर सकते हैं।

### 1. से空工作目录开始

भंडारण के लिए प्रयोग किए जाने वाले अध्ययन परियोजनाओं के लिए निम्न कार्य निष्पादित करेंः

```bash
mkdir -p agent-skills-first-run
cd agent-skills-first-run
TARGET_ROOT="$(pwd -P)"
printf 'TARGET_ROOT=%s\n' "$TARGET_ROOT"
ls -A
```

अंतिम एक आदेश में कोई आउटपुट नहीं होना चाहिए। यदि कोई आउटपुट है, तो कृपया एक रिक्त सूची बदलें ताकि इस समीक्षा में शुद्ध स्पष्ट सीमाएं हों।

अपने पहले कौशल के लिए  Create Catalogue:

```bash
mkdir -p my-first-skill
```

创建 `my-first-skill/SKILL.md`, सामग्री इस प्रकार हैः

```markdown
---
name: my-first-skill
description: Turn rough meeting notes into a compact decision record when the user asks to capture a technical decision.
---

# Decision record

Extract the decision, context, alternatives, owner, and next review date.
If the notes do not contain a decision, ask one clarifying question instead
of inventing one.
```

验证该文件是否已成功创建目标目录中:

```bash
test -f my-first-skill/SKILL.md
```

无任何输出和退出码为 0 表示文件已存在──

### 2. पूर्ण जाँच यंत्र संकुल स्थापित

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             `agent-skills-first-run`वर्तमान में:

```bash
npx skills add cluster1900/ai-engineering-from-scratch-zh --skill skill-contract-reviewer --full-depth
```

选择你当前正在使用的代理 宿主和作用域──安装器会列出 `skill-contract-reviewer` और इसके लेखन के लक्ष्य स्थान  अवश्य जोड़ा जाना चाहिए `--full-depth`参数, क्योंकि इस वर्ग में प्रदान की जाने वाली कौशल एक ऐसी है जिसमें संदर्भ, स्क्रिप्ट और स्थैतिक संपत्ति का एक ढांचा है।

`SKILL_ROOT`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             `SKILL.md`का सूची, न कि पाठ्यक्रम स्रोत सूची, न ही वर्तमान कार्यक्षेत्रः

```bash
# 将占位符替换为安装器打印出的绝对路径
SKILL_ROOT="$(cd "/absolute/path/to/skill-contract-reviewer" && pwd -P)"
test -f "$SKILL_ROOT/SKILL.md"
printf 'SKILL_ROOT=%s\n' "$SKILL_ROOT"
```

यदि मेजबान बैठक पहले से ही खुल चुकी है, तो कृपया नई बैठक शुरू करें या मेजबान कौशल का उपयोग करें।

### 3. 显然调用 यह

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             `agent-skills-first-run`कार्यसूची के लिए, इस मेजबान द्वारा समर्थित स्पष्ट भाषा का उपयोग करेंः

| 宿主 | 显式调用方式 |
|---|---|
| Codex | 输入 `skill-contract-reviewer`，或从 `/skills` 菜单中选择，然后提交审查请求 |
| Claude Code | 输入 `/skill-contract-reviewer` 紧跟审查请求 |
| 通用可移植回退 | `Use skill-contract-reviewer to review the target package.` |

अनुरोध में उपयोग मुद्रित `SKILL_ROOT`和 `TARGET_ROOT`绝对路径── आवश्यकताएँ होस्टिंग के लिए वर्तमान कार्यसूची के अमूर्त आदेशों पर निर्भर नहीं होने के बजाय, निष्पादन से पहले अपने आदेशों को पूरा करने और प्रदर्शित करने के लिएः

```text
Use skill-contract-reviewer to review <TARGET_ROOT>/my-first-skill. The installed bundle root is <SKILL_ROOT>. Run python3 <SKILL_ROOT>/scripts/check_skill.py <TARGET_ROOT>/my-first-skill. Before running it, show the fully resolved argv. Return the validation report, selected primitives, and one sentence for each selection. Include the resolved script path, resolved target path, cwd, argv, and exit code as execution evidence.
```

解析后的命令应呈现如下结构,不留任何未填充的占位符:

```bash
python3 "/absolute/install/path/skill-contract-reviewer/scripts/check_skill.py" \
  "/absolute/workspace/path/agent-skills-first-run/my-first-skill"
```

सफल परीक्षा के परिणाम निम्नलिखित तीन विशेषताओं को पूरा करते हुए प्राप्त किए जाने चाहिएः

1. 宿主能按名称准确找到 `skill-contract-reviewer`
2. 审查器 सफलता读取程序包契约并运行其附带的验证脚本──
3. प्रतिक्रिया में एक सत्यापन रिपोर्ट शामिल है, जिसमें उदाहरण शामिल हैं, जिसमें संरचनात्मक त्रुटि नहीं है, और बुनियादी संरचनात्मक चयन के लिए उचित सुझाव दिए गए हैं।

执行证据中还必须明确列出脚本路径、目标路径、当前工作目录(cwd)、精确参数数组(argv) 以及退出码──一个缺乏这些段的流报告并不能证明附带的配套脚本确实执行了──

यदि मेजबान ने इस कौशल की रिपोर्ट करने की आवश्यकता नहीं है, तो कृपया स्थापना लक्ष्य पथ, पुनः स्कैन या फिर से शुरू करने की जांच करें।

### 4. 探查隐式选择(अवसरित चयन)

एक नया एजेंट बारी खोलें, एक ही कार्य में प्रवेश लेकिन**不提及**इस कौशल का नामः

```text
Review <TARGET_ROOT>/my-first-skill as a reusable agent package and tell me whether its package contract is valid.
```

यदि मेजबान ने उपयोगकर्ता को चुने गए कौशल दिखाए, तो रिकॉर्ड करें कि क्या यह स्वचालित रूप से चुना गया है।`skill-contract-reviewer` यदि मेजबान निर्णय के मार्ग के विवरण का खुलासा नहीं करता है, तो गुप्त चयन को अप्रत्याशित के रूप में चिह्नित किया जाएगा स्पष्ट उपयोग हमेशा के लिए मेजबान के पार-परिवहन योग्यमूल साधनों है

### 5.  स्वच्छ वातावरण

仅移除已安装的审查器程序包:

```bash
npx skills remove skill-contract-reviewer
```

选择与安装时相同的主人和作用域──在重新扫描或新建会话后,显然请求 `skill-contract-reviewer` इस कौशल को वापस करना चाहिए अपरिहार्य. आप रख सकते हैं `my-first-skill`पश्चात पाठ्यक्रम का उपयोग करने के लिए, इस दिशा में सीखने के बाद प्रयोग सूची को पूरी तरह से हटाया जा सकता है

## 问题

假设您的团队拥有一套非常可靠的发布上线工作流:找出已合并的改动;检查数据库迁移说明;更新变更记录;执行打包命令;并输出上线审查清单;

यदि इस कार्यप्रवाह को सीधे एक लंबे प्रॉम्प्ट में डाला जाए, तो हालांकि इसे कॉपी करना आसान है, लेकिन इंजीनियरिंग में काम करने में त्रुटि सामने आती हैः इस प्रॉम्प्ट में स्थिर पहचान की कमी है, कोई सेवा नहीं है, कोई नियम नहीं है, कोई संसाधन नहीं है, कोई सीमा नहीं है, कोई पैकेज संरचना नहीं है, और बुनियादी इंजीनियरिंग के एक श्रृंखला के प्रश्नों का उत्तर नहीं दे सकता हैः इसका उपयोग करने का अधिकार किसके पास है? मॉडल को कब चुना जाना चाहिए? यह किस स्क्रिप्ट को निष्पादित कर सकता है? कौन से फाइलें विश्वसनीय हैं? ऊपर दिए गए लेख में संपीड़ित होने पर, कौन से मूल नियम जीवित रह सकते हैं?

इसके विपरीत, चरम त्रुटि, सभी दोहराए जाने योग्य निर्देशों को एक मस्तिष्क में एक कौशल में बनाना है। कोडबुक विनियमों, निश्चितता स्वचालित स्क्रिप्ट, बाहरी उपकरण, घटनाओं के लिए एक उपकरण और एक प्रतिनिधि द्वारा सौंपा गया है।`SKILL.md`, उत्पन्न कैटलॉग सामान्य संरचना के समान प्रतीत होता है, वास्तव में एक विशिष्ट मेजबान के अज्ञात व्यवहार को गहराई से बंधा करता है।

सॉफ्टवेयर इंजीनियरिंग का प्राथमिक कार्य है**分类**: इस पर विचार करने से पहले कि यह कैसे तैयार किया जाए, पहले यह पता लगाएं कि यह क्या है।

## 概念

### कौशल 封装过程性知识 (प्रक्रियागत ज्ञान)

एजेंट कौशल एक है`SKILL.md`इस प्रवेश पत्र में यमुना की मुख्य सामग्री शामिल है।

```figure
skill-package-anatomy
```

यह**目录**केवल एक ही मार्कडाउन फाइल ही है जो कि विदेश भुगतान के लिए न्यूनतम इकाई है।`SKILL.md`                                                                                                                                                                                                                                                              

### 临近概念辨析

| 构件类型 | 核心职责 | 何时加载或运行 | 不应被冒充为 |
|---|---|---|---|
| Prompt | 塑造单次模型交互 | 由应用或用户内联引入 | 包含丰富资源的带版本软件包 |
| 代码库规范（Repository instructions） | 阐明某特定代码库的固有通用准则 | 编码运行时进入该作用域时载入 | 可复用的具体任务工作流 |
| Agent Skill | 提供可复用的过程性知识 | 显式或隐式激活时载入 | 强安全隔离边界 |
| MCP Tool | 暴露类型化的远程能力 | 由模型或应用程序主动发起调用时 | 复杂详细的端到端操作步骤 |
| Hook（钩子） | 在特定事件发生时执行确定性逻辑 | 当所声明的事件发生时触发 | 具有概率性的模型自主路由 |
| Subagent（子代理） | 委托具有独立上下文和状态的任务 | 由编排器创建或调用时启动 | 静态的只读指令包 |
| Plugin（插件） | 分发更大规模的运行时功能扩展 | 宿主安装或启用它时生效 | 可移植的 skill 契约本身 |
| 习得的 Skill 库（Learned skill library） | 存储通过实践探索习得的行为沉淀 | 策略检索到先验程序或轨迹时 | 基于规范标准的 `SKILL.md` 软件包 |

### Skill एक शब्द के दो अलग-अलग विचार

वैज्ञानिक अनुसंधान के क्षेत्र में,  कौशल कभी-कभी सीखे गए प्रक्रम कोडों, सफल बातचीत के मार्गों, या विशिष्ट वातावरण के लिए रणनीति के टुकड़ों का संदर्भ देता है।

इस श्रृंखला के पाठ्यक्रम में एजेंट कौशल काफी अलग है। यह एक हाथ से लिखित या चयनित सॉफ्टवेयर पैकेज है, जिसमें स्पष्ट रूप से घोषित फ़ाइल सिस्टम अनुबंध, कौशल कैटलॉग और डेटा, प्रगतिशील प्रकटीकरण, संचालन समय द्वारा संचालित विनियमन तंत्र, और मेजबान द्वारा सख्ती से नियंत्रित उपकरण अधिकारों के साथ-साथ एक स्पष्ट रूप से घोषित सॉफ्टवेयर पैकेज है। यह एजेंट द्वारा सहायक उत्पन्न या सुधार किया जा सकता है, लेकिन इसका प्रारूप स्वयं मजबूत रसायन विज्ञान या खोज प्रशिक्षण पर निर्भर नहीं करता है।

| 评估维度 | Agent Skill 软件包 | 习得的 Skill 库 |
|---|---|---|
| 基本单元 | 包含 `SKILL.md` 的目录 | 程序代码、策略片段、交互轨迹或记忆记录 |
| 创建方式 | 人工编写、生成或精选策划 | 通常由 agent 在环境交互中自主探索习得 |
| 选用机制 | 依赖目录描述（Description）加运行时策略 | 基于任务状态的向量检索或策略匹配 |
| 执行方式 | 模型遵循 Markdown 指令并调用宿主工具 | 环境直接执行存储的行为逻辑或代码产物 |
| 可移植性 | 程序包契约可在所有兼容的宿主间流通 | 通常与特定环境及特定的动作空间深度绑定 |
| 评测标准 | 路由准确率、制品质量、安全及宿主兼容性 | 强化学习奖励值、任务成功率、泛化能力及库规模 |

इन दोनों विचारों में एक-दूसरे के लिए एक ही नाम के साथ एक-दूसरे के लिए एक ही परियोजना के रूप में एक ही नाम के साथ एक ही परियोजना के रूप में एक ही परियोजना के रूप में एक ही क्षमता है।

### पोषित करने के लिए मूल नियम

एजेंट कौशल 规范在前面中强制要求两个必填字段:

```yaml
---
name: release-readiness
description: Inspect a release candidate when the user asks whether a version is ready to publish.
---
```

`name`यह एक निश्चित पहचानकर्ता है, जो नियमों के अनुरूप होना चाहिए, और उसके साथ पूरी तरह से मेल खाना चाहिए।`description`यह मानव दृष्टि से उपलब्ध दस्तावेज है और भाषाई मार्ग के लिए एक मॉडल है।**能做什么**और**何时应当选用它**

核心规范允许的可选字段包括:

| 字段 | 用途 | 可移植性说明 |
|---|---|---|
| `license` | 声明该程序包的开源或商用许可条款 | 核心标准规范 |
| `compatibility` | 声明环境要求（如 Python 3.10+、特定 CLI 工具等） | 核心标准规范 |
| `metadata` | 携带字符串键值的自定义扩展数据 | 核心标准规范 |
| `allowed-tools` | 建议预先批准的工具列表 | 实验性特性；不同宿主支持度不一 |

मार्कडाउन में ऑपरेशन मार्गदर्शन शामिल है। इसे स्पष्ट रूप से कार्यप्रवाह की परिभाषा करना चाहिए।

```markdown
# Release readiness

Use this workflow for a release candidate, not for ordinary development builds.

1. Read `references/release-policy.md`.
2. Run `python3 scripts/inspect_release.py --format json`.
3. Stop if the report contains a blocking failure.
4. Produce the checklist from `assets/release-checklist.md`.
5. Ask for approval before any publish or tag action.
```

### 运行时扩展(रनटाइम एक्सटेंशन) है द्वितीय स्तर

部分 होस्टिंग अनुमति देता है अग्रिम सामग्री में अतिरिक्त फ़ील्ड या संबंधित विशिष्ट विन्यास फ़ाइलों में लिखने के लिए।

| 行为特性 | 宿主扩展示例 | 属于通用核心规范？ |
|---|---|:---:|
| 对模型自主路由隐藏，但保留用户手动直接调用 | `disable-model-invocation` | 否 |
| 对用户的命令菜单隐藏，但允许模型自主路由选用 | `user-invocable` | 否 |
| 在斜杠命令菜单中展示参数使用提示 | `argument-hint` | 否 |
| 在被委托的隔离子上下文中运行该 skill | `context`, `agent` | 否 |
| 固定模型型号或思考计算等级（Reasoning Effort） | `model`, `effort` | 否 |
| 注册生命周期自动化钩子 | `hooks` | 否 |
| 在 Codex 中禁用隐式调用 | `agents/openai.yaml` 策略 | 否 |

 प्रत्येक विशेष विस्तार को बाहरी अनुकूलन उपकरण के रूप में देखा जाना चाहिए  सुनिश्चित करें कि इन खंडों को भी निकालने के बाद भी, कोर वर्कफ़्लो अभी भी वैध रूप से उपलब्ध है; उनके लिए एक निम्न श्रेणी का दस्तावेज लिखें, और वास्तव में उनके मेजबान पर एक लक्षित परीक्षण पूरा करें  अज्ञात विशेष खंडों को सीधे अनदेखा किया जा सकता है  रिपोर्ट अस्वीकार, या केवल मूल रूप से रखा गया है और कोई भी व्यावहारिक कार्य नहीं किया गया है 

### अग्रिम पदार्थ निष्पादित की जा सकती है

पूर्व डेटा में कौशल सही ढंग से मॉडल द्वारा पढ़ा जाता है, पहले से ही सिस्टम के संचालन व्यवहार में परिवर्तन कर रहे हैंः

- 格式错误的 `name`सेवा की विफलता का प्रत्यक्ष कारण होगा।
- 含糊不清的 `description`गलत इरादे के मार्ग से होगा।
- केवल कृत्रिम रूप से प्रयोग करने वाले संकेत इस कौशल को मॉडल के उपलब्ध कौशल सूची से पूरी तरह से हटा देंगे।
- 工具预授权配置会改变宿主是否弹出用户授权确认框──
- 上下文委托设置会将后续执行重定向到独立子代理 会话中──

पहले की तरह, आवंटन दस्तावेजों और व्यवसाय कोड की समीक्षा करना अनिवार्य है पहले की सामग्री की समीक्षा करना अनिवार्य है पहले की सामग्री को स्वचालित रूप से सत्यापित करना अनिवार्य है पहले की स्थिति परीक्षण करना अनिवार्य है पहले संस्करण नियंत्रण में प्रवेश करना अनिवार्य है पहले की प्रक्रिया को Eval परीक्षण प्रणाली में प्रवेश करना अनिवार्य है

### कौशल का जीवन चक्र

```figure
skill-runtime-lifecycle
```

चित्र में प्रत्येक तीर एक स्वतंत्र असफलता के साथ सीमाओं का प्रतिनिधित्व करता हैः

1. **服务发现（Discovery）：**पूर्व विनियोजन के कैटलॉग पथ में खोज योग्य प्रोग्राम पैकेज
2. **静态校验（Validation）：**प्रलेख के खुलासे से पहले, निश्चित रूप से त्रुटिपूर्ण या असुरक्षित प्रक्रम को रोकें।
3. **编目索引（Cataloging）：**                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             `name``description`, absolut niet提前全量加载──
4. **决策选择（Selection）：**मॉडल या स्पष्ट निर्देश द्वारा यह निर्धारित किया जाता है कि क्या यह कौशल वर्तमान कार्य से संबंधित है या नहीं।
5. **按需激活（Activation）：**`SKILL.md`正文全量载入模型可见的上下文中──
6. **渐进披露（Disclosure）：** केवल विशिष्ट शाखाओं में जब वास्तव में आवश्यकता होती है, तब केवल संदर्भ या संपत्ति पढ़ना
7. **执行推进（Execution）：**मेजबान के अधिकारों की समीक्षा तथा सा बॉक्स पृथक्करण नियमों के तहत विभिन्न प्रकार के मेजबान उपकरण का उपयोग करना।
8. **结果核验（Verification）：**独立于模型的自述表态,客观核验最终产品质量──

混 इन चरणों से गलत सोच मॉडल का कारण बनता हैः पाया गया कौशल सक्रिय होने के बराबर नहीं है; सक्रिय कौशल यह वर्णित सभी संचालन अधिकार प्राप्त करने के बराबर नहीं है; एकल उपकरण का उपयोग करने के लिए निष्कासित नहीं किया गया है अंतिम परिणाम के बराबर है।

skill-tool-orthogonality

कौशल सही में किसी उपकरण के नाम का उल्लेख कर सकता है, लेकिन वास्तविक उपकरण पंजीकरण और उपयोग अधिकार पूरी तरह से मेजबान के संचालन के लिए समर्पित हैं। यदि उपकरण परिवेश में अनुपस्थित है, कौशल को स्पष्ट रूप से एक स्पष्ट श्रेणीकरण विवरण या सीधे स्पष्टीकरण देना चाहिए, यह निश्चित रूप से गलत नहीं माना जा सकता है कि किसी उपकरण का उल्लेख करने की क्षमता के साथ ही उपकरण का निर्माण किया जाएगा।

### कौशल तथा कोड विवरण (संपादकीय निर्देश) विभिन्न भूमिका क्षेत्रों में आते हैं

代码库说明文件(如 `AGENTS.md`) आप का वर्णन करने के लिए**当前所处**पर्यावरण: निर्माण आदेश, कोडिंग शैली, फ़ाइल नियम और सुरक्षा लाल लाइन उत्पन्न करना।

जब दोनों एक साथ लागू होते हैं, तो उपयोगकर्ता के तत्काल निर्देशों और वर्तमान कोडबुक के मौजूदा नियमों में अधिक प्राथमिकता होती है, और कौशल पर एक बंधन होता है। उदाहरण के लिए, एक सामान्य पुनः निर्माण कौशल स्थानीय कोडबुक पर नियंत्रण नहीं कर सकता है।

### कौशल 之间不进行代码级 आयात

एक कौशल एक अन्य कौशल को अनुकूलित करने के लिए एक निर्देशक एजेंट के रूप में सही कर सकते हैं, लेकिन यह निश्चित रूप से प्रोग्रामिंग भाषा स्तर के कोड नहीं है ।`import`                                                                                                                                                                                                                                                              

कौशल के आधार पर लेखन में, इसे अवलोकन योग्य कार्यप्रवाह चरणों के रूप में वर्णित किया जाना चाहिएः

```markdown
After producing the candidate changelog, invoke the `release-risk-review` skill.
Pass the candidate path and require a blocking or non-blocking verdict.
If that skill is unavailable, stop and report the missing dependency.
```

इस प्रकार की अभिव्यक्ति से निर्भरता का स्पष्ट परीक्षण किया जा सकता है, और मेजबान को संचालन के दौरान अनुपालन रणनीति को निष्पादित करने का अवसर प्रदान किया जाता है।

इसके बाद प्रत्येक जीवन चक्र के चरण में एक-एक गहनता होगी: 24वीं कक्षा सेवा खोज और क्रमिक प्रकटीकरण; 25वीं कक्षा गहनता से अनुकूलन रणनीति और अर्थ मार्ग; 26वीं कक्षा सख्ती से अधिकार नियंत्रण और खाट से अलग होने का समाधान; 27वीं कक्षा में संपूर्ण प्रक्रिया को सख्ती से मूल्यांकन के माध्यम से वितरित करने योग्य प्रकाशन उत्पाद के रूप में बनाया जाएगा।

## 课后深练

1. उपयोग `TaskShape`अपनी टीम के दैनिक 5 वास्तविक आरडीई कार्यप्रवाहों के लिए संरचनात्मक वर्गीकरण करें। प्रत्येक के लिए विभिन्न घटक संयोजनों के परिदृश्यों का उपयोग करके तकनीकी चयनात्मक तर्क लिखें।

3. एक नए कार्य के दौरान विस्तारित खंडों को whitelist में जोड़ा गया है। स्वचालित परीक्षणों को लिखकर यह साबित किया गया है कि फाइल को सफलतापूर्वक पहचानने के साथ ही, अभी भी शुद्ध रूप से स्थानांतरित करने योग्य कौशल के साथ स्पष्ट रूप से अलग किया गया है।

## 关键术语

| 术语 | 通俗说法 | 精确工程含义 |
|---|---|---|
| Agent Skill | "保存好的 Prompt 模板" | 包含过程性操作指南与可选资源的标准化、可发现文件目录 |
| 可移植核心（Portable Core） | "所有运行时共享的通用字段" | 由 Agent Skills 官方规范所定义的基础契约标准 |
| 运行时扩展（Runtime Extension） | "额外的 Frontmatter 字段" | 平台特定的专有配置，其行为生效需要对应宿主适配器的支持 |
| 激活（Activation） | "Skill 跑起来了" | Skill 的正文指令被完整载入模型可见的上下文，后续执行可能滞后发生 |
| Skill 依赖（Skill Dependency） | "Import 另一个 Skill" | 由运行时负责调度的调用关联步骤，受到环境可用性与权限策略的严密审查 |
| Tool 契约（Tool Contract） | "函数 Schema 声明" | 为某项外部能力所定义的输入、输出、权限、副作用、错误码以及审计证据规范 |
