## 无状态契约

2026 के जुलाई माह के समझौते के प्रावधानों को हटा दिया गया है।`initialize`交互握手,`notifications/initialized`और `Mcp-Session-Id` अतीत में हाथ में मौजूद सूचनाएं, अब सीधे प्रत्येक अनुरोध द्वारा स्वयं ले जाने के लिएः

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "summarize_repo",
    "arguments": {"audience": "developer"},
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {"sampling": {}},
      "io.modelcontextprotocol/clientInfo": {
        "name": "lesson-client",
        "version": "1.0.0"
      }
    }
  }
}
```

सर्वर 会在每个请求上校验验协议版本──版本缺失或非字符串类型属于无效参数,返回 `-32602` समर्थित नहीं संस्करण 字符串返回 `-32022`, और सटीक डेटा के साथ ले `{"supported":["2026-07-28"],"requested":"<client version>"}`若缺失样本能力 则返回 `-32021`,并将 `data.requiredCapabilities`设为 `{"sampling":{}}`

没有 JSON-RPC `id`                                                                                                                                                                                                                                                              `202 Accepted`

सर्वर को भी निष्पादित करना होगा`supportedVersions`键、能力、`ttlMs`和 `cacheScope``server/discover`方法, ताकि ग्राहक 调用工具 之前能够获知并缓存服务器的契约──由于发现 声明 `tools`, सर्वर भी अनिवार्य रूप से लागू करना होगा .`tools/list`其确定性的 `summarize_repo`描述符包含合法的 वस्तु 类型 `inputSchema``resultType: "complete"`、सर्वर की पहचान और सार्वजनिक 缓存提示──

प्रत्येक सफल आधुनिक अनुबंध के परिणामों में एक भेदभावकर्ता शामिल हैः

- `resultType: "complete"`ऑपरेशन पूरा हो चुका है।
- `resultType: "input_required"`बताएं कि ग्राहक को इन-इन-इन इनपुट अनुरोध को पूरा करना होगा और पुनः परीक्षण करना होगा।
-  विस्तार नियमन अतिरिक्त परिणाम प्रकार को परिभाषित कर सकता है, उदाहरण के लिए कक्षा 13 में कार्य  विस्तार बढ़ाया गया `"task"`

## 单轮 MRTR 交互流程

सर्वर ने अनुरोध को संसाधित करते समय क्लाइंट को नहीं बुलाया। यह निम्न परिणामों के साथ वापस आ गयाः

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "resultType": "input_required",
    "inputRequests": {
      "pick_files": {
        "method": "sampling/createMessage",
        "params": {
          "messages": [
            {
              "role": "user",
              "content": {
                "type": "text",
                "text": "Choose three representative files and return a JSON array."
              }
            }
          ],
          "systemPrompt": "Return only the requested value.",
          "modelPreferences": {
            "costPriority": 0.8,
            "intelligencePriority": 0.2
          },
          "maxTokens": 400
        }
      }
    },
    "requestState": "opaque-integrity-protected-value"
  }
}
```

ग्राहक 验证 स्वयं समर्थन नमूनाकरण, लागू इसके审核批准与模型策略,并获取模型响应── इसके बाद, ग्राहक 发送一个带有全新的 JSON-RPC id 的新请求:

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {
    "name": "summarize_repo",
    "arguments": {"audience": "developer"},
    "inputResponses": {
      "pick_files": {
        "role": "assistant",
        "content": {
          "type": "text",
          "text": "[\"README.md\", \"server.py\", \"docs/intro.md\"]"
        },
        "model": "host-model",
        "stopReason": "endTurn"
      }
    },
    "requestState": "opaque-integrity-protected-value",
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {"sampling": {}}
    }
  }
}
```

यह पुनः प्रयास एक पूर्ण नया अनुरोध हैः पुनः प्रयास करने के लिए विधि और पैरामीटर, केवल वर्तमान चरण के साथ जोड़ा गया।`inputResponses`,并原封不动地逐字节回显 `requestState`

MRTR  केवल अनुमति दी गई है`tools/call``prompts/get`和 `resources/read`中──सर्वर 绝不能从无关方法中返回 `input_required`

## 多轮 स्टेटस मैनेजमेंट

इस वर्ग में दो मॉडल का प्रयोग किया जाता हैः

1. `pick_files`返回一个JSON 数组──
2. `summary`返回最终的摘要文字──

क्योंकि प्रत्येक पुनः परीक्षण केवल इस दौर के उत्तर को ले जाता है, सर्वर को वर्तमान चरण (अवधि) और अगले चरण में प्रवेश करने के लिए मध्य डेटा की आवश्यकता होती है।`requestState`मध्य में

कृपया इस मूल्य को संभावित हमलावर नियंत्रण में डेटा के रूप में माना जाए। केवल चरण नाम के लिए सरल हस्ताक्षर करना पर्याप्त नहीं है।

- 经过鉴权的主体 (सत्यापित मूल), और स्व-घोषणा के बजाय `clientInfo`.
- 发起调用原始方法;
- 原始参数的摘要(डिजेस्ट);
- 较短的过期时间;
- वर्तमान चरण तथा अनुभव के मध्य मूल्य

जब ग्राहक 绝对不能读取状态内容, कृपया पहचान अधिकार का उपयोग करें  सत्यापित एन्क्रिप्शन) `-32602`

ग्राहक 绝不能解析或改 `requestState` इसकी एकमात्र जिम्मेदारी है कि वह पुनः प्रयास करते समय मूल रूप से इस स्ट्रिंग को पुनः प्रसारित करे

## 模型偏好 केवल संदर्भ के लिए

`costPriority``speedPriority``intelligencePriority`ये एक दूसरे से स्वतंत्र प्राथमिकताएं निर्धारित करती हैं। ये संभावना वितरण नहीं हैं, कुल मिलाकर 1 की आवश्यकता नहीं है।

यदि आप अभी भी पुराने संस्करण को बनाए रखने के लिए नमूनाकरण प्रक्रिया में हैं, कृपया `includeContext`保持为 `"none"` अन्य पर निम्न पाठ मोड में अपघटन के जोखिम में वृद्धि होगी, और स्वयं पर ही त्याग दिया गया है कृपया अनुरोध में केवल स्पष्ट रूप से न्यूनतम पर निम्न पाठ को ही प्रसारित करें

## सुरक्षा

इन-इन नमूना अनुरोध के लिए, ग्राहक एकमात्र विश्वास सीमा हैः

- जब रणनीति को कृत्रिम स्वीकृति की आवश्यकता होती है, तो उपयोगकर्ता स्पष्ट रूप से सर्वर को प्रदर्शित करता है जो मॉडल को निष्पादित करने की आवश्यकता होती है।
- सीमा MRTR 轮次上限──否则恶意服务器可能会构建无休止的模型消费循环──
-                                                                                                                                                                                                                                                               
- 限每轮往返字节数和符号数
-  अस्वीकार वर्तमान ग्राहक क्षमताओं में अज्ञात प्रविष्टि अनुरोध

- 记录发起的方法及输入请求钥匙, साथ ही日志 में संवेदनशील 内容 में प्रवेश करने से बचें

| Sampling | 已弃用特性，用于请求 client 端的模型执行文本补全 |
| MRTR | 多轮往返请求（Multi Round-Trip Requests），用于在请求中获取 client 输入的无状态重试模式 |
| `InputRequiredResult` | 带有 `resultType: "input_required"` 的结果对象 |
| `inputRequests` | Server 分配的映射表，包含内嵌的 elicitation、sampling 或 roots 请求 |
| `inputResponses` | Client 在当前轮次提交的响应，键名与 `inputRequests` 一一对应 |
| `requestState` | 不透明的 server 状态字符串，由 client 原样回显并由 server 校验完整性 |
| `resultType` | 现代 MCP 返回结果中必须包含的类型判别器 |
| 直接模型集成（Direct model integration） | 新建 server 需要模型推理时的官方推荐替代方案 |
| Capability 门禁（Capability gate） | 防止向未声明相应支持的 client 发送内嵌请求的安全规则 |
| 循环预算（Loop budget） | 本次操作允许的最大轮次、token 数、字节数、执行时长以及花费上限 |

## 旧版兼容性

 फिक्स्ड 2025-11-25 संस्करण में क्लाइंट अभी भी जीवित कनेक्शन पर पुराने प्रकार के सर्वर का उपयोग कर शुरू हो सकता है `sampling/createMessage`流程── कृपया इस व्यवहार को संस्करण विशेष रूप से उपयोग किए जाने वाले एडिप्चरों में सख्ती से अलग करें── कृपया 2026-07-28 सर्वर के बुनियादी ढांचे के रूप में वार्तालाप मार्गों का उपयोग करें──

官方 SDK 可以将现代的 `input_required`处理程序转换为适应旧版对端的通信―― इस प्रकार 片是兼容性边界, इसका मतलब यह नहीं है कि इसमें नई निर्भरता के तर्क को जोड़ने की अनुमति दी जाए
