## 问题

एक पढ़ने खरीद आदेश मेल एजेंट  जरूरत है मुक्त ग्रंथों को परिवर्तित करने `{customer, line_items, total_usd}`                                                                                                                                                                                                                                                              

**方法一：提示模型输出 JSON。** JSON प्रतिक्रिया,字段包括客户、line_items、total_usd。前沿 मॉडल पर 85% से 95% समय उपलब्ध है。会以六种方式失败:缺少大括号、尾随逗号、类型错误、幻觉字段、在 टोकन 限制处截断、泄漏类似

**方法二：生成后验证。**स्वतंत्रता उत्पादन 解析  根据 schema 验证, असफलता के बाद पुनः प्रयास  विश्वसनीय लेकिन महंगा  आप प्रत्येक पुनः परीक्षण के लिए भुगतान करना चाहते हैं, और काटने बग प्रत्येक बार एक बार पर अधिक खर्च एक दौर 

**方法三：Constrained Decoding。**提供商在解码时强制执行方案──无效 टोकन 会从采样分布中被掩盖掉──输出保证可解析,并且保证通过验证──失败会收到一种模式:拒绝(模型判断输入不符合方案) ‖

2026 तक, प्रत्येक अग्रणी प्रदाता ने एक प्रकार का तरीका प्रदान किया है।

- **OpenAI。** `response_format: {type: "json_schema", strict: true}`, यदि मॉडल अस्वीकार करता है तो प्रतिक्रिया में शामिल है`refusal`

- **Pydantic AI。** `output_type=InvoiceModel`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             `InvoiceModel``RunResult`

## 概念

### JSON योजना 2020-12  通用语

प्रत्येक प्रदाता JSON योजना 2020-12 को स्वीकार करता है।

- `type`:`object``array``string``number``integer``boolean``null`之一──
- `properties`:字段名到 उप योजना का映射──
- `required`: अवश्य प्रकट होना चाहिए
- `enum`: अनुमति मूल्य का समापन संग्रह
- `minimum`/`maximum`(数字),`minLength`/`maxLength`/`pattern`(字符串)
- `items`: प्रत्येक तत्व के उप-निर्देश के लिए प्रयोग किया जाता है
- `additionalProperties`:`false`禁止额外字段(默认值因模式而异)

OpenAI कड़ा मोड  तीन आवश्यकताओं को बढ़ाया गया: प्रत्येक संपत्ति को सूचीबद्ध किया जाना चाहिए `required`मध्य, सभी स्थानों में होना चाहिए।`additionalProperties: false`, और कोई अनिर्णित नहीं हो सकता है`$ref`यदि इन आवश्यकताओं का उल्लंघन होता है, तो एपीआई अनुरोध पर 400 वापस लौटाएगा

### पायदानटिक, पायथन 绑定

Pydantic v2  के माध्यम से `model_json_schema()`डेटाक्लास आकार का मॉडल उत्पन्न JSON Schema。पायडान्टिक AI ने इसके लिए एक कव्हर बनाया है, इसलिए आप इस प्रकार लिख सकते हैंः

```python
class Invoice(BaseModel):
    customer: str
    line_items: list[LineItem]
    total_usd: Decimal
```

एजेंट फ्रेमवर्क 会在边界处把方案 转换到OpenAI सख्त मोड、Anthropic `input_schema`या जुड़वां `responseSchema`◊ मॉडल输遇以类型化 `Invoice`实例返回──验证错误会抛出 `ValidationError`,并带有类型化错误路径──

### Zod,TypeScript 绑定

ज़ोड`z.object({customer: z.string(), ...})`) है TS等价物──OpenAI के नोड SDK 暴露 `zodResponseFormat(Invoice)`, यह एपीआई के JSON योजना के लिए परिवर्तित किया जाएगा उपयोगिता लोड.

### अस्वीकरण

कड़ा मोड 不能强迫模型回答──如果输入无法适应方案邮件是一首诗,不是发票),模型会发出包含原因的 `refusal`字段── आपका कोड इसे विफलता के रूप में नहीं, बल्कि पहले परिणाम के रूप में लेना चाहिए। अस्वीकरण भी सुरक्षा संकेत के रूप में किया जा सकता हैः जब मॉडल को संरक्षित सामग्री मेल से क्रेडिट कार्ड नंबर लेने के लिए कहा जाता है, तो वह सुरक्षित कारणों से अस्वीकार के साथ वापस लौटाएगा।

### 开放环境中的 प्रतिबंधित डिकोडिंग

开放权重实现三种技术的使用

1. **Grammar-based decoding**(`outlines``guidance``lm-format-enforcer`): स्कीम से निर्माण निर्धारक परिमित ऑटोमैटोन; में प्रत्येक चरण, मास्क 掉会违反FSM के टोकन लॉजिट्स──
2. **带 JSON parser 的 logit masking**:运行一个与模型同步的流媒体 JSON पार्सर;在每一步计算有效-下一个代码集合──
3. **带 verifier 的 speculative decoding**:廉价草案模型 提议 टोकन,verifier 强制执行方案──

 वाणिज्यिक प्रदाता संघ ने एक को पीछे की ओर चुना ∙2026 के नवीनतम स्तर यह है: लघु संरचनात्मक उत्पादन सामान्य उत्पादन की तुलना में अधिक तेज़ है, लंबी संरचनात्मक उत्पादन की गति लगभग समान है ∙

### 三种失败模式

1. **Parse error。**输出不有效 JSON──在严格模式下不会发生──在非严格 提供商上仍可能发生──
2. **Schema violation。**输出可以解析,但违反方案──严格模式下不会发生──严格模式外很常见──
3. **Refusal。**模型 अस्वीकार करना ️

### 重试策略

जब आप कड़ा मोड में नहीं हैं, तो नीचे नीचे मानव उपकरण उपयोग, गैर कड़ा OpenAI, पुराने जुड़वां से अधिक है, पुनः प्राप्ति मोड हैः

```
generate -> parse -> validate -> if fail, inject error and retry, max 3x
```

एक बार पुनः प्रयास करना सामान्यतः पर्याप्त है। तीन बार पुनः प्रयास करना कमजोर मॉडल को पकड़ने में सक्षम है।

### 小模型支持

प्रतिबंधित डिकोडिंग  लघु मॉडल के लिए उपयुक्त  संरचनात्मक कार्य पर, एक व्याकरण प्रवर्तन के साथ 3B परमानुओं के खुले मॉडल, प्रदर्शन मूल सुझाव के 70B परमानुओं के मॉडल का उपयोग करने से बेहतर है यह संरचनात्मक आउटपुट उत्पादन पर्यावरण के लिए महत्वपूर्ण मुख्य कारण हैः यह विश्वसनीयता और मॉडल का बड़ा समाधान करता है🏻

## 关键术语

| 术语 | 人们常说 | 实际含义 |
|------|----------------|------------------------|
| JSON Schema 2020-12 | “schema spec” | 每个现代提供商都支持的 IETF-draft schema dialect |
| Strict mode | “保证符合 schema” | OpenAI 通过 Constrained Decoding 强制执行 schema 的标志 |
| Constrained decoding | “Logit masking” | decode 时的强制执行，会 mask 无效的下一个 Token |
| Refusal | “模型拒绝” | 输入无法适配 schema 时的类型化结果 |
| Parse error | “无效 JSON” | 输出无法解析为 JSON；在 strict 下不可能发生 |
| Schema violation | “形状错误” | 已解析但违反 type / required / enum / range |
| `additionalProperties: false` | “不允许额外字段” | 禁止未知字段；OpenAI strict 中必需 |
| Pydantic BaseModel | “类型化输出” | 会发出并验证 JSON Schema 的 Python class |
| Zod schema | “TypeScript output type” | 用于提供商输出验证的 TS runtime schema |
| Grammar enforcement | “开放权重 constrained decode” | 基于 FSM 的 logit masking，如 outlines / guidance 中所用 |
