## 问题背景

एजेंट होस्ट को आमतौर पर कई एमसीपी सर्वर के साथ एक साथ संचार की आवश्यकता होती है। इसे प्रत्येक सर्वर को खोजने की आवश्यकता होती है।

`2026-07-28`规范 स्थिरता संचालन को बेहद सरल बनाता है, क्योंकि प्रत्येक अनुरोध पूरी तरह से स्वयं शामिल है।

- 支持首选版本的现代 Server;
-  लौटें पहचान योग्य संस्करण या हेडर  त्रुटि का आधुनिक सर्वर;
- कभी नहीं सुना है`server/discover`का पुराना सर्वर;
- जब तक प्राप्त करने के लिए ।`initialize`握手前都保持沉默的老旧服务器──

यदि सभी डिटेक्शन त्रुटियों को विरासत सर्वर के रूप में माना जाता है, तो यह बेहद खतरनाक है। आधुनिक अनुरोधों के प्रारूप में त्रुटि, सर्वर के अधिभारित, पुराने सर्वर के साथ जुड़े हुए प्रक्रियाओं के साथ, सभी एक ही सुपरटाइम या कनेक्शन का खंडन कर सकते हैं।

### 现代服务发现

`server/discover`返回支持的版本、Server 能力、使用说明、缓存提示以及推的 Server 身份──客户端 选择双方均支持的最高现代版本──

 शुद्ध आधुनिक ग्राहक के लिए, सेवा खोज विकल्प है; लेकिन स्टूडियो  मोड में दृढ़ता से अनुशंसित उपयोग  कुछ पुराने सर्वर प्रारंभ से पहले व्यवसाय को प्राप्त करने में सक्षम होते हैं, इसलिए सीधे भेजते हैं `tools/list`हो सकता है कि सफल होने की संभावना हो।`server/discover`能够建立分明的时代分界线──

### स्टडियो 兼容性探测流程

双时代(दो युग) स्टूडियो क्लाइंट 在发送任何其他请求之前,优先发送携带其首选现代元数据的 `server/discover`可能产生三类结果:

1. **DiscoverResult（成功发现）**सर्वर आधुनिक वास्तुकला हेतु, साझा समर्थन संस्करण का चयन करता है, और प्रत्येक अनुरोध पर डेटा ले जाने के तरीके से व्यावसायिक संचार जारी रखता है।
2. **Recognized modern error（已识别的现代协议错误）**सर्वर 仍然为现代架构──若返回 `-32022`, से `data.supported`中选择可用版本并使用新请求 ID 重试;若为头条或能力 错误,修正请求内容即可──**严禁回退发送 `initialize`。**
3. **Ambiguous signal（歧义信号）**:अज्ञात JSON-RPC 报错、超时、连接关闭或空响应均无法确定协议时代──必须默认按失败关闭(未能关闭),除非该端被运维显然配置了继承 兼容白名单──

已识别的现代协议错误码 में शामिल हैंः

- `-32020`हेडरअसमान (अनुरोध शीर्षक से अनुरोध तत्व असमान)
- `-32021`अनुपलब्ध (आवश्यक) ग्राहक क्षमता (अवश्यक)
- `-32022`असमर्थितप्रोटोकॉल संस्करण ((不支持的协议版本)

Even对端已列入遗产 白名单,已识别的现代错误也证明其为现代服务器──一旦服务器表现出理解现代错误词汇的能力,发送 `initialize`हम खतरनाक संस्करण के लिए एक गिरावट हमला बना रहे हैं।

绝不能把 `-32601`(विधि未找到) विरासत में प्रवेश के लिए पर्याप्त प्रमाण के रूप में। यह केवल इस मामले के लिए है कि एक बार सीमित समय के लिए एक विरासत खोज शुरू करने के लिए पात्र है।

## 核心专业术语

| 术语 | 规范定义 |
|------|---------|
| 对端 (Peer) | Client 端维护的单个 Server 传输句柄及其发现信息的记录实体 |
| 协议时代 (Protocol era) | 现代逐请求元数据模式，或旧版初始化握手语义 |
| 服务发现探测 (Discovery probe) | 用于识别 stdio 对端时代的初始 `server/discover` 请求 |
| 已识别现代错误 (Recognized modern error) | 证明对端属于现代架构并禁止 Legacy 回退的特定协议错误 |
| Legacy 白名单 (Legacy allowlist) | 运维显式授权对指定对端进行一次受限兼容探测的配置 |
| 正向 Legacy 证据 (Positive legacy evidence) | 针对受支持旧版协议返回的有效、ID 匹配的 `initialize` 结果 |
| 合并命名空间 (Merged namespace) | 跨所有活跃对端规范化后的工具全局名称集合 |
| 冲突策略 (Collision policy) | 处理重名工具的加前缀或报错拒绝规则 |
