## 核心问题

调用普通的Python 函数很简单――但通过AI होस्ट 调用远程能力,则是一个典型契约问题――

服务端发布描述符 (descriptor) ∼ ग्राहक इस वर्णक को मॉडल के उपर्युक्त अवतरण और उपयोगकर्ता इंटरफ़ेस में परिवर्तित करेगा। मॉडल उत्पन्न करने के लिए调用参数──网关可能根据镜像的 HTTP 标题进行请求路由── सेवा端执行该工具── अंततः, ग्राहक निर्णय लेता है कि क्या वापसी का परिणाम पर्याप्त सुरक्षित और प्रभावी है, ताकि मॉडल को वापस लाया जा सके।

整条调用链条 में यदि कोई सीमा है तो कोई गड़बड़ है, तो यह पूरी श्रृंखला को नष्ट कर देगा

考虑以下五种常见故障:

- 描述符声明 एक वस्तु का परिणाम लौटाता है, लेकिन सेवा端 वास्तव में एक सरणी को लौटाता है。
- 客户端在 `nextCursor`ऩेकयययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययययय
- संवेदनशील टोकन परमानेंट को HTTP 标题 में दर्शाया जाता है, जिससे सभी मध्यस्थ एजेंटों और日志 प्रणाली को उजागर किया जाता है।
- 包含 यूनिकोड का रूट मूल्य मूल संकेत के रूप में भेजा जाता है, जिससे वेब关 और स्रोत स्टेशन के लिए वर्ण क्रम का समाधान असंगत हो जाता है।
- स्वचालित पूरक पूर्णविराम बिंदु एक बिना अधिकार का उपयोग करने के लिए उत्पादन पर्यावरण के एक प्रवर्तक द्वारा सिफारिश की उत्पादन पर्यावरण के नामों:.

इन दोषों का समाधान करने के लिए कोई बेहतर उपाय नहीं है। इन दोषों का समाधान करने के लिए एक बेहतर उपाय है।

## 契约流水线

हम प्रत्येक उपकरण को पांच चरणों में विभाजित करेंगेः

1. **发现（Discover）**:读取确定性、已分页的工具列表──
2. **准入（Admit）**: प्रत्येक उपकरण का प्रयोग करें विवरण符并执行本地安全策略──
3. **调用（Invoke）**:कक्षा调用参数并构建传输层元数据──
4. **执行（Execute）**:运行工具处理函数并对错误进行正确分类──
5. **消费（Consume）**: मॉडल के उपयोग से पहले, सामग्री के खंडों और संरचनात्मक आउटपुट को प्रयोग किया जाता है।

```figure
mcp-contract-pipeline
```

मेजबान 拥有准进关口和消费关口的主导权──服务端不能强迫客户端盲目信任其注解、方案或输出结果──

## JSON योजना है运行时边界

MCP में`2026-07-28`规范中,`inputSchema``outputSchema`均采用 JSON Schema──当省略 `$schema`声明时,默认方言为 2020-12──

输入 Schema 必须是一个方案对象―― यहां तक कि एक उपकरण को किसी भी घटक की आवश्यकता नहीं है, इसे स्वीकार्य प्रारूप में भी घोषित किया जाना चाहिएः

```json
{
  "type": "object",
  "additionalProperties": false
}
```

यह `{ "type": "object" }`严格多,后者允许传入任意多余属性──

输出 योजना वैकल्पिक है. लेकिन सेवा डेम पर एक बार प्रकाशित हो गया है.`outputSchema`, प्रत्येक बार पूर्ण वापसी के परिणाम के रूप में, हम इस समझौते के अनुरूप वापसी का वादा करते हैं।`structuredContent`, भले ही परिणाम में शामिल हो`isError: true`यह भी है। त्रुटि चिह्न केवल निष्पादन परिणामों के लिए वर्गीकृत है, यह प्रकाशित आउटपुट अनुबंधों को कभी भी मुक्त नहीं कर सकता है। ग्राहक को निष्क्रिय विश्वास वर्णक के बजाय निष्क्रिय परीक्षा परिणामों को सक्रिय करना चाहिए।

###  संरचनात्मक सामग्री किसी भी JSON मूल्य हो सकता है

मत करो `structuredContent`硬编码为字典(डिक्ट/ऑब्जेक्ट) ⋅ यह हो सकता हैः

- एक वस्तु;
- एक सरणी;
- एक स्ट्रिंग;
- एक संख्या;
- एक बुलियन;
- `null`

उदाहरण के लिए नीचे इस वापसी संख्या के उपकरणः

```json
{
  "name": "tag_catalog",
  "inputSchema": {
    "type": "object",
    "additionalProperties": false
  },
  "outputSchema": {
    "type": "array",
    "items": {"type": "string"}
  }
}
```

सफलतापूर्वक वापसी का परिणाम पूरी तरह से वैध हैः

```json
{
  "resultType": "complete",
  "content": [
    {
      "type": "text",
      "text": "[\"contracts\", \"mcp\", \"stateless\"]"
    }
  ],
  "structuredContent": ["contracts", "mcp", "stateless"],
  "isError": false
}
```

पश्चात्य सामंजस्य बनाए रखने के लिए, पुनः संरचनात्मक परिणामों को आमतौर पर पाठ  सामग्री ब्लॉक में जोड़ा गया JSON  पाठ में क्रमबद्ध किया जाना चाहिए।`structuredContent`才是.

### 简明校验器 अभी भी सीमाओं की मूलभूतता को स्पष्ट कर सकता है

इस कोर्स में एक JSON Schema 校验子集 को लागू करने का विशेष उद्देश्य है, ताकि यह पूर्ण रूप से पायथन 标准库 के दायरे में बने रहे।

- वस्तु, सरणी, स्ट्रिंग, पूर्णांक, संख्या, बुलियन और शून्य प्रकार;
- आवश्यक अनिवार्य गुण;
- `additionalProperties: false`.
- सरणी वस्तुएं;
- enum 枚举值;
- 字符串 न्यूनतम लम्बाई minLength。

यह उत्पादन-स्तर के परीक्षक के पूर्ण कार्यान्वयन का विकल्प नहीं है।**校验发生的时机与位置**: खोज के बाद वर्णक पर परीक्षण किया जाता है, निष्पादन से पहले अनुकूलन पैरामीटर पर परीक्षण किया जाता है, साथ ही खपत से पहले संरचनात्मक परिणाम पर परीक्षण किया जाता है।

##  सामग्री ब्लॉक विभिन्न लागतों को वहन करना

`content`संख्याओं को कई प्रकार के सामग्री ब्लॉक प्रकारों को इकट्ठा किया जा सकता हैः

| 类型 | 适用场景 | 核心安全与控制边界 |
|------|------------|---------------|
| `text` | 人类与模型可读的摘要文本 | 将文本视为不可信输出 |
| `image` | 以 Base64 编码的视觉凭证 | 严格校验媒体类型（media type）与文件大小 |
| `audio` | 以 Base64 编码的语音或音频 | 严格校验媒体类型与时长上限 |
| `resource_link` | 客户端后续可按需拉取的 URI | 在后续读取资源时重新执行鉴权 |
| `resource` | 直接内嵌在当前结果中的数据 | 在当前调用立即强制执行载荷与内容上限 |

资源链接(`resource_link`) यह सुनिश्चित नहीं करता कि यह संसाधन अवश्य उपलब्ध होगा।`resources/list` यह इस उपकरण के उपयोग से लौटने का एक संदर्भ है  जब ग्राहक इस URI का उपयोग करने का प्रयास करता है, तो उसे अभी भी अपनी स्थानीय संसाधन पहुंच नियंत्रण रणनीति को लागू करने की आवश्यकता होती है

आंतरिक संसाधन`resource`) अतिरिक्त नेटवर्क वक्रों से बचें, लेकिन वर्तमान प्रतिक्रिया पत्र के आकार में वृद्धि करें।

本课例代码中 `evidence_bundle` परिणामों में इस प्रकार के पांच प्रकार शामिल हैं ग्राहक द्वारा प्रत्येक ब्लॉक पर वैधता परीक्षण करने के लिए परिणामों को स्वीकार करने से पहले आयोजित किया जाएगा

## `x-mcp-header`यह मार्ग से डेटा

`inputSchema` आंतरिक के किसी विशेषण का वर्णन किया जा सकता है `x-mcp-header` Streamable HTTP 传输协议 के तहत, ग्राहक सम्मेलन इस पैरामीटर को प्रतिबिंबित करेगा `Mcp-Param-{name}`标头

```json
{
  "region": {
    "type": "string",
    "x-mcp-header": "Region"
  }
}
```

जब `region: "eu-west"`时,传输层即发发出如下标题:

```http
Mcp-Param-Region: eu-west
```

 इस नोट को पेश करने का उद्देश्य लोड संतुलनकर्ता, नेटगैन या रणनीति इंजन को पूर्ण JSON अनुरोधों को बिना किसी हल के पूर्ण JSON अनुरोधों के मामले में पूरा करने का मार्ग देना है**绝对不能**पहचान प्रमाण पत्र या संवेदनशील डेटा को प्रसारित करने के लिए उपयोग किया जाता है।

इस संबंध में सख्त प्रतिबंधों को लागू किया गया है।

- 标头名称必须非空,且符合HTTP फ़ील्ड-नाम टोकन 语法规范;
- 标头名称在不区分大小写的前提下必须全局唯一;
- 参数属性 प्रकार केवल स्ट्रिंग、पूर्णांक या बुलियन हो सकता है;
-                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              `number`(浮点数)
- यह केवल सीधे दिखाई दे सकता है`inputSchema.properties`के प्रथम स्तर के सीधे-सीधे सेण में;
- पूरी संख्या में मूल्य सीमा को सीमित करना होगा `-9007199254740991`तक `9007199254740991`(जावास्क्रिप्ट सुरक्षा संपूर्ण संख्या दायरा)

位置规则是语法级别的,并且必须是安全失败 (失败) 机制――必须穿越整个树 Schema tree,而不能仅仅检查校验器巧识别顶级属性――只要注解现象嵌套对象的`properties`नीचे`oneOf`分支中,`items`अंदर से गुजरना`$ref`引用的定义中, या किसी भी आउटपुट Schema में,都必须坚决拒绝――解析引用不会使引用的节点变成直接的一级属性――

इस कक्षा में एक सुरक्षा रणनीति तैनात की गई है जिसमें प्रत्येक छवि का नाम शामिल है।`password``secret``token``api_key`या `authorization`सेवा के लेखक को दर्पण संवेदनशील पैरामीटर नहीं चाहिए, जबकि ग्राहक इस सुझाव को सख्त प्रवेश नियंत्रण नियमों के लिए लागू कर सकते हैं।

审计时只记录标题名称,不记录其具体数值──例代码会记录审计事件 `Mcp-Param-Region`, और विशिष्ट मूल्य `eu-west`排除在审计日志之外──

### HTTP 标题 के निर्माण में संख्यात्मक कोड

参数值 केवल निम्नलिखित शर्तों को पूरा करने पर ही, केवल सीधे शुद्ध पाठ के रूप में में शीर्षक में संचरण किया जा सकता हैः非空字符串, ASCII 可见字符 द्वारा`!`तक `~`) का गठन, और इसमें कोडित सैनिकों का समावेश नहीं है।

```text
=?base64?{Base64UTF8}?=
```

उनमें से `Base64UTF8`यह पैरामीटर के लिए पूरी तरह से सटीक UTF-8 字节 अनुक्रम के लिए किया गया मानक Base64 编码──绝对不要在此之前对字符串执行 trim(删除首尾空格) 规范化或替换操作──Unicode 字符、空字符串、空格、制表符、控制字符、CR或LF、带有前导或尾随空白的值,以及任何原始的依据`=?base64?`पहले के मूल्य को कोडिंग करना होगापहले के मूल्य को पुनः कोडिंग करना होगा, यह सुनिश्चित करने के लिए कि प्राप्तकर्ता मूल लिखित पाठ को ठीक से वापस कर सके, लेकिन इसे ट्रांसफर लेयर भाषा के लिए गलत तरीके से हल न करे

                                                                                                                                                                                                                                                              `true`या `false`◊ पूर्णांक को 10 में एकीकृत करने के लिए एक स्ट्रिंग बनाने के लिए, और जावास्क्रिप्ट सुरक्षा पूर्णांक के दायरे में पड़ना चाहिए।

अस्वीकार करना HTTP पर वापस आना चाहिए`400`और JSON-RPC  त्रुटि कोड `-32020` अनुरोधित निकाय के मूल्य और कोडित के बाद के शीर्षक स्वरूप लेखा रिकॉर्ड की सामग्री से बाहर हैं, लेखा रिकॉर्ड में केवल पहचान किए गए शीर्षक नाम और अस्वीकार कारणों की श्रेणी दर्ज की जाती है

`code/main.py`直接模拟了这个边界逻辑──[第 09 课](../../09-mcp-transports/) आगे व्याख्या HTTP विधि एवं प्रोटोकॉल संस्करण संयोग्यता सहित व्यापक  Streamable HTTP 校验顺序

## विभाजन का प्रतीक अस्पष्ट है

MCP का सूची संचालन प्रभागों के आकार का निर्धारण करने के लिए एक ही निर्णय का पालन करना आवश्यक हैः

```python
if result.get("nextCursor") is None:
    break
cursor = result["nextCursor"]
```

**绝对不要**写成如下形式:

```python
if not result.get("nextCursor"):
    break
```

क्योंकि`""`यह भी वैध है! यदि सीधे पायथन का वास्तविक मूल्य निर्धारित किया जाए, तो यह पूरे समय में टूट जाएगा।

客户端绝不能尝试游标解码,自增运算, नए游标与旧游标比对判断顺序,或推断页码. 服务端可能会签名游标,绑定它到特定目录版本,或映射它到底层私有状态,这些都属于服务端内部实现细节.

उदाहरण सेवाएं पहले पृष्ठ पर वापस आ गई हैं।`""`◊ ग्राहक द्वारा दूसरे पृष्ठ पर अनुरोध भेजने पर मूल रूप से इस मूल्य को ले जाना चाहिए।

```text
<first request with no cursor>
<second request with cursor "">
```

无效的游标输入应产生 JSON-RPC अमान्य पैरामीटर 错误(错误码 `-32602`)。

- संख्या परिणाम अपने संख्या आउटपुट योजना 校验──

- 标头审计事件仅记录标头名称,不记录其具体数值──

## 生产环境故障模式

| 故障现象 | 学习者看到的表象 | 正确处理方案 |
|---------|-----------------------|------------------|
| 客户端假定输出必定是 object | 合法的数组校验失败或被静默包装 | 依据发布的 Schema 进行校验，不假定结果必须为 object |
| 空字符串游标被当成 False 处理 | 最后一页数据意外丢失 | 只要 `nextCursor` 存在且非 null，就继续拉取下一页 |
| 镜像了敏感参数值 | 凭证密钥暴露在代理、WAF 或链路追踪日志中 | 拒绝该描述符，将机密保留在受保护的请求体内部 |
| 原始 Unicode 或空白字符直接镜像 | 网关与源站解析不一致，或值被意外规范化 | 使用 Base64 UTF-8 哨兵编码并在解码后进行比对 |
| 注解隐藏在 Schema 的复杂分支中 | 客户端在准入时漏检了路由元数据 | 遍历整棵 Schema 树，仅允许直接位于一级的属性携带注解 |
| 镜像了大整数 | 中间 JavaScript 代理对路由数值进行了舍入 | 拒绝超出 JavaScript 安全整数范围的数值 |
| 标头与请求体不一致 | 网关路由给服务 A，而源站实际执行服务 B | 在业务分发前以 HTTP `400` 和 JSON-RPC `-32020` 拒绝 |
| 忽略了输出 Schema | 下游程序消费了损坏的脏数据结构 | 在交给模型或应用程序前进行严格校验 |
| 盲目信任返回的资源链接 | 调用方直接读取了未获授权的 URI | 对每一次资源读取重新执行鉴权 |
| 自动补全共享了全局建议列表 | 多租户敏感隔离名称被泄露 | 按调用者身份、引用上下文与权限范围进行过滤 |
| 将工具注解当作安全策略 | 破坏性危险操作跳过了二次确认 | 在注解之外建立独立的授权与审批流 |
| 单个格式错误的工具搞垮整个发现流程 | 整台 MCP 服务端完全不可用 | 拒绝有问题的描述符，独立准入其余合规工具 |

## कैपस्टोन 串联

चरण 13 के कैपस्टोन परियोजनाओं को एक सक्षम कई सेवा-समूहों से एकजुट करने की आवश्यकता है।

इस कोर्स के वितरण उपकरण का उपयोग कैपस्टोन के चार मुख्य प्रमाणपत्रों का मूल्यांकन करने के लिए किया गया हैः

- 确定性和完整的游标分页发现过程;
- मॉडेल के सामने प्रयोग के लिए उपकरण विवरणक;
- िकक्षाओं द्वारा पारित संरचनात्मक आउटपुट और कड़ाई से परिभाषित सामग्री ब्लॉक;
- 严密守护授权边界的补充与路由元数据──

सिर्फ एक बार के लिए मत करो`tools/call`调用成功就宣称兼容网关规范──请务必捕获描述符、分页链路追踪、已准备入工具集、被拒绝工具集,以及至少一个完整的校验通过结果──

## 关键术语

| 术语 | 含义 |
|------|---------|
| `inputSchema` | 定义工具所接受参数的 JSON Schema 对象 |
| `outputSchema` | 定义 `structuredContent` 格式的可选 JSON Schema |
| `structuredContent` | 工具执行结果所生成的任意 JSON 结构化数值 |
| 内容块（Content block） | 具备类型化标记的 text、image、audio、resource_link 或 embedded resource |
| `x-mcp-header` | 将基础类型参数镜像为 Streamable HTTP 标头元数据的 Schema 注解 |
| 不透明游标（Opaque cursor） | 服务端发出的分页标记，客户端不得解释其内部含义 |
| 补全引用（Completion reference） | 正在请求参数补全的 Prompt 名称或资源 URI/模板 |
| 准入（Admission） | 客户端根据本地策略决定公开暴露还是拒绝已发现描述符的决策过程 |
