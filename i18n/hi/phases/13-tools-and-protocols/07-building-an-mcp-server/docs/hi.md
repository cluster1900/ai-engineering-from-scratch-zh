# 构建 MCP Server:无状态 पायथन और टाइपस्क्रिप्ट

> आधुनिक MCP सर्वर 绝不记住握手状态── यह प्रत्येक अनुरोध में मौजूद डेटा को एक्ज़ेक्ट करता है, उत्तर के हैंडलर को निष्पादित करता है, और एकल प्रकार के साथ पहचान के परिणामों को लौटा देता है──

**Type:** Build
**Languages:** Python, TypeScript
**Prerequisites:** Phase 13 · 06（MCP 基础）
**Time:** ~85 分钟

## 学习目标

- एमसीपी `2026-07-28`规范实现强制要求的 `server/discover`方法──
- प्रत्येक प्राप्त अनुरोध पर परीक्षा प्रोटोकॉल संस्करण संख्या एवं ग्राहक क्षमता विवरण।
- 以确定性排序暴露 उपकरण、संसाधन 和 संकेत 列表──
- सही परिणामों में वापसी`resultType`、सर्वर पहचान (सेवर पहचान)
- पायथन और टाइपस्क्रिप्ट में, स्टूडियो के अलग-अलग बिन्दुओं के परिवर्तन से पूर्ण रूप से समान अस्थिर प्रोटोकॉल समझौते को प्राप्त किया जाता है।

## 问题背景

पहली खबर प्राप्त करने के बाद मेमोरी में क्लाइंट की क्षमता को सहेजने के लिए सर्वर, हालांकि सरल, लेकिन उत्पादन में बहुत कमज़ोर है। एक ही प्रक्रिया बाद में कई क्लाइंटों को सेवा प्रदान करने के लिए हो सकती है; दूरस्थ अनुरोध भी अलग-अलग श्रमिकों को भेजा जा सकता है; पुरानी क्षमता की घोषणा अधिक संभावना है कि पहचान अधिकार सीमाओं को पार करने के कारण सूचना लीक हो।

एमसीपी `2026-07-28`规范通过使**每个请求自描述**इस समझौते के स्तर की समस्या को पूरी तरह से हल किया गया है। आपका एप्लिकेशन अभी भी स्थायीकृत नोटों, कार्य कार्यों या स्पष्ट स्थिति के लिए रख सकता है।

इस कोर्स में दो बार एक नोट सर्वर का निर्माण किया जाएगाः पायथन और टाइपस्क्रिप्ट संस्करण केवल अपने मूल मानक आधार का उपयोग करके प्रोटोकॉल को लागू करने के लिए, दोनों पूरी तरह से एक ही इंटरफ़ेस विधि का खुलासा करते हैं, और पूरी तरह से एक ही संचार रिपोर्टिंग समझौते को लागू करते हैं।

## 核心概念

### 现代请求分发循环(डिस्पैच लूप)

```text
读取一行 JSON-RPC 文本
解析外层 Envelope
若为通知（Notification），则不予响应
针对当前请求校验 params._meta
根据 method 执行路由分发
使用 resultType 与 serverInfo 封装成功结果
写回一行 JSON-RPC 响应文本
立即遗忘当前请求作用域的元数据
```

स्टूडियो के तहत, तीन महत्वपूर्ण नियम हैंः

-  केवल स्टडआउट 写入 JSON-RPC 消息; सभी调试与诊断日志 को स्टडआउट तक निर्देशित करना होगा
- 报文以换行符分隔,并在每次写回应后执行 flush──
- जब आप ईओएफ तक पहुंचते हैं, तो प्रक्रिया तुरंत समाप्त हो जाती है।

### अनुरोध करें

प्रत्येक अनुरोध में निम्नलिखित शामिल होना चाहिएः

```json
{
  "params": {
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {},
      "io.modelcontextprotocol/clientInfo": {
        "name": "notes-client",
        "version": "1.0.0"
      }
    }
  }
}
```

पिछला दो खंड`clientInfo`यदि पहचान डेटा प्रदान किया गया है, तो इसकी डेटा संरचना का परीक्षण किया जा सकता है, लेकिन इसे सुरक्षा प्रमाण पत्र के रूप में नहीं देखा जा सकता है।

यदि संस्करण समर्थित नहीं है, तो त्रुटि कोड वापस करें`-32022`और साथ`requested``supported` यदि अनुरोध करें कि डेटा गायब हो, अवैध तत्वों में से एक हो, तो त्रुटि कोड लौटाएं `-32602`️ इतिहास से अनुपलब्ध मूल्य डेटा को कभी भी भरना संभव नहीं है

### 强制的服务发现 (निश्चित रूप से अनिवार्य खोज)

现代 सर्वर 必須实现 `server/discover`एक पूर्ण सेवा खोज परिणामों में समर्थित आधुनिक प्रोटोकॉल संस्करण शामिल हैं  सर्वर  क्षमता संग्रह  चयन योग्य उपयोग विवरण  कैशरी सुझाव  और परिणाम `_meta`मध्य सर्वर पहचान पहचानः

```json
{
  "resultType": "complete",
  "supportedVersions": ["2026-07-28"],
  "capabilities": {
    "tools": {"listChanged": false},
    "resources": {"listChanged": false, "subscribe": false},
    "prompts": {"listChanged": false}
  },
  "ttlMs": 3600000,
  "cacheScope": "public",
  "_meta": {
    "io.modelcontextprotocol/serverInfo": {
      "name": "notes-server",
      "version": "2.0.0"
    }
  }
}
```

服务发现并非解锁 सर्वर की पूर्व शर्तें大门──客户端 完全可以在不调用发现的情况下直接发起 `tools/list`, क्योंकि `tools/list` स्वयं ने  पूरी तरह से समान अनुरोध डेटा  ले लिया है

### उपकरण ((工具)

`tools/list`返回具有确定性排序工具 描述符列表──稳定排序能提高响应缓存命中率,并保持模型快速上下文的稳定性──该结果同样要求携带 `ttlMs`和 `cacheScope`

`tools/call`返回内容块(सामग्री ब्लॉक) और `isError`⇒ जब समझौता अनुबंध या विधि तत्व अवैध है, वापस JSON-RPC  त्रुटि प्रतिक्रिया; जब अनुबंध के उपकरण 调用成功触发, लेकिन व्यापार निष्पादन स्तर में विफलता, वापस आ रहा है `isError: true`का नियमित परिणाम

उपकरण नोट (नोट) केवल होस्ट का सुझाव देने के लिए, नहीं अनिवार्य निष्पादन का प्रतिनिधित्व करता हैः

- `readOnlyHint`
- `destructiveHint`
- `idempotentHint`
- `openWorldHint`

मेजबान को इनका उपयोग इंटरफेस कन्फर्मेशन और यूआई प्रस्तुति के लिए करना चाहिए, लेकिन सर्वर को व्यावसायिक स्तर पर वास्तविक प्राधिकरण परीक्षण को लागू करना चाहिए।

### संसाधन (स्रोत)

`resources/list`返回稳定的 URI 描述符──`resources/read`返回带类型内容──在 `2026-07-28`规范中, दोनों ही सम्भावित हैं, जो कि सम्मिलित होना चाहिए `ttlMs`和 `cacheScope`

 उपयोगकर्ता विशेष निजी नोट डेटा के लिए, उपयोग किया जाना चाहिए `cacheScope: "private"` साझा कायाकल्प का अधिकार प्राप्त नहीं किया जा सकता

现代数据变更推送 अब उपयोग नहीं किया जा रहा है `resources/subscribe`◊ ग्राहक 通过发起 `subscriptions/listen`घोषणा`resourceSubscriptions`या सूची परिवर्तन घटनाओं को प्राप्त करने के लिए

### हर सफलता का परिणाम एक प्रकार का होता है

कोड कार्यान्वयन में, आप सभी सफल प्रतिक्रियाओं को संसाधित करने के लिए एक एकीकृत पैकेजिंग मशीन का उपयोग कर सकते हैंः

```python
def complete(payload):
    return {
        "resultType": "complete",
        **payload,
        "_meta": {SERVER_INFO_KEY: SERVER_INFO},
    }
```

列表,读取和服务发现的处理员 会额外增加 `ttlMs``cacheScope`集中化处理能够防止个人处理者 疏漏了现代规范所必需的字段──

### 绝不发起 सर्वर 端请求

现代 सर्वर ग्राहक से सीधे संबंधित सूचना भेज सकता है या ग्राहक द्वारा ओपन किया जा सकता है `subscriptions/listen`流中推送通知──但 सर्वर **绝不能**主动发起独立的 JSON-RPC अनुरोध

जब हैंडलर  नमूनाकरण  प्राप्ति या जड़ 输入时, यह वापस एक `input_required`结果── ग्राहक में satisfaction के अनुरोध के प्रवेश के बाद, उपयोग करें पूर्ण नई अनुरोध आईडी 重新发起原始方法调用──

## 核心专业术语

| 术语 | 规范定义 |
|------|---------|
| 无状态 Server (Stateless server) | 仅从每个请求自身的元数据处理调用，无任何协议 Session 内存记忆 |
| `server/discover` | 强制实现的现代方法，用于向调用方公布支持的版本与功能集 |
| 完整结果 (Complete result) | 携带 `resultType: "complete"` 的成功现代结果 |
| 可缓存结果 (Cacheable result) | 附带强制 `ttlMs` 与 `cacheScope` 提示的发现、列表或只读结果 |
| 确定性列表 (Deterministic list) | 逻辑相同的注册表必须输出完全一致、可复现的条目顺序 |
| Server 身份 (Server identity) | 在结果 `_meta` 中携带的 `io.modelcontextprotocol/serverInfo` 标识 |
| Tool 业务错误 (Tool error) | Tool 调用正常被解析执行，但业务逻辑失败，返回包含 `isError: true` 的 content |
| 协议错误 (Protocol error) | 非法的 JSON-RPC 格式或无效的 MCP 请求参数，直接通过顶层 `error` 报错返回 |
