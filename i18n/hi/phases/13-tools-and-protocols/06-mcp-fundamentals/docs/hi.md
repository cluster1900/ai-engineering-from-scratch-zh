## 问题背景

एक ही ऑपरेटिंग प्रक्रिया या HTTP Worker पर, MCP सर्वर विभिन्न क्लाइंटों से दो अनुरोधों को लगातार प्राप्त कर सकता है, जिनकी क्षमता अलग-अलग है। यदि सर्वर एक अनुरोध पर घोषित उपरोक्त वाक्य को याद रखता है या उस पर निर्भर करता है, तो यह गलत तरीके से आवेदन अधिकार नियमों को लागू करता है, या असंगत रिपोर्ट संरचना को वापस देता है।

एमसीपी `2026-07-28`规范 ने इस भेदभाव को पूरी तरह से समाप्त कर दिया हैः**协议核心完全无状态** सर्वर को केवल वर्तमान अनुरोध पर निर्भर होना चाहिए ताकि यह तय कर सके कि वर्तमान अनुरोध को कैसे संसाधित किया जाए, और यह कनेक्शन के इतिहास पर निर्भर नहीं करता है

इसने मन के मॉडल को पूरी तरह से बदल दिया। पुराने समय के क्रम में पहले कनेक्शन स्थापित करना, फिर हाथ पकड़ना, और अंत में व्यवसाय संचालन शुरू करना शामिल था।

1. ग्राहक 发送一个完全自述的独立请求──
2. सर्वर 校验该请求携带的协议版本和客户端 能力──
3. सर्वर 处理对应的方法──
4. सर्वर 返回带类型标识的结果(प्रकारित परिणाम) या JSON-RPC 错误──

अगला अनुरोध इस पूर्ण प्रक्रिया को शून्य से दोहराएगा।

## 核心概念

### सर्वर 原语(सर्वर आदिम)

MCP सर्वर 暴露三个核心原语:

1. **Tools（工具）**                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             `tools/list`发现并由 `tools/call`调用──
2. **Resources（资源）**: URI 寻址的数据,通过 `resources/list`发现并由 `resources/read`读取──
3. **Prompts（提示模板）**:可复用模板,通过 `prompts/list`发现并由 `prompts/get`染──

जड़ें √ नमूनाकरण एवं लॉगिंग √`2026-07-28`模式中为了兼容性予保留, लेकिन已被明确标记为废弃 (废弃) .全新实现中,应使用显式的工具或资源 输入替代 Roots,使用直接模型提供商 API 替代样本,使用 stderr或 OpenTelemetry 替代登录.

### JSON-RPC लिफाफे

एमसीपी 底层 JSON-RPC 2.0 का उपयोगः

- अनुरोधः`{jsonrpc, id, method, params}`
- 响应(उत्तर):`{jsonrpc, id, result}`या `{jsonrpc, id, error}`
- 通知(सूचना):`{jsonrpc, method, params}`,无 `id`字段

अनुरोध में `id` केवल जुड़े एकल प्रतिक्रिया के लिए, कोई भी अनुबंध स्तर का सत्र नहीं बनाएगा

### आवश्यक अनुरोध डेटा

हर आधुनिक अनुरोध में`params`内部携带一个 `_meta`वस्तुओं:

```json
{
  "jsonrpc": "2.0",
  "id": 7,
  "method": "tools/list",
  "params": {
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {},
      "io.modelcontextprotocol/clientInfo": {
        "name": "course-client",
        "version": "1.0.0"
      }
    }
  }
}
```

协议版本号(`protocolVersion`) और ग्राहक 能力(`clientCapabilities`) है अनिवार्य अनिवार्य fills के;; ग्राहक के रूप में(`clientInfo`) सूचनाओं के लिए, स्वयं के प्रकाशन और परीक्षण के लिए, सुरक्षा प्रमाणों के रूप में नहीं किया जा सकता है।

सर्वर  strictly banned from previous request、studio  process environment、HTTP connect or transmission layer अनुरोध में से इन डेटा को अलग से अनुमानित करना

### 完整结果与 सर्वर पहचान

प्रत्येक सफलता के आधुनिक परिणाम में शामिल हैं`resultType`常规的终态结果使用 `"complete"`◊सर्वर को भी परिणाम में अपनी पहचान घोषित करनी चाहिए:

```json
{
  "jsonrpc": "2.0",
  "id": 7,
  "result": {
    "resultType": "complete",
    "tools": [],
    "ttlMs": 30000,
    "cacheScope": "public",
    "_meta": {
      "io.modelcontextprotocol/serverInfo": {
        "name": "notes-server",
        "version": "1.0.0"
      }
    }
  }
}
```

`tools/list``resources/list``prompts/list``resources/templates/list``resources/read`और `server/discover`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             `ttlMs`(毫秒存活时间) और `cacheScope`(缓存范围) ◊ सुरक्षा का默认值 है `ttlMs: 0`和 `cacheScope: "private"`◊ सूची के परिणामों में अनुच्छेद निश्चितता क्रमबद्धता का उपयोग करना चाहिए, यह सुनिश्चित करना कि समान मूल्य के प्रतिसाद स्थिर भंडारण कुंजी और संगत मॉडल पर निम्न वाक्य उत्पन्न कर सकें

### 无握手的服务发现(हात हिलाने के बिना खोज)

प्रत्येक आधुनिक सर्वर                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           `server/discover`◊ ग्राहक व्यवसायिक विधि के प्रारंभ में इसका उपयोग करने के लिए कर सकता हैः

- `supportedVersions`सर्वर 支持的协议版本列表
- `capabilities`:सर्वर  प्रदान क्षमता字典
- 可选的使用说明文档(`instructions`)
- 结果 `_meta`मध्य सर्वर पहचान
- 缓存提示`ttlMs`和 `cacheScope`)

 सेवा का पता लगाना बहुत उपयोगी है, लेकिन यह यात्रा की शर्त नहीं है।`tools/list`作为第一请求,因为该请求本身已经完整携带了协议版本和客户端能力──

यदि अनुरोध का संस्करण समर्थित नहीं है, सर्वर वापस JSON-RPC  त्रुटि कोड `-32022`और साथ डेटाः

```json
{
  "requested": "2027-01-01",
  "supported": ["2026-07-28"]
}
```

ग्राहक  चुनें दोनों पक्षों द्वारा साझा समर्थन का आधुनिक प्रोटोकॉल संस्करण, और पूर्ण नए JSON-RPC का उपयोग करें अनुरोध आईडी  पुनः परीक्षण करें。

### 单次请求的完整生命周期

कृपया निम्नलिखित क्रमशः पालन करें

1. 解析单个 JSON-RPC संकुल
2. 校验 `jsonrpc`字段为 `"2.0"`, अस्तित्व में है`id`,`method`爲字符串, और `params`उद्देश्य के लिए।
3. 校验 `params._meta`中包含版本字符串与能力对象; यदि डेटा गायब या स्वरूप अवैध है, तो त्रुटि कोड वापस करें `-32602`
4. HTTP के लिए, एक प्रोटोकॉल संस्करण के शीर्षक, विधि शीर्षक और उत्तर के नाम के साथ तुलना करें।`-32020`(यहां तक कि उनमें से एक संस्करण मूल्य समर्थित नहीं है)
5. स्थापित करने के बाद, यदि अनुरोध के संस्करण समर्थित है, लेकिन सर्वर असंगत है, वापस आ जाओ `-32022`
6. 检查所需能力, फिर उसके अनुसार `method`路由并校验方法专有参数──
7. 在具体处理器 执行前完成认证 (ईमानदारी)
8. 返回带有 सर्वर 身份信息的完整结果(पूर्ण परिणाम)。
9. 立即遗忘当前请求作用域的协议元数据──

इस कठोर क्रम में विभिन्न संरचनाओं के बीच असहमतियां उत्पन्न हो सकती हैं।`Mcp-Name: notes.read`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             `params.name: notes.delete` यह भी रूप प्रविष्टि  सूचना के मिश्रण  संस्करण परामर्श  क्षमता की कमी  अधिकार की विफलता  और हैंडलर  व्यापार रिपोर्ट  एक दूसरे के भेदभाव के निदान प्रमाणों  बन जाता है

关闭 stdin या关闭 HTTP 响应连接 仅代表传输层生命周期的结束, यह किसी भी 协议 सत्र को समाप्त नहीं करेगा, क्योंकि आधुनिक MCP 根本不存在协议 सत्र

## 核心专业术语

| 术语 | 规范定义 |
|------|---------|
| 无状态协议 (Stateless protocol) | 每一个请求都自包含解析它所需的完整元数据 |
| 请求元数据 (Request metadata) | 在 `params._meta` 中携带的协议版本、Client 能力声明及推荐的 Client 身份 |
| `server/discover` | 强制实现的 Server 方法，用于声明支持版本、能力、使用说明及身份 |
| `resultType` | 每个现代成功结果上的类型鉴别字段（如 `"complete"`） |
| 可缓存结果 (Cacheable result) | 必须包含 `ttlMs` 与 `cacheScope` 提示的查询或列表结果 |
| 协议时代 (Protocol era) | 现代基于每次请求元数据的模式，或旧版连接作用域初始化的模式 |
| 传输生命周期 (Transport lifetime) | 进程、连接或响应流的物理生存周期，不等同于协议 Session |
| `-32022` | 不支持的协议版本错误码，返回请求的版本及支持的版本列表 |
