### तीन स्तरीय रक्षा सिद्धांत

 स्पष्ट रूप से यूआरआई स्वयं वैधता का प्रमाण नहीं है

1. **鉴权（Authorization）：**क्या इस कार्यक्षेत्र का उपयोग करने के लिए इस पारदर्शिता अधिकार के विषय को अनुमति है?
2. **路径限制（Containment）：** नियमन के बाद के लक्ष्य क्या यूआरआई को अधिकार प्राप्त कार्यक्षेत्र की सीमाओं के भीतर सख्ती से रखा जाता है?
3. **沙箱隔离（Sandbox）：**यदि सर्वर में घुसपैठ हो तो क्या ऑपरेटिंग सिस्टम इसे प्रभावी ढंग से रोकने में सक्षम होगा?

可运行服务器 会维护一个信任工作区 URI 白名单,规范化处理百分号编码的路径,校验真实的路径组件边界,并执行物理删除前即时重新检查路径限制──

幼稚的字符串前检查是存在严重漏洞的:

```text
allowed:   file:///work/notes
attacker:  file:///work/notes-evil/secret.md
traversal: file:///work/notes/%2e%2e/private.md
```

इन दोनों बुरी इच्छा पथों को वैधता के समान प्रतीत होता है। पहले नियमन करना आवश्यक है, फिर पथ घटक के लिए पुनः क्रमबद्ध करना आवश्यक है।

##  प्रत्येक अनुरोध के लिए क्षमता  परामर्श

支持表单模式 उबावे का ग्राहक 会声明:

```json
{
  "io.modelcontextprotocol/clientCapabilities": {
    "elicitation": {"form": {}}
  }
}
```

空的 उत्तेजना क्षमता ((即 `"elicitation": {}`) केवल एक ही मॉडल का समर्थन करने के बराबर है।`"elicitation": {"form": {}}`इसी प्रकार समर्थन दिखाएँ एकल मोड──लेकिन केवल URL 模式 को घोषित करें`"elicitation": {"url": {}}`) 则不支持表单―― सर्वर 绝不能内嵌当前请求的功能 中所缺失的模式, भले ही पहले की अनुरोध ने इस मोड को घोषित किया हो――

हर अनुरोध को भी साथ ले जाना चाहिए`io.modelcontextprotocol/protocolVersion` संस्करण अनुपलब्ध या गैर-字符串 प्रकार वापसी `-32602`▽ 不支持的版本字符串返回 `-32022`और निश्चित नहीं है`supported``requested`डाटा── अनुपस्थिति या केवल समर्थित URL का अनुरोध 会返回 `-32021`,并将 `data.requiredCapabilities`设为 `{"elicitation":{"form":{}}}`

没有 JSON-RPC `id`का संदेश सूचना के अंतर्गत आता है. इसे सीधे संसाधित करें, JSON-RPC सफलता या त्रुटि प्रतिक्रिया न भेजें.`202 Accepted`

`clientInfo` निदान के लिए शामिल किया जाना चाहिए, लेकिन यह स्व-घोषणा है, और उपयोगकर्ता के रूप में पहचान के अधिकारों का उपयोग नहीं किया जा सकता है

सर्वर 实现 `server/discover`और वापस शामिल हैं`resultType: "complete"``supportedVersions`、 क्षमताएँ`ttlMs`और `cacheScope` इस आधुनिक डिजाइन के लिए, यह बाहरी रूप से घोषित नहीं होगा Roots क्योंकि यह उपकरण घोषित करता है, यह भी अनिवार्यता को प्राप्त करता है`tools/list`该结果返回确定性 `notes_delete`描述符、合法的 वस्तु 类型 `inputSchema`、सर्वर की पहचान और सार्वजनिक 缓存提示──

## URL 模式(URL मोड)

URL 模式发送一个安全的网址以进行带外(外带)交互:

```json
{
  "method": "elicitation/create",
  "params": {
    "mode": "url",
    "message": "Connect the report service to continue.",
    "url": "https://mcp.example.com/connect/report-service"
  }
}
```

जब संवेदनशील जानकारी को सीधे सर्वर द्वारा नियंत्रित वेब प्रक्रम में दर्ज किया जाना चाहिए (उदाहरण के लिए, तीसरे पक्ष के ओएथ प्राधिकरण) , कृपया URL के मॉडल का उपयोग करें।

`accept` प्रतिक्रिया केवल उपयोगकर्ता द्वारा URL खोलने के लिए सहमति व्यक्त की है, यह प्रमाणित नहीं करता है कि बाहरी बातचीत सफलतापूर्वक पूरी हो गई है।`input_required`परिणाम

URL निकासी 绝绝不能替代 MCP क्लाइंट और MCP सर्वर के बीच पहचान अधिकार तंत्र── यह MCP सर्वर 代表用户 执行外部交互而设计的── सर्वर 必须将浏览क端的用户与发起 MCP 操作的同一已识别权主体紧密绑定──

## 响应分支与处理分支

कृपया विभिन्न कार्य को 视作严的产品逻辑决策,而非同义别名:

| 动作 | 含义 | 安全的 Server 处理行为 |
|---|---|---|
| `accept` | 用户提交了交互内容 | 校验内容并继续执行 |
| `decline` | 用户明确表示拒绝 | 返回一个执行完成且非错误的拒绝结果 |
| `cancel` | 用户关闭对话框或未能完成交互 | 安全停止并允许稍后重试 |

绝不要将缺失内容解读为默许同意. 绝不要将衰退. 转换为重复追问的死循环.

## 关键术语

| 术语 | 2026-07-28 中的含义 |
|------|------------------------|
| Roots | 已弃用的提示性工作区指引，不具备鉴权或沙箱隔离能力 |
| 显式权限范围（Explicit scope） | 在请求参数中清晰可见的工作区、目录或 resource 句柄 |
| 路径限制（Containment） | 规范化路径组件校验，确保目标严格限制在受控边界之内 |
| Elicitation | 在 MCP 操作执行期间用于获取用户输入的 client 特性 |
| 表单模式（Form mode） | 使用受限扁平 schema 的带内（in-band）结构化用户输入 |
| URL 模式（URL mode） | 针对敏感或外部工作流的带外（out-of-band）Web 交互 |
| MRTR | 多轮往返请求，返回 input-required 结果后由 client 发起全新重试 |
| `requestState` | 不透明的状态凭证，由 client 原样回显并由 server 进行完整性校验 |
| Decline（拒绝） | 用户明确作出的拒绝操作 |
| Cancel（取消） | 用户主动关闭界面或在未获批准的情况下中断交互 |
