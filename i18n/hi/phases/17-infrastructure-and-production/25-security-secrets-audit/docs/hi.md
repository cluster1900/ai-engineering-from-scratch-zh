## 学习目标
- 列举四种秘密管理反模式(VCS में कॉन्फिग फाइलों, हार्डकोड किए गए env, सारणी पत्र, स्थैतिक कुंजी), और उनके लिए एक विकल्प प्रस्तावित करें।
- 解释 AI-gateway-pulls-from-vault पैटर्न 为什么是2026 उत्पादन मानक
- 实现一个带一致的标记化(同值 →同位持人) के PII स्क्रबर,让语义得以保留──
- 2026 में वर्सेल की आपूर्ति श्रृंखला की घटना के बारे में बताएं, साथ ही इसके बारे में सीआई/सीडी प्रमाणपत्र स्वच्छता के बारे में भी बताएं।

## 问题
एक अभ्यर्थी ने एपीआई कुंजी के साथ प्रस्तुत किया।`.env`他们很快删除它──但这些键已经进入了 git history──吉特卫视扫描已经捕获它,而你的转换过程是在Slack 通知团队──更新40个配置文件──重新部署所有服务──8小时后,你的服务的一半已经上线了,另一半还在等待部署窗户──

इसके अलावा, उपयोगकर्ता संकेत 包含 मेरा SSN है 123-45-6789. शीघ्र भेजा गया है OpenAI.

इसके अलावा, आपके ईकेएस क्लस्टर के भीतर एलएलएम पॉड किसी भी इंटरनेट होस्ट का उपयोग कर सकता है। कोई भी DNS खोज के माध्यम से डेटा को हमलावर नियंत्रित डोमेन में निकाल सकता है।

एमएलएम सेवाओं की सुरक्षा 必须处理这三类矢量── वॉल्ट समर्थित क्रेडेंशियल──PII स्क्रबिंग──网络输出过选──审计日志──

## 概念
### 集中式 vault + IAM-रोल खींच

**Vault**: हाशिकोर्प वॉल्ट, एडब्ल्यूएस सीक्रेट्स मैनेजर, एज़्यूर की वॉल्ट, जीसीपी सीक्रेट मैनेजर──单一事实来源──

**IAM role**: app/gateway 通过其IAM पहचान 进行认证, बजाय स्थिर कुंजी──Vault 在代币 生命周期内返回秘密──

**The AI-gateway pattern**गेटवे में अनुरोध पर खजाने से 拉取 `OPENAI_API_KEY`在库中轮换;下一次请求拿到新钥匙──无需重新配置──

### रोटेशन पॉलिसी ≤ 90 दिन

सभी एपीआई कुंजी, वाल्ट रूट टोकन, सीआई/सीडी क्रेडेंशियल, यथासंभव स्वचालित रोटेशन, हाते रोटेशन, रिकॉर्ड और ट्रैकिंग की आवश्यकता

### गुप्त स्कैन

- **TruffleHog** प्रति प्रतिबद्धताएं  रीजेक्स + एंट्रॉपी 检测。
- **GitGuardian** वाणिज्यिक,准确率高──
- **Gitleaks** ओएसएस, में CI मध्य संचालित

हर बार प्रतिबद्धता करते हैं, और काम करते हैं।

### शून्य-विश्वास की स्थिति

- सभी खातों को MFA को सक्षम करना होगा।
- 通过 SAML/OIDC SSO
- आरबीएसी (Role-based) या एबीएसी (A attribute-based) बारीक अनाज के उपयोग में है।
- अल्पकालिक टोकन ((以小时计,而不是天)
- डिवाइस की मुद्रा   केवल डिस्क एन्क्रिप्शन के कॉर्प डिवाइस को सक्षम करने की अनुमति देता है 

### पीआईआई / पीआईआई स्क्रबिंग

 शीघ्र  अपने infra  से पहले छोड़ने में:

1. संस्था मान्यता (स्पेस एनईआर, प्रेसिडियो, वाणिज्यिक)
2. 屏蔽匹配到的实体:`"My SSN is 123-45-6789"`→ `"My SSN is [SSN_TOKEN_A3F]"`
3. एक समान मूल्य 映射到同一位持有者,让LLM保留关系──
4. 可选: LLM प्रतिक्रिया पर रिवर्स मैपिंग करें

स्थैतिक रेजेक्स फ़िल्टर 能捕获基本模式;NER 能捕获更多──两者都用──

### इनपुट + आउटपुट गार्डरेल

इनपुटः पहले से ज्ञात जेलब्रेक रोकें, प्रतिबंधित विषयों पर; उपयोगकर्ता के अनुसार दर-सीमा बनाएं।

आउटपुट: प्रयोग करें रेगएक्स स्क्रब 泄露的秘密(API कुंजी पैटर्न、 अस्वीकार संदर्भ 中的 ईमेल पैटर्न), प्रयोग करें वर्गीकरण 检测 नीति उल्लंघन──

### नेटवर्क एक्जिट व्हाइटलिस्ट

LLM सेवाएँ 位于专用子网:
- श्वेत सूचीः`api.openai.com``api.anthropic.com`、वेक्टर डीबी एंडपॉइंट्स、वॉल्ट एंडपॉइंट्स。
- 其他一切: ड्रॉप
- DNS 通过 अनुमति-केवल resolver (DNS-टनेलिंग एक्स्फिल से बचें) 

### लेखा परीक्षा लॉग

- 任何 गार्डरेल यात्राएँ──

## 关键术语
| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Vault | "secrets store" | 集中式 credential management service |
| IAM role | "identity-based auth" | app assume 的 role；返回 short-lived creds |
| OIDC for CI/CD | "cloud-issued tokens" | CI 中没有 static keys — 通过 OIDC 建立 identity |
| TruffleHog / GitGuardian / Gitleaks | "secret scanners" | commit-time secret detection |
| RBAC / ABAC | "access control" | Role-based vs attribute-based |
| PII scrubbing | "data masking" | 移除敏感 entities 或对其 tokenization |
| Consistent tokenization | "stable placeholders" | Same value → same token each time |
| Mesh approach | "Mesh tokenization" | 保留语义的 tokenization pattern |
| Egress whitelist | "outbound allowlist" | 只有允许的 domains 可访问 |
| Audit log | "immutable history" | 用于 compliance 的 append-only record |
