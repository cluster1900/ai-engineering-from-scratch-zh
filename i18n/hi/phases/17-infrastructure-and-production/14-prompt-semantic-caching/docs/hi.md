## 问题
आप अपनी RAG सेवा को शीघ्र कैशिंग प्रदान करते हैं। आप हिट दर को मापते हैं; केवल 7%। आपके प्रॉम्प्ट स्थिर दिखते हैं, लेकिन वास्तव में नहीं हैं। सिस्टम प्रॉम्प्ट में वर्तमान तिथि, अनुरोध आईडी शामिल है, और विविधता के लिए एक नया कैश प्रविष्टि है। प्रत्येक अनुरोध को एक नया कैश प्रविष्टि में लिखा जाता है, इसे शून्य के लिए पढ़ लिया जाता है।

इसके अलावा, आपका एजेंट प्रत्येक उपयोगकर्ता प्रश्न के लिए होगा और दस टूल कॉल चलाएगा। दस अनुरोध पहले कैश में लिखे जाएंगे।

कैशिंग एक अनुबंध है, एक ध्वज नहीं है।

## 概念
### L2  प्रदाता प्रोम्प्ट/प्रिफिक्स कैशिंग

प्रदाता  भंडारण cacheable prefix का ध्यान KV, और अगले एक मेल इस prefix का अनुरोध ऊपर दोहराओ इसका उपयोग करें. आप केवल एक बार भुगतान लिखना लागत, पढ़ें  लगभग मुफ्त में.

**Anthropic (Claude 3.5 / 3.7 / 4 series)**:अनुरोध 中的显式 `cache_control`मार्कर──你标记哪些块可缓存──TTL:5-मिनट(लेख लागत为 1.25x आधार) या 1 घंटे(लेख लागत为 2x आधार)──缓存 रीडःClaude 3.5 Sonnet 上为$0.30/M，而 fresh 为 $3.00/M  便宜 10x(docs.anthropic.com,截至2026-04)。不同型号的价格 不同(Opus/Haiku 分别发布);始终交叉核对现场价格页──

**OpenAI**: ≥1024 टोकन के संकेत स्वचालित कैशिंग(platform.openai.com,2026-04)。 कोई स्पष्ट ध्वज नहीं──在当前 gpt-4o/gpt-5 दर कार्ड ऊपर, कैश इनपुट 约比 ताजा 便宜 10x──doc 和 रिलीज नोट्स 都没有发布官方hit-rate आधार; सामुदायिक रिपोर्ट 在精心设计提示 后大多集中在 3060%──监控`usage.cached_tokens`अपनी स्थिति को मापने के लिए।

**Google (Gemini)**: स्पष्ट एपीआई के माध्यम से संदर्भ कैशिंग; 1M-टोकन संदर्भ अर्थ अर्थ में कैशिंग के लाभ अधिक

**Self-hosted (vLLM, SGLang)**:चरण 17 · 06 介绍 RadixAttention  अपने स्वयं के कंप्यूटर में ऊपर उसी मोड को अपनाने

### L1  एप्लिकेशन 级 सेमेटिक कैशिंग

之前,先哈希提示、对其做嵌入,并查找相似的缓存请求(同胞性高于门值,通常为0.95+) ⋅命中时,返回缓存响应──未命中时,调用 LLM 并缓存结果──

ओपन सोर्सःरेडिस वेक्टर समानता、GPTCache、Qdrant。 वाणिज्यिकःपोर्टकी कैश、हेलिकॉन कैश。

विक्रेता सटीकता का दावा करता है कि यह प्रतिक्रिया की कैश प्रतिक्रिया है, जो कि एक बार में नहीं बल्कि एक बार में होती है।

- खुला-अंत चैट:10-15%
- संरचित FAQ/सहायता:40-70%。
- कोड प्रश्न:20-30%
- आवाज एजेंट दोहराए गए संकेतः50-80%

### समानांतरता विरोधी पैटर्न

आपका एजेंट 10 टूल कॉल करता है। सभी 10 में एक ही 4K-टोकन सिस्टम प्रॉम्प्ट है। एंथ्रोपिक कैश प्रति अनुरोध लिखता है। पहली बार कैश-लेखन प्रदाता पर शीघ्रता देखें  लगभग 300 एमएस 完成。 दो से 10 अनुरोध एक ही मिलीसेकंड विंडो में पहुंचते हैं, और प्रत्येक व्यक्ति कैश मिस करेगा── आप 10 बार लिखने के लिए प्रीमियम, 0 बार पढ़ने की छूट का भुगतान करते हैं──

修复:बैच के साथ अनुक्रमिक-पहला  单独发起请求 1, फिर में 1 का कैश 已填充 后再触发 2-10──给第一工具调用 增加300 ms;节省 5-10x 账单──

### गतिशील सामग्री विरोधी पैटर्न

अपने सिस्टम की शीघ्रता यह दिखता हैः

```
You are a helpful assistant. The current time is 14:32:17.
User ID: abc123. Today is Tuesday...
```

हर अनुरोध अद्वितीय है। प्रत्येक अनुरोध शून्य हिट में लिखा जाएगा।

修复: सभी वास्तविक स्थिति की सामग्री को कैश करने योग्य पूर्वावलोकन में स्थानांतरित करें; गतिशील सामग्री को कैश सीमा में जोड़ें  इसके बादः

```
[cacheable]
You are a helpful assistant. [rules, examples, instructions]
[/cacheable]
[dynamic, not cached]
Current time: 14:32:17. User: abc123.
```

प्रोजेक्टडिस्कवरी ने इस तरह से कैश हिट दर को 7% से बढ़ाकर 74% कर दिया और इस एनाटॉमी को जारी किया।

## 关键术语
| Term | What people say | What it actually means |
|------|----------------|------------------------|
| L2 prompt cache | "prefix cache" | Provider 存储重复 prefix 的 KV |
| `cache_control` | "Anthropic cache marker" | 标记 cacheable blocks 的显式 attribute |
| Cache write premium | "write tax" | 从首次 miss 到 cache 的额外成本（1.25x 或 2x） |
| L1 semantic cache | "embedding cache" | 调用 LLM 前在 app-level 进行 hash-and-embed |
| GPTCache | "LLM caching lib" | 流行的 OSS L1 cache library |
| Cache hit rate | "hits / total" | 从 cache 服务的 requests 占比 |
| Parallelization anti-pattern | "the N-write trap" | N 个 parallel requests 会 N 次 miss cache |
| Dynamic content trap | "the time-in-prompt trap" | prefix 中的 dynamic bytes 会破坏 hit rate |
| RadixAttention | "intra-replica cache" | SGLang 的 prefix-cache implementation |
