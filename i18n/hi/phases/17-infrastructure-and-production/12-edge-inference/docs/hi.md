## 概念

### बैंडविड्थ 才是真正的上限

Decode 会为每代币 读取完整的重量 集合──一个 Q4 का 7B मॉडल 3.5 GB──以 50 GB/s 读取 3.5 GB 需要 70 ms理论上限约为 ~14 tok/s──在 90 GB/s 高端移动DRAM) 下,上限移动到 ~25 tok/s──低于这个数字时,再多计算也没有帮助──

डाटा सेंटर HBM3 以 3 TB/s 读取同样 3.5 GB 只有需要1.2 ms上限是830 tok/s──同样模型,同样重量──不同的内存子系统──

### एप्पल न्यूरल इंजन (M4 / A18)

- सर्वोच्च 38 TOPS──एकजुट स्मृति(CPU और ANE 共享同一个池)没有复印机的费用──
- केयर एमएल + के माध्यम से `.mlmodel`编译模型访问,或通过 PyTorch 经由 धातु प्रदर्शन शेडर्स(MPS)访问。
- Llama.cpp धातु बैकेंड MPS का उपयोग करें, सीधे उपयोग नहीं करते ANE; देशी ANE  को कोर ML रूपांतरण की आवश्यकता है。
- 2026 साल iOS ऐप्स का सर्वोत्तम अभ्यास पथः INT4 वजन + FP16 सक्रियण का उपयोग करें कोर ML──

### क्वालकॉम हेक्सागोन(स्न्यापड्रैगन एक्स एलिट / 8 जे 4)

- सर्वोच्च 45 TOPS── एक सीपीयू और जीपीयू के साथ एक साथ, लेकिन स्वतंत्र मेमोरी डोमेन के साथ SoC में एकीकृत।
- QNN(क्वालकॉम न्यूरल नेटवर्क)SDK एवं AI हब 提供从PyTorch/ONNX का रूपांतरण──
- चैट टेम्पलेट्स ✓ लामा 3.2 ✓ फि-3 ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓ ✓

### इंटेल / एएमडी एनपीयू (Lunar Lake, Ryzen AI 300)

- 40-50 TOPS── सॉफ्टवेयर Apple/Qualcomm के पीछे है; OpenVINO सुधार कर रहा है, लेकिन अभी भी आला है──
- सबसे उपयुक्त विंडोज एआरएम सह पायलट एप्लिकेशन; एएमडी/इंटेल डेस्कटॉप पर ऊपर स्थानीय-पहले के लिए उपयोग किया जाता है मूल 场景──

### वेबजीपीयू + वेबएलएम

- 通过 WebGPU कम्प्यूटर शेडर 在浏览क 中运行模型;无需安装──
- M3 मैक्स ऊपर, लामा 3.1 8B Q4 ~ 41 टॉक / s  के माध्यम से एक ही बैकेंड, लगभग है मूल के 70-80% 
- वेबएलएलएम में 17.6k GitHub सितारे; ओपनएआई-संगत जेएस एपीआई; अपाचे 2.0।
- 2026 कवरेजःक्रोम एंड्रॉइड v121+、सफारी आईओएस 26 GA,फ़ायरफ़ॉक्स एंड्रॉइड 仍在追赶──总体约为 ~70-75% मोबाइल कवरेज──

### एनवीडीए जेटसन परिवार

- ओरिन नैनो सुपर(8GB):可容纳 लामा 3.2 3B、Phi-3,并具有不错的托克/s──
- AGX Orin: vLLM 以 ~40 tok/s 运行 gpt-oss-20b。
- Thor / T4000(JetPack 7.1): AGX Orin के 2x के लिए प्रदर्शन, समर्थन EAGLE-3 और NVFP4──
- TensorRT Edge-LLM(2026) EAGLE-3 का समर्थन करें अनुमानित डिकोडिंग、NVFP4 वजन、छंटों में प्रीफिलडेटासेंटर अनुकूलन 已移植到边缘──

### प्रत्येक लक्ष्य का मात्रा 选择

| Target | Format | Notes |
|--------|--------|-------|
| Apple ANE | INT4 weights + FP16 activations | Core ML conversion path |
| Qualcomm Hexagon | QNN INT8 / INT4 | AI Hub converters |
| WebGPU / WebLLM | Q4 MLC（q4f16_1） | 使用 `mlc_llm convert_weight` + 编译后的 `.wasm`；不支持 GGUF |
| Jetson Orin Nano | Q4 GGUF 或 TRT-LLM INT4 | Memory-bound |
| Jetson AGX / Thor | NVFP4 + FP8 KV | Edge-LLM path |

### बढ़त ऊपर के लंबे संदर्भ में फंदे

Llama 3.1 का 128K संदर्भ है डेटा सेंटर 功能── 8GB रैम के मोबाइल पर,4GB मॉडल + 32K टोकन के 2GB KV कैश + ओएस ओवरहेड = OOM──Edge तैनाती  4K-8K में बनाए रखने के लिए संदर्भ को रखेंगे, जब तक कि सक्रिय KV क्वांटिज़ेशन को स्वीकार न करें(Q4 KV)──

### आवाज एक हत्यारा ऐप है

आवाज एजेंटों के लिए विलंबता  संवेदनशील(पहला टोकन < 500 ms)  स्थानीय निष्कर्ष नेटवर्क विलंबता को पूरी तरह से समाप्त करेगा── भाषण-से-पाठ के साथ व्हिस्पर टर्बो संस्करणों 可在边上运行) 结合后,边缘推理就成为生产质量的语音循环──

## 关键术语

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| ANE | "Apple neural engine" | M-series 和 A-series 中的 on-device NPU；unified memory |
| Hexagon | "Qualcomm NPU" | Snapdragon NPU；用于访问的 QNN SDK |
| WebGPU | "browser GPU" | W3C-standardized browser GPU API；Chrome/Safari 2026 |
| WebLLM | "browser LLM runtime" | MLC-LLM project；Apache 2.0；OpenAI-compatible JS |
| Jetson | "NVIDIA edge" | Orin Nano / AGX / Thor / T4000 family |
| TRT Edge-LLM | "edge TensorRT" | TensorRT-LLM 的 2026 edge port；EAGLE-3 + NVFP4 |
| Unified memory | "shared pool" | CPU 和 NPU 看到同一块 RAM；没有 copy overhead |
| Bandwidth-bound | "memory limited" | Decode 受读取 weights 的 bytes/sec 限制 |
| Core ML | "Apple conversion" | 用于 ANE-native models 的 Apple framework |
| QNN | "Qualcomm stack" | Qualcomm Neural Network SDK |
