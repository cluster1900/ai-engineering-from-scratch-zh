# 国际化（i18n）

英文课程是规范版本。翻译后的**课程** Markdown 由机器生成，且**绝不提交到 `main`**——它们位于单独的 `translations` branch 中，站点会在 runtime 以获取英文内容时所用的相同免费方式获取这些内容（`raw.githubusercontent.com`）。不使用 Vercel function，不使用 KV，也没有按浏览次数计费。唯一的例外是各语言的 **README**，它们为保证质量而手工编写并提交到 `main`（见下文）。

此 pipeline 仅覆盖 `phases/` 下的课程。认证课程仍然只提供英文版本，并且有意排除在机器翻译和图书生成流程之外。

默认引擎是 **NLLB-200**（[No Language Left Behind, Meta AI, 2022](https://arxiv.org/abs/2207.04672)）。这是一个覆盖 200 种语言的开放翻译 Model，运行在 **GitHub Actions runner 内部，不需要 API key，也不会产生账单**。计算使用免费的 CI runner，完全没有翻译 API 成本。付费 LLM provider（Anthropic/OpenAI）和 DeepL 仍可通过 `--provider` 作为质量更高的可选升级方案。

## 组成部分

`languages.json` registry 驱动机器翻译相关界面，包括课程、站点切换器和图书 Matrix。各语言的 **README 是独立的**：其语言集合与翻译 block 位于 `scripts/readme_translations.py` 中，为保证质量而手工编写，并且独立于 registry。

| 组成部分 | 位置 | 是否提交到 main？ |
|-------|-------|--------------------|
| 语言 registry | `languages.json` | 是（一个小文件） |
| 课程翻译 script | `scripts/translate_lessons.py`（仅处理说明文本的 walker） | 是 |
| README generator 与翻译 | `scripts/build_readme_i18n.py` + `scripts/readme_translations.py`（手工编写） | 是 |
| CI workflow | `.github/workflows/translate.yml`（按语言 × phase 分片） | 是 |
| 已翻译课程 Markdown | `translations` branch，`i18n/<lang>/…/<lang>.md` | 否（位于单独 branch） |
| 已翻译 README | `i18n/<lang>/README.md`，由 `README.md` 的 header 链接 | **是** |
| 已翻译图书 | `scripts/build_book.py --lang <code>` 读取已翻译 Markdown，并将 `aiefs-vol{n}-{slug}-<lang>.epub/.pdf` 作为 release asset 输出（每节课均提供英文 fallback） | 否（release asset） |
| 切换器选项 | `site/langs.js`（由 `build.js` 根据 `source`/`ci:true` 集合生成） | 否（与 `data.js` 一样被 gitignore） |
| 站点切换器 | `site/lesson.html` | 是（UI 与 fetch 逻辑） |

## 添加语言

在唯一事实来源 `languages.json` 中添加一个 entry。字段如下：

- `code`——用于文件名、URL 和切换器 value 的 tag。
- `name`——英文名称，用于 LLM provider Prompt。
- `native`——显示在切换器中的 label。
- `nllb`——FLORES-200 code（例如 `zho_Hans`、`tur_Latn`）；默认 NLLB provider **必须提供**此字段——如果请求的语言没有该字段，`translate_lessons.py` 将退出。
- `ci`——设为 `true` 会将该语言加入自动 push 触发的 workflow 构建 Matrix。无论此值如何，`workflow_dispatch` 都可以请求任何已注册语言。

两个 Matrix 都读取 `ci: true`，因此同一个 flag 会让某种语言同时加入课程翻译**和**站点切换器——`build.js` 只会将 `source`/`ci:true` 语言输出到 `site/langs.js`，所以切换器绝不会提供站点无法加载的语言。README bar 独立运行：它可以列出 `readme_translations.py` 支持的任何语言。无需修改其他内容。

## 运行方式

1. 当 push 到 `main` 的内容更改了 `phases/**/docs/en.md`、`languages.json` 或翻译 workflow 本身时，会触发 `.github/workflows/translate.yml`。认证课程变更不会触发它。
2. Matrix 中的**每个（语言、phase）组合对应一个 job**。在 CPU runner 上完整运行一种语言的 503 节课程大约需要 27 小时，远超 6 小时的 job 时限，因此按语言运行的 job 在发布前总会超时。按 phase 拆分后，最大的 job（phase 19，共 85 节课程）约需 4.5 小时，远低于时限。每个 job 都会从 branch 恢复对应语言的先前输出，运行 `translate_lessons.py --phase <phase>`，并通过 fetch-and-retry loop 仅将自己的 `i18n/<lang>/phases/<phase>/` slice 推送回去，因此互不重叠的 slice 可以无冲突地合并。
3. 站点的语言切换器会设置 `?lang=<code>`；`fetchLesson` 从 `…/translations/i18n/<lang>/…/<lang>.md` 获取内容，如果该翻译尚未发布，则会 **fallback 到规范英文版本**。英文（`lang=en`）与 i18n 引入前的 fetch 路径保持逐字节一致。

## 绝不浪费一次运行

每节课程都使用其英文源文件的 `sha256` 作为 key，存入按（语言、phase）划分的 cache（`i18n/<lang>/.cache/<phase>.json`）。该 cache 由 runner 按课程写入，并在 job 完成后**发布到 `translations` branch**。因此：

- 第一次运行只会翻译一次全部内容。之后每次完整运行都只会重新翻译英文内容实际发生变化的课程——其他内容均为 cache hit，并会立即跳过。
- 被取消或中断的 phase job 不会发布，因此会丢失该 job 在 runner 本地的进度；下一次运行将从该 phase **最后发布的** cache 继续。由于每个 shard 只包含一个 phase，它可以从容地在 job 时限内完成并发布。

## 各语言 README

README 是 landing page，因此其翻译采用**手工编写**方式以达到最高质量，而不是由机器生成；这些文件位于 `main` 的 `i18n/<lang>/README.md`。`scripts/readme_translations.py` 保存以精确英文 block 为 key 的翻译字符串；`scripts/build_readme_i18n.py` 会复制英文 README，并仅替换其中已翻译的行区间，以此重新构建每个文件。其他所有内容——banner、badge、584 行课程表、全部代码和链接*文本*——都会原样保留（每次运行都通过 round-trip identity check 断言这一点）。唯一有意进行的转换发生在链接和图片*目标*上：仓库根目录相对路径会添加 `../../` 前缀，使其在两层目录深度下仍能正确解析（fenced code 会被跳过，因此看起来像链接的代码保持不变）。任何没有翻译的 block 都会 fallback 到英文，因此翻译覆盖率可以逐个语言提升。

`python3 scripts/build_readme_i18n.py --check` 会在 CI（`curriculum.yml`）中运行。如果任何已提交的 README 过期，该命令就会失败；每当 README-counts bot 同步英文统计 block 时，也会重新生成这些文件。

## 翻译期间受保护的内容

NLLB 是句子翻译器，而不是遵循指令的 Model，因此 walker 只会让它看到说明文本。它逐行处理课程：fenced code block、表格、图片行和 metadata header（`**Type:** … **Time:**`）都会原样传递；对于其他每一行，它会使用占位符保护 inline `` `code` ``、`$math$`、图片引用、完整 Markdown 链接、`**bold**` 术语和 URL，只翻译它们之间的纯文本片段，然后再恢复原内容。之所以保留粗体片段，是因为在本课程中，它们几乎总是应当保持英文的技术术语（Skip-gram、negative sampling）。

此行为经过机械验证：使用恒等“翻译”运行 walker，可以逐字节重现全部 **503 节课程**，因此实际运行只能更改说明文本。如果占位符无法完成 round-trip，该课程会保留英文版本（fail-safe）。

## 成本

默认 provider `nllb`：**免费。** NLLB-200 在 GitHub Actions runner 中运行——不需要 API key、secret，也没有按 Token 计费的账单。唯一使用的资源是免费 CI 计算资源；Model 会在运行之间缓存，并且只重新翻译发生变化的课程（sha256 cache）。Vercel 成本不会改变。

可选升级方案（`--provider anthropic|openai|deepl`）可以提高流畅度。如果以后希望优化访问量较高的语言，每种语言完整运行一次的成本为几十美元以内。这些 provider 从 `LLM_API_KEY` 环境变量读取 key（DeepL 使用同一个变量作为 auth key）。NLLB 始终是零成本默认选项。

## 质量示例

以下是翻译到 Step 1 的 `05 · 03 Word Embeddings`，展示说明文本如何自然呈现，同时代码、数学表达式、`king - man + woman`、技术术语和 metadata header 保持不变。此示例具备 LLM 级别的流畅度（即 `--provider anthropic` 的输出效果）；免费的 NLLB-200 默认方案在内容保护方面可靠且完全忠实，但措辞略显朴素。如果希望达到这种润色水平，可以在以后将访问量较高的语言升级到 LLM provider。

### 简体中文 (zh)

> # 词Embedding —— 从零实现 Word2Vec
>
> > 词以其所处的语境为意。用一个浅层网络训练这个想法,几何结构便会自然浮现。
>
> **Type:** Build · **Languages:** Python · **Prerequisites:** 阶段 5 · 02(BoW + TF-IDF)、阶段 3 · 03(从零实现Backpropagation) · **Time:** 约 75 分钟
>
> **问题** —— TF-IDF 知道 `dog` 和 `puppy` 是不同的词,但不知道二者含义几乎相同。在 `dog` 上训练的分类器无法泛化到讨论 `puppy` 的评论。你可以靠列举同义词勉强弥补,但这在罕见词、领域术语,以及所有你未曾预料的语言上都会失效。
>
> 你想要的是这样一种表示:`dog` 和 `puppy` 在空间中彼此靠近;`king - man + woman` 落在 `queen` 附近;在 `dog` 上训练的模型能免费地把部分信号迁移到 `puppy`。
>
> **核心概念** —— **分布假说**(Firth,1957):"要了解一个词,就看它与哪些词为伴。" Word2Vec 有两种形式:**Skip-gram** 给定中心词预测周围词(窗口为 2 时 `cat -> (the, sat, on)`);**CBOW(连续词袋)** 给定周围词预测中心词。网络只有一个隐藏层且无非线性:输入是词表上的 one-hot Vector,输出是 softmax,训练后丢弃输出层,隐藏层权重即为Embedding。诀窍是用**负采样(negative sampling)**把对 10 万词的 softmax 转成二分类。

### Türkçe (tr)

> # Kelime Gömmeleri —— Word2Vec'i Sıfırdan
>
> > Bir kelime, birlikte bulunduğu kelimelerden ibarettir. Bu fikri sığ bir ağ ile eğitin, geometri kendiliğinden ortaya çıkar.
>
> **Type:** Build · **Languages:** Python · **Prerequisites:** Aşama 5 · 02 (BoW + TF-IDF), Aşama 3 · 03 (Sıfırdan Geri Yayılım) · **Time:** ~75 dakika
>
> **Problem** —— TF-IDF, `dog` ve `puppy`'nin farklı kelimeler olduğunu bilir ama neredeyse aynı anlama geldiklerini bilmez. `dog` üzerinde eğitilen bir sınıflandırıcı, `puppy` hakkındaki bir yoruma genelleme yapamaz. Eş anlamlıları listeleyerek geçiştirebilirsiniz, ama bu; nadir terimlerde, alana özgü jargonda ve öngöremediğiniz her dilde başarısız olur.
>
> `dog` ve `puppy`'nin uzayda birbirine yakın düştüğü, `king - man + woman`'ın `queen`'e yakın indiği bir temsil istiyorsunuz. Word2Vec bunu verdi: iki katmanlı bir ağ, trilyon token'lık eğitim, 2013'te yayımlandı.
>
> **Kavram** —— **Dağılımsal hipotez** (Firth, 1957): "Bir kelimeyi birlikte bulunduğu kelimelerden tanırsın." İki tür: **Skip-gram** merkez kelimeden çevredekileri tahmin eder (pencere 2 ile `cat -> (the, sat, on)`); **CBOW** çevredekilerden merkezi tahmin eder. Ağın doğrusal olmayan aktivasyonu olmayan tek bir gizli katmanı vardır: girdi one-hot vektör, çıktı softmax'tır; eğitimden sonra çıktı katmanı atılır, gizli katman ağırlıkları gömmelerdir. Püf nokta, 100 bin kelimelik softmax'ı **negatif örnekleme (negative sampling)** ile ikili sınıflandırmaya çevirmektir.

请注意，在这两种语言中，`dog`、`puppy`、`king - man + woman`、`softmax`、`one-hot`、`Skip-gram`、`CBOW`、`TF-IDF`、`Word2Vec` 以及 `**Type:** / **Time:**` label 都保持原样，而周围的说明文本则完成了本地化。这种保护由占位符 round-trip 机制强制实施，而不是依赖 Model 自行判断。
