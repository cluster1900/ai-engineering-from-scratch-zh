# 国际化（i18n）

英文课程是规范源。翻译后的**课程** Markdown 由流水线生成，或由贡献者提交审核，且**不会提交到 `main`**；它们位于单独的 `translations` 分支，网站在运行时通过与获取英文相同的免费方式（`raw.githubusercontent.com`）读取。无需 Vercel functions、KV，也没有每次浏览的费用。各语言的 **README** 单独维护，并提交到 `main`（见下文）。

本流水线仅覆盖 `phases/` 下的课程。认证课程仍仅提供英文版，并明确排除在机器翻译和电子书生成之外。

默认引擎是 **NLLB-200**（[No Language Left Behind, Meta AI, 2022](https://arxiv.org/abs/2207.04672)），这是一个覆盖 200 种语言的开放翻译模型，**直接在 GitHub Actions runner 中运行，无需 API 密钥，也不会产生账单**。计算资源来自免费的 CI runner，完全没有翻译 API 费用。付费 LLM 提供方（Anthropic/OpenAI）和 DeepL 仍可通过 `--provider` 选用，作为更高质量的升级方案。

## 组成部分

`languages.json` 注册表驱动课程自动翻译、界面翻译和网站语言切换器。电子书构建器也从中读取语言名称。各语言的 **README 独立维护**：完整文档列在 `scripts/audit_readme_locales.py` 的 `FULL_LOCALES` 中，存放于 `i18n/<lang>/README.md`。`scripts/readme_translations.py` 中的区块映射仍可辅助起草。这两份 README 清单都不会启用课程或界面翻译任务。

| 组成部分 | 位置 | 是否提交到 main？ |
|-------|-------|--------------------|
| 语言注册表 | `languages.json` | 是（一个小文件） |
| 课程翻译脚本 | `scripts/translate_lessons.py`（仅处理正文的遍历器） | 是 |
| README 维护与结构审计 | `scripts/build_readme_i18n.py` + `scripts/audit_readme_locales.py` | 是 |
| CI 工作流 | `.github/workflows/translate.yml`（按语言 × 阶段分片） | 是 |
| 翻译后的课程 Markdown | `translations` 分支，`i18n/<lang>/…/<lang>.md` | 否（独立分支） |
| 翻译后的 README | `i18n/<lang>/README.md`，从 `README.md` 顶部链接 | **是** |
| 翻译后的电子书 | `scripts/build_book.py --lang <code>` 读取翻译后的 Markdown，并将 `aiefs-vol{n}-{slug}-<lang>.epub/.pdf` 作为发布附件输出（逐课回退到英文） | 否（发布附件） |
| 切换器选项 | `site/langs.js`（由 `build.js` 根据 `source`/`ci:true`/`site:true` 集合生成） | 否（与 `data.js` 一样，被 gitignore 忽略） |
| 网站语言切换器 | `site/lesson.html` | 是（界面与获取逻辑） |
| 网站界面字符串（导航、侧边栏、检查点、面板） | `site/ui-strings.json`（英文键列表与各语言的覆盖译文）+ `scripts/translate_ui_strings.py` + `site/ui-i18n.js`（运行时） | 是（源文件与运行时） |
| 翻译后的界面字符串 | `translations` 分支，`i18n/<lang>/ui.json`，由运行时获取 | 否（独立分支） |

## 添加语言

在唯一事实来源 `languages.json` 中添加一个条目。字段如下：

- `code`：用于文件名、URL 和切换器值的标签。
- `name`：英文名称，用于 LLM 提供方的提示词。
- `native`：切换器中显示的标签。
- `nllb`：FLORES-200 代码（例如 `zho_Hans`、`tur_Latn`）；默认 NLLB 提供方**必须**使用此字段。请求的语言缺少它时，`translate_lessons.py` 会退出。
- `ci`：`true` 启用课程和界面的自动翻译，并使该语言可在网站上选择。
- `site`：`true` 使该语言可选，并启用界面自动翻译，但不自动翻译课程。由贡献者维护的课程应使用此选项。

课程任务矩阵读取 `ci: true`。界面任务矩阵和网站切换器接受 `ci: true` 或 `site: true`；切换器还包含英文源语言。显式的 `workflow_dispatch` 请求可以翻译任意已注册的非源语言，包括贡献者维护的语言。对于没有 `ci: true` 的语言，翻译器只填充尚无已发布文件的课程：它保留每一份现有的贡献者译文，即使其英文已变化，并将其列出以供审核。如需有意替换它们，请在本地向 `translate_lessons.py` 传入 `--replace-maintained`。

巴西葡萄牙语（`pt-BR`）和波斯语（`fa`）使用自动流水线。现有葡萄牙语（`pt`）URL 仍受支持。两个葡萄牙语标签都使用 NLLB 的 `por_Latn` 模型代码，它不会区分地区变体。巴西葡萄牙语的 README 和界面用词可以显式固定；自动生成的课程正文仍有必要接受巴西葡萄牙语审校。

繁体中文（`zh-TW`）使用 `site: true`，使审核后的课程可通过面向 `translations` 分支的 PR 提交，而不因英文源更新被覆盖。将文件放在 `i18n/zh-TW/phases/<phase>/<lesson>/docs/zh-TW.md`，保留英文代码、路径、链接和元数据键。尚未发布译文的课程会回退到英文。此标志启用界面和课程阅读器，并不会添加翻译版电子书的发布工作流。

README 语言栏独立维护：列出 33 个语言区域版本和规范英文。`pt-BR`、`zh-TW` 等地区标签对应不同的 README 目标。添加完整 README 译文时，应翻译全文，在根 README 添加链接，并在覆盖率和结构审计通过后将代码加入 `FULL_LOCALES`。确保从两层目录深度出发的仓库相对目标路径正确。不要在语言栏发布未完成的草稿。其语言集合必须与 `FULL_LOCALES` 完全一致；维护命令不会生成或发布不完整文档。

## 运行方式

1. 向 `main` 推送并修改 `phases/**/docs/en.md`、`languages.json`、界面字符串、任务选择器、课程翻译器或其固定版本的依赖，或翻译工作流本身时，会触发 `.github/workflows/translate.yml`。认证课程变更不会触发它。随后 `scripts/translate_matrix.py` 读取推送范围，只启动可能受影响的任务：每个 `docs/en.md` 发生变化的阶段，为每种自动翻译语言启动一个任务；某语言新标记为 `ci: true` 时启动其全部阶段；`site/ui-strings.json` 或其翻译器变化，或某语言新标记为 `ci` 或 `site` 时启动界面字符串任务。若注册表只修改 `dir`、`locale` 或名称等元数据，不启动任何任务。每次推送运行还会将 `translations` 分支上已发布的源哈希与当前英文比较，并加入每个落后的自动（语言、阶段）任务：即记录过期、缺失或成为孤立记录的情况。因此，被取消（较新的推送会替换 `translate` 并发组中等待的运行）或失败的运行，会由下一次推送修复。若此次推送还改变任务所运行的代码（`translate.yml`、`translate_lessons.py` 及其导入模块，或 `.github/translate-requirements.txt`），或脚本无法读取范围（新分支、强制推送、缺失提交），则启动所有任务。手动运行保留所请求的语言和阶段。
2. 任务矩阵为**每个（语言、阶段）组合分配一个任务**。在 CPU runner 上，为一种语言完整翻译 523 节课大约需要 27 小时，远超 6 小时的任务时限，因此按语言分配的任务总会在发布前超时。按阶段拆分后，最大的任务（第 19 阶段，85 节课）约需 4.5 小时，明显低于时限。每个任务从分支恢复该语言先前的输出，运行 `translate_lessons.py --phase <phase>`，并通过获取与重试循环，仅将自己的 `i18n/<lang>/phases/<phase>/` 分片推送回分支，使互不重叠的分片能够无冲突地合并。
3. 网站语言切换器设置 `?lang=<code>`；`fetchLesson` 获取 `…/translations/i18n/<lang>/…/<lang>.md`，若译文尚未发布，则**回退到规范英文源**。英文（`lang=en`）的获取路径与引入国际化之前逐字节一致。

## 避免重复翻译

每节课都以英文源的 `sha256` 为键，记录在按（语言、阶段）划分的缓存（`i18n/<lang>/.cache/<phase>.json`）中。缓存在 runner 中逐课写入，并在**任务结束时发布到 `translations` 分支**。因此：

- 首次运行会将全部课程翻译一次。此后每次完成的运行都**仅**重新翻译英文源确实发生变化的课程，其余课程均命中缓存并立即跳过。
- 被取消或中断的阶段任务不会发布，因此会丢失该任务在 runner 本地的进度。下次包含此阶段的运行，会从**最后一次已发布**的缓存继续。由于每个分片只有一个阶段，它可以在任务时限内完成并发布。下一次推送运行会包含每个已发布哈希落后于英文的自动阶段，因此无需手动重启；留空输入的手动运行仍会一次性恢复全部阶段。
- 当某节课被删除或移动时，其旧阶段的下一次运行会删除该课的机器译文和缓存记录。贡献者维护的文件永远不会被删除。当整个阶段目录被删除时，它的分片会留在 `translations` 分支上，直到有人手动删除。
- 课程任务结束后，`scripts/translation_freshness.py` 会向运行摘要写入一张表，列出每种已发布语言的最新、过期、缺失和孤立课程，以及没有源哈希的已发布课程，并发出警告，点名每个过期或未记录的课程。对于 `zh-TW` 这类贡献者维护的语言，这份清单就是英文修正后需要同步的已审核译文集合。在本地运行：`git fetch origin translations:refs/remotes/origin/translations && python3 scripts/translation_freshness.py`。

## 各语言的 README

README 是落地页。`FULL_LOCALES` 中列出的语言版本需要翻译读者可见的正文、标题、表格、课程标题、链接标签和图片说明。代码、命令、标识符、URL 和相对目标保持不变；产品名称、已发表论文标题和通用专业术语可以保留原拼写。每份完整的 `i18n/<lang>/README.md` 作为独立文档维护，确保重新生成不会丢失编辑修正。

README 语言栏中的 33 个非英文目标均为完整文档。历史区块渲染器仍可辅助起草，但不会通过维护命令发布文件。只有在翻译整份 README、将语言加入 `FULL_LOCALES`，并更新各语言的语言栏后，才添加新语言。

英文 README 变化时，要更新每个语言版本的相应段落。`i18n/readme-source.sha256` 记录已审阅的英文源，只排除统计区块中的读者数、页面浏览量和日期。标题、段落、表格、链接或图示发生变化后，CI 会失败，直到译文完成审阅。审阅所有语言版本后，更新记录并运行检查：

```bash
python3 - <<'PYTHON'
import sys
sys.path.insert(0, 'scripts')
from audit_readme_locales import SOURCE, SOURCE_DIGEST, source_fingerprint
SOURCE_DIGEST.write_text(source_fingerprint(SOURCE.read_text(encoding='utf-8')) + '\n', encoding='utf-8')
PYTHON
python3 scripts/build_readme_i18n.py --check
python3 scripts/test_audit_readme_locales.py
```

审计会比较标题和正文区块数量、链接目标、显式锚点、每条带链接的课程行（上游当时为 528 条）、编程语言标签、Markdown 与 HTML 表格结构、围栏和内联代码、命令示例、Mermaid 拓扑，以及简介、统计、阶段摘要和学习时间表中的数值事实。它拒绝未翻译的英文正文、标题、表格单元格、图片说明、图示标签和目录树说明，并对共享技术名称和特定语言拼写设置明确例外。这些检查可以发现覆盖不全和结构偏差，却不能证明语言流畅度或细微的技术含义正确；这些仍需编辑审阅。

CI 运行覆盖率和结构检查。验证后，README 数量同步机器人只将读者数、页面浏览量和 ISO 日期复制到各语言的统计区块。它保留翻译后的措辞，绝不会从不完整的区块映射重新生成全文。课程数量或其他英文内容变化时，机器人发布更新前仍须完成翻译审阅。

## 网站界面

课程正文来自 `translations` 分支，但周围的界面（顶部导航、课程侧边栏开关、“本页目录”、检查点循环、测验标题、代码与输出面板、上一页/下一页按钮、首页和目录标签）在页面模板中是静态英文。`site/ui-i18n.js` 在浏览器中翻译这一层。`header.js` 会在每个页面加载它，避免某个页面悄然遗漏。

- `site/ui-strings.json` 是唯一手动维护的输入。`keys` 列出页面使用的英文界面字符串（gettext 模型：英文文本就是消息 ID）。`overrides` 为机器翻译可能出错的字符串固定各语言译文，主要是 Build、Run、Prove、Complete 等单词标签。添加标签时将其追加到 `keys`；添加语言时，在 `languages.json` 中标记 `ci: true` 或 `site: true`。两者都不要求手工编写译文。
- `scripts/translate_ui_strings.py` 在 `translate.yml` 中运行（每种 `ci:true` 或 `site:true` 语言一个小任务），并将 `i18n/<lang>/ui.json` 写到 `translations` 分支。对每个键，优先采用覆盖译文，其次采用此前发布的译文（发布文件会记录固定过的键，因此删除覆盖后会重新翻译，而不是冻结旧译文），否则通过与课程相同的提供方层翻译（默认 NLLB，可用 `--provider anthropic|openai|deepl` 升级）。文件名、路径、命令、`@handles` 和 `{n}` 计数占位符受与课程翻译器相同的占位符机制保护；占位符未能保留的键会保持英文，而不是发布错误译文。大多数运行无需翻译任何内容，也不会加载模型。
- `site/ui-i18n.js` 在运行时从 translations 分支获取 `i18n/<lang>/ui.json`，采用与课程相同的路径；语言尚未发布时回退到英文。它遍历文本节点以及 `aria-label`、`title`、`placeholder` 属性，跳过代码、已渲染的课程 Markdown（网站注入的面板除外）、测验内容、课程标题及语言选择器中的语言自称。`MutationObserver` 处理后续渲染的界面；切回英文时恢复原字符串。键中可用 `{n}` 表示由构建数据填入的计数，例如目录简介：运行时匹配任意数值，并将其带入译文，因此新增阶段或课程不会让键失去匹配。在从右到左的语言中，符合条件但未被词典翻译的英文文本（课程数据、术语表条目、未翻译文案）会在其元素上标记 `lang="en" dir="ltr"`，使标点和数值范围正确显示，而翻译后的界面保留页面方向。Flex 和 grid 容器不变，以维持组件布局的镜像效果；切换语言时会移除这些标记。
- 切换器在语言变化时分发 `aifs:lang` DOM 事件，因此运行时也能在没有 `AIFS_onLangChange` 处理器的页面上工作，例如首页。
- `curriculum.yml` 中运行两项检查。某个键不再出现在任何页面或脚本中，或覆盖译文固定了不在列表中的键时，`node --test site/test_ui_i18n.js` 会失败。因此，文案修改后会明确指出失去对应文本的键，而不是悄然丢弃其译文。`python3 scripts/test_translate_ui_strings.py` 覆盖翻译器的优先级（先覆盖译文，再已发布译文，最后模型）、占位符保护和端到端写入。

## 翻译时保护的内容

NLLB 是句子翻译器，而非遵循指令的模型，因此遍历器只让它接触正文。它逐行处理课程：围栏代码块、表格、图片行和元数据头（`**Type:** … **Time:**`）原样通过；对于其他每一行，它用占位符保护内联 `` `code` ``、`$math$`、图片引用、完整的 Markdown 链接、`**bold**` 术语和 URL，只翻译它们之间的纯文本片段，然后还原。粗体片段会被保留，因为在本课程中，它们几乎总是应保留英文的专业术语（Skip-gram、negative sampling）。

这一点通过机械检查验证：使用不改变内容的“翻译”运行遍历器，可以**逐字节重现全部 523 节课**，因此真实运行只会改变正文。若占位符未能完整还原，该课程会保留英文（安全回退）。

## 费用

默认提供方 `nllb`：**免费。** NLLB-200 在 GitHub Actions runner 中运行，无需 API 密钥或其他机密凭据，也没有按 token 计费的账单。唯一使用的资源是免费的 CI 算力；模型会在各次运行之间缓存，只有发生变化的课程才会重新翻译（sha256 缓存）。Vercel 费用不变。

可选升级（`--provider anthropic|openai|deepl`）可提高译文流畅度，每种语言完整翻译一轮约需十几到几十美元，适合日后润色访问量较高的语言。这些提供方从 `LLM_API_KEY` 环境变量读取密钥（DeepL 使用同一变量读取认证密钥）。NLLB 仍是零成本的默认选项。

### 简体中文 (zh)

> # 词嵌入 —— 从零实现 Word2Vec
>
> > 词以其所处的语境为意。用一个浅层网络训练这个想法,几何结构便会自然浮现。
>
> **Type:** Build · **Languages:** Python · **Prerequisites:** 阶段 5 · 02(BoW + TF-IDF)、阶段 3 · 03(从零实现反向传播) · **Time:** 约 75 分钟
>
> **问题** —— TF-IDF 知道 `dog` 和 `puppy` 是不同的词,但不知道二者含义几乎相同。在 `dog` 上训练的分类器无法泛化到讨论 `puppy` 的评论。你可以靠列举同义词勉强弥补,但这在罕见词、领域术语,以及所有你未曾预料的语言上都会失效。
>
> 你想要的是这样一种表示:`dog` 和 `puppy` 在空间中彼此靠近;`king - man + woman` 落在 `queen` 附近;在 `dog` 上训练的模型能免费地把部分信号迁移到 `puppy`。
>
> **核心概念** —— **分布假说**(Firth,1957):"要了解一个词,就看它与哪些词为伴。" Word2Vec 有两种形式:**Skip-gram** 给定中心词预测周围词(窗口为 2 时 `cat -> (the, sat, on)`);**CBOW(连续词袋)** 给定周围词预测中心词。网络只有一个隐藏层且无非线性:输入是词表上的 one-hot 向量,输出是 softmax,训练后丢弃输出层,隐藏层权重即为嵌入。诀窍是用**负采样(negative sampling)**把对 10 万词的 softmax 转成二分类。

### Türkçe (tr)

> # Kelime Gömmeleri —— Word2Vec'i Sıfırdan
>
> > Bir kelime, birlikte bulunduğu kelimelerden ibarettir. Bu fikri sığ bir ağ ile eğitin, geometri kendiliğinden ortaya çıkar.
>
> **Type:** Build · **Languages:** Python · **Prerequisites:** Aşama 5 · 02 (BoW + TF-IDF), Aşama 3 · 03 (Sıfırdan Geri Yayılım) · **Time:** ~75 dakika
>
> **Problem** —— TF-IDF, `dog` ve `puppy`'nin farklı kelimeler olduğunu bilir ama neredeyse aynı anlama geldiklerini bilmez. `dog` üzerinde eğitilen bir sınıflandırıcı, `puppy` hakkındaki bir yoruma genelleme yapamaz. Eş anlamlıları listeleyerek geçiştirebilirsiniz, ama bu; nadir terimlerde, alana özgü jargonda ve öngöremediğiniz her dilde başarısız olur.
>
> `dog` ve `puppy`'nin uzayda birbirine yakın düştüğü, `king - man + woman`'ın `queen`'e yakın indiği bir temsil istiyorsunuz. Word2Vec bunu verdi: iki katmanlı bir ağ, trilyon token'lık eğitim, 2013'te yayımlandı.
>
> **Kavram** —— **Dağılımsal hipotez** (Firth, 1957): "Bir kelimeyi birlikte bulunduğu kelimelerden tanırsın." İki tür: **Skip-gram** merkez kelimeden çevredekileri tahmin eder (pencere 2 ile `cat -> (the, sat, on)`); **CBOW** çevredekilerden merkezi tahmin eder. Ağın doğrusal olmayan aktivasyonu olmayan tek bir gizli katmanı vardır: girdi one-hot vektör, çıktı softmax'tır; eğitimden sonra çıktı katmanı atılır, gizli katman ağırlıkları gömmelerdir. Püf nokta, 100 bin kelimelik softmax'ı **negatif örnekleme (negative sampling)** ile ikili sınıflandırmaya çevirmektir.

注意，`dog`、`puppy`、`king - man + woman`、`softmax`、`one-hot`、`Skip-gram`、`CBOW`、`TF-IDF`、`Word2Vec` 以及 `**Type:** / **Time:**` 标签在两种语言中均原样保留，周围的正文则已完全本地化。这种保留由占位符的往返还原机制强制保障，而非交由模型自行决定。
