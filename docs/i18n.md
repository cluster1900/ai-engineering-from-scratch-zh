# Internationalization (i18n)

> 同步说明：本文描述上游 fe27da89 的国际化流水线，并非本中文分支的直接提交操作指南。本次只同步文档；新增审计脚本、任务选择器与语言配置尚待独立 PR 同步。所有代码和文档变更仍须通过分支与 PR 审核。

英文课程是规范源。翻译后的**课程** Markdown 由流水线生成，或由贡献者提交审核，且**不会提交到 `main`**；它们位于单独的 `translations` 分支，网站在运行时通过与获取英文相同的免费方式（`raw.githubusercontent.com`）读取。无需 Vercel functions、KV，也没有每次浏览的费用。各语言的 **README** 单独维护，并提交到 `main`（见下文）。

This pipeline covers lessons under `phases/` only. Certification curricula remain English-only and are intentionally excluded from both machine translation and book generation.

The default engine is **NLLB-200** ([No Language Left Behind, Meta AI, 2022](https://arxiv.org/abs/2207.04672)), an open translation model covering 200 languages, which runs **inside the GitHub Actions runner with no API key and no bill**. Compute is the free CI runner; there is no translation-API cost at all. Paid LLM providers (Anthropic/OpenAI) and DeepL remain available as optional higher-quality upgrades via `--provider`.

## Pieces

`languages.json` 注册表驱动课程自动翻译、界面翻译和网站语言切换器。电子书构建器也从中读取语言名称。各语言的 **README 独立维护**：完整文档列在 `scripts/audit_readme_locales.py` 的 `FULL_LOCALES` 中，存放于 `i18n/<lang>/README.md`。`scripts/readme_translations.py` 中的区块映射仍可辅助起草。这两份 README 清单都不会启用课程或界面翻译任务。

| Piece | Where | Committed to main? |
|-------|-------|--------------------|
| Language registry | `languages.json` | Yes (one small file) |
| Lesson translation script | `scripts/translate_lessons.py` (prose-only walker) | Yes |
| README 维护与结构审计 | `scripts/build_readme_i18n.py` + `scripts/audit_readme_locales.py` | 是 |
| CI workflow | `.github/workflows/translate.yml` (sharded per language × phase) | Yes |
| Translated lesson markdown | `translations` branch, `i18n/<lang>/…/<lang>.md` | No (separate branch) |
| Translated README | `i18n/<lang>/README.md`, linked from the header of `README.md` | **Yes** |
| Translated books | `scripts/build_book.py --lang <code>` reads the translated markdown and emits `aiefs-vol{n}-{slug}-<lang>.epub/.pdf` as release assets (English fallback per lesson) | No (release assets) |
| 切换器选项 | `site/langs.js`（由 `build.js` 根据 `source`/`ci:true`/`site:true` 集合生成） | 否（与 `data.js` 一样，被 gitignore 忽略） |
| Site switcher | `site/lesson.html` | Yes (the UI + fetch logic) |
| Site chrome strings (navigation, sidebar, checkpoints, panels) | `site/ui-strings.json` (English key list + per-language overrides) + `scripts/translate_ui_strings.py` + `site/ui-i18n.js` (runtime) | Yes (source and runtime) |
| Translated chrome strings | `translations` branch, `i18n/<lang>/ui.json`, fetched by the runtime | No (separate branch) |

## Add a language

Add one entry to `languages.json`, the single source of truth. Fields:

- `code` — the tag used in filenames, URLs, and the switcher value.
- `name` — English name, used in the LLM-provider prompt.
- `native` — label shown in the switcher.
- `nllb` — the FLORES-200 code (e.g. `zho_Hans`, `tur_Latn`); **required** for the default NLLB provider — `translate_lessons.py` exits if a requested language has none.
- `ci`：`true` 启用课程和界面的自动翻译，并使该语言可在网站上选择。
- `site`：`true` 使该语言可选，并启用界面自动翻译，但不自动翻译课程。由贡献者维护的课程应使用此选项。

课程任务矩阵读取 `ci: true`。界面任务矩阵和网站切换器接受 `ci: true` 或 `site: true`；切换器还包含英文源语言。显式的 `workflow_dispatch` 请求可以翻译任意已注册的非源语言，包括贡献者维护的语言，因此只有在确实希望替换已变更课程的译文时，才应请求这些语言。

巴西葡萄牙语（`pt-BR`）和波斯语（`fa`）使用自动流水线。现有葡萄牙语（`pt`）URL 仍受支持。两个葡萄牙语标签都使用 NLLB 的 `por_Latn` 模型代码，它不会区分地区变体。巴西葡萄牙语的 README 和界面用词可以显式固定；自动生成的课程正文仍有必要接受巴西葡萄牙语审校。

繁体中文（`zh-TW`）使用 `site: true`，使审核后的课程可通过面向 `translations` 分支的 PR 提交，而不因英文源更新被覆盖。将文件放在 `i18n/zh-TW/phases/<phase>/<lesson>/docs/zh-TW.md`，保留英文代码、路径、链接和元数据键。尚未发布译文的课程会回退到英文。此标志启用界面和课程阅读器，并不会添加翻译版电子书的发布工作流。

README 语言栏独立维护：列出 33 个语言区域版本和规范英文。`pt-BR`、`zh-TW` 等地区标签对应不同的 README 目标。添加完整 README 译文时，应翻译全文，在根 README 添加链接，并在覆盖率和结构审计通过后将代码加入 `FULL_LOCALES`。确保从两层目录深度出发的仓库相对目标路径正确。不要在语言栏发布未完成的草稿。其语言集合必须与 `FULL_LOCALES` 完全一致；维护命令不会生成或发布不完整文档。

## How it runs

1. 向 `main` 推送并修改 `phases/**/docs/en.md`、`languages.json`、界面字符串、任务选择器或翻译工作流本身时，会触发 `.github/workflows/translate.yml`。认证课程变更不会触发它。随后 `scripts/translate_matrix.py` 读取推送范围，只启动可能受影响的任务：每个 `docs/en.md` 发生变化的阶段，为每种自动翻译语言启动一个任务；某语言新标记为 `ci: true` 时启动其全部阶段；`site/ui-strings.json` 或其翻译器变化，或某语言新标记为 `ci` 或 `site` 时启动界面字符串任务。若注册表只修改 `dir`、`locale` 或名称等元数据，不启动任何任务。若此次推送还改变任务所运行的代码（`translate.yml`、`translate_lessons.py` 及其导入模块，或 `.github/translate-requirements.txt`），或脚本无法读取范围（新分支、强制推送、缺失提交），则启动所有任务。手动运行保留所请求的语言和阶段。
2. The matrix is **one job per (language, phase)**. A full 523-lesson language run is ~27h on a CPU runner, far past the 6-hour job limit, so a per-language job always timed out before publishing. Splitting by phase keeps the largest job (phase 19, 85 lessons) near ~4.5h, well under the limit. Each job restores its language's prior output from the branch, runs `translate_lessons.py --phase <phase>`, and pushes only its own `i18n/<lang>/phases/<phase>/` slice back with a fetch-and-retry loop, so disjoint slices merge without collisions.
3. The site's language switcher sets `?lang=<code>`; `fetchLesson` pulls `…/translations/i18n/<lang>/…/<lang>.md` and **falls back to canonical English** if that translation isn't published yet. English (`lang=en`) is byte-identical to the pre-i18n fetch path.

## Never wastes a run

Every lesson is keyed by the `sha256` of its English source in a per-(language, phase) cache (`i18n/<lang>/.cache/<phase>.json`), written per lesson in the runner and **published to the `translations` branch when the job finishes**. So:

- The first run translates everything once. Every completed run after it re-translates **only** lessons whose English actually changed — everything else is a cache hit and is skipped instantly.
- 被取消或中断的阶段任务不会发布，因此会丢失该任务在 runner 本地的进度。下次包含此阶段的运行，会从**最后一次已发布**的缓存继续。由于每个分片只有一个阶段，它可以在任务时限内完成并发布。推送只有在某阶段的英文发生变化时才会包含该阶段，因此失败或取消后，应手动启动工作流并留空输入，以恢复全部阶段。

## Per-language README

README 是落地页。`FULL_LOCALES` 中列出的语言版本需要翻译读者可见的正文、标题、表格、课程标题、链接标签和图片说明。代码、命令、标识符、URL 和相对目标保持不变；产品名称、已发表论文标题和通用专业术语可以保留原拼写。每份完整的 `i18n/<lang>/README.md` 作为独立文档维护，确保重新生成不会丢失编辑修正。

README 语言栏中的 33 个非英文目标均为完整文档。历史区块渲染器仍可辅助起草，但不会通过维护命令发布文件。只有在翻译整份 README、将语言加入 `FULL_LOCALES`，并更新各语言的语言栏后，才添加新语言。

英文 README 变化时，要更新每个语言版本的相应段落。`i18n/readme-source.sha256` 记录已审阅的英文源，只排除统计区块中的读者数、页面浏览量和日期。标题、段落、表格、链接或图示发生变化后，CI 会失败，直到译文完成审阅。审阅所有语言版本后，更新记录并运行检查：

```bash
python3 - <<'PYTHON'
import sys
sys.path.insert(0, 'scripts')
from audit_readme_locales import SOURCE, SOURCE_DIGEST, source_fingerprint
SOURCE_DIGEST.write_text(source_fingerprint(SOURCE.read_text(encoding='utf-8')) + '\n', encoding='utf-8')
PYTHON
python3 scripts/build_readme_i18n.py --check
python3 scripts/test_audit_readme_locales.py
```

审计会比较标题和正文区块数量、链接目标、显式锚点、每条带链接的课程行（上游当时为 528 条）、编程语言标签、Markdown 与 HTML 表格结构、围栏和内联代码、命令示例、Mermaid 拓扑，以及简介、统计、阶段摘要和学习时间表中的数值事实。它拒绝未翻译的英文正文、标题、表格单元格、图片说明、图示标签和目录树说明，并对共享技术名称和特定语言拼写设置明确例外。这些检查可以发现覆盖不全和结构偏差，却不能证明语言流畅度或细微的技术含义正确；这些仍需编辑审阅。

CI 运行覆盖率和结构检查。验证后，README 数量同步机器人只将读者数、页面浏览量和 ISO 日期复制到各语言的统计区块。它保留翻译后的措辞，绝不会从不完整的区块映射重新生成全文。课程数量或其他英文内容变化时，机器人发布更新前仍须完成翻译审阅。

## Site chrome

Lesson bodies come from the `translations` branch, but the interface around them (header navigation, the lesson sidebar toggle, "On this page", the checkpoint loop, quiz headings, the code and outputs panels, previous/next buttons, homepage and catalog labels) is static English in the page templates. `site/ui-i18n.js` translates that layer in the browser. `header.js` loads it on every page, so a page cannot silently omit it.

- `site/ui-strings.json` 是唯一手动维护的输入。`keys` 列出页面使用的英文界面字符串（gettext 模型：英文文本就是消息 ID）。`overrides` 为机器翻译可能出错的字符串固定各语言译文，主要是 Build、Run、Prove、Complete 等单词标签。添加标签时将其追加到 `keys`；添加语言时，在 `languages.json` 中标记 `ci: true` 或 `site: true`。两者都不要求手工编写译文。
- `scripts/translate_ui_strings.py` 在 `translate.yml` 中运行（每种 `ci:true` 或 `site:true` 语言一个小任务），并将 `i18n/<lang>/ui.json` 写到 `translations` 分支。对每个键，优先采用覆盖译文，其次采用此前发布的译文（发布文件会记录固定过的键，因此删除覆盖后会重新翻译，而不是冻结旧译文），否则通过与课程相同的提供方层翻译（默认 NLLB，可用 `--provider anthropic|openai|deepl` 升级）。文件名、路径、命令、`@handles` 和 `{n}` 计数占位符受与课程翻译器相同的占位符机制保护；占位符未能保留的键会保持英文，而不是发布错误译文。大多数运行无需翻译任何内容，也不会加载模型。
- `site/ui-i18n.js` 在运行时从 translations 分支获取 `i18n/<lang>/ui.json`，采用与课程相同的路径；语言尚未发布时回退到英文。它遍历文本节点以及 `aria-label`、`title`、`placeholder` 属性，跳过代码、已渲染的课程 Markdown（网站注入的面板除外）、测验内容、课程标题及语言选择器中的语言自称。`MutationObserver` 处理后续渲染的界面；切回英文时恢复原字符串。键中可用 `{n}` 表示由构建数据填入的计数，例如目录简介：运行时匹配任意数值，并将其带入译文，因此新增阶段或课程不会让键失去匹配。在从右到左的语言中，符合条件但未被词典翻译的英文文本（课程数据、术语表条目、未翻译文案）会在其元素上标记 `lang="en" dir="ltr"`，使标点和数值范围正确显示，而翻译后的界面保留页面方向。Flex 和 grid 容器不变，以维持组件布局的镜像效果；切换语言时会移除这些标记。
- The picker dispatches an `aifs:lang` DOM event on change, so the runtime works on pages that have no `AIFS_onLangChange` handler, such as the homepage.
- Two guards run in `curriculum.yml`. `node --test site/test_ui_i18n.js` fails when a key no longer appears in any page or script, or when an override pins a key that is not in the list, so a copy edit names the orphaned key instead of silently dropping its translations. `python3 scripts/test_translate_ui_strings.py` covers the translator's precedence (override, then published, then model), placeholder protection, and the end-to-end write.

## What is protected during translation

NLLB is a sentence translator, not an instruction-following model, so the walker never lets it see anything but prose. It processes the lesson line by line: fenced code blocks, tables, image lines, and the metadata header (`**Type:** … **Time:**`) pass through verbatim; on every other line it protects inline `` `code` ``, `$math$`, image refs, full markdown links, `**bold**` terms, and URLs behind placeholders, translates only the plain-text fragments between them, then restores. Bold spans are kept because in this course they are almost always technical terms (Skip-gram, negative sampling) that should stay English.

This is verified mechanically: running the walker with an identity "translation" reproduces all **523 lessons byte-for-byte**, so a real run can only ever change prose. If a placeholder fails to round-trip, that lesson keeps its English (fail-safe).

## Cost

Default provider `nllb`: **free.** NLLB-200 runs in the GitHub Actions runner — no API key, no secret, no per-token bill. The only resource is free CI compute; the model is cached between runs and only changed lessons are re-translated (sha256 cache). Vercel cost does not change.

Optional upgrades (`--provider anthropic|openai|deepl`) give higher fluency at low-tens-of-dollars per full pass per language, if you later want to polish a high-traffic language. Those providers read the key from the `LLM_API_KEY` environment variable (DeepL uses the same variable for its auth key). NLLB stays the zero-cost default.

## Quality sample

Below is `05 · 03 Word Embeddings` translated through Step 1, showing that prose reads naturally while code, math, `king - man + woman`, technical terms, and the metadata header survive untouched. This sample is LLM-tier fluency (what `--provider anthropic` produces); the free NLLB-200 default is solid and fully faithful on the preservation guarantee, with slightly plainer phrasing. Upgrade a high-traffic language to an LLM provider later if you want this level of polish.

### 简体中文 (zh)

> # 词嵌入 —— 从零实现 Word2Vec
>
> > 词以其所处的语境为意。用一个浅层网络训练这个想法,几何结构便会自然浮现。
>
> **Type:** Build · **Languages:** Python · **Prerequisites:** 阶段 5 · 02(BoW + TF-IDF)、阶段 3 · 03(从零实现反向传播) · **Time:** 约 75 分钟
>
> **问题** —— TF-IDF 知道 `dog` 和 `puppy` 是不同的词,但不知道二者含义几乎相同。在 `dog` 上训练的分类器无法泛化到讨论 `puppy` 的评论。你可以靠列举同义词勉强弥补,但这在罕见词、领域术语,以及所有你未曾预料的语言上都会失效。
>
> 你想要的是这样一种表示:`dog` 和 `puppy` 在空间中彼此靠近;`king - man + woman` 落在 `queen` 附近;在 `dog` 上训练的模型能免费地把部分信号迁移到 `puppy`。
>
> **核心概念** —— **分布假说**(Firth,1957):"要了解一个词,就看它与哪些词为伴。" Word2Vec 有两种形式:**Skip-gram** 给定中心词预测周围词(窗口为 2 时 `cat -> (the, sat, on)`);**CBOW(连续词袋)** 给定周围词预测中心词。网络只有一个隐藏层且无非线性:输入是词表上的 one-hot 向量,输出是 softmax,训练后丢弃输出层,隐藏层权重即为嵌入。诀窍是用**负采样(negative sampling)**把对 10 万词的 softmax 转成二分类。

### Türkçe (tr)

> # Kelime Gömmeleri —— Word2Vec'i Sıfırdan
>
> > Bir kelime, birlikte bulunduğu kelimelerden ibarettir. Bu fikri sığ bir ağ ile eğitin, geometri kendiliğinden ortaya çıkar.
>
> **Type:** Build · **Languages:** Python · **Prerequisites:** Aşama 5 · 02 (BoW + TF-IDF), Aşama 3 · 03 (Sıfırdan Geri Yayılım) · **Time:** ~75 dakika
>
> **Problem** —— TF-IDF, `dog` ve `puppy`'nin farklı kelimeler olduğunu bilir ama neredeyse aynı anlama geldiklerini bilmez. `dog` üzerinde eğitilen bir sınıflandırıcı, `puppy` hakkındaki bir yoruma genelleme yapamaz. Eş anlamlıları listeleyerek geçiştirebilirsiniz, ama bu; nadir terimlerde, alana özgü jargonda ve öngöremediğiniz her dilde başarısız olur.
>
> `dog` ve `puppy`'nin uzayda birbirine yakın düştüğü, `king - man + woman`'ın `queen`'e yakın indiği bir temsil istiyorsunuz. Word2Vec bunu verdi: iki katmanlı bir ağ, trilyon token'lık eğitim, 2013'te yayımlandı.
>
> **Kavram** —— **Dağılımsal hipotez** (Firth, 1957): "Bir kelimeyi birlikte bulunduğu kelimelerden tanırsın." İki tür: **Skip-gram** merkez kelimeden çevredekileri tahmin eder (pencere 2 ile `cat -> (the, sat, on)`); **CBOW** çevredekilerden merkezi tahmin eder. Ağın doğrusal olmayan aktivasyonu olmayan tek bir gizli katmanı vardır: girdi one-hot vektör, çıktı softmax'tır; eğitimden sonra çıktı katmanı atılır, gizli katman ağırlıkları gömmelerdir. Püf nokta, 100 bin kelimelik softmax'ı **negatif örnekleme (negative sampling)** ile ikili sınıflandırmaya çevirmektir.

Note how `dog`, `puppy`, `king - man + woman`, `softmax`, `one-hot`, `Skip-gram`, `CBOW`, `TF-IDF`, `Word2Vec`, and the `**Type:** / **Time:**` labels stay verbatim in both languages while the surrounding prose is fully localized. That preservation is enforced mechanically by the placeholder round-trip, not left to the model.
