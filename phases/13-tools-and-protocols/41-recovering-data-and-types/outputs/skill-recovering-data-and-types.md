给定你自行构建的 x86-64 目标文件、其 `llvm-objdump -d -r` 清单，以及接收待研究类型指针的函数，产出指令所证明的字段布局、循环所证明的步长、存在 `-g` 构建时与 DWARF 布局的比较，以及任何指令都无法提供的名称和限定符。可在 Claude、Cursor、Codex、OpenClaw、Hermes 或任何读取 SKILL.md 的 agent 中使用此技能。

## 必需输入

- 目标文件、生成它的确切编译器与命令，以及从同一目标文件捕获的 `llvm-objdump -d -r` 文本。
- 第一个参数指向该类型的函数名称，或将同一对象传给这些函数的调用点。
- 若有，同一源码的 `-g` 构建及其 `llvm-dwarfdump --debug-info` 文本。
- 对 C++ 目标文件，提供符号表以及保存虚函数表的 `.data.rel.ro.*` 节的重定位记录。
- 第 41 课的分析遍和读取器（`code/main.py`），或能够记录每个字段背后指令的等价实现。

## 步骤

1. 将清单解析为函数。将每条重定位行附加到其上方的指令，使调用携带被调用方名称。
2. 以 System V 参数寄存器中的指针为初始状态，对每个函数进行前向跟踪。将基址保存指针的每个内存操作数记录为访问，包含根、偏移、宽度、类别、符号性和存储标志。记录 64 位增量，将后向分支记录为循环，并记录每次调用的参数值。
3. 对每个循环，将通过同一基址寄存器进行的同宽访问分组。如果偏移间隔为 `d`，循环步长为 `k * d`，且有 `k` 个不同偏移，则将它们折叠到一个偏移，并记录 `unrolled`。完成这一步前，不要相信任何超出步长的偏移。
4. 收集所有类别的步长证据：移位和乘法产生的索引比例因子、循环步幅、偏移差，以及调用点的元素偏移。步长是它们的最大公约数。为每个数值标明类别。
5. 构建字段。合并同一偏移和宽度的访问。只有从字段加载的值随后被用作基址或通过 `lea` 推进时，才将该字段标记为指针。将宽度不同的重叠访问记录为冲突。
6. 若有 `-g` 构建，通过缩写表以及重定位后的 `.debug_str_offsets` 和 `.debug_addr` 表读取其 DWARF 5。对照 `llvm-dwarfdump` 检查单元头、成员偏移和字节大小。逐字段比较，将每行标为 `match`、`no-evidence`、`size-mismatch`、`pointer-unproven`、`kind-mismatch` 或 `unexpected`。
7. 根据 System V 规则检查恢复的布局：每个字段位于自身大小的整数倍处；大小是最严格对齐的整数倍；空隙出现在规则要求填充的地方。违反规则意味着紧凑布局结构体、位字段或字段推断错误。
8. 对 C++ 目标文件，从重定位读取每个 `_ZTV` 符号：到顶层对象的偏移、类型信息，然后从内部 16 字节处的地址点读取槽位。读取每个 `_ZTI` 的类别、名称字符串和基类。对于寄存器从对象偏移 0 加载的每个 `call *disp(%reg)`，将其解析为 `disp / 8`，并按类列出候选函数。解修饰每个 `_Z` 名称，并对照 `llvm-cxxfilt --no-strip-underscore` 检查。
9. 将每个名称、限定符、被指向类型和别名假设写为未知或推断。指令不提供其中任何一项。

## 必需报告

针对该类型报告：

- 目标文件名称、编译器、构建命令和清单路径
- 见证函数，以及它们共享同一类型的证据（调用点或分析人员断言）
- 字段表，包含偏移、大小、类别、符号性、访问次数和每次访问的地址
- 指针证明及对应解引用指令
- 步长表，包含每个值及其类别、折叠的循环、最终步长和大小
- 存在 `-g` 构建时与 DWARF 比较的各行，以及已检查的单元头值
- 按 System V 规则进行的对齐检查
- 对 C++：虚函数表及槽位与符号、类型信息类别和基类、虚调用及槽位与候选、解修饰名称
- 全部未知项：没有证据的成员、未证明的指针、名称、限定符、被指向类型

## 必须拒绝的做法

- 未检查循环展开，就报告超出步长的偏移。
- 将单个循环增量当作元素大小。
- 没有解引用证据，就将 8 字节字段称为指针。
- 将 1 字节比较认定为有符号或无符号 char。
- 没有调用点证据或记录的断言，就将多个函数的访问合并成一个结构体。
- 在可重定位目标文件中，按原始索引读取 `.debug_str`，或不应用重定位就读取 `.debug_addr`。
- 用 DWARF 5 布局解析 DWARF 4 头。
- 从符号起点而非地址点读取虚函数表槽位。
- 将某个目标文件缺失虚函数表当作该类没有虚函数表的证明。
- 将反编译器的类型名称直接复制到报告中作为证据。
- 编造成员名称。

## 产出

返回以下章节：

1. 见证：函数、根和别名证据。
2. 访问：包含地址的完整访问表。
3. 布局：字段、指针证明、冲突、空隙和对齐检查。
4. 步长：每个值及类别、应用的折叠、步长和大小。
5. DWARF：单元头检查和比较行，或声明不存在调试构建。
6. C++：虚函数表、类型信息、虚调用和解修饰名称，或声明目标文件没有这些内容。
7. 未知项：证据未能覆盖的每个成员、类别、名称和限定符。

以第一个未知项结尾。如果没有未知项，说明与 DWARF 匹配的成员数，以及相互一致的步长来源数。
