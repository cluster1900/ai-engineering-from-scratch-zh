给定你编写并带调试信息编译的程序、该构建的反汇编清单，以及前期分析得到的静态结论列表，执行一次调试器运行并保存会话记录，为每项结论在每次停止时生成一条证据记录。可在 Claude、Cursor、Codex、OpenClaw、Hermes 或任何读取 SKILL.md 的 agent 中使用此技能。

## 必需输入

- 源码、确切编译命令及生成的二进制。只调试你自己制作的构建。
- 该二进制的 `llvm-objdump -d` 或 `objdump -d` 清单，使断点地址来自清单，而非凭记忆填写。
- 结论涉及的结构体类型的 DWARF 转储，或 `ctypes` 布局，作为字段偏移来源。
- 待检验结论，每项用一句话指明函数、寄存器或地址、预期值或边，以及来源课程或文档。
- 调试器：macOS 上使用 Command Line Tools 或 Xcode 的 lldb，Linux 上使用 lldb 或 gdb。记录版本字符串。

## 步骤

1. 阅读清单。为结论涉及的每个函数记录起止地址。对具有边结论的函数中的每个条件分支，记录分支地址、目标和顺序落下地址。
2. 运行任何内容前，将调试器命令写入文件：每个函数一个 `breakpoint set -n`，每个分支后继一个 `breakpoint set -a ADDR -s MODULE`，一个读取参数寄存器、第一个参数后方内存及栈帧变量的停止钩子；随后是 `run`、所需观察点、固定数量的 `continue`，最后是 `breakpoint list` 和 `watchpoint list -v`。
3. 使用 `settings set interpreter.stop-command-source-on-error false` 以批处理模式运行调试器，使进程退出后的命令失败不会结束会话。保存完整输出作为会话记录，在头部写入命令行和调试器版本。
4. 将会话记录解析为各次停止。每次停止包含程序计数器、函数、停止原因、钩子打印的寄存器和内存，以及栈帧变量。将钩子输出附加到其后的停止报告。
5. 在每次可检验某结论的停止处评判它。寄存器结论将寄存器与栈帧变量比较。字段偏移结论按 DWARF 偏移解码内存字，并与栈帧变量字段比较。边结论读取函数入口处的被比较值，检查下次停止是否为提升后条件预测的后继。调用边结论在进程退出后统计入口停止次数。
6. 观察一致时写 `confirmed`，不一致时写 `refuted`，没有停止能够检验时写 `not-observed`。说明未观察到的原因：断点从未命中、观察点从未设置，或进程没有退出。
7. 对同一源码的优化构建重复执行。编译器内联函数处可能出现已解析但命中次数为 0 的断点，应将这些结论保持为 `not-observed`；但若结论涉及调用边本身，完整运行会反驳它。
8. 若运行无法启动，记录确切错误。在 macOS 上，沙箱 shell 报告 `attach failed ((os/kern) invalid address)`，而缺少 `com.apple.security.get-task-allow` 的强化目标会拒绝任务端口。两者都不是关于程序本身的证据。

## 必需报告

- 编译器、调试器版本、操作系统，以及每个使用的二进制的构建标志
- 会话记录文件名及生成每个文件的命令
- 按顺序列出停止，包含程序计数器、函数、原因和读取的寄存器
- 每项结论及判定、产生判定的停止索引和观察文本
- 运行结束时的断点和观察点命中次数
- 进程退出状态及标准输出
- 仍为 `not-observed` 的结论及各自原因

## 必须拒绝的做法

- 将断点已解析视为代码运行的证明。
- 将命中次数为零视为函数是死代码的证明。
- 没有 DWARF 或 ABI 规则提供的字段偏移，就通过指针读取结构体。
- 在非函数入口的停止处比较参数寄存器，因为它此时可能保存遗留值。
- 仅根据分支指令而非后继处停止来评判边结论。
- 对优化构建中存放在寄存器里的局部变量设置观察点，并将没有命中作为证明。
- 对不是你构建的二进制运行调试器，或附加不属于你的进程。
- 判定后删除会话记录。会话记录才是证据，判定由它推导。
- 将单个输入上的运行报告为对全部输入的结论。

## 产出

返回以下章节：

1. 构建：编译器、标志、调试器，以及所用清单和 DWARF 文件。
2. 计划：原样的命令文件，注明每个断点地址及来源。
3. 停止：时间线，每次停止一行。
4. 判定：每项结论一行，包含确认、反驳、未观察到的次数及最终判定。
5. 未观察到：每项没有停止检验的结论及原因。
6. 环境事实：二进制签名标志、硬件观察点数量，以及任何启动错误。

以第一项被反驳的结论结尾。如果没有，说明停止次数以及由这些停止确认的结论数量。
