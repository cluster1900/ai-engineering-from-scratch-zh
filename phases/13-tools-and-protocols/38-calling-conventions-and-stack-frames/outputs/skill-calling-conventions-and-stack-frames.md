给定自己构建的目标文件、其 `llvm-objdump -d -r` 清单，以及函数的 C 签名，生成参数位置、帧布局、返回寄存器，并将每项推断与所依据的 ABI 规则核对。该技能可用于 Claude、Cursor、Codex、OpenClaw、Hermes 或任何读取 SKILL.md 的智能体。

## 必需输入

- 目标文件、准确编译命令和编译器版本。
- 与目标文件一起保存的该文件的 `llvm-objdump -d -r` 清单。
- 每个研究函数的 C 签名，以及每种结构体类型的字节大小。
- 构建目标文件所用的 ABI。从文件头读取：ELF `e_machine` 62 表示 System V AMD64 psABI，COFF Machine 0x8664 表示 Microsoft x64，ELF `e_machine` 183 表示 AAPCS64，Mach-O `cputype` 0x0100000c 表示 Apple arm64。
- 第 38 课的分析器（`code/main.py`），或能区分数据读取与地址读取的等价实现。
- 可选：不带 `-fno-asynchronous-unwind-tables` 构建的目标文件，用于读取 `.eh_frame` 或 `.pdata` 与 `.xdata`。

## 步骤

1. 从目标文件头识别 ABI，在读取任何指令前记下适用规范。
2. 读取序言：x86-64 上的 push、可选的 `mov %rsp, %rbp` 和 `sub $N, %rsp`；AArch64 上的 `sub sp`、以 sp 为基址保存 x19 至 x30 的 `stp` 和 `str`，以及 `mov x29, sp` 或 `add x29, sp, #k`。记录每个保存寄存器相对入口栈指针的偏移，以序言到达的最深栈指针位置作为帧大小。
3. 遍历函数体一次，记录每个先读后写的参数类寄存器。内存操作数及 `lea` 的基址和索引寄存器都算读取。`mov`、`lea`、`cvtsi2sd` 及清零模式 `xor r, r` 的目标仅算写入。调用后，将易失寄存器集合标记为已写。
4. 将入口栈指针上方的每次加载记录为栈参数槽：System V 从 8(%rsp) 起；Microsoft x64 在 32 字节影子空间上方，从 40(%rsp) 起；AAPCS64 从 0(sp) 起。使用已记录的帧指针偏移转换基于 `rbp` 和 `x29` 的偏移。
5. 寻找返回寄存器：退出前最后一次访问为写入的结果寄存器。作为数据操作数读取会排除候选，作为地址基址读取则不会。隐藏结果指针是既被用于存储又复制到 `rax` 的第一个参数寄存器，或 AArch64 上的 `x8`。
6. 将 ABI 规则应用于 C 签名：System V 将每个八字节单元分类为 INTEGER、SSE 或 MEMORY，从两个独立列表取寄存器；Microsoft x64 将槽 k 分配给 RCX/RDX/R8/R9 或 XMM0 至 XMM3，非 1、2、4、8 字节结构体按引用传递；AAPCS64 分配 x[NGRN] 和 v[NSRN]，超过 16 字节的结果使用 x8。比较预期位置与观察位置，并逐条规则记录一致性。
7. 检查栈帧规则：被写入的被调用者保存寄存器必须出现在保存集合；每次调用满足 `(rsp + 8) % 16 == 0` 或 `sp % 16 == 0`；每次 Microsoft x64 调用在返回地址下方至少有 32 字节；Microsoft x64 或 AAPCS64 不访问栈指针以下空间，System V 至多使用 128 字节；尾声恢复序言保存的内容，栈指针回到入口值。
8. 有栈展开数据时，解码并比较：将 `UWOP_PUSH_NONVOL`、`UWOP_ALLOC_*` 与压栈和分配操作比较，将 `DW_CFA_offset` 规则与保存寄存器偏移比较，将最深 CFA 偏移与最深栈指针比较。
9. 有其他工具时，用准确命令采集它对同一函数的原型或参数列表，记录其与源码、字节的一致和不一致之处。

## 必需报告内容

对每个函数，报告：

- 目标文件名、格式、机器架构、ABI、编译器、构建命令、清单路径
- 序言字节和文本、保存寄存器及入口偏移、帧字节数、帧指针偏移或不存在
- 先读后写的参数寄存器、栈参数偏移、溢出保存的参数寄存器及偏移、Microsoft x64 的 home 存储
- 返回寄存器或隐藏指针，以及设置它的指令
- 调用深度、影子空间字节数、栈指针以下使用的字节数
- 每项检查的规则、预期、观察和是否一致
- 存在数据时每个函数的栈展开交叉检查
- 其他工具输出及命令，并将每项不一致作为发现

## 必须拒绝的做法

- 因为目标是 x86-64 就按 System V 读取；COFF 意味着 Microsoft x64。
- 将 `cvtsi2sd` 或 `xor r, r` 的目标算作读取，从而虚构浮点或整数参数。
- 丢弃仅作为 `lea` 基址或索引读取的寄存器，从而漏掉参数。
- 将先写入再消费的寄存器视为返回寄存器。
- 将 `push rbp` 当成帧指针的证明；只有其后的 `mov %rsp, %rbp` 才建立帧指针。
- 从 `lea` 报告栈参数；`lea` 计算地址，不加载数据。
- 从入口栈指针而非当前栈指针衡量红区使用。
- 函数体会压入传出参数时，仍用最深 CFA 偏移与序言帧大小比较。
- 没有源码签名或字节作核对，就接受工具原型。
- 分析并非自己构建或无权研究的程序。

## 输出

返回以下各节：

1. ABI：格式、机器架构、规范，以及决定它的文件头字节。
2. 序言与栈帧：字节、保存寄存器、帧大小、帧指针、红区或影子空间使用。
3. 参数：观察的寄存器和栈槽、签名给出的预期、逐条规则的一致性。
4. 结果：返回寄存器或隐藏指针，以及设置它的指令。
5. 调用点：深度、对齐、影子字节、传出寄存器和存储。
6. 栈展开交叉检查：展开码或 CFI 规则与序言解析的比较。
7. 其他工具：命令、输出，并将每项不一致作为发现。

最后指出第一项不一致。如果没有，说明一致检查的数量和覆盖函数的数量。
