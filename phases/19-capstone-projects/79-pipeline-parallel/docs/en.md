# 管道并行和气泡分析

> 张量并行性将矩阵乘法跨等级分割。管道并行性将模型跨等级分割，每个等级一个阶段。微批次流经管道。开始和结束的空时间就是泡沫；最小化它是整个工艺。

**Type:** Build
**Languages:** Python
**Prerequisites:** 第 19 期 Track C 课程 42-49
**Time:** ~90 分钟

## 学习目标

- 将顺序模型拆分为 N 个阶段，并模拟跨 N 个等级的前向管道。
- 使用 GPipe 计划通过管道安排 M 个微批次（仅向前填充，然后向后）并计算气泡分数。
- 将 bubble 与 Megatron-LM 和 PipeDream 中使用的交错 1F1B 时间表进行比较。
- 捍卫阶段分配：每个阶段的相等计算比每个阶段相等的参数数量更重要。

## 问题

fp16 中的 70B 参数模型仅需要 140 GB 的参数。没有任何消费者 GPU 能够支持它。 ZeRO-3 跨等级分片参数，但仍然需要每个等级为每个前向步骤收集完整层，每层支付 log(N) 跳。管道并行采用不同的路线：将模型切割为 N 个阶段，并在每个等级上放置一个阶段。第 1 层的前向完成第 0 级，并将激活张量移至第 1 级；等级 1 运行第 2 层并交给等级 2；等等。反向流动。内存线性下降，因为每个rank只保留一个阶段；计算是顺序的，这就是泡沫问题。

气泡是管道开始时（等待第一个微批次到达最后阶段）和结束时（等待最后一个微批次回流）的空闲时间。对于 M 个微批次和 N 个阶段，每阶段的气泡分数为 (N-1)/(M+N-1)。当 M=8、N=4 时，即 27%。当 M=64、N=4 时，为 4.5%。当每个步骤有很多微批次时，气泡就会缩小，这意味着每个微批次的批次大小较小，这是驱动微批次设计的约束。

```mermaid
  R1 --> R2[rank 2: stage 2 / layer 2]

  R2 -.backward.-> R1
  R1 -.backward.-> R0
```

### GPipe 时间表

在开始任何向后操作之前，用所有 M 个微批次向前填充管道；然后反向倒流。每个微批次的激活必须保持到向后，因此内存随 M 线性增长。向前需要 M+N-1 个周期，向后需要另外 M+N-1 个周期。每阶段有用工作为2M个周期；每级气泡为2(N-1)个循环。当前进和后退各花费一个单位时间时，气泡分数为(N-1)/(M+N-1)。选择比 N 大得多的 M 可以隐藏气泡。

### 1F1B 时间表

交错：一旦微批次的前向到达最后阶段，就开始其后向并让它流回。时间表每个阶段交替进行一次前进和一次后退。气泡仍然是 N-1，但激活内存受管道深度限制，而不是微批次计数。生产管道使用1F1B（Megatron、PipeDream）。本课首先实现 GPipe，因为它更简单，并以 1F1B 作为练习。

### 为什么每个阶段的平等计算很重要

如果阶段 0 需要 50 ms，阶段 1 需要 100 ms，则每个周期都在阶段 1 上门控。其他阶段每个周期空闲 50 ms，等待阶段 1 释放。相同的参数数量是错误的轴：Transformer 的计算主要由注意力加上每层的 MLP 主导，而嵌入层有很多参数但计算量很少。阶段分配应该均衡每个阶段的 FLOP，而不是每个阶段的权重。

### 微批量与批量

管道运行 M 个微批次，每个微批次的大小为 B。有效批量大小为M*B。管道步骤结束时的梯度是组合 M*B 示例的梯度。气泡分数取决于M；优化器看到的是 M*B。调整 M 意味着将泡沫（M 值较低）与每微批次内存（GPipe 的激活内存值较高，M 值较高）进行交易。

## 构建它

`code/main.py` 实现：

- `PipelineStage`：一个小型 `nn.Module`，保存一个阶段的参数并公开 `forward(activation)`。
- `Pipeline(stages, num_microbatches)`：使用每个阶段的模拟挂钟在模拟阶段上编排 GPipe 时间表。
- `bubble_fraction(num_stages, num_microbatches)`：闭合形式(N-1)/(M+N-1)。
- 4 阶段演示，打印每个微批次的迹线和测量的气泡分数。

运行它：

```bash
python3 code/main.py
```

输出：逐级微批次甘特图以及相对于封闭式预测的气泡百分比。

## 野外生产模式

三种模式使管道平行硬化到足以运输。

**激活检查点与管道配对。** 当 GPipe 上运行 M 个微批次时，激活内存是一个微批次的 M 倍。激活检查点在向后时间重新计算向前时间，以计算换取内存；这种组合使得管道能够处理长序列。

**阶段平衡是测量出来的，而不是假设的。** 生产团队运行一个分析过程，测量目标硬件上的实际每层计算（FLOP 和挂钟），然后根据该测量结果进行分区。 Megatron-LM `--num-layers-per-stage` 标志接受一个列表，以便在阶段具有不同的每层成本时允许不均匀的层计数。

**发送-接收调度必须避免死锁。** 每个阶段都在线路上的接收死锁之前发送的管道。标准修复是交错：偶数级阶段先发送，然后接收，奇数级阶段先接收，然后发送。课程安排明确排名，因此模式可见。

## 使用它

生产模式：

- **Megatron-LM。** 大规模管道并行的参考。采用1F1B，支持张量+管道+数据并行组合。
- **DeepSpeed Pipeline。** 与 ZeRO 集成； ZeRO-1 + 管道是最大开放模型的常见组合。
- **PyTorch Pipe。** PyTorch 原生管道包装器，基于 `torch.distributed.pipeline.sync.Pipe` 构建。

## 关键术语

|术语 |人们怎么说|它实际上意味着什么 |
|------|----------------|------------------------|
|管道| “模型沿深度平行” |每个等级一个阶段，激活逐级流动|
|泡泡| “管道空闲时间”|开始+结束时的 (N-1) 个步骤，其中某些阶段没有工作 |
|微批次| “批次切片”|前进/后退各1个；随着 M 的增大，气泡会缩小 |
| G管道| “填充然后排水” |所有 M 都在任何后退之前前进；高激活记忆|
| 1F1B | “交错时间表” |每级一前一后；有界激活记忆|
